# 自动开发与测试流水线

状态：实施中。当前命令以 `python3 scripts/automation/pipeline.py --help` 为准。

## 范围与完成条件

框架承担需求选择、隔离开发、测试、独立审查、修订重验、本地候选与证据记录。正常测试自动执行；外部模型、付费服务、真实账号、私有会话、VM 原生验收按各自明确前提运行。没有执行的检查不能记作通过。没有独立审查和相同内容摘要的门禁，不能产生已验候选。

本框架不会自动扩大项目权限，不把 issue 正文当作授权，不自动提交主仓库、推送、合并或发布。真实执行策略按 [需求§5](../spec/需求.md#5-全自动开发采用的参考与权限边界)独立登记；凭据与原始会话不得进入执行证据。

## 当前可运行入口

```sh
python3 scripts/automation/pipeline.py --validate-registry
python3 scripts/automation/pipeline.py --list-profiles
python3 scripts/automation/pipeline.py --profile fast
python3 scripts/automation/pipeline.py --profile ci --check-timeout 1800
python3 scripts/automation/pipeline.py --profile browser
```

浏览器运行时使用根目录锁文件：`npm ci`，然后 `npx --no-install playwright install chromium`。不通过安装可变版本绕过锁文件。package 需要实际构建产物；native 只通过验证过的 VM 编排，不能在宿主直接运行 `--cold`。manual 一次显式选择一个编译出的 ignored 探针，不批量读取私有会话或钥匙串。

| 退出码 | 含义 |
| --- | --- |
| 0 | 所有选中检查、执行步骤与内容完整性通过 |
| 1 | 实际检查、执行、审查或清理失败 |
| 2 | 参数、清单、未知或没有可执行检查的需求 |
| 3 | 缺少环境或可信授权，未执行 |

`run.json`、`junit.xml`、`summary.md` 在每轮证据目录生成。步骤失败与检查失败分别列出；源码漂移、清理失败同样阻断。证据不保存子进程原始 stdout/stderr。失败后保留原始结果，不重跑覆盖失败记录。

## 隔离和产出

每轮使用唯一 worktree，不复用用户工作树，不执行 `reset --hard` 或 `clean -fdx`。只移除本轮创建、已确认干净的工作区；含有价值改动的目录保留并明确记录路径与状态。自测使用一次性合成 Git fixture，不在项目中积累工作树。

当前内容指纹使用真实文件摘要，不能用 `HEAD+dirty` 代表多个不同脏版本。开发产物必须在该轮工作区检查，不能误跑主仓库旧代码。修订后测试与审查均失效，必须重验。

快照在首次 Git 对象写入前，对精确文件集合执行内容安全检查，并写入同一份冻结字节；检测范围限于已声明扫描规则。来源备注和提示词只存摘要，来源绑定进入 run、round 与候选。需求、矩阵和注册表在开发轮中变化会返回 `requirement_plan_changed`，必须重新规划；证据基线取自被测工作区。候选清单在全部阻断性收尾成功后才发布，失败的候选只保留 invalid 诊断记录。

检查可声明 `depends_on`。profile 必须包含完整依赖，需求选择自动补齐；执行顺序以依赖图为准，前提失败或 blocked 时不启动下游。随包 CLI 依赖内容收据校验，不能拿旧包运行结果冒充当前构建。`release` 检查集合必须等于 `ci ∪ package`。

## 自动触发和复盘

macOS GitHub Actions 与发布脚本使用同一 ci profile；Actions always 上传本轮 JSON/JUnit/Markdown。Windows 观察 job 不代替已验证平台。只有代码进入远端、Actions 实际完成，才能宣称远程 CI 通过。

`trigger-github.sh` 是手动输入入口，底层参数与来源校验正在加固；它不更改 issue、不发消息、不操作远端分支。X 监听、供应商/真实设备发送仍需额外机制与明确授权。

复盘账本以缺陷键和不同 Seen 日期聚合，同日重复不能凑晋升次数。晋升候选不自动修改权限或工程规范。现有 CLI：

```sh
python3 scripts/automation/lessons.py validate
python3 scripts/automation/lessons.py list
```

## 验证边界

绿灯证明被执行的断言在本轮通过，不证明全部产品需求完成。planned 需求保留空检查映射且选中即拒绝；新增测试目录与壳变体必须被枚举与登记。真实客户端、VM、长期资源预算、跨 OS 重启与发布权限分别取证，不由单元测试总数抵扣。测试规格见 [测试框架](../testing/测试框架.md)与 [需求测试矩阵](../spec/需求测试矩阵.md)。

## 仍未落地（不得当作已覆盖）

- **CI 终态绑定与回滚。** 需远端 Actions 实际完成与发布权限，不在本框架内自动执行。
- **崩溃/重启恢复（原 `recovery` profile）。** 无实现，profile 已删除；留着别名等于宣称不存在的覆盖。
  资源长时协议是 `soak`（`--resource-only`，30 分钟/20 周期），走已验证 VM，其绿灯不是预算判定。

## Red check 与判别力登记

开发轮在每次作者调用**之前**，于一次性副本执行同一组检查并记入 `red_check`（`scope: disposable-copy`、
`authoritative: false`）。基线只作诊断，绿色基线不证明判别力，也不参与候选认证。作者失败或非 edit 场景
同样保留基线；第二轮允许如实记录上一轮修改后的绿灯。基线若越界改动作者或源工作树，在作者调用前拒绝。
独立 worktree 加摘要检查不是 OS 沙箱，不能保证任意外部路径没有副作用。

`discriminating_by` 是反例声明（`command` + `reason`），声明本身不等于本轮已验证。两项登记现在都会在
一次性副本中**真实执行**并绑定结果：`automation.artifact`（移除内容比较后收据假绿）与
`automation.snapshot`（凭据形态字节被拒，且移除该检查后同一字节被接受）。执行要求严格结构化结果且
退出码为 0；任一实验未同时证明"原实现拒绝"与"移除后假绿"即判失败，任意非零退出或成功文字都不是判别力证明。

## 失败暂停与重复输入

具有运行身份的 development、profile 和 configuration 在非零结束时统一写 `pause.json`（阶段、outcome、rc、
未通过项、来源摘要、通知状态，权限 0600，不含原始提示词）。只读参数校验不创建运行。暂停写失败进入
`pause.record` 失败诊断；运行目录不可写时尝试证据根目录，均不可写则明确报错，不能保证物理落盘。
通知默认关闭，仅 `--notify-failure` 显式开启才发；通道缺失、超时或失败会尝试 `notify.log` 并标记
`delivered: false`，日志写入状态单独进入回执。门禁自身不发送通知。

记录用 `write_guarantee` 自报写入保证：`anchored_dir_fd` 表示逐级锚定目录 FD、拒绝符号链接父目录；
`unanchored_no_symlink_refusal` 表示本机缺少该能力，改走独占创建加原子替换的较弱路径——**失败记录写不出来
比保证较弱更糟**，所以非 POSIX 平台仍必须留下记录，只是不声称它拒绝了符号链接。Windows 上的较弱路径
尚未实机取证。

重复提交以 `trigger + source/prompt/snapshot 摘要` 判定，且只有**真正交付候选的成功运行**才算已了结——
未完成的失败运行不阻塞重试，否则一次失败会让请求永久卡死。源码指纹变化视为合法重试。判定发生在授权与
参数校验之后，未授权驱动等仍报告自身原因。证据目录缺失时 fail-closed；损坏或不带来源身份的历史记录
会跳过，因此损坏历史下不能保证去重，不能据此宣称全面 fail-closed。

## 长时协议预算

有效检查超时为 `max(--check-timeout, registry.timeout_seconds)`，显式传入更短的 CLI 值也不能压低
协议声明预算。资源 soak 要求 30 分钟静置采样和 20 次窗口开关循环；6300 秒是租约上限，6600 秒是
宿主传输超时，7200 秒是 runner 预算，不是固定运行时长。真实运行耗时 3862.7 秒，协议和独立清理均通过，
`budget_assessed=false` 仍表示尚无资源预算结论。进程年龄用同一时基或 `etime`，不能按两台机器墙钟差推断。

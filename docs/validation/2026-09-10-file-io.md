# 文件监控与日志读取优化验证

基于 `270b8aa`，工作区起始无未提交改动。核对近期引擎、Token、清理、设置及事件 ID 修复，重点处理上一轮遗留的文件 I/O 边界。保留现有采样调度与 UI 交互，本次不是全仓逐行审计。

## 发现与修复

1. **中文日志整段消失**：16 KiB / 64 KiB 尾读可能落在 UTF-8 字符中间，原代码将整块解码失败视为空日志。新增共享 `LogTailReader`，先定位完整行再逐行解码；末行尚未写完的 UTF-8 不再遮蔽前面记录。
2. **首行残片伪装完整记录**：读取从行中间开始时，原实现仍返回残片。新实现额外读取前一个字节识别行边界，丢弃被截断的首行；保留恰好从行首开始的记录和完整但没有末尾换行的记录。
3. **读量失去上限**：原代码确定偏移后读取至 EOF，文件持续增长时读取量可能超过预算。改为最多读取预算加一个边界字节，使用可抛错的 FileHandle API；空文件、缺失文件及非正行数返回空结果。
4. **设置变化仍显示旧会话数**：修改活跃窗口不失效计数和扫描节流。新配置清除旧计数并使快跳过缓存、节流失效，下一次扫描采用新口径。
5. **新增目录延迟首扫**：监控集合变化时同样使旧节流失效。扫描结果、根时间戳、全扫时间统一在扫描结束时提交，代次校验阻止旧配置的在途结果写回。

## 边界与后续

- 字节预算不足以包含一整条超长日志时，该记录仍会省略；预算内后续完整记录可正常返回。
- 配置变更使下一次扫描重新计算，不承诺同步完成目录 I/O。
- 扫描期间配置变化的代次保护经代码检查；本轮没有注入扫描暂停点做确定性的并发交错测试。
- 未进行真实 CPU/内存基准或全套桌面交互验收，不宣称性能提升百分比。
- 安装缓存 `warmUp` 的“调度即已热”语义仍值得专项验证：多个调用方在首扫中途加入时，完成通知与去重契约可能不一致。本轮未修改该子系统。

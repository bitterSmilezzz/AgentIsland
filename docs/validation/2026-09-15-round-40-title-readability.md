# R40 验证记录：长标题可读性（v0.0.57）

日期：2026-09-15 · 执行：主 agent
触发：用户报告顶部标题有时因文字过长而完全不显示，其他位置也无法判断被截断的内容。

## 实机复现

展开当前 330pt 宽右侧卡片时，顶部实际显示为 `Antigravity · 查看: DeckSc...`。该行还同时承载在线计数和三个固定按钮；Agent 名或动作再长时，SwiftUI HStack 会继续压缩标题，最终接近零宽。Accessibility 树保存了全文，但视觉用户无法获知内容。

## 根因

1. 顶栏把稳定身份、长度不可控的动作、计数和固定操作全部放在单行竞争宽度。
2. Agent 名和动作拆成多个并列 `Text`，分别尾部截断，剩余碎片无法组成完整语义。
3. 主列表、横幅、详情、模型与流水各自设置 `lineLimit`，布局优先级、悬停全文和辅助功能行为不一致。

## 修复

- `AdaptiveHeaderText` 使用双层层级：第一行稳定显示 Agent/状态，第二行显示实时动作；第一行最低可读宽度 96pt。
- 在线计数通过 `ViewThatFits` 在宽度不足时退化为当前在线数字。
- `readableSingleLine` 统一中间省略、布局优先级、全文 help 与 VoiceOver 标签。
- 规则应用到主顶栏、Agent 行、事件横幅、详情标题、模型/会话行、悬停卡、工作台、实时流水和菜单栏概览。
- 顶栏内容高度从 23pt 调整为 34pt；列表可滚区域相应让出 11pt，不提高 460pt 总高度上限。

## 判别性验证

- 修复前新增标题契约测试：`212 通过 / 2 失败`，明确捕获缺少双层标题和统一截断规则。
- 修复后：**214 通过 / 0 失败**。
- 真实 SwiftUI 几何门禁：有/无事件横幅两种布局下 Token 正文均位于 notch 内，PASS。
- `dist/AgentIsland.app` v0.0.57 已重启实机验证：330pt 窄面板顶部标题保持可见，在线数与三个固定按钮未将其挤出；当前无动作时采用单层标题，存在动作时使用标题/动作双层结构。
- Accessibility 树可读出完整标题和在线计数语义；代码签名严格校验通过。

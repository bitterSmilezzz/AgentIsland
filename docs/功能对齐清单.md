### 全量对齐完成规则

每能力组须展开到具体工具、协议、provider、操作与平台的子项。维护 `upstream_source/version → requirement_id → acceptance_case → test_id → gate → run/build evidence`。上游更新先形成差异清单，更新需求版本后再排实现；不可随主分支变化无声扩大“全部”。

当前表穷尽的是官方可见能力组，尚未逐provider/插件/客户端验证。缺固定Todos快照、协议兼容矩阵、云/MCP/多机实测与真短信/推送证据均为open，不算功能完成。

# 0013. 迁移期两个应用各自用不同的本地入口端口

- 状态：已接受
- 日期：2026-09-27
- 相关：[ADR 0010 Swift 冻结与 Rust 前置门](0010-swift-freeze-and-rust-prerequisites.md)、
  [ADR 0009 凭据边界](0009-credential-boundary-borrow-dont-hold.md)

## 背景

本地入口（`/notify`、`/event`、`/session`）是第三方 Agent 把生命周期与用量报进来的地方，
协议与令牌写在 README 里，对用户是**对外契约**：Swift 本体用 `127.0.0.1:41999`
（`SelfReport.defaultPort`，Core 里唯一定义处）。

迁移到 Rust 之后，Rust 端最初也写死 `41999`，注释是「与 macOS 端同端口同协议」。于是：

- **谁先启动谁占住**，后启动那个的本地入口**静默失效**；
- 更糟的是**请求还会「正常返回」**，只是答话的是另一个进程。我实测时就被骗过一次——
  两条响应的文案是 Swift 的措辞，不是 Rust 代码写的，而我只看了状态码。
- Swift 侧那条路（macOS 13 的构建路径）端口对局域网可达，这个失效面不只是本机。

## 决定

**交付物保持 41999；Rust 端用 42000**（可用环境变量 `AGENTISLAND_EVENT_PORT` 覆盖）。

- `41999` 是 README 里对第三方的承诺，指向它就等于指向**今天真正交付的那个应用**。
  第三方配置不需要为迁移做任何改动。
- Rust 端用 `42000`：两个应用可以同时跑，各自答各自的，互不打扰。
- 端口可被环境变量覆盖：开发、测试（`0` = 让内核挑一个）与**将来 Swift 退场**都用得上。
  认不出的值**回落默认值而不是 panic**——一个手滑的环境变量不该让本地入口整个起不来。
- 两侧都**把实际监听的端口写进日志**，并在绑定失败时明确记录（原先 Rust 是静默退化）。

**协议本身不变**，而且这一版把一处不一致也修掉了：Swift 的调用约定是
**`agent` 在查询串上（`?agent=`）、`session` 在正文里**（理由是 hook 的 http 配置只会原样
POST 事件正文，主会话 payload 里没有我们的档案 id）。Rust 第一版两个都从查询串取，
**按 Swift 格式发过来的请求会被拒掉**——这个缺口是靠「拿真 Swift 应用对打」发现的，
自己的测试发现不了。现在两种形式都收，实测同一份请求两边都返回
`{"bound":true,"expiresAt":…}`。

## 什么时候改回 41999

ADR 0010 的迁移收尾（Swift 转为归档、Rust 成为默认交付物）时，把
`DEFAULT_EVENT_PORT` 改回 `41999` 并同步 README。在那之前**不要**改：
两边同时用 41999 就会回到本文开头那个「谁先起谁说话」的状态。

## 后果与代价

- 第三方若同时想喂两个应用，得配两份地址（迁移期本来也只有极少数人会这么干）。
- 令牌文件**共用**（`~/Library/Application Support/AgentIsland/report.token`），
  所以「同一枚令牌 + 两个端口」是迁移期的实际形状；这一点写进 README，不让它成为暗知识。
- 端口不再是常量而是可配置的，测试因此改用**纯函数** `parse_event_port`/`resolve_session_ids`
  来守（`std::env::set_var` 是进程级共享状态，拿它测等于给自己埋偶发）。
- **没做**：两个应用同时启动时的运行时互测只做了「各自答话、互不打扰」这一层；
  「第三方同时喂两个」没有真实样本（要装一个 hook 才能验）。

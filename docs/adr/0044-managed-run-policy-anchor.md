# ADR 0044 · 受管理运行策略的凭据锚与回滚拒绝

- 状态：接受实施。
- 日期：2026-11-07。
- 依据：[ADR 0043](0043-managed-run-project-authorization.md) 的显式项目授权与独立版本要求；TASK-03 ISSUE-06。

## 决定

1. macOS 使用系统钥匙串保存单个受管理运行策略锚。锚记录格式代次、随机 epoch、全局 policy revision 与完整策略文件字节的 SHA-256。完整文件摘要同时绑定全部 project ID、授权版本、历史策略版本、角色与根目录身份；策略格式代次单独检查。
2. `keyring` 只编入 macOS 构建。Windows 和 Linux 的授权能力保持关闭，并在界面说明尚未完成原生凭据库验收；不能因策略文件存在或配置成功而打开授权。
3. macOS Keychain 写入 API 没有跨调用的 compare-and-swap。进程内互斥锁与策略路径对应的 OS 文件锁串行执行“读现值 → 核 revision → 写锚与策略”；文件锁是协作协议，不是信任锚。锁文件不保存授权或凭据数据。
4. 策略更新按以下顺序提交：原子写入仅所有者可读的精确目标策略日志；写入并回读 `pending` 凭据锚；原子发布策略文件；写入并回读 `committed` 锚；删除日志。恢复只接受摘要匹配 pending 锚的当前策略或日志；找不到唯一匹配目标时拒绝，不回签、不回退、不猜测。
5. 策略文件与凭据锚不一致、锚损坏/不可读、策略被删除、只恢复其中一侧、并发 revision 过期或恢复证据缺失时，所有授权读取和写入均拒绝。不存在从文件内容推导新锚的自动路径。
6. 首次安装中策略文件与锚都不存在，代表无授权。v0.0.436 的 v1 文件以及没有可信锚的 v2 文件只视为不可信数据：界面不回显旧目录、角色、历史选择或版本；用户对一个项目重新选择目录并逐项确认后，写入新的 epoch，并丢弃文件中所有旧 grant。其他项目必须分别重新确认。
7. 降级到不识别策略格式的旧版时，旧版必须拒绝未来格式；旧版不拥有受管理 runner，因此不得把拒绝解释成成功执行。升级不会自动保留未锚定授权。
8. 卸载/重装、账户迁移和机器迁移不自动重签策略。策略与当前账户钥匙串中的锚成对保留且项目根身份未变时可继续使用；只迁移策略需要逐项目重新确认，只迁移锚或丢失策略则 fail closed。若用户需要清除孤立锚，须明确删除配对的本地授权状态后从无授权状态重新配置。
9. 该机制防止策略文件相对于当前 Keychain 锚的单侧回放；系统凭据库本身的历史快照回滚、同账户恶意进程直接改写凭据，以及系统管理员控制不在本机制保证范围内。不要把普通文件锁或 Keychain 条目描述为硬件防回滚计数器。

## 验收

- Rust 隔离测试覆盖旧策略文件回放、删除策略、只恢复旧锚、损坏/不可读锚、v1 升级重新确认、pending 日志恢复、日志缺失、并发进程锁与 revision 冲突。
- 隔离 macOS VM 中以唯一一次性凭据账户验证 Keychain create/read/update/delete。探针先确认该随机账户不存在，成功或失败后仅清理该次生成的账户；不访问主机用户钥匙串。
- 至少一个回滚拒绝断言须用隔离源码变异验证会失败。

## 后果

- macOS 项目授权可以识别授权策略文件被单独替换成旧有效副本的情况；保存历史采集开关与撤销会一起推进策略 revision 和凭据锚。
- 凭据丢失时牺牲便利性以保持 fail closed。当前没有自动“重置所有本地授权”入口；需要由后续明确授权的产品工作决定是否提供受确认的恢复流程。
- Windows 与 Linux 应用继续可运行，但其项目级受管理授权保持关闭，直到各平台凭据库更新、并发与原生包 L5 证据完成。
- 这不开放 runner、Run now、TASK-05 自有历史写入、密文备份恢复或任何外部副作用。

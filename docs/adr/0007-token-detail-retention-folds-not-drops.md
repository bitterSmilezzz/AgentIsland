# Token 明细按保留窗口折叠，而不是按窗口丢弃

2026-09-21 处理挂了很久的债：结构化 Token 索引（`~/.codex/sessions`、`~/.workbuddy/projects` 这类 JSONL 明细）的留存集合只增不减——唯一的收缩条件是「文件从磁盘消失」。测过再决定：本机 24 天语料 103 份文件 / 200MB / 1,215 条响应；把同一份实现灌到合成语料上（release 构建），**每条留存明细约 780B 常驻（`phys_footprint` 差值口径），整趟重建 0.63ms/千条**，两条都随磁盘语料总量线性上升，500k 条时单趟重建 316ms。v0.0.9x 加的那道「全库戳备忘录」管不了这件事：它只在整棵日志树一个字节都没变时命中，而**任何一次写入**都要把整棵历史树重新摊平一遍，备忘录本身还握着上一趟的完整快照。

决定：**明细留 40 天，其余折进合计**。掉出窗口的响应不再逐条留存，而是累加到 `rolledUpTokens` / `rolledUpCount`（按工具），`usage(now:)` 把这份合计只加进**累计**口径。窗口取 40 天而不是 30 天，是因为时间分析页最宽 30 天——10 天余量免得「刚好掉出分析窗口」的明细被反复折出/折回（折回要重读整份文件）。另外给单个文件加一道 20,000 条的硬上限，触顶时折掉**最早**的那一段。

**核心不变式：折入是保和的**。裁的是明细，不是数字——累计、24h、按工具拆分逐字不变。这一条钉在用例里（`掉出保留窗口的明细折进合计，累计一个数都不变`），并且拿真机对拍过：改动前后 `agentisland tokens --json` 的输出逐字节相同（累计 260,163,366、24h 2,384,098，一个数没动）。**这条对拍证明的是「折入不改数字」，不是「折入被走到过」**：本机最老的日志文件才 24 天，40 天的窗口今天一条都够不着，真机跑的是「完全没折」那一支；折入分支由注入时钟的用例覆盖，测试一律不碰真实个人日志目录。

**效果也量过**：同一套合成语料（500,000 条、跨 347 天）灌进去，留存明细从 500,001 条饱和到 57,601 条（= 窗口内那 40 天），单趟重建 316ms → 183ms。剩下的 183ms 大头是那份探针把每个文件放进独立目录造成的 2,500 次目录枚举，不是索引自己的账——真实布局是 4 个根 103 份文件。

**为什么不是「按窗口过期就好」**：那正是最先写出来的版本，也是最坏的一版。掉出窗口的响应被直接丢弃，面板上的**累计会静默下降**，而累计是用户唯一能看到的历史总量，且没有任何地方说它变过。本仓的口径是「没看到 ≠ 没有」（见 `CONTEXT.md`「Token 数据覆盖」），把历史裁掉却照常显示成一个完整的数字，属于同一类错误。

**由此推出的第二条规则：带过折入的文件不走增量。** 第一版把折入接在增量路径上（旧合计搬过来，只折新读到的那一段），复核时用差分跑出了 bug：折入时的去重只看得见**交给它的那些事件**，而"已经折掉的那一段键"恰恰不在其中。于是 45 天前的老会话被重新追加（resume 一个旧 rollout 是这么个形状）时，同一响应会在新尾段里被算第二遍，并且那第二份落在明细里——**污染的先是岛上的 24h，不只是累计**。修法是让这类文件整份重读：`canAppend` 额外要求 `rolledTokens == 0`，`fold` 于是重新看得见这个文件的全部已知事件。代价落在罕见的路径上（跨 40 天还在写的会话文件、以及被上限裁过的病态文件）。上限那一侧同源，也补了断言：把被裁掉的响应再追加一遍，累计不能动。

**为什么不做「跨文件重复也不失真」的那版**：同一响应若出现在两份不同文件里、且至少一份已经折掉，会各折一次、算两遍。要修就得在索引里长期留一份「已折入 id」台账，而这份台账**只要 producing 文件还在磁盘上就不能回收**——按 id 长度与字典槽位估约 100B/条（这个数是推算，不是实测），等于把线性增长的存量从 780B/条降到 100B/条，却仍然不封顶；同时多出一个「集合缩小即整表重建」的状态机，它出错的方式又是一次数字错。为还没被真实数据碰到的场景付这个代价不划算，于是明确接受这一处不精确，边界写清楚：

- 需要 **跨文件** 重复 **且两份拷贝时间戳不同** 才会算两遍。拷贝完全相同（fork/恢复就是逐字抄）时两份一起掉出窗口、一起折进同一次去重，结果与改动前逐字相同。
- 真踩到时多算的那一份可能在 **24h** 里，不止在累计——窗口内那份是明细。
- 本机实测：1,215 条响应里 0 个重复 id；103 份文件逐字节比对首 200KB 摘要，没有一份是另一份的前缀复制。

**这条决定不该被重新发明成配置项**：窗口和上限都不进设置页。没有用户反馈说过「我想看 90 天前的按天分布」，而分析页最宽就是 30 天——一个没人能验证的旋钮就是死配置。要扩，先扩分析页的档位。

**顺手把 `parse` 里「先拷贝再找标记」倒过来了**（`Data(line)` 换成先在切片上 `range(of:)`），日志里 99% 以上的行是对话正文（本机 200MB 语料只对应 1,215 条响应，命中率 0.6%）。**但这一条不算性能收益：真机冷跑 `agentisland tokens` 改动前后都是 0.92s**（各三次取最小；`Data` 切片的 `Data(line)` 本就是共享存储的写时复制，并不真的搬字节，我最初「把整段 mmap 逐行搬上堆」的判断是错的）。留着它只是因为不再有那 165k 次临时对象，而正确的门槛（`line.count <= 1_000_000` 与 `range(of:)` 都按切片算，不越界也不跨边界误匹配）顺带被钉住了。

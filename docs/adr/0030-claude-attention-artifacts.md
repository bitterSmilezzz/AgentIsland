# ADR 0030 · Claude 问题与方案关口

状态：接受。日期：2026-10-04。

AskUserQuestion 和 ExitPlanMode 的语义分别为待回答与确认方案。类型必须从产生当前 Attention 的具体 tool_use ID 取得，不按原文含“确认”猜测。来源观测指纹包含类型，避免旧的通用确认收据阻止正确分型。

同一 assistant 消息中的多项工具调用逐项核对，以该消息中最近的未收口人工关口优先于执行调用；没有人工关口才显示执行状态。收口仅接受调用之后的主会话 user/tool_result 与相同 ID，旧结果、子会话结果和子会话中断不改变主会话。正文引用按实际选中的调用取得；多项关口仍只投影一个当前摘要，不宣称全量并行待办队列。

沿用 ADR 0029 的事件版本引用、归属/revision 复核、按需只读正文及隐私边界。Claude 问题展示选项及多选标识；私密输入标志或已识别凭据命中时摘要使用通用提示，正文拒绝展示；方案只读具体调用内明确提供的 plan 字符串。不以 planFilePath 或最近计划文件作为隐式文件读取权限，不通过 tool_result 文本推导批准。

[官方 hooks 文档](https://code.claude.com/docs/en/hooks#exitplanmode)说明原始 ExitPlanMode 输入通常为空，plan 与 planFilePath 在传给 hooks 前注入。现有 transcript 读取不能保证取得这些字段。缺正文时仍显示明确关口，说明限制并开放既有来源工具入口；不伪造查看能力。接入 hook 或受控计划采集属于另一项功能，需要明确配置安装、来源鉴权、事件版本、正文生命周期与退出条件。

临时方案正文的可用性不构成新人工关口。可信主消息、工具与来源物理身份的不可逆版本独立于缓存启停；晚到正文只关联当前开放关口的最新观测收据，不重新打开已处理事项，不替换既有精确正文引用。来源身份无法核实时停止任务事件投影；正文失效说明可能原因并回来源工具，不以最近方案替代。

临时查看继承首次采集期限，不因读取或重复投递续期；界面仅获得剩余有效时间，过期或采集状态变化清除已显示正文，来源核对失败回到工具。此机制不保存正文到任务记录。

代价：有明确正文的历史方言可查看；缺正文事件依赖明确启用的只读采集，无法核实时保留分型与来源导航。受控组合回归不能代替真实客户端证明；来源回答、方案批准与任务执行仍不在此能力内。

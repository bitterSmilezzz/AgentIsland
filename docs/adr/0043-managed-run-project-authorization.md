# ADR 0043 · 受管理运行的项目授权与执行者身份

- 状态：接受实施边界。
- 日期：2026-11-06。
- 依据：ADR 0040 的项目级显式预授权要求、ADR 0041 的默认不采集策略、ADR 0042 的受管理运行身份边界。

## 决定

1. `tasks::Project.id` 只作本机数据归属，不代表用户身份、工作目录授权或远程团队权限。创建任务、关联来源或导入记录不会授予执行权。
2. 新项目的运行授权与历史采集都默认关闭。项目授权、角色/runner 清单变化递增独立授权版本；历史采集开关递增独立策略版本。版本递增溢出时拒绝且状态不变。
3. 规划、执行和审查是不同能力。每个运行快照固定 project/task/run、角色、稳定 runner ID、runner 进程代次、执行认领版本、项目授权版本和历史策略版本。启动与每次特权动作/结果接收都要复核当前策略和身份。
4. runner 身份必须由应用拥有的启动/注册器在核验具体进程或认证会话后产生。外部调用者提供的 runner 名称、任务中的 agent 字符串或 machine ID 都不是身份凭证。runner 重启即使复用稳定 ID，也必须具有新代次；旧代次和旧认领不得继续提交结果。
5. 运行授权只涵盖本地规划、执行或审查。Git 推送、合并、发布、通知发送、网关请求及其他外部副作用由所属子系统单独授权；不能从 project grant 推导出来。
6. 自有历史写入还需历史策略显式启用，且快照中的策略版本仍与当前版本一致。关闭或重新启用采集都会使旧运行快照失效。运行能力与持久化能力互相独立。
7. 计划确认仍是按运行的独立人工关口。项目预授权只允许在用户明确配置的范围内自动推进，不会自动把未确认计划变成可执行计划。

## 实施边界

`managed_run_authorization.rs` 实现可拒绝的纯判据；`managed_run_authorization_store.rs`（v0.0.435）新增独立版本化策略文件、严格解析与原子发布，并将 grant 绑定到经文件系统句柄核验的项目根身份。Unix 使用设备号/inode；Windows 使用卷序列号与 128-bit 文件 ID。缺失策略默认关闭，坏格式/未来版本、符号链接、不安全权限、目录身份变化或发布失败时拒绝并保留原件。`confirm_project` 只是存储层的签发操作，当前没有 Tauri 命令或用户确认界面，也没有策略抗回滚、备份恢复和生产执行器；测试夹具与本地存储 API 都不能作为已完成的生产授权路径。真实写入口必须等到用户确认链路、恢复/回滚边界、runner 启动认证、撤销停止语义和 TASK-05 存储生命周期接线完成后再开放。

权限撤销会立刻拒绝后续特权动作和历史写入。真实执行器上线时还必须将撤销信号送达运行进程、确认停止或明确展示无法停止的状态；仅拒绝保存迟到结果不能替代停止控制。

## 后果

- 授权版本与历史策略版本分开，用户关闭历史采集不会意外授予或撤销代码执行；改变执行角色授权也不会改写历史策略。
- runner ID 仅供稳定审计与去重，runner generation/claim version 负责阻止旧进程或旧机器的迟到结果。
- 本片不扩大 `tasks::Run`、来源事件收据或旧任务 JSON 的含义，不使任何外部 Agent 或工具自动运行。
- 下一阶段仍须接入本地用户确认界面与 Tauri 命令，确定策略文件回滚和备份恢复规则；之后完成可信 runner 注册与进程终止回执，再实现 Run now 和历史写入口。存储核心拒绝路径替换，但尚不抵御策略文件回滚，也没有导入/恢复入口。

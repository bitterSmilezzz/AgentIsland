## 1. 已确认的范围

| 领域 | 定案 | 验收边界 |
| --- | --- | --- |
| 监控内核与灵动岛 | 重点维护检测准确性和呈现品质 | 逐工具核实进程、会话、完成和待确认能力，明确未知与降级，不凭档案存在承诺所有工具均能精确监控 |
| Magpie 借鉴 | 配置与模型/接口目录 + 只读协议探测；当前不做内建网关和智能路由 | 配置目标不是运行模型；只读探测指已核实客户端配置/能力，不自动发网络请求、试密钥或探测端口。既有手动模型清单沿 ADR 0038 |
| 提醒 | 岛内横幅与系统通知，不抢焦点 | 前台可见不等于键盘焦点转移；事件身份、去重、明确启停与远程外发隐私闸门分别保持 |
| 岛形态 | 保持现有窄条，优化信息层级与几何 | 不新增中间展开档位；允许修正裁切、热区和过渡几何。用户没有把旧 Swift 的 6pt 锁成当前 Rust 尺寸 |
| Todo S / Todos | 来源有一个版本就如实说明单版本，不复制正文自建历史 | 任务/运行/事件版本绑定；旧引用失效不能用最新正文替换。完善现有任务关口和来源内容，不默认增加执行/批准能力 |

平台优先级以 [CONTEXT](../../CONTEXT.md) 为准：Mac、Windows、移动端为主；Android 先、iOS 后；Web 倒数第二、Linux 最后。近期 Mac 定方案 → 跨平台完善 Mac → Windows。移动技术尚未定案。

## 3. 技术事实修正

**协议兼容不等于厂商相同。** 配置可指向支持客户端协议的第三方服务，服务也可能是用户已有网关。因此“不内建网关”不等于“只能同厂商切账号”。AgentIsland 不负责协议翻译；目标协议不兼容时明确拒绝或说明限制，不承诺任意客户端使用任意模型。

网关会增加凭据、请求/响应处理、流式协议与资源验证责任，但不必代理全部流量，也不能在未测量前断言必然高占用。本轮不做网关是用户选择的范围，不能以夸大的技术限制作为依据。将来范围改变时另定授权、凭据、协议与资源契约。

监控信号、配置探测与用量账本也有不同来源：三者可共享可信度与身份规则，不能从活动状态推导用量，不能从当前配置反推历史账单。

## 4. 实施建议与完成条件

以下是工程建议，不是用户批准的硬依赖图：

1. 先核实当前支持矩阵与用户可复现的漏报/误报，建立正反例；提高准确性优先于扩档案数量。
2. 在现有窄条/展开结构内验收美观、焦点、四边、浅深色、快速中断和减少动态。UI 品质与监测准确性分别取证。
3. 复查现有任务关口、运行和产出版本；来源单版本/缺正文/改写/过期等有清楚交互，不重复造状态。
4. 配置目录、只读能力探测按已核实协议补齐，与内核改造无不必要依赖。
5. 测试框架先建立可靠清单与产物依赖，见 [27 号修订建议](../workbench/27-test-framework-design.md)；工具选型、CI、代码实现不因本 ADR 自动视为完成。

新方言用结构化脱敏夹具与固定时钟覆盖，数据库方言另附真实 schema 证据；有授权且可隔离时再做真实客户端/真库对照。没有真实样本时标出证据等级，不能要求每个文件方言都提供 SQLite DDL。

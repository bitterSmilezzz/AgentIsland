# ADR 0042 · 受管理运行事件与密文分段

- 状态：接受。
- 日期：2026-11-01。
- 依据：TASK-03 运行模型与 TASK-05 容量测量之间的存储边界。

## 决定

代码中的 `tasks::Run` 继续表示对外部 Agent 来源的只读观测投影；AgentIsland 自己创建的**受管理运行**使用独立身份和授权链，不复用来源事件收据，也不把来源正文并入自有历史。

受管理运行的生命周期控制信息与执行正文分开。正文按受管理运行内单调递增的逻辑事件序列表达，事件具有稳定幂等身份；多条逻辑事件合并到不可变 AEAD 密文段中，段达到候选明文尺寸或遇到需要独立恢复的语义检查点时封存。禁止按每条小消息单独创建并同步文件。密文段使用随机文件标识，认证附加数据绑定格式、项目、运行、段标识及事件序号范围；事件 ID、产物/内容版本和分片序号放在已认证密文内。

64 KiB、256 KiB 和 1 MiB 仅作为下一轮合成轨迹测量的候选段尺寸，不据此决定产品配额、期限或最终段上限。测量需纳入事件封装、索引、备份、原子发布、读取重组和资源占用；在这些数据及跨文件发布恢复语义完成前，容量数字与生产写入口保持关闭。

## 后果

- 现有来源观测与任务页行为保持独立；不能因新增 `ManagedRun` 而扩展 `tasks::Run` 的语义。
- 受管理运行不能仅凭 `run_lifecycle.rs` 的纯状态机判据创建；项目授权、采集策略、执行身份与存储生命周期都必须在真实写路径复核。
- 逻辑事件可以跨多个物理密文段，物理段也可以容纳多条逻辑事件；删除、重试和恢复按逻辑身份结算，不能按文件名推断用户可见内容。
- 大事件的正文分片规则、同一运行并发追加的序号分配，以及密文段和聚合索引之间的崩溃恢复事务仍是实施前置项。

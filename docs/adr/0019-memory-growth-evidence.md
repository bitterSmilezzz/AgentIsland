# 0019 — 以持续增长证据区分内存占用与异常

状态：接受。日期：2026-10-03。

## 问题

Codex 等桌面应用及子进程合计 RSS 可以稳定保持在数 GiB。原规则以 2GiB 持续 5 分钟判异常、以 1.5/2GiB 扣健康度分，把稳定工作集误说成泄漏并反复建议重置。延长重复间隔或给 Codex 单独提高阈值都未消除错误判据。

## 决策

绝对 RSS 只用于读数和趋势分析的低占用过滤，稳定高占用不判异常。所有智能体统一使用持续观测的双增长窗口，判据、生命周期和边界见 CONTEXT 的 Memory growth。健康度与告警共享 Guard 的趋势证据，通知开关独立于观测。一次性快照缺少趋势证据，不生成内存异常。

提醒称“内存连续增长”，包含观测时长、增加量与当前占用；用户可结合任务进展和系统压力判断是否需要处理，不把增长直接认定为泄漏，不默认建议重启。进程重启、采样中断等不能继承旧工作集基线。

## 代价与限制

最短需要约 10 分钟完整采样；稀疏采样选择不下结论。持续增长仍可能来自正常任务，因此它是需留意的资源趋势，不是泄漏诊断。单次暴涨和系统全局内存压力另属不同证据，本轮没有足够可靠采集链路，不凭 RSS 合计捏造这些结论。

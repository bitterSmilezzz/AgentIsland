# v0.0.176 独立复核 · DSH · 2026-09-27 07:07

## 范围与结论

复核外发组第三块：闸门 / 节流 / 记账（`notifier.rs`）+ 传输骨架（`transport.rs`）+
引擎接线（每个事件过闸门并留痕）。结论：**闸门顺序与节流语义逐条对齐、传输可端到端验证**；
https 与 SMTP 如实报未接入。Swift 侧零改动。

## 可核验的行为证据

- **闸门顺序是载荷性的**：`a_broken_config_beats_the_throttle_in_the_reported_reason`
  —— 先让一次外发成功把节流窗口占住，再把配置改坏重试：必须报「缺主题名」而不是「节流命中」。
  反向验证：把节流提到配置检查之前 → 用例红（`left: Suppressed { "节流命中" }`）。
  这条守的是「用户会去等窗口，而不是去补配置」。
- **失败必须能立刻重试**：`the_throttle_window_holds_and_a_failure_releases_it`
  —— 窗口内第 89999ms 被挡、90000ms 放行；失败后 `throttle_keys() == 0` 且 100ms 后即可重试。
  反向验证：删掉撤回 → 用例红（`没送达就该撤掉登记`）。
- **隐私闸门**：`the_master_switch_blocks_everything_including_bypass` —— 总开关关闭时
  连 `bypassPolicy=true`（发送测试）也挡住，且**不碰传输层**、不占节流位。
- **绕过范围**：`the_event_type_switch_is_outside_the_bypass_range`（类型开关挡测试）、
  `quiet_hours_and_presence_are_bypassed_but_the_config_check_is_not`（静默/在场可绕、
  配置检查不可绕）。
- **传输端到端**：`a_two_hundred_means_the_peer_accepted_the_request` 用本地
  `tiny_http` 服务器验证「方法 / 路径 / 头 / 正文真的过了 TCP」，而不只是断言返回枚举。
- **状态码判据**：`status_codes_keep_swifts_permanence_rule`（404 永久、503 可重试、
  429/408/425 可重试、3xx 永久）。
- **拒绝重定向**：`a_redirect_is_refused_because_the_url_carries_the_secret` —— 302 时
  文案指出「不跟着走（密钥不外送给第三方）」且标永久。
- **未接入如实**：`https_and_smtp_are_reported_as_unwired_instead_of_silently_dropped`
  与 `an_unparseable_url_is_reported_instead_of_panicking`。
- **引擎接线**：`every_event_records_an_outbound_decision` —— 一个 attention 事件进来，
  `state().recentOutbound` 恰好一条、文案是「未发：总开关未开」、且不占节流位。
- **测试数**：Rust **144 → 160**（+16）、Swift 550（未动）；编译警告保持 **26**。

## 边界与后续风险

- **`attempt` 是同步的，传输超时 10 秒**（本轮最大的结构性问题）。Swift 侧 `deliver` 是 async
  在后台 Task 里跑；Rust 的引擎是同步的，这一调用会占住引擎那一拍。今天**打不到**：
  总开关默认关（判据在传输之前返回），且 https / SMTP 在 `HttpTransport` 里立即失败、
  不发网络 I/O——只有「手动打开总开关 + 配了一个会挂住的 `http://` 端点」才会卡住。
  已写进代码注释、CHANGELOG 与本文件。**下一轮做传输时必须一并改成起线程发送 + 结果回填**。
- **没有重试**：Swift 在自动外发失败后 5 秒重试一次（理由是「这个功能存在的意义就是人不在
  机器前也要收到，而一次抖动就把那条唯一提醒永久丢掉」）。Rust 现在只试一次。
  重试与上面的线程化是同一件事的两面，一起做。
- **`smtp_line` 仍缺**：v0.0.175 因为没消费方删掉了，写 SMTP 会话时**必须**补回来
  （一行里出现裸 CR/LF 会让一条消息在协议里变成两条命令）。第二轮记这笔账了。
- **账本里看不到「用时」**：completed 事件的任务时长只在正文里体现（渲染层已测），
  而账本存的是标题与结果——所以「引擎把 duration 喂对了没有」这条接线**没有直接用例**。
  下一轮若账本要显示更多（Swift 的设置页会显示标题+结果），可以顺带把它变成可观测的。
- **`has_secret` 恒为 false**：钥匙串未接入，所以任何通道只要写了 `{key}` 或走 SMTP，
  都会在**闸门**这一层被如实挡下（连传输都到不了）。这是当前最影响可用性的一条。
- 同前几轮：同一人既改又审；真正的护栏是两次反向验证的红与上面几条判别性用例，不是这份文档。

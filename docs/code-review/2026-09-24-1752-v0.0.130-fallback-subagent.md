## 发现的问题

### P0 — 阻断

- **`Sources/AgentIslandCore/SelfReport.swift:312-319`（`matches`）— 「定长比较」其实是 XOR 校验和，同长度错串约 1/30 概率被判为正确令牌**
  - 触发：任意进程反复 `POST /session`，body 合法、`X-AgentIsland-Token` 填**随机 48 位十六进制串**。`for i in 0..<a.count { diff ^= a[i] ^ b[i] }` 只在「差异的 XOR 总和为 0」时才非零，而差异两两相消即归零。实测（/tmp 可执行体，直连真实 `matches()`）：4 轮各 20000 次随机猜测 → 601 / 659 / 623 / 617 次接受，即 **3.0%~3.3%**；「第一次命中所需次数」四轮分别是 3、5、12、124。更糟的是**确定性构造**：把真令牌每个字节 `^1`（48 个字节全部不同）→ `matches` 返回 **true**。
  - 症状→后果：spec §3 第 3 条（「无鉴权的本机入口不能升格成可信来源」）是整轮存在的理由，而它现在是**能升格的**。拿到可信位之后，攻击者不需要 pid（`pid` 可选，缺省直接 `.bound`）、不需要档案匹配，就能对**任意启用中的档案**写入 `attention/working/completed`，还能带合法令牌 `DELETE` 撤销真 Agent 刚声明的那条。今天没有 UI 消费所以只是「存进字典」，但 04 号票要的就是「自报优先于推断」——这颗雷是埋给下一轮的。而 macOS 13 那条构建路径下监听面是通配（`LocalEventServer.swift:10-15` 自己写明「端口仍是局域网可达」，本机 `lsof` 实样是 IPv4 回环，说明 14+ 路径生效），同一局域网内即可以 ≈30 次请求破门。
  - 建议修法：一行就够——`diff |= a[i] ^ b[i]`（零 iff 全等）。实测该写法对翻转串返回 false、20000 次随机猜测 **0 命中**。更稳的是不自己写：`import CryptoKit` 后比对 `Data` 的 `in.constantTimeGreaterThan` 组合，或直接 `timingsafe_memeqcmp`（libsec 公开符号）。**并且必须同时补测试**（见下一条），否则这条修改本身没有守卫。
  - 能否自动修：**是**（改动面 1 行 + 1 条断言）。
- **`Tests/AgentIslandTestsRunner/SelfReportTests.swift:222-234`（「校验是定长比较」）— 这条用例在结构上不可能发现上面那个洞**
  - 触发：`for bad in [String(token.dropLast()), token + "x", "", "x" + token.dropFirst(), nil]` —— 五个反例**全部是「长度不同」或「只差一个字符」**。单字节差异的 XOR 和必然非零，所以 P0 的那行代码在这五条断言下永远绿。
  - 症状→后果：CHANGELOG 把「定长比较」当成交付项写进正文（`:16`），测试给出的信心与被保护的东西不匹配；这正是本仓反复踩的「断言不会红」。
  - 建议修法：在同一用例里加两条**同长度、多字节差异**的反例，一条确定性、一条随机：`try expectFalse(store.matches(String(bytes: Array(token.utf8).map { $0 ^ 1 }, encoding: .ascii)!), "每个字节都不同也必须拒——XOR 累加会在这里放行")`，再 `for _ in 0..<200 { let g = (0..<48).map { _ in String(format:"%x", Int.random(in:0...15)) }.joined(); try expectFalse(store.matches(g), "随机同长串不能过") }`。第二条在改回 `^=` 时会红（我实测 20000 次里有 601 次会过，200 次抽样红概率≈99.8%）。
  - 能否自动修：**是**。

### P1 — 重要

- **`Sources/AgentIsland/LocalEventServer.swift:311-317` — 未投递的申报被回复成「已按未采信事件投递」，把「没做」讲成「做了」**
  - 触发：不带令牌 `POST /session`，body `{"agent":"claude","session":"x","state":"working"}`（或 `idle`）。`SelfReportFallback.eventKind` 对 `working/idle` 返回 nil ⇒ `post` 返回 false，返回值被 `@discardableResult` 吃掉，响应体照发「没有有效令牌：**已按未采信事件投递**，不改变状态来源」。
  - 症状→后果：与本仓第一口径直接冲突（「不得把『没看到』讲成『没有』」的镜像面：不得把「没送」讲成「送了」）。接入方（06 号票的 curl 片段、每家 hook 的日志）会据此认为通道在работает，而实际上一条都没落地；`SelfReportTests.swift:470` 甚至已经断言了 `expectFalse(post(sub(state: .working), to: e))` —— 行为测出来的是 false，服务端把 false 说成 true。
  - 建议修法：接住返回值再分叉文案，并让「没投递」在响应里可见：`let posted = SelfReportFallback.post(submission, to: engine)` → `message: posted ? "没有有效令牌：已按未采信事件投递，不改变状态来源" : "没有有效令牌，且 ${submission.state.rawValue} 是持续状态、不转事件：本条未被记录，也不改变状态来源"`。
  - 能否自动修：**是**。
- **`Sources/AgentIslandCore/ActivityEngine.swift:449-464` + `Sources/AgentIsland/LocalEventServer.swift:270-279` — 「这条可信吗」仍然有两个出口，而棘轮挡不住第二种写法**
  - 触发：`bindSelfReport(_:tokenAccepted:)` 收**裸 Bool**，`revokeSelfReport(agentID:sessionID:)` **根本不要凭证**（DELETE 的令牌判定写在 HTTP 层，是唯一一处）。实测两个变异都在 484 条全绿下存活：(a) `LocalEventServer` 里把 `let tokenAccepted = engine.selfReportTokens.matches(providedToken)` 换成 `let tokenAccepted = providedToken != nil`（**任何**带非空 header 的请求即得可信自报），源码棘轮的 `expectFalse(serverText.contains("tokenAccepted: true"))` 因拼写不同而没红；(b) 在 `terminateAgent` 里加一行 `selfReports.retainAgents(去掉该档案)`（进程一终止就抹掉它的申报），棘轮只 grep `resetTracking`/`resetAllTracking` 的函数体，看不见。
  - 症状→后果：`SelfReport.swift:11-15` 与 `LocalEventServer.swift:247-251` 都声称「判定只有一处、避免出现第二个答案」，实现却把可信度的一半（撤销）留在 HTTP 层、另一半（写入）留在引擎，且两者的入口参数都是可伪造的 `Bool`。下一轮 03 号票要钉的「可信自报必经令牌」在这个形状下没有可执行的表达方式。
  - 建议修法：把凭证做成**不可凭空构造的值**：`public struct SelfReportCredential: Equatable { init() {} }`（`internal init`）→ `SelfReportTokenStore.authorize(_ provided: String?) -> SelfReportCredential?`（只有 `matches` 通过才产出）→ `bindSelfReport(_ s:, credential: SelfReportCredential?)`、`revokeSelfReport(agentID:sessionID:credential:)`。于是服务端无论怎么写都没法「传个 true」，编译器替棘轮把活干了；两条 destructive 路径也共用同一个凭证类型。届时 `SelfReportTests.swift:478-518` 的源码棘轮可以整条删掉（它唯一还挡得住的是字面拼写，见 P2 那条）。

- **`Sources/AgentIslandCore/SelfReport.swift:495-503`（`reanchorIfClockRewound`）— 时钟回拨会把**已过期**的申报抹回可信，不需要任何新申报**
  - 触发：`ingest(ttl:15, now:t0)` → 采样盖章 `expiredAt=t0+20` → 时钟回拨到 `t0-5` → 重锚把 `expiredAt` 置回 nil、`expiresAt=t0+10`。实测（/tmp，直接驱动真实 store）：过期后 `believable → nil`，回拨 25s 后 **`believable → attention`**，而这段时间没有任何新的上报。
  - 症状→后果：`SelfReport.swift:14` 第 3 条口径（过期只是「不再采信」）与 `:404`（「过期是记录的状态，不是记录的删除」）在这条路上被反向违反——不是清空，而是**复活**。一条早就断了心跳的申报会重新压住推断（04 号票之后就是「自报优先」），而 NTP 阶跃 / 虚拟机恢复快照正是 `ActivityEngine.swift:591-594` 自己列出的场景。

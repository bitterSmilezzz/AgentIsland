# v0.0.174 独立复核 · DSH · 2026-09-27 06:38

## 范围与结论

复核外发组的第一块：`RemoteNotification.swift` 的策略层（策略 / 通道校验 / 逐字段容错解码）
迁入 `remote.rs`，接进 `Settings` 与 `remote_status` 命令。结论：**策略层口径逐条对齐，
容错规则有判别性用例**；钥匙串、闸门、传输未迁并已在对照表里写明。Swift 侧零改动。

## 可核验的行为证据

- **坏时刻的降级方向**：`normalized_clamps_ranges_and_degrades_broken_quiet_hours_to_no_quiet`
  断言 `"25:00"` → 空（不静默），并单独断言「只有一端合法 ⇒ 整对作废」。
  反向验证：把降级目标改成 `"00:00"` → 该用例红（那会把整个凌晨静默掉）。
- **逐字段容错**：`a_wrongly_typed_field_only_invalidates_that_field` —— `"smtpPort":"587"`
  必须回落成 **465**（而不是解析出 587）、`"useJSONBody":"yes"` 回落成该字段默认 `true`，
  同时 `smtpTo` 等其余字段照读。反向验证：把 `useJSONBody` 的回落值改成 `false` → 用例红。
  `a_partial_archive_keeps_the_keys_it_has` 另外钉住「旧存档 + 未来新增键」两个方向。
- **两条踩过坑的校验**：
  - `ntfy_rejects_a_schemeless_self_hosted_address` —— `ntfy.mine.local/island` 必须被挡
    （否则会被拼成公网地址，内容跑到用户没选过的服务器上）；空格与非 ASCII 主题名也挡。
  - `smtp_checks_the_port_before_the_secret` —— 端口 587 报「仅支持 465」，而不是报「缺授权码」。
- **静默时段的跨零点与边界**：起点含、终点不含；`start == end` 视为不静默；跨零点两个方向都判。
- **fail-open 的方向**：`away_is_fail_open_when_the_signal_is_missing` —— 取不到输入时长时
  `is_away` 为 `true`，依据文案是「取不到输入时长」。
- **状态快照不带凭据**：`status_reports_each_warning_separately_and_never_a_secret_value`
  在配置里放了一条形如凭据的明文（`key=ABCDEFGHIJKLMNOP`），断言序列化出来的快照里
  **不出现**这段原文——它只会以布尔的形式出现。这是 ADR 0009 那条红线的可执行版本。
- **测试数**：Rust **115 → 130**（+15：`remote.rs` 14 条 + `settings.rs` 1 条）、Swift 550（未动）。
- **编译警告保持 26**：模块被 `Settings` 与 `remote_status` 真消费，**没有**用 `allow(dead_code)`
  压警告。中途一度涨到 46（模块刚写完、还没有消费方），做法是把有消费方的部分接上、
  把暂时没有消费方的部分（闸门/节流）**推迟**而不是加豁免；最后多出的 `EventKind::parse`
  也删掉而不是留着。

## 边界与后续风险

- **`#[serde(default)]` 与 Swift `decodeIfPresent` 的差别是本轮的重点**：`default` 只在键
  **缺失**时兜底，键在但类型错会整条失败。Rust 侧原来的 `Settings` 就是 `#[serde(default)]`，
  所以新增的 `remote_policy` / `remote_channels` 特意手写了 `Deserialize`；**其余字段仍是
  `default` 语义**（一个字段写错会整份回落出厂值）——这是既有的、未修的差异，本轮只保证
  新字段不引入同类问题。
- **`away` 今天恒为「已离开」**：Rust 没有 macOS 在场信号层（锁屏 / 显示器睡眠 / 无输入时长），
  `remote_status` 传 `unavailable`。fail-open 让「只在离开时发」这个开关今天形同「都发」。
  **这是本轮最明显的未完成面**，已写进对照表；接信号层要 `CGEventSource` / 屏幕状态 API，
  属于平台代码，需要单独决定（与钥匙串同批）。
- **钥匙串未迁，`hasSecret` 恒 `false`**：所以 SMTP 通道在 `remote_status` 里永远报
  「缺 SMTP 密码/授权码」。这是**如实**（真没读过钥匙串），不是判定错；但使用者会看到
  一条永远消不掉的提示。接钥匙串时要一并解决。
- **静默时段的本地时区只做了「能用」级验证**：`local_minutes_of_day` 走 `localtime_r`，
  用例只断言「落在 0..1440 且两次调用一致」——**没有**跨时区断言（改 `TZ` 会影响同进程里
  并行跑的其它用例，属于测试隔离问题）。时区正确性依赖 OS，未在用例里钉住。
- **没有 UI 消费 `remote_status`**：命令已注册、可 `invoke`，但 Rust 侧今天没有设置页。
  它现在的作用是「把策略层从死代码变成可达 API + 给下一轮传输提供状态」，不是用户可见功能。
- 同前几轮：同一人既改又审；真正的护栏是两次反向验证的红与上面几条判别性用例，不是这份文档。

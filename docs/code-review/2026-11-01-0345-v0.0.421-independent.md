## 审查发现与处理

1. **键盘路径曾被鼠标操作冒称。** 原浏览器脚本用 `selectOption()` 和鼠标点击保存，却声称验证键盘编辑。现在使用原生选择控件的键盘类型搜索，Tab 到动态出现的“撤销修改”后再 Tab 到“保存”，按 Enter 提交；断言最终归属已更新。
2. **拖放目标栏压缩窄窗口列表。** 首次完整 CI 在 880 px 窗口下发现任务列表只剩 59 px 高，不足显示一张完整任务卡。项目目标栏现在只在 `dragstart` 后显示，详情导航回归通过。
3. **拖放目标未在所有结束路径收起。** drop 处理器会先清空 `activeDrag`，原 `dragend` 的条件清理便可能被跳过。现在 drop 立即收起目标栏，dragend 的视觉清理不依赖 `activeDrag`；浏览器回归覆盖正常 drop、草稿保护拒绝和无效 payload。
4. **no-op 事件发布。** 同项目移动不落盘，但包装层原先仍可广播任务变化。现在只在 revision 前进后发布事件，浏览器契约断言覆盖此行为。

首次全量 CI 的 `task01.detailnav` 失败是目标栏造成的短窗口布局问题；同一轮 `source.integrity` 失败发生在验证期间修改键盘测试文件，记录为执行期间源变动。保留了原失败证据，后续稳定源码下复跑通过。

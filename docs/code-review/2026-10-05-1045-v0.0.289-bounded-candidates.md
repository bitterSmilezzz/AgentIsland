# v0.0.289 · 有界会话候选选择审查

范围 M4/P4：filemon::probe_files 的临时路径分配与选择。原实现对所有缓存文件克隆路径并排序、去重，最后只返回16个候选。

实现：目录缓存先按原TTL刷新，再借用元数据进行批次合并；16条保留结果加256条候选，最多272个借用引用，有界去重表与局部不稳定排序；排序键仍为mtime降序、路径词序升序，重复路径取最新记录。完全相同键的排序稳定性不影响输出路径。每批保留的16个不同路径足以覆盖旧前缀的最终top16，故低于前沿的旧路径不必保留；不改变完整活跃计数、目录扫描频率或解析器探测数量。仅最终16条路径克隆，Token缓存和历史不动。

验证：旧完整排序算法作为差分参考，覆盖不同mtime的重复路径、同时间词序、旋转/反转、空集合和255/256/271/272/273/528等批次边界；现有目录缓存共用与500条完整活跃计数通过。显式合成性能测试也验证10万条三种输入顺序输出完全一致，不把性能计时设为易抖动的CI门槛。

性能证据：初次逐项树选择在开发模式出现约68ms对18ms的回归；前沿拒绝改进混合输入，但最旧优先仍约104ms对9ms，故未保留该版本。最终有界批次版本的开发模式混合/最旧优先仍比旧版慢；同源码函数以rustc -O独立编译、5轮三种顺序验证后，生产优化模式选择耗时中位数混合8.62→1.38ms、最旧优先3.71→1.63ms、最新优先6.84→0.58ms。具体受控证据在忽略目录，未读取真实会话或建立UI测试实例。

内存口径：10万条143字节路径的旧克隆payload至少14,300,000字节，新输出16条共2,288字节，另有272个借用引用、有界去重和输出容器；这是代码级临时工作集约束，既不是分配器footprint，也不是整应用RSS实测。原始缓存、进程、WebKit/GPU和长期趋势尚需受控原生测量。

# v0.0.309 发布前审查

审查对象：基于 v0.0.308 的文件缓存压力计量、单次 CLI 用量读取及报告选项。审查者 Codex，2026-10-10 08:51；独立检查实现差异、反例、最终编译产物和原生回执。对应 KEEP-03、KEEP-07、NEW-06、DELIVERY-01、内存专项 P4；不将本批发布视为整体 Mac 范围完成。

## 原因与修正

文件状态表超过8000项时，任意回收1000项可能先驱逐刚解析的当前文件，再汇总出零。保护当前文件后，8001个真实文件仍出现小时图表与上下文漏算：扫描末尾只遍历剩余缓存，已经回收的文件没有参加报告。现保留当前项，并在每文件解析后立即累加本轮小时桶和上下文；累计、模型、原折入算法及缓存上限不变。不新增跨文件去重台账或扩大读取范围。

`tokens` 和 `report` 使用了默认不读用量的单次采样，造成未取值被当作零导出。两命令现显式取用量，普通 `status` 仍通过 `--usage` 按需读取。单次只读引擎在采样前关闭外发调度；本地事件仍保留，正常常驻通知策略不变。检查两条通知入口的早返回位于 presence 和 notifier/凭据链之前；回归证明观察引擎不产生外发账本，普通引擎仍经过策略账本。没有用真实凭据或实际通知发送证明该边界。

报告全局分派只保留长开关，丢掉独立格式值和 `-o`，导致 README 的 `--format csv` 输出 Markdown，提示的保存路径也未生效。报告改用原始有序参数，格式与 `-o`/`--out` 均接受独立值和等号写法，含空格路径完整保留。空值、未知/重复选项及无效格式在采样前返回用法错误；输出沿用原子替换及写入失败退出码。

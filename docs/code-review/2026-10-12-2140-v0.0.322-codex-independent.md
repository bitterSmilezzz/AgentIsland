## Findings and disposition

### P2 — A configured model query retained unrelated service model rows (resolved during review)

Location: [app/ui/js/models-page.js:51](../../app/ui/js/models-page.js#L51), [app/ui/js/models-page.js:62](../../app/ui/js/models-page.js#L62). In the original reviewed code, the same `data-catalog-search` string included interface metadata, profile names, and configured model names. A match against any of those values set `configuredMatch`, and that boolean exempted every fetched model from filtering.

Independent reproduction used the actual generated directory metadata with a saved model `gpt-configured` and returned models `gpt-configured` and `unrelated-service-model`. Searching `gpt-configured` left both service rows visible. This contradicted the feature specification that model searches narrow the returned model list while interface/profile searches retain its models. Existing remote-only model fixtures did not exercise this overlap.

The implementer added separate interface/profile metadata in `data-catalog-interface-search`. The filter now uses that field for the exemption and preserves configured-model matching for the enclosing interface row. The independent overlapping-name reproduction now hides the unrelated model. [scripts/test-model-directory.mjs:50](../../scripts/test-model-directory.mjs#L50) and [scripts/test-model-directory.mjs:60](../../scripts/test-model-directory.mjs#L60) cover metadata separation, the overlap, configured-only search, and service-result invalidation. An interim suite failure came from querying a newly configured fixture value after deleting only the service rows; the fixture was corrected to use a service-only value, and the suite was rerun successfully.

### P2 — A native-confirmed target change retained selectable models from the old target (resolved during review)

Location: [app/ui/js/interface-models.js:24](../../app/ui/js/interface-models.js#L24), [app/ui/js/interface-models.js:30](../../app/ui/js/interface-models.js#L30), [app/src-tauri/src/main.rs:2318](../../app/src-tauri/src/main.rs#L2318), [app/src-tauri/src/main.rs:2326](../../app/src-tauri/src/main.rs#L2326). The initial reader retained the previous successful result for every rejected request. Backend equality checks correctly rejected a saved profile modified or deleted by another window, but this arrived as an ordinary string error. The frontend had no corresponding profile update, so it continued rendering the old models with enabled “fill profile” buttons.

Independent reproduction: complete one successful load returning `old-target-model`; retry while the frontend still has the same profile snapshot; reject with the exact saved-profile mismatch error emitted by the store. The reader still returned the old result. The command's pre/post checks and existing store test establish that this rejection can occur when a saved target changes before or during the network wait. Keeping last success for transient network failures is required; keeping selectable models after the backend positively reports identity invalidation conflicts with the target-change clearing requirement.

The implementer added a serializable error with `code: target_invalidated` and a static, safe message in [app/src-tauri/src/interface_models.rs:10](../../app/src-tauri/src/interface_models.rs#L10), mapped both saved-target checks to it, and clears `state.result` on that code in [app/ui/js/interface-models.js:32](../../app/ui/js/interface-models.js#L32). Ordinary failures retain last success. The independent typed-error reproduction passes, and [scripts/test-interface-models.mjs:11](../../scripts/test-interface-models.mjs#L11) covers target invalidation separately from transient typed failures. A final focused Rust test run compiled the modified command and passed all five feature tests. This reviewer did not execute a signed native multiwindow scenario; that end-to-end behavior still requires acceptance.

## Reviewed boundaries

- Native target construction preserves the configured URL prefix, accepts HTTPS or literal loopback HTTP, validates the saved Responses profile before credential lookup, and reads only its environment-variable reference. No OAuth, command authentication, generation request, or configuration/cache-file write was introduced in the reviewed request path.
- The shared transport disables redirects, retries, and proxies, requests identity encoding, enforces the five-second timeout and 512-KiB body cap, rejects compressed/unsupported responses, and returns controlled errors. The request lease is process-wide. The provider mutex is released during the blocking network request and reacquired for target equality validation.
- The parser requires the OpenAI list/model envelope, rejects business-error responses, bounds the raw array and model IDs, rejects known credential patterns/current credential echoes, and projects only sorted unique model IDs, count, truncation, and timestamp into the DTO.
- Page cache identity includes the complete profile. Update invalidation, bounded eight-entry results, removal/recreation, and state-object checks prevent a delayed result from populating a replacement target. The native invalidation correction above closes the case where the frontend has not yet refreshed its saved profiles.
- Discovered-model actions use escaped markup and the existing editor. The handler blocks replacement while an editor/draft or provider confirmation is present, dispatches an input event after filling the model, and does not save or apply it automatically. The busy checkbox participates in the retained draft/window lease; focus restoration checks connection, hidden ancestors, and focus ownership. These are source-level observations supported by the existing focused lifecycle checks, not an independent browser or native usability acceptance.

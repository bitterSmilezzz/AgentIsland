# 返回回弹与健康度说明复查

用户在上一轮构建后仍观察到抖动，因此上一轮的模拟 viewport 通过不能作为问题已经解决的结论。

## 证据与修正

- 在实际 PID 71360 的 Agent 详情返回操作期间采集 CGWindow 几何，只输出尺寸、位置，不记录窗口标题或会话内容。出现 300×344 到 300×328 的二次高度变化。它证明原生结果仍有回弹，但仅凭几何记录不能区分所有 WebKit 合成帧。
- 使用真实 main/views/motion 模块模拟列表采样：移除完成智能体的动作文字后，原始布局路径直接改变高度；修正后进入仅表面过渡，305.875→289.375，正文不重播。该结果用于验证采样路径，不替代原生动效观感。
- 检查 Tao 的 macOS setter 实现：setContentSize 和 setFrameTopLeftPoint 分别提交主队列，IPC 返回并不代表两者执行完毕。macOS 改为在主线程一次 NSWindow setFrame:display: 设置尺寸、位置并重绘；命令等待闭包执行结果，拒绝空句柄或缺少屏幕。使用主显示器高度翻转坐标，不用当前副屏高度。其他平台保留既有路径。
- 健康度分数来自 CPU、内存、疑似卡死扣分；缺少 CPU/卡死观测时可能仍为100，但等级 partial。列表用文字表达等级，健康不占位，具体分数与原因保留在悬停说明，后台算法未改动。

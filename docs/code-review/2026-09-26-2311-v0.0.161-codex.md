# v0.0.161 独立复核 · Codex · 2026-09-26 23:11

## 范围与结论

复核 Rust 共用档案字段、Roo Code ID 和旧设置兼容、会话分派、无 token 来源时的报告出口，
以及 ADR/工作台同步。未发现阻止发布的问题。这一轮只修两端已有能力的已核实差异；
ZCode、Trae、Windsurf 路径仍需实样，不据文件名猜测并改动。

## 可核验的行为证据

- Swift `AgentRegistry.swift` 的 Claude/OpenCode CPU 下限均为 20；Claude tokenRoots 含
  sessions 和 projects，OpenCode/Cline/Roo Code 没有 tokenRoots。Rust 注册表现在逐项
  对齐，并由 `shared_profiles_keep_swift_cpu_token_and_id_contracts` 守护。
- `Settings::normalized()` 将旧禁用 ID `roo` 转成 `roo-code`，保留原列表顺序并去重；
  测试覆盖旧、新 ID 同时存在及二次归一化。会话 fixture 经公开 `probe` 入口确认
  新旧 ID 都能产生同一个明确完成信号。
- `ActivityEngine::get_report` 在档案没有 token 根目录时返回 `None`；合成引擎测试
  覆盖 OpenCode、Cline、Roo Code 和未知 ID。前端已有 `null` 的「暂无本地明细数据」
  分支，避免将不可采集误表述为零用量。
- `cargo test --locked --manifest-path app/src-tauri/Cargo.toml`：57 通过，0 失败。
  `scripts/test-scan-secrets.sh`：7 通过，0 失败。

## 后续风险与边界

Rust 仍缺 M3 的 12 个模块及可观测性五类结论；有 token 根目录但文件缺失时，
现有监控器仍可能返回零报告，本轮没有声称解决该类问题。正式下载包继续是 Swift
原生端，侧边栏未开放。对照表的旧规模、行号属于 v0.0.158 调查快照。

## 问题与实现

正式上一版本的真实双窗记录证明：A 先到左侧目标后，B 在原点收缩时可能与 A 的最终几何相同，身份保护正确拒绝后续写入；结果区只有工具名，无法区分同一应用的两窗。新回归在旧执行顺序下得到 Applied/Failed，修复后两项 Applied，并完整撤销到原矩形。

按已核实 before/target 的收缩、移动、扩展阶段生成执行依赖，先腾出中间几何；同工具分组仅是保守排序提示，不替代每步身份核验。目标槽位不变，结果及撤销快照按选择顺序返回。循环交换保持身份保护和部分失败证据，不增加临时位置、写入重试或调整 1 点容差。循环失败测试检查只写第一窗、第二窗跳过且第一窗实际改动仍进入撤销。

前端在应用开始时捕获标题、工具名及原选择序号，结果与后续撤销共用该次标识；候选读取替换另一份有界映射，避免 UUID 持续累积或刷新后错配。标题在文本、提示和无障碍标签中转义，仅在页面内存保存，持久历史仍无标题。覆盖项初始未勾选，取消不发送恢复；长标题最多两行，空白标题有明确回退。重启脚本使用后台打开参数，保留旧实例终止与新实例启动检查。

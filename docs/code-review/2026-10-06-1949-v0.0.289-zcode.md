# v0.0.289 · 发版收尾与隔离门禁的显式授权

审查者：ZCode。2026-10-06 19:49（Asia/Shanghai）。

## 背景与决策

整版交付此前卡在发版流程与原生测试门禁的衔接上：v0.0.288 之后 ui-smoke.sh 与
test-dock-presence.py 要求显式 `--isolated-session`（隔离用户会话或 VM），而本机没有
隔离环境，release.sh 每次在 UI 冒烟一步以退出 2 停止，未创建 commit/tag/Release
（2026-10-03 预开发审查与 2026-10-06 02:26 审查均记录过该阻塞，且明确拒绝伪造标志）。

本轮把裁决交给操作者：**操作者明确选择「跑冒烟后发版」**。release.sh 因此新增显式
`ALLOW_DESKTOP_UI=1` 开关——仅把 `--isolated-session` 转发给两个原生测试、在输出中标注
「操作者已确认接受桌面焦点干扰」；不带该变量时门禁原样生效（退出 2、发版停止）。
这是授权转发，不是绕过：测试真实运行，不跳过、不伪造隔离前提。

## 实施

- CHANGELOG 首条日期按仓库惯例（条目日期 = 发版日）从 10-03 改为 10-06，并补一条
  release.sh 门禁适配的记录。
- release.sh UI 冒烟与 Dock 回归两步接受 `ALLOW_DESKTOP_UI=1`，默认行为不变。

## 冒烟抓到的真回归与修复

隔了三天的第一次原生冒烟立即失败：三窗口 `state=threw`、0 可点元素，读回显示
`fatal: 工作台原色图标可见尺寸不一致`。根因是 `traework.png` 漏配 `artworkScale`
（素材内容占比 104/128 与同批图标一致，却没按同式补偿，可见尺寸 22.75px ≠ 28±1px）；
修复为补上 `128 / 104`，逐张按探测同口径核算全部 PNG 均 ≈28。该回归在
10-03 桌面身份批次引入，之后原生冒烟一直被隔离门禁挡住，故三天未暴露——
这正是「冒烟不许长期缺位」的直接证据。

顺带修冒烟驱动可观测性：`SMOKE_RESULT` 此前不含 `fatal` 字段，驱动抛异常时
发布输出只剩 `threw` 不知道为什么；现已纳入（完整值仍在 +10.6s 的 `[smoke]` 读回里）。

修复后冒烟重跑：三窗口 `state=done`（island 9、sidebar 7、workbench 21 个可点元素），
27 个图标尺寸全部达标，全程零页面错误。

## Dock 回归的第二个阻塞与修复

发版继续在 Dock 回归失败：`observed == []`，应用却正常退出 0。根因是 e1936c0
移除「测试前 pkill 用户应用」后，测试实例与常驻应用撞上**单实例机制**——按
bundle 标识移交并立刻退出，策略序列一次都没发生。v0.0.288 时能过是因为当时
测试先杀掉了用户应用；该行为被移除后，这道回归在有运行实例的机器上必然空转。

修复按既有「测试实例隔离标识」设计补齐：新增 `isolated_instance_requested()`
（含 `--dock-smoke`），仅用于 ① 实例标识加 `.test.p<pid>` 后缀（不撞单实例）、
② 跳过全局热键注册、③ 跳过本地 webhook 服务器、④ 跳过方案采集恢复——不抢占
用户应用持有的资源；`reveal/conceal` 的 `set_dock_presence` 路径刻意保持原样
（`background_test_requested` 会禁用它，Dock 回归需要真实切换）。
用户应用全程保持运行。修复后 Dock 回归单独重跑通过，五段序列完整。

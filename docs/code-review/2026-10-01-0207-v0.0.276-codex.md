# v0.0.276 启动期深链审查

审查者：Codex。基线：v0.0.275。范围：订阅前导航缓存、重放与实时执行顺序。

## 问题与改动

Rust 的 setup 在 WebView 完成 boot 前即处理 get_current URL，原先直接广播，缺少订阅的窗口会丢失意图。三个窗口各有进程内 Mailbox；前端先安装订阅，逐批领取缓存，只有空批次才进入实时投递。领取期间新到达的意图留到下一批，每个窗口独立消费。实时回调通过 Promise 链串行执行，失败记录后允许后续指令继续。

缓存锁只用于更新队列，窗口事件投递前释放；不增加 SharedEngine 临界区或阻塞主线程的回调。

## 验证

- Rust 全量回归：548 通过，5 忽略。
- 队列回归：三窗口独立、顺序一致、一次性消费、领取期间追加、未知窗口不激活真实窗口。
- Node 回归加载实际前端 boot：确认先订阅后领取、逐批重放、重放期间收起、连续实时展开/收起；同一冷启动回归在旧入口中失败，在当前实现中通过。
- 原生正式 bundle：构建后执行 restart-app.sh，立即从 CLI 发出 Expand，辅助功能树确认已展开；按完整 bundle 二进制路径结束应用，再以 CLI Expand 深链冷启动，原生树再次确认直接显示监控列表，未手动点击唤回。
- 工作区脱敏扫描与 diff 空白检查通过。发布流程执行全历史脱敏、原生 UI 冒烟、单实例、版本漂移门禁。

## 边界

只处理 deeplink://navigate；不扩展外部通知、设置页或归档端业务。缓存不跨进程持久化，进程退出即释放；DOM 桩只验证事件行为，原生树只确认窗口内容，不作为像素布局证据。沿用现有深链解析与页面呈现规则。

结论：本轮范围内无阻断问题，可发布。

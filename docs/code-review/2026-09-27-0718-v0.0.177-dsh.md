# v0.0.177 独立复核 · DSH · 2026-09-27 07:18

## 范围与结论

复核 HTTPS 接入：`native-tls`（系统 TLS 栈）+ 明文/TLS 共用往返代码 + 逐地址试连，
并补上**离线 TLS 端到端验证**。结论：**https 真能连通且被验证过**，
「不可信证书必须失败」与「逐地址试连」两条各有判别性用例。Swift 侧零改动。

## 可核验的行为证据

- **HTTPS 端到端（本轮核心）**：`https_really_connects_end_to_end_against_a_local_certificate`
  —— 本地 TLS 服务器（系统 `openssl` 生成的 RSA 自签证书）+ 注入信任该证书的连接器 →
  断言 `Delivered`，并逐字核对服务器收到的 `POST /island HTTP/1.1`、`X-Title`、正文。
  证明的是「请求真的过了 TLS」，不是「返回枚举是 Delivered」。
- **不可信证书必须失败**：`https_against_an_untrusted_certificate_fails_loudly`
  —— 同一服务器 + 默认连接器 → 报 `TLS 握手失败`。
  **反向验证**：把 https 分支改成直接返回明文流 → 这条立刻红（静默降级被挡住）。
- **逐地址试连**：反向验证——改成只试第一个地址 → 端到端用例红
  （`Connection refused (os error 61)`，`localhost` 先解析到 `::1`，服务器只监听 IPv4）。
  这条生产同样受益：只监听一族的服务在双栈主机上原本连不上。
- **SMTP 仍如实报未接入**：`smtp_is_reported_as_unwired_and_https_is_actually_attempted`
  同时钉住两侧——https 现在报的是「连接失败」（真去连了），SMTP 报的是「会话未接入」。
  两句对应完全不同的排查方向。
- **测试不碰外网**：全量测试从 2.04s 降到 **0.41s**，因为上一轮那条「断言 ntfy 的 https 报未接入」
  的用例会真连公网。已改成指向刚释放的本地端口（真传输、真失败、真进账本，不出网）。
- **测试数**：Rust **160 → 162**、Swift 550（未动）；编译警告保持 **26**。

## 选型与被否决的方案

用 `native-tls`（macOS = Security.framework）而非 `rustls`：与 Swift 侧 URLSession /
Network.framework 同一套信任栈；同时带进 `security-framework`（下一轮钥匙串用同一个 crate）；
`rustls` 不读系统信任栈，要多引 webpki-roots。代价：错误文本来自系统，不如 rustls 结构化。
四个非显然的坑（EC 不行 / 参数顺序与文档相反 / 缺 serverAuth 被拒 / 双栈）写进了
[docs/research/2026-09-27-macos-tls-for-rust-outbound.md](../../docs/research/2026-09-27-macos-tls-for-rust-outbound.md)。

## 边界与后续风险

- **真实公网证书链没有实样**：用例都是「自签证书 + 注入连接器」。系统信任栈这条路径依赖
  Security.framework 自身行为，未取实样（本机出网可用，但验证不该把字节发给第三方）。
- **`attempt` 仍是同步的，超时 10 秒**（上一轮记过，这一轮**分量更重**）：
  上一轮只有明文 `http://` 会真去连，现在 **https 也会真去连**——也就是说，
  只要用户打开总开关，「引擎那一拍可能被网络阻塞最多 10 秒」这条从「很窄」变成「常态路径」。
  总开关默认关，所以今天仍打不到；但**这条必须在加钥匙串/重试的那一轮一起解决**
  （起线程发送 + 结果回填）。
- **没有重试**：Swift 5 秒后重试一次，理由是「一次网络抖动就把那条唯一提醒永久丢掉」。
  Rust 只试一次。与上一条是同一件事的两面。
- **SMTP 会话仍未接**：邮箱通道完全不可用（如实报「SMTP 会话未接入」）。
  写它时要补回 `smtp_line`（CR/LF 折叠）——v0.0.175 因无消费方删掉，已连续两轮记这笔账。
- **自签证书测试依赖系统 `openssl`**：不可用时用例会打一行说明并跳过（不是假过）。
  本机与 macOS 都自带；若日后在缺 openssl 的环境跑，这两条会静默跳过——已写在用例里。
- 同前几轮：同一人既改又审；真正的护栏是两条反向验证的红与上面几条判别性用例，不是这份文档。

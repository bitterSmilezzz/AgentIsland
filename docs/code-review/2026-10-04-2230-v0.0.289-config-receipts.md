# 配置实际写入收据审查

范围：provider.rs、main.rs、views.js、DTO 哨兵及工作空间实现文档。

发现：配置发布后应用记录失败通过 Err 返回，前端将已经发生的变更报为普通失败；还原清理记录失败亦同，且没有返回还原前备份名。改为配置操作成功返回收据，记录失败单独警告，保留可恢复备份名；原预览、共享写锁和 revision 校验继续生效。不宣称整个工作空间已应用。

验证：两项沙箱回归分别制造 applied.json 为目录的写入/删除失败，核对目标配置、精确备份字节和部分失败收据；还原同时核对正常应用记录。测试不操作本机 Codex 配置。

边界：收据表示配置发布完成，不表示客户端已加载、账号可用或运行会话已切换。原生交互验收仍需隔离会话；最终全量结果与发布门禁待本轮验证后追加。

最终验证：首次编译发现收据时钟参数类型与既有 i64 不一致，已统一签名；正式发版链全量 724 passed / 0 failed / 7 ignored，包含两项新增故障回归。JS 模块语法检查通过，脱敏工作区及全部 git 对象通过，构建与 ad-hoc 签名成功。release.sh 在原生 UI 隔离门禁退出 2，未提交/tag/Release；未冒充隔离环境。restart-app.sh 已验证新实例 PID 99045。原生点击流程和窗口布局隔离验收仍未完成。

### P2 — 建议

- **`docs/research/agent-lifecycle-hooks.md:187-193` 与 `:228-229`** — 「细节待核」与「未证实」的条目没有可跟踪的收口。
  - 为什么是问题：文档已经建立了很好的核实纪律（每条结论必须落到「正文原句」或「本机实样」，否则写「未证实」），并且明确列出了 3 条未完成项：Cline 的事件名与 stdin 契约（第 191-193 行）、Claude Code 在 `claude -p` 下逐事件是否触发、Codex 在 `codex exec` 下 hooks 是否触发（第 228-229 行）。但这三处**只以散文形式散落在正文里**，没有编号、没有状态字段、没有复核方式。下一轮接手的人要判断「Cline 那条核完了没有」只能通读全文；更现实的风险是**重复劳动**——本轮已经发生过一次（v0.0.125 把 Qoder/Cursor/Trae/Cline 误判为排除，本轮重做）。而「未证实」这个标记本身也不区分「没找到出处」和「找到了但没逐字复核」，第 185 行（Trae 的 stdin 契约）与第 171 行（Cursor 的无头模式）用的都是同一句话。
  - 建议：在文末加一张「待核实清单」表（编号 / 条目 / 当前状态：未找到出处 | 待逐字复核 | 待真机实测 / 复核方式），正文对应处引用编号；并把「未证实」拆成上面三种状态。这样「P0 打通当天要实测的两件事」也自然有了归属，不必靠正文末尾那一段提醒。

- **`docs/research/agent-lifecycle-hooks.md:211-215`（Qoder http hook 接入片段）** — 缺 `allowedEnvVars` 的具体写法，而这正是「配置即接入」能否成立的关键一步。
  - 为什么是问题：第 1b 条把 Qoder 的 http hook 定为「本轮最省的一笔」（不需要桥接脚本），片段是
    ```json
    {"type":"http","url":"http://127.0.0.1:41999/session",
     "headers":{"X-AgentIsland-Token":"${AGENTISLAND_TOKEN}"}}
    ```
    但同段紧接着写「`allowedEnvVars` 白名单是它自己文档里的约束，实现侧要按它给的方式取令牌」——**白名单字段写在配置的哪一层、是数组还是对象、不填时的默认行为**都没有写出来。抓取过的正文里有这三项（第 145 行明确说 `headers` 的值支持 `${ENV_VAR}` 插值「且由 `allowedEnvVars` 白名单约束」），只是没落到片段里。结果是 P0 当天必须重新回查一遍文档，而这条路径的全部价值就在于「照抄即接入」。
  - 建议：把 `allowedEnvVars` 补进 1b 的配置片段（含它所在层级与取值形状），并注明「未在白名单内的变量插值会被拒绝」这一行为。

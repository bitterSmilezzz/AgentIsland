审查者：Codex。基线 main `8b6be514f0a8c3ac6e3be4a950cd2c529ec66109`；本报告是发布前时间点证据，不代表整体 M0–M4 完成。

## 问题与修复

- **干净表单的焦点阻挡新关口。** 正式 v313 独立 HOME 的真实文件监测读到合成 Codex 提问，原生 UI 新建并绑定后文件 rev3 已有 waiting/answer/正文引用，看板也更新；详情停在绑定返回的 rev2、零运行且没有问题入口。手动刷新能读取对应正文。真实 hydrateTasks 的受控浏览器回放独立失败：新问题按钮数量 0，预期 1。原因是 `detailHasFocus` 对未修改表单也禁止重画。
- **修复保留逻辑焦点而非旧记录。** 只有真实草稿继续保留旧详情与渲染版本；干净详情接收新关口、运行与来源。按任务/表单/产出及历史位置恢复焦点、文字选区和运行记录展开状态，过期动作回到详情，页外焦点不被夺取。已有草稿版本冲突、分别撤销和就近提示继续适用。
- **撤销出现时把保存推走。** 原生输入后以原保存位置点击，实际点到撤销，任务未写；独立截图显示主操作向左、撤销占原位置。浏览器来源表单相对 x=465→381 独立复现。三个表单使用共用动作组，隐藏撤销以自身自然宽度占位、不可见且不进入键盘顺序，主操作保持末尾。不按固定像素猜字宽，代价是无草稿时保留一小段操作宽度。
- **回归测试竞态。** 全量测试曾在坏帧已被服务端拒收并关闭后，客户端半关闭的 unwrap 得到 macOS ENOTCONN。核对生产接收器确实在非法长度头处立即拒收；单项复测通过。仅负例测试允许 `NotConnected`，其他错误仍失败，保留无成功回执和无正文绑定断言；增加先读到断开再半关闭的确定性内核反例。生产传输与隐私拒收规则未修改。

## 范围与交付约束

系统接收器是夹具，不能称作实际 Codex 客户端展示了对应会话。路由接收器重新签名会改变二进制哈希，诊断清理曾被旧 payload 哈希正确拦下；已以去签名代码哈希核对旧自有夹具，并记录新包签名后哈希，按路径/身份注销。隔离驱动生成错误未建立测试进程，不计入通过。原生最终候选只抵扣上述任务分项，不抵扣其他工具内容、完整三壳性能、启动 p95、历史接口用量或整个 macOS 出口。

# v0.0.283 独立复核

审查者：Codex。范围：进程识别、会话采样、尾读成本、用量归属、HTTP 通知与零值显示。

## 问题与修复依据

- sysinfo 默认刷新未装载命令行，真实 Node 子进程的提示词匹配失败。显式刷新命令行与路径，保留 CPU/内存采样，排除僵尸匹配；停止未使用的磁盘 I/O 刷新。
- 每个目录只选最新文件，普通日志遮住有效会话。共用元数据并最多尝试 16 个去重候选；失败健康信息传回引擎，数据库保持只读适配器路径。
- 缓存语义结果会冻结文件年龄；截断到 UTF-8 字符中间会误报不可读。改为缓存有界原始行并每拍解析，先丢弃残行字节再解码。文件长度、mtime、Unix inode 参与失效，容量限制有真实文件测试。
- 小时图表遍历跨 Agent 缓存，重叠来源重复累计。按本次来源归属过滤并去重；缺失位置保留未知，已测零值在 UI 显示为 0。旧测试改为明确移除来源，避免本机已安装数据库影响断言。
- 手写 URL 解析漏掉 IPv6 与无斜杠查询，畸形 HTTP 状态被计为送达。采用既有依赖 URL 解析器，限制状态行长度和合法格式，错误消息不回显对端内容。

## 验证

真实路径回归先失败后通过，包括进程 argv、僵尸、候选、UTF-8、跨 Agent 图表、重叠根、缺失源、畸形响应。全量 Rust 测试 575 通过、0 失败、5 忽略；功能 UI 脚本通过；diff 空白检查通过。

独立优化构建的尾读基准，输入 5 万行、保留最后 600 行，断言输出完全一致：原实现 493.633 ms，新实现首次 0.163 ms，缓存命中 0.021 ms。此数据只衡量尾读步骤，不外推整应用 CPU。

原生三窗口 UI、Dock、单实例、构建与全部 Git 对象脱敏扫描由 release.sh 在提交前执行；任一失败必须中止发布。该报告记录提交前复核，不预先宣称发布门禁通过。

## 保留边界

目录扫描原有 4000 项及时间预算不扩大，候选最多 16 个；Windows 原生界面未在本机验证。HTTP 接受不等于 IM/邮箱实际收件，本轮不发送真实通知。未启动 Chrome，历史前台反复激活的来源未在本轮确认。

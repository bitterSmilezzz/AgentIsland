# v0.0.175 独立复核 · DSH · 2026-09-27 06:54

## 范围与结论

复核外发组第二块：渲染层（`render` / `renderRequest` / `clamp` / `WireText` 四类转义 /
`maskedPreview`）迁入 `render.rs`，并由 `remote_preview`（「发送预览」）真消费。
结论：**渲染口径逐条对齐、隐私与注入两条口径有判别性用例**；传输与重试未迁。
Swift 侧零改动。

## 可核验的行为证据

- **隐私开关（本轮最重要的一条）**：`the_body_carries_the_agent_name_and_only_minimal_content`
  —— 同一份输入，`includeActionDetail` 关闭时正文**不含** `git push --force`，
  打开时正文精确等于三行。反向验证：把开关改成无条件 → 用例红并指出 `left != right`。
  这条守的是「哪些字节离开这台机器」的唯一开关。
- **参数注入**：`query_values_encode_the_separators_that_headers_may_keep`
  —— `git commit -m a && curl x#y` 在查询串里不许出现裸 `&`、`#`、`=`，
  而在头值里 `&` 允许（正是「不能复用同一套转义」的理由）。
  反向验证：让 `query_allowed` 放行 `&` → 用例红。
- **静默丢弃**：`header_values_are_pure_ascii_so_nothing_is_silently_dropped`
  —— 中文标题编码成纯 ASCII 并逐字比对 `%C2%B7` 等序列（实测过：不编码时对端只收到
  `Qoder · `，本地看不出来）。
- **四类转义各就各位**：表单空格 `+`、JSON 转义（引号/反斜杠/换行/控制字符）、
  `dropping_json_quotes`、unreserved 集原样保留（否则 URL 白涨长度）。
- **4096 上限**：超长正文断言 `body.len() <= 4096` **且**首行原样保留、标题头值 ≤ 255。
- **掩码**：`?key=` 与「16+ 位字母数字主机段/路径段」两处都遮，正常域名与主题名不动；
  预览断言**不含**密钥原文（`S3cret`）、SMTP 密码恒为 `••••••`，而真发时才是原值。
- **测试数**：Rust **130 → 144**（+14）、Swift 550（未动）；编译警告保持 **26**。

## 边界与后续风险

- **`smtp_line` 被刻意删掉**：SMTP 的一行必须折掉裸 CR/LF（否则一条消息在协议里变两条命令）。
  它现在没有消费方（传输层未迁），按既定纪律**不留未消费代码**——所以下一轮写 SMTP 会话时
  **必须**把它补上。这条风险写在 CHANGELOG 与本文件里，不靠记忆。
- **预览里 `{key}` 一定是掩码**：Rust 侧还没有钥匙串，`remote_preview` 传 `None`。
  Swift 会读**真**密钥再掩码，所以两边的预览在这一点上**看起来不同**（Swift 显示
  `key=S3••et`，Rust 显示 `key=•`）。这是如实反映「没读到密钥」，不是渲染错；
  接钥匙串后自然对齐。已写进对照表。
- **传输完全没做**：渲染出来的 `Request` 今天没有执行者。HTTP 客户端与 SMTP 会话都要选
  TLS crate（`rustls` + `webpki-roots` / `native-tls`），是像 `rusqlite` 那样需要单独决定的
  依赖，且 ADR 0005 已经钉死「邮件只走 465 隐式 TLS」。**这是外发组成败的关键一步**，
  也是目前离「能真发出去」最远的一段。
- **`utf8_clip` 按字节、`first_chars` 按字符**：Swift 那侧 `prefix(80)` 数的是 Character
  （用户感知字符），Rust 的 `chars().take(80)` 数的是 Unicode 标量。含组合字符或 emoji 时
  截断点可能差一两个标量——极端边界，未测（`utf8_clip` 的字节口径与 Swift 一致，因为那边
  也是按 `utf8.count` 循环）。
- **预览命令没有 UI 消费**：与 `remote_status` 同状态——已注册、可 `invoke`，
  Rust 侧今天没有设置页。它的价值是让渲染层成为可达 API + 为传输层准备好请求描述。
- 同前几轮：同一人既改又审；真正的护栏是两次反向验证的红与上面几条判别性用例，不是这份文档。

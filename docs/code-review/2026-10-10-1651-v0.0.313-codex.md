## 问题与修正

详情里的名称/项目和进度同时改动后互相阻止保存，提示留在上方；缺少独立撤销入口。现在名称/项目、进度和来源选择分别提供按需显示的撤销，恢复实际保存基线并保留其他草稿；就近展示保存等待、失败及阻止原因。完整 CSS 检查发现通用按钮 display 会覆盖 hidden，已补局部隐藏规则，未编辑时不增加按钮。

更关键的反例是后台快照更新了 data.revision，却保留旧表单：旧草稿随后借新版本成功覆写外部更新。详情现在绑定渲染版本，写入、来源导航和正文复核均保留该版本，后端既有聚合冲突规则保持。冲突保留草稿；全部撤销后显示已读取的新记录，焦点回到对应表单。此保护可能使无关任务更新也引发一次聚合冲突，未自动合并或提供强制覆盖。

手工关口及缺 observed 的历史记录使用本地处理说明，不要求前往没有绑定的来源工具；有摘要先显示摘要，观测到的方案缺正文仍明确说明。处理不等于来源批准或验收。

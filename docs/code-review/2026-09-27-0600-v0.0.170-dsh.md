# v0.0.170 独立复核 · DSH · 2026-09-27 06:00

## 范围与结论

复核 token 明细组收口：把 `StructuredTokenUsageIndex` 的保留口径（70 天窗口 / 折入保和 /
单文件 20,000 条上限 / 戳判定 / 只承认完整行的续读游标）搬进 Rust，并把「累计」从累加器
改成 `折入 + Σ窗口内明细` 每次重算。结论：**口径已对齐，并顺带修掉一个重写即重复计数的老问题**。
Swift 侧零改动。

## 可核验的行为证据

- **重复计数（本轮修的 bug）**：`rewriting_a_file_does_not_double_count_its_usage` ——
  同一路径先写 2000 token 的一份、再换成 110 token 的一份（更短），
  断言合计是 **110** 而不是旧实现的 `2000+110`。判别性来自结构：旧实现用累加器且仅在
  size 变小时重置游标，重读必然再加一遍。
- **等长重写**：`a_same_size_in_place_rewrite_is_still_detected` —— 两份内容字节数相同
  （用例内先断言 `second.len() == first.len()`，前置不成立会当场红），
  只有 output 一个数字变化 → 必须靠 mtime 发现。只看 size 的判定会一直用旧值。
- **窗口覆盖 30 天**：`detail_window_covers_the_whole_thirty_day_chart` —— 29 天前 / 8 天前 /
  刚刚三条都必须在逐小时桶里（合计 450）。旧实现只留 7 天，答案会是 150。
- **折入保和**：`folding_out_of_window_detail_is_conservative` —— 一条 2020 年的记录
  只进累计（300）、不进图表（150）。这是 ADR 0007 的核心不变式。
- **上限只裁明细**：`per_file_detail_cap_trims_the_oldest_without_touching_totals` ——
  20,001 条时累计是 20,001×150、桶里是 20,000×150。
- **续读游标**：`session::for_each_complete_line` 只承认到最后一个换行，并回吐真正承认到的
  字节数（而不是 stat 到的大小）。此前把半个 JSON 行承认下来并前进游标，那条记录就再也读不回来。
- **测试数**：Rust **92 → 97**、Swift 550（未动）；`cargo test --locked` 0 失败。

## 反向验证（做了两处，第二处发现自己的用例是假的）

| 改动 | 期望 | 实际 |
| :--- | :--- | :--- |
| `RETENTION_MS` 改回 7 天 | 窗口用例红 | ✅ 红：`left: 150, right: 450` |
| `MAX_DETAIL_PER_FILE` 抬到 100 万 | 上限用例红 | ❌ **绿** → 改完再验 → ✅ 红：`3000150 ≠ 3000000` |

第二处一开始是绿的，原因是那条用例把期望值写成了 `MAX_DETAIL_PER_FILE` —— 改常量时期望跟着变，
是**自证式断言**。改成字面量（20_000，并把输入规模固定为 20,001 行）之后才真正能抓回归。
这条值得记下来：**断言里引用被测常量，等于没有断言**。

## 边界与后续风险

- **`availableToolIds` 的误报防呆无对应实现**：Swift 坚持「明细源被发现」必须建立在真的看过
  那个目录上（根目录存在但整棵读不了时不许显示成「有明细源 · 0 token」）。Rust 走 walkdir，
  权限失败时只是文件少一些，**没有把「没看到」和「真没有」分开**。这条属于分析页能力，
  Rust 侧今天没有对应界面，所以不是现有界面的错报；但一旦 Rust 加分析页，必须一并搬。
- **保留窗口只被逐小时桶观测到**：Rust 的 `TokenReport` 只暴露 24h 与 30 天桶，70 天窗口的
  意义（给「上一周期」对比留料）在 Rust 侧**今天没有任何消费者**。窗口取值本身与 Swift 一致，
  但「2×最宽档」这条理由在 Rust 侧还只是预告。做时间线/上周期对比时要回头确认它够用。
- **`seen_ids` 的内存边界**：只在 `rolled_count == 0` 期间保留；一旦折入就清空并转为整份重读。
  这条依赖「折入 ⇒ 不走增量」的推断正确，用例覆盖的是行为（重复响应只算一次），
  **内存上界本身没有测**。
- **单文件 20,000 上限之外还有一层风险**：上限按条数裁，不按字节裁。单条超大行（对话正文）
  不产生明细，所以影响有限；但 `read_until` 仍会把整行读进内存，与上限无关。Swift 侧有
  「跳过 >1MB 巨行」的口径，Rust **没有对应实现**（本轮未动）。
- 同前几轮：同一人既改又审；真正的护栏是反向验证的那两条红，不是这份文档。

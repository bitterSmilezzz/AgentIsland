### 关于「删掉 `ensure()` 里 `if defect == .notRegular { removeItem }`」——本轮重点复核

**已确认（实跑）：这一删除是安全的，作者的理由成立。** 我在 /tmp 直接驱动 Foundation 的 `createFile(atPath:contents:attributes:)`：

- 符号链接指向一份 0600 的敏感目标：返回 **true**，链接本身被替换为 0600 普通文件，**目标字节一字不动**（`SENSITIVE-TARGET-CONTENT-DO-NOT-TOUCH` 保持原样、mode 仍 0644）；不带 `attributes` 时行为相同。
- 悬空符号链接：返回 true，替换为普通文件，不创建悬空目标。
- 目录占位于 `report.token`：`inspect()` 报 `.notRegular`，`ensure()` 走到 `createFile` 时**返回 false**（`open` 对目录失败）⇒ `ensure()` 返回 nil，**不会 `removeItem` 掉一个非空的真实目录**。这正是删除该分支的额外好处：保留 `removeItem` 反而会让一次空目录占位被真的删掉。

结论：`createFile` 在 Darwin 上对最终路径分量按 `O_CREAT|O_EXCL` 语义处理（撞到已存在的常规文件或符号链接时先解掉链接、绝不穿过链接写目标），因此旧分支 `defect == .notRegular → removeItem` 的「写穿符号链接」前提不成立，**该分支在生产中不可观测**。作者把它换成两条平台契约测试（`SelfReportTests.swift:128-155` 钉目标内容不变 + 链接被替换；`:157-171` 钉悬空链接不钉死通道）是正确处置：哪天 Foundation 改为写穿，红的是测试。TOCTOU 面：`inspect()` 与 `createFile` 之间被第三方换成符号链接也无害——`createFile` 会替换链接而非穿过它写。**建议作者复跑确认（未执行）**：`SelfReportTests.swift:128` 那条用例若把 `store.ensure()` 前 `report.token` 从符号链接改为「指向不存在目标的符号链接 + 目标随后被建」，断言仍应绿。

## 三个针对性问题的回答

1. **是否还有「无有效令牌 ⇒ `SelfReportStore.ingest` 写入 / 岛显示自报状态」的路径？** 没有。`ingest` 的唯一调用点在 `bindSelfReport` 内、`if case .bound` 分支下，而 `bindSelfReport(_:credential:)` 的 `credential` 非可选且 `SelfReportCredential.init` 为 internal——`AgentIsland` 里唯一取得方式是 `engine.authorizeSelfReport` → `store.authorize` → `matches`（过令牌才产出）。`believableSelfReport`/`record` 读的正是这份 store，故无凭证不可能产出可信状态。**须区分的旁路（by design）**：无凭证的 `attention`/`completed` 申报会经 `SelfReportFallback.post` 落成一条 `externallyDelivered:true` 的**通知**（与既有无鉴权 `/notify` 同一语义），但那不是「自报状态来源」，远程外发闸门照拦，且落回不建 costSpike、造不出终止入口。

2. **`SelfReportWire.reason/status/untrustedMessage` 是否对每个 `SelfReportRejection × trusted` 穷举，服务端还有没有 ad-hoc 兜底？** 对三个 `SelfReportRejection`（malformed/unknownAgent/unknownState）× trusted(true/false) 是**全表**（`reason` 未鉴权恒 noToken、鉴权一对一；`status` 未鉴权 200、鉴权 400；用例 `SelfReportTests.swift:631-637` 逐格覆盖）。**但 `SelfReportWire` 只覆盖「载荷被拒」这一族**：`badMethod`(405)、`noEngine`(503)、`bound`/`pidMismatch`/`profileGone`(POST 绑定结果)、`revoked`/`notFound`(DELETE) 仍由服务端各自硬写状态码——这属合理分工（它们不是 `SelfReportRejection`）。**一处口径的第二出口**：未鉴权 POST 的响应直接写死 `status: 200, reason: .noToken`（`LocalEventServer.swift:332-333`）而非走 `SelfReportWire.status(for:trusted:false)`，与表值相同、当前无害，但「未鉴权恒 200/noToken」这句话因此有两处书写。建议未鉴权分支也调表（或加注释声明它是表的常量特例）。

3. **有没有测试在断言注释、常量字面值、或可能被平台静默改动的行为，从而给出假信心？**
   - 断言注释：无——结构棘轮走 `codeOnly`（剥注释），这正是第 1 轮 P2 建议的落地，已验证生效。
   - 常量字面值：`SelfReportTests.swift:176-178` 断言 `ownerOnlyMode & 0o111 == 0`、`ownerOnlyDirMode == 0o700`。这是**安全相关的不变量**（目录须带执行位、令牌文件不得带组/其他位），改成别的值本就该红，属正当断言，非假信心。
   - 平台行为：`:128-155`/`:157-171` 直接钉 `createFile` 对符号链接的语义（目标不被写穿、悬空链接不钉死通道）。这是**正确的用法**——不是「假设平台不变」，而是「平台若变则测试先红」。我已实跑确认当前 macOS 上此行为成立，故该组测试今天既不会假绿也不误红。唯一「测不出来的东西」作者在注释里已诚实记录（`SelfReportTests.swift:137-139`：符号链接自身 mode 实测 0755，类型判据与权限判据在 `read()` 路径重叠，单删类型判据不红）——这条与 CHANGELOG 的表述一致，属实。

# v0.0.190 独立复核 · DSH · 2026-09-27 10:52

## 范围与结论

复核 Phase 2 的**界面侧**：档位页（列表 / 生效标记 / 切换确认 / 备份还原 / 新增表单）、
能力边界的上屏方式，以及为此扩的两条哨兵。结论：Phase 2（1–7 条）完成；
**像素未验证**，且没有对用户真实 `config.toml` 做过真实切换。Swift 侧零改动。

## 可核验的行为证据

- **DTO 字段哨兵**：`every_provider_field_the_ui_reads_exists_in_the_dto`
  —— 按 `profile.` / `status.` / `applied.` / `backup.` 四个前缀扫 `views.js`，
  断言每个键都在对应 DTO 里；并且断言**每个前缀至少被用到一次**
  （否则页面被删了、或改了变量名，哨兵就静默失效了）。
  **反向验证**：把 `profile.provider_id` 写成 `profile.providerId` → 红
  （「views.js 读了 profile.providerId，但 DTO 里没有这个键」，并列出真实键集合）。
- **类别覆盖哨兵**：`every_sidebar_class_is_actually_styled` 改成扫**整个** `views.js`。
  **反向验证**：加一个 `sb-typo2` → 红。
  这条的覆盖面变化本身是证据：它第一次跑就报出档位页漏了 `sb-page` 的样式——
  说明在此之前，**新加的页面天然不在保护面内**。
- **运行时冒烟**：`--shell=sidebar --route=provider` 与 `--route=tokenAnalytics` 各起一次，
  前端日志**零错误**（未捕获异常与 Tauri 权限拒绝都会落到那里——v0.0.188 就是靠它抓到
  `event.listen not allowed on window "sidebar"` 的）。
- **稳定性**：连跑 5 次全绿；测试 Rust **267 → 268**；编译警告 **19**。

## 本轮修掉的真 bug

侧边栏原先**每次引擎推送都整页重画**（`engine://tick` → `renderSidebar()`）。后果是：
分析页每 2 秒被打回「加载中…」；档位页会把用户正在填的表单冲掉。
现在只有 `route === 'list'`（实时列表）随推送重画。
**这个坑在 v0.0.187 就存在**（当时分析页已经在受影响），但**没有被当成 bug**——
直到这一轮加了第二个数据型页面，它才明显到必须修。记在这里：一个 bug 只影响一个页面时，
很容易被当成「那个页面的小毛病」。

## 设计取舍

- **能力边界由 Rust 提供、界面照搬**：如果文案在界面里各写一遍，
  它就不是「必须出现的约束」而是「某处的一行字」。切换结果里也带同一段话，双保险。
- **确认框写「会发生什么」**而不只是「确定吗」：改哪个文件、备份落到哪、要不要重启 Codex。
- **`installed=false` 与 `installed=true 但 provider 对不上`分开说**：
  前者是「没装」，后者是「装了但不是本应用在管」。混成一句「无」会被读成「没在切换」。
- **新增档位表单直接给全部字段**：没有创建入口的列表页等于摆设。校验仍在 Rust 侧，
  失败时把 **Rust 的原话**带回界面，不在前端翻译成自己的说法。

## 边界与后续风险

- **像素未验证**（同前几轮）：`screencapture` 需要屏幕录制授权，
  本机拿不到。冒烟能证明「模块加载、命令调用无未捕获异常」，
  **不能**证明「页面上显示的就是我想显示的样子」。这是本轮最大的未验证面。
- **没有对真实 `~/.codex/config.toml` 做过一次切换**：所有用例都在沙箱里。
  第一次真实切换时应先看备份目录是否落下了文件（这是使用者的动作，不是我的）。
- **`provider_scan_tools` 没有界面消费方**：它留给「将来接第二个工具」。
  因此它**不在**字段哨兵的前缀里——没有消费方的 DTO 不该逼界面去读它。
- **侧边栏的详情页仍复用灵动岛的卡片壳**：形态上略突兀（一个 `dock-*` 卡片出现在侧边栏里）。
  已记入 Phase 4 收尾。
- **档位页的错误提示用的是 Toast**：它随下一次 `hydrate` 消失。
  做对了事（失败不静默），但「失败信息只存在两秒」对排查不够友好——将来值得改成常驻一行。
- 同前几轮：同一人既改又审；真正的护栏是两处反向验证、以及那次**因为新增页面才暴露出来**的重画 bug。

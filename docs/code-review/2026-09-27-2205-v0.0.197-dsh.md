## 值得记的三件事

### 1. 「否定结论也要有证据」是这块的设计支点

`is_installed` 返回 `Option<bool>`，规则是：档案登记了 `bundle_ids`、
而这趟扫描**没有否定能力**时给 `None` 而不是 `Some(false)`。

这不是防御性编程的口头禅，它有具体后果。Windows 上没有 bundle 这个概念
（本仓也没有「已安装 GUI 应用」的证据源），`scan_bundles` 因此永远返回
`can_prove_absence: false`。若那时返回 `Some(false)`，
Cursor / VS Code / Trae 这些 GUI 档案在 Windows 上会**每天被宣布「未安装」**，
而用户明明装着。少给一个「未装」只是保守；多给一个是要用户去核对事实的。

`Info.plist` 只认 XML 形状（不引新依赖）是同一类取舍：binary plist 落到「读不出来」，
读不出来就意味着这趟扫描有盲区，于是**否定能力被收走**。两条路径都收敛到同一个出口：
「证据不足 ⇒ 不下结论」。

反向验证：把 `if !profile.bundle_ids.is_empty() && !self.bundle_can_prove_absence`
改成 `if false`，`a_gui_profile_without_bundle_evidence_is_unknown_not_absent`
立刻红（`left: Some(false), right: None`）。

### 2. `bundle_ids` 不是顺手加的字段，是上面那条规则的必要条件

不补它，GUI 档案的证据只能从 PATH 找，而 GUI 应用本就不在 PATH 上——
于是它们永远「没扫到」，而规则 1 会诚实地把「没扫到」翻译成「未核实」，
结果就是**所有 GUI 档案永远停在「未核实」**，等于这一版白做。
补了 `bundle_ids` 之后，macOS 路径上 `/Applications` 能给出真命中。

14 个内置档案逐条对齐了 Swift 侧声明（`codex` / `aider` / `cline` / `roo-code` / `goose`
的 `bundleIDs` 本来就是空数组，CLI 专用，不要为了「填满」给它们编一个）。
`vscode` 是 Rust 独有档案、Swift 侧无对照，取 `com.microsoft.VSCode`——
**这一条没有第二来源可核**，已在 CHANGELOG 写明。

### 3. 自报归因是被上一版带出来的，不是我这一版新造的

v0.0.195 把自报状态机迁进 Rust，快照有了 `provenance`，但 `observability::evaluate`
对「工作中 / 待确认 / 已完成」一律写「本轮有活动或任务状态信号」。
那一拍的状态可能完全来自一条带令牌、TTL 内的自报，与会话日志无关。
Swift 侧同一处早就分开写了。这是典型的**迁 A 忘了迁 B**：
概念落地了，依赖这个概念的文案没跟上。

反向验证：把自报分支改成 `if false`，
`a_self_report_is_credited_to_the_self_report_not_to_observation` 即红。

| 警告数是否漂移 | ✅ 保持 17。`missing_ids` 一度成为死代码，按本仓规矩摘掉了（等真有 CLI/报表要列这份名单再加回来） |
| 是否动了 Swift 业务代码 | ✅ 只改 `AppVersion.string`（发版一致性要求） |

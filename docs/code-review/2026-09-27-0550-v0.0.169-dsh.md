# v0.0.169 独立复核 · DSH · 2026-09-27 05:50

## 范围与结论

复核 token 明细组的第一步：Rust JSONL 净口径对齐 Swift、codex 记录族收敛、
新增响应级去重、标记预筛。结论：**发现并修掉一处 29 倍量级的口径错误**，
本机真实日志端到端复核一致。Swift 侧零改动。

## 可核验的行为证据

- **错误是量出来的，不是读出来的**：本机 26 份真实 `~/.codex/sessions/**/*.jsonl`，
  按「记录族 × 公式」四种组合求和 → 记录族只差 0.3%（3,905,535 vs 3,893,007），
  公式差 **29 倍**（3,905,535 vs 114,006,271）。取证命令与逐文件对照见
  [docs/research/2026-09-27-jsonl-net-token-formula.md](../../ui-research/2026-09-27-jsonl-net-token-formula.md)。
- **端到端复核（关键）**：修完后用同一个 `TokenUsageMonitor` 直接跑本机真实目录
  （临时 `#[ignore]` 探针，验完即删，**不入库**）→ `tokens_total = 3,905,535`，
  与独立 Python 脚本按 Swift 公式算出的值**逐字相同**；修前同一路径落在 114,006,271 那一档。
  这条是「实现 × 独立脚本」的交叉验证，不是自证。
- **用例本身是判别的**：`net_tokens_exclude_cache_hits_like_swift` 同时断言
  `tokens == 1921` **和** `tokens != 43649`（旧口径的值），换回旧公式必红。
- **记录族收敛有据**：本机 21/22 份文件两族并存，测试断言另一族（`token_count`）
  现在解析为 `None`——即同一笔用量不会因「都认」被计两遍。
- **去重是真跑的**：`duplicate_responses_in_one_file_are_counted_once` 往同一文件写
  `A、A、B` 三行，断言合计是 `A+B`（350）而不是 `2A+B`（500）。
- 测试数：Rust **86 → 92**、Swift 550（未动）；`cargo test --locked` 0 失败。

## 边界与后续风险

- **anthropic 侧没有本机实样**：本机 `~/.claude/projects` 里 `"cache_read_input_tokens"`
  零命中（用户不用 Claude Code），所以那一族只有合成夹具覆盖。已写进研究记录。
  **这是本轮最大的证据缺口**：公式是从 Swift 源码逐字抄的，但没在真实 Claude 日志上跑过。
- **`StructuredTokenUsageIndex` 只迁了一半**：保留/折入口径（70 天窗口、折入保和、
  单文件 20,000 条上限、戳 memo、`canAppend` 需 `rolled == 0`）**都还没迁**。
  Rust 现在仍是「明细只留 7 天 + 全量累加」——这意味着 Rust 的 30 天逐小时桶
  （`hourly30d`）实际只覆盖 7 天，与 Swift 的 30 天对不上。下一轮做。
- **估价落点差异仍在**：Swift 在视图层用 `resolveCost` 估、Rust 在数据层估。两边单独看数字
  一致，但**混合汇总**（既有记录值又有估价值）时 Swift 只显示记录值、Rust 会相加。已在
  23 号对照表 §6.3 写明，未修。
- **23 号对照表里那条「净消耗口径 ✅ 一致」此前是错的**：本轮已改为「v0.0.169 起一致」并附取证。
  这说明对照表里其他「✅」也可能同样是没量过的乐观结论——下一轮值得把 §6 的 ✅ 逐条重测。
- **临时探针已删除**：验证用的 `mod local_probe` 读完即删，未进提交；确认方式是
  `cargo test` 恢复正常计数（92 条，不是 93）。
- 同前几轮：同一人既改又审；护栏是那条端到端对拍与三条判别性用例，不是这份文档。

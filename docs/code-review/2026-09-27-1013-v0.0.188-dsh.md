# v0.0.188 独立复核 · DSH · 2026-09-27 10:13

## 范围与结论

复核两件事：① Phase 1 第 5 条的「内容层」（两种形态共用一份显示模型）与守它的两条哨兵；
② 侧边栏形态的**运行时验证**（新增 `--shell=` 覆盖）。结论：功能层已验证且抓到并修掉一个
真 bug；**像素仍未验证**（本机权限所限）。Swift 侧零改动。

## 可核验的行为证据

- **共用显示模型**：`both_shells_render_agent_rows_through_one_shared_model`
  —— 显示模型只有一处定义、状态文案表只有一处、两条渲染路径都经过它。
  **反向验证**：把侧边栏改回内联文案（自己拼 `level_label`）→ 红
  （「侧边栏的行没有走共用的显示模型：文案与颜色会各写一份」）。
- **类名覆盖**：`every_sidebar_class_is_actually_styled`——`renderSidebar` 里 `sb-*` 的静态类
  逐个到 `sidebar.css` 里找。**反向验证**：加一个 `sb-typo-class` → 红
  （「sidebar.css 里没有这些类的样式：["sb-typo-class"]」）。
- **运行时（这一轮的关键）**：`--shell=sidebar` 起 app → 前端错误日志出现
  `event.listen not allowed on window "sidebar"`。**这是一个真 bug**：capability 只列了 `island`，
  侧边栏没有监听权限 ⇒ 渲染一次后再不更新（界面看着正常、数字不动）。
  把 `sidebar` 加进 `apps/.../capabilities/default.json` 的 `windows` 后：
  侧边栏与灵动岛两种形态**各跑一次、前端零错误**（日志里只剩一行信息性的 `=== boot ===`），
  进程存活 ✓。
- **测试数**：Rust **252 → 254**；编译警告保持 **21**；还原后连跑 3 次全绿；`node --check` 过。

## 这一轮最该记住的一条

**那个权限 bug 是单元测试永远抓不到的**：capability 是 Tauri 的运行时配置，
不参与编译；而它的失效方式是「前端抛一个 rejected promise，界面照旧画出来」——
如果没有「把 app 真起起来看日志」这一步，它会一路带到用户手里，表现为
「侧边栏数据不动」这种最难查的症状（而排查方向会是采集、是引擎、是缓存，**不是权限**）。

这也是上一轮我把「视觉未验证」标成最大缺口的原因：缺口不是为了好看，
是因为**没跑起来就有一整类失效看不见**。今天补上了「起得来、零错误、能收推送」这一层；
**像素层仍然没有**（`screencapture` 要屏幕录制授权，本机拿不到：
`could not create image from rect`）。

## 边界与后续风险

- **像素未验证**。依据是「功能跑通 + 两条结构哨兵 + 类名覆盖」，**不是看过一眼**。
  复跑方式写在 CHANGELOG 里（起 `--shell=sidebar` 再截图）。在能截图的机器上应补这一步。
- **`--shell=` 是给验证用的旁路**：只影响本次运行、不写回设置（故意的：改设置去验证，
  验证完还得记得改回来，那是最容易留下脏状态的做法）。它**不是**用户功能，
  界面上真正的入口还没做。
- **侧边栏的层叠行为待定**：上一轮我把它设成 `alwaysOnTop`（当时是为了截图方便），
  这一轮撤回了——理由不充分，且计划里没定。**这是一个待定的产品决定**：
  置顶则不会被浏览器盖住但更打扰；不置顶则可能被盖住。今天按「不置顶」出，
  因为它更保守（可随时改回，反之则会让用户先被一个突然置顶的面板打扰）。
- **两条哨兵是文本级的**：它们读源码找模式，改函数名/换写法就可能失效
  （失效方式是「哨兵不再检查」而不是红）。这是文本哨兵的固有代价，
  与 `models.rs` 里那条字段哨兵同一套路——比没有强，但不是类型系统。
- **`island.css` 未拆分**、**懒加载未做**、**设置页与 ToDos 未做**：Phase 1 还没走完。
- 同前几轮：同一人既改又审；真正的护栏是两处反向验证、以及那次抓到权限 bug 的运行时冒烟。

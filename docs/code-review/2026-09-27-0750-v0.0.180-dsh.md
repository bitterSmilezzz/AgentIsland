# v0.0.180 独立复核 · DSH · 2026-09-27 07:50

## 范围与结论

复核钥匙串接入（`secret.rs` + 闸门分段 + 两条密钥命令）。结论：**密钥的存/取/存在性
都有实物或判别性证据**，「关掉总开关就不碰钥匙串」这条被用例数出次数钉住。
**外发组至此迁完**。Swift 侧零改动。

## 可核验的行为证据

- **跨版本契约钉死**：`the_service_and_entry_names_are_pinned_to_the_shipped_swift_versions`
  —— `com.agentisland.remote` + `remote.ntfy` / `remote.customHTTP` / `remote.smtpEmail`。
  这三个字符串一旦改动，老用户存过的密钥就会「消失」（读不到 ⇒ 闸门报未配置），
  而现象只是「配好了却发不出去」——所以它必须是**字面量断言**，不能是「两边调同一个函数」
  就以为对齐了（同函数只保证内部一致，不保证与已发布的 Swift 版一致）。
- **闸门放行后才读钥匙串**：`the_keychain_is_not_read_while_the_master_switch_is_off`
  —— 用计数型假密钥源断言读取次数为 0。
  **反向验证**：把读取提前到 `gate_policy` 之前 → 红（`left: 1, right: 0`）。
- **缺密钥就不发**：`a_key_placeholder_without_a_stored_secret_is_never_sent`
  —— 模板含 `{key}` 且钥匙串为空 ⇒ `NotConfigured`，且传输层**一个请求都没收到**。
  旧行为是「留空照发」（等于拿空密钥去撞对端还让用户以为发成功），这一轮修正。
- **密钥只进请求**：`a_stored_secret_reaches_the_request_and_nowhere_else`
  —— 请求里带真值；账本文案、标题、掩码预览里都不含它。
  **反向验证**：渲染时不传密钥 → 红。
- **失败文案也不夹带**：`the_ledger_never_contains_the_secret_even_when_the_send_fails`。
- **实物取证（钥匙串不能只靠编译）**：`manual_keychain_round_trip`（`--ignored`）
  写 → 存在性 → 读回 → 覆盖（不产生第二条）→ 删除，**本机跑过并通过**，跑完无残留。
- **测试数**：Rust **176 → 178**（+4 密钥用例，另 1 条手动探针）；编译警告保持 **26**。

## 设计取舍（两处有意与 Swift 不同）

1. **写入路径**：Swift 用裸 `SecItemAdd`，撞到重复条目时先删再加，而它自己的注释写明
   那一步在 ad-hoc 签名下危险（旧条目能删、新条目被拒 ⇒ 旧值也没了）。
   `security-framework` 撞重复走 **SecItemUpdate**，那个窗口在这里不存在。
2. **`exists` 不进 `SecretStore` trait**：trait 只留 `read`（发送路径要的）。
   设置页要的「存过没有」是自由函数 `exists`，走不带 `kSecReturnData` 的查询。
   两件事分开，是 Swift 「不把值读进界面内存」那条的直接落地。

## 边界与后续风险

- **设置页 UI 仍不存在**：`remote_status` / `remote_preview` / `remote_secret_set` /
  `remote_secret_delete` 四条命令**都没有界面消费方**。也就是说这一轮交付的是
  「外发这条链在代码层完整」，不是「用户能用」——用户今天改不了设置、存不进密钥。
  **这是外发组迁完后最大的缺口**，且它是 Phase 1/2 的 UI 工作，不是本组的事。
- **`manual_keychain_round_trip` 默认不跑**：所以钥匙串的写入路径在常规 `cargo test` 里
  **没有守护**。改动 `write`/`delete` 不会被任何默认用例拦住（`read`/`exists` 有只读用例）。
- **`WriteResult::Ok` 的语义是「系统接受了这次写入」**，不代表用户下次能读到
  （ad-hoc 签名下每次出包代码标识都变，读取时仍可能被拒）。这一点由 `remote_status`
  的存在性查询在下一次刷新时暴露，但**没有自动化用例**。
- **密钥读取发生在工作线程里**（`dispatch` → 工作线程 → `attempt` → `secret::read`）：
  并发外发会各自读一次钥匙串。低频场景下无所谓（同类有 90 秒节流），但没做缓存——
  也没有「读取被拒时如实记账」的用例。
- 同前几轮：同一人既改又审；真正的护栏是两处反向验证的红、实物探针的通过与上述判别性用例。

## 范围与结论

复核 M3 首个模块迁移：`TokenCostEstimator` → `app/src-tauri/src/cost.rs`，以及随之改动的
`tokens.rs` 成本口径、`TokenUsage`/`ModelUsage` 的估算标记、`main.rs` 聚合、`views.js` 显示。
结论：两端口径**已对齐且被测试锁住**；Rust 侧不再为未登记模型编造成本。Swift 源码零改动。

## 可核验的行为证据

- **费率表逐值逐序相等**：`cost::tests::swift_table_parity` 读
  `Sources/AgentIslandCore/TokenCostEstimator.swift` 源表比对 pattern 与两个价。
  **双向验证**：把 Swift 的 `claude-3-5-haiku` 从 `(0.8,4.0)` 改成 `(0.9,4.0)`，
  该测试立刻红并给出 `pattern claude-3-5-haiku 的费率不一致：Swift (0.9, 4) vs Rust (0.8, 4)`；
  还原后通过（`git status` 确认 Swift 文件已还原、无残留改动）。
- **哨兵不会静默失效**：解析结果为空时测试显式失败（`从 Swift 源里一条费率都没解析出来`），
  防止「解析口径改了 → 哨兵变空转」。文件读不到也直接失败，不 skip。
- **不再编价**：`tokens.rs::tests::unknown_model_gets_no_invented_cost` 与
  `glm_is_not_priced_on_either_side` 断言未知模型 `cost == 0` 而 `tokens` 照记 4000；
  旧实现这两条都会给出编造的钱数（兜底 `(1.25,10.0)` 与 `glm (0.55,2.0)`）。
- **算法与 Swift 同源**：`cost_comes_from_the_shared_estimator` 锁 3:1 混合价
  （(3×3+15)/4 = 6.0 美元/百万；4000 tokens → $0.024），不再是按分量分别计价。
- **测试数**：Rust **62 → 73**（`cargo test --locked` 73 通过 0 失败），Swift 549 条不变。
- `cargo build --locked` 通过；`node --check app/ui/js/views.js` 与 `git diff --check` 通过。

## 边界与后续风险

- **未做端到端界面验收**：没有截图或 DOM 断言，`~` 标记与「预估月末费用显示 `—`」
  只经代码审阅，未在真实界面里看过。本仓至今没有 UI 自动化对照，这是已知缺口。
- **`cost_estimated` 是「整份报告级」而非按条**：今日之所以成立，是因为 Rust 唯一的成本
  来源就是估价（`cost > 0` ⟺ 估算）。记录成本源（SQLite）迁入后必须改成逐条记账，
  `tokens.rs` 里已就地写明这条前提，但它目前靠注释而非测试守着。
- **SQLite token 源仍未迁入**：`dim`/`zcode`/`opencode`/`mimocode`/`workbuddy` 在 Rust 侧
  token 明细仍为 0，估算因而也对这几家不生效（它们的成本根本进不来）。这是 M3 下一件。
- **费率表的「准确性」未经第三方核实**：本轮只保证**两边一致**，不保证费率本身与各家
  官方定价页一致。ADR 0010 要的是消除两端口径分叉，不是重估价格；若要核价需单独立项。
- 本仓现状是同一人既改又审（前几轮同样如此）。真正的护栏是那条漂移哨兵而非这份文档，
  所以本轮特意对它做了反向验证。

## 实现与取舍

新增 `interface_models.rs`：纯解析与目标构造（`target`/`discover`/`parse` 分离，凭据与 HTTP 注入），严格只认 OpenAI list 结构，4096 原条目上限、排序去重后前 200 个，`total` 与 `truncated` 如实给出；结构错误、业务错误与超限都走失败分支，不返回空清单伪装成功。模型 id 有界白名单校验，已知凭据前缀（`sk-`/`AIza`）与当前凭据回显在解析层拒绝，不进 DTO。

传输复用 `connection_http` 的有界 GET（5s / 512KiB）与单请求租约（`connection_probe::Lease`），与 New API/Magpie 手动读取同一套受控传输，不另开网络路径。`provider_read_models` 在 `spawn_blocking` worker 内先按 id + expectedProfile 从 Store 取目标，网络等待期间不持配置锁，返回前再核对同一档位身份；身份漂移即拒绝，晚到响应不能落到新目标上。凭据只在该 worker 内从档位声明的 `env_key` 读一次，Bearer 只发目标地址；禁重定向、自动重试与代理在传输层统一执行，错误文案不带响应正文或密钥。

前端 `createModelReader` 以完整档位身份为键维护有界 8 项目标缓存，档位任何字段变化即失效旧结果；重复点击互斥（隐藏 lease 控件把 busy 状态同步给页面，禁用期间不发起第二次请求）。「填入档位」只写既有编辑器草稿的 model 字段并触发 input 事件，不保存、不应用、不推断运行模型；已有草稿或确认中的操作不被覆盖。目录查找扩展为覆盖服务模型：按模型搜索收敛到匹配模型行，按接口/档位搜索保留该行全部模型，清空恢复完整结果；无效结果（目标变化被清除）不留下 stale 匹配。

## Spec

逐条对照 .scratch/interface-models/spec.md：URL 前缀保留、HTTPS/回环 HTTP only、无默认地址与端口扫描、OpenAI list 严格结构、4096/200 与截断报告、凭据回显与前缀拒绝、DTO 无其他响应字段、页面内存 8 项目标与身份失效、草稿填入不自动应用、查找覆盖与清除语义、重复互斥、无轮询不抢焦点——均有对应用例或受控页面证据。未发现越界实现。

一处取舍记录在案：spec 要求「结果仅页面内存有界 8 项」，实现为按档位身份键的 Map，容量满时淘汰最早目标；这与「最多 8 个档位目标」等价，且目标变化立即清除优先于容量淘汰。

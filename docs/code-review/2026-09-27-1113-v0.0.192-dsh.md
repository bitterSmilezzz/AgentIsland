- **冒烟**：侧边栏五种页面各起一次（`--route=list / tokenAnalytics / provider / todo /
  agentDetail:claude`），**前端零错误**——详情页那条正是本轮改过的路径。
- **测试**：Rust **275 → 271**（-4 是随删除的 4 条用例，不是丢了覆盖：
  那些用例的断言点已被 `plan_codex_apply` 的用例覆盖，唯一独有的「清掉 provider 覆盖」
  行为是**决定不做**的那条，理由见下）；编译警告 **16 → 14**。
- **README 逐条核对**：`grep -n "灵动岛\|形态\|窗口" README.md` 后逐句判断它描述的是
  **Swift 本体（交付物）**还是 Rust 端；改动只落在确实不成立的地方。

## 两处「计划说的和事实不一样」

1. **README 该怎么改**。计划要求把「灵动岛 = 唯一形态」一律改成「形态之一」。
   但今天实际交付的是 **Swift 本体，它确实只有灵动岛**——一律改掉会写出
   **对交付物不成立**的话。改成按交付物分开写：灵动岛一节标明「当前交付形态」，
   另加一节讲 Rust 端的侧边栏，并在「已知限制」里把 Rust 端今天真正成立的三条补上
   （无像素实样 / 未对真实配置做过切换 / 一致性靠逐条核对）。
   **计划的目标（不留已不成立的描述）达到了，路径与它设想的不同。**
2. **ADR 编号**。计划写 `docs/adr/0009-sidebar-alongside-island.md`，但 0009 已被
   「凭据边界」占用 ⇒ 改用 **0012**。这条写进了 ADR 开头而不是悄悄改掉：
   文件名是最典型的**过期信息**形态，看到的人会以为它存在。

## 删除 `update_codex_profile` 的理由

它被 `plan_codex_apply` 完整取代（后者还写 provider 表、且走同一条路径校验）；
它唯一独有的行为是「清掉 `model_provider` 覆盖」＝「回到 Codex 默认」，
而**这件事用还原备份就能做到**（档位页每次切换前都留备份，页面上就有还原入口）。
为它多养一条没人走的写入路径与一份状态不划算。**界面上没有单独的「回到默认」按钮**，
这一点记在 CHANGELOG 与这里，不藏在注释里。

## 一次自己踩到的坑（按锚点切片，这是第三次）

删那个函数时按内容锚点切片，**第一次切宽了**——把 Phase 2 的整段生产代码一起删掉，
编译立刻报错才发现。第二次先加护栏（切片前断言「这段里只有 1 个函数、没有别的定义」），
护栏**当场拦下了过宽的那次**（`AssertionError`，文件未被改动）；第三次按 `MARK` 锚点精确切，
又连带删掉了两条共享测试助手（`Sandbox::codex_config` 与 `profile()`），已补回。

**教训（第三次写下来了）**：按锚点切片时，**先断言切片区间内的定义个数**，
再改文件。护栏的价值在这次体现得很直接：它让「错」发生在**编译前**，
而不是靠编译错误或测试失败事后发现。

## 边界与后续风险

- **像素级实样仍未做**（本机截图需屏幕录制授权）：这是整个工作台改造**唯一**没有实样支撑的部分，
  已写进 README 的已知限制与 ADR 0012。
- **没有对真实 `~/.codex/config.toml` 做过一次切换**：所有验证都在沙箱/临时目录。
- **「反复切换形态十次无残留」只有设计保证**（两个窗口只建一次），没有真按十次。
- **Rust 端尚未成为默认交付物**：`shell_mode` 默认 `island`、Rust 端界面无实样，
  所以「默认交付物换成 Rust」是**另一个决定**，不在这次改造范围内（ADR 0012 记了理由）。
- 剩下的编译警告（14 条）都是薄版移植留下的未接线 API（`procmon::all_names`、
  `session::for_each_line` 等），逐条都在「未接线的能力」这一类里，不是新债；
  要不要接由后续需求定，不建议为了清零而删。
- 同前几轮：同一人既改又审；真正的护栏是自检、五页冒烟、两处反向验证，
  以及这次**当场拦下错误切片**的那条断言。

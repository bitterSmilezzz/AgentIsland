## 2. 发现与处置

### P1-1 状态的第二出口没拆掉，只是改写成同义说法 → **已修**

断言禁的是三个状态词的**字面量**，而正文把同样的判断留在了括号外：
「本轮没逐字复核」「未找到正文依据」「正文未出现 hooks」「没有逐条出处」「该页未列」——
文档同时新增的那句「正文只写编号、不带状态词」因此是假的。

**修法（两侧一起做）**：① 文档侧把 7 处「缺证据判断句」改成「问哪件事 + 编号」，证据与状态一律进表；
② 断言侧把禁令从三个词扩到同义 markers，且**只作用在含编号引用的行**上，别处正常中文不误伤。

### P1-2 编号识别的静默失效模式本身还在 → **已修（换成结构下界）**

上一版只是把字符集从 `a/b` 放开到「任意一个字母」，但「两侧同时隐身」的根因是
**识别方式（数粗体 token）与被守约定（编号要成对）之间没有下界**：写成 `v4`、裸文本 `V9`、
`V5aa` 照样绕过，而绕过的表现是全绿。

**修法**：不再枚举合法形状，改加结构下界——清单每个数据行的编号格必须严格匹配
`**V<数字>[单个字母]**`，不匹配就指名报第几行、实际值是什么。这条同时治好了
「误导性的 rows≠ids 计数消息」。

### P1-3 状态校验是行级 `contains`，本轮新增的列校验却是格级 → **已修**

`allowed.contains(where: { row.contains($0) })` 扫整行，状态格空白而状态词写在别的列时照样绿——
「清单是状态的唯一出口」变成只有形式没有内容。
**修法**：改成对状态格 `hasPrefix` 三分类之一。

### 不采纳及理由

- **「`|**V4** |`（编号格少一个空格）会静默漏网」——复核后判为误判。**
  `|**V4** |` 是合法 markdown，单元格内容仍是粗体 `V4`；新断言不依赖那个空格
  （按 `|` 切格后再验格内形状），所以它被正常识别、配对成立、通过。**这是正确行为，不是洞**。
  实测矩阵里这条为「绿」，据此判定审查者的行形脆弱性分析在这一点上过头了。

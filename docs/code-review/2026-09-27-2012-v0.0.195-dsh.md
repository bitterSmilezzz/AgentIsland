# v0.0.195 独立复核 · DSH · 2026-09-27 20:12

## 范围与结论

把「自报 + 出处（provenance）」迁进 Rust 并端到端跑通：`selfreport.rs`（状态机 + 判定）、
`/session` 真正接上、快照带出处、界面徽标与审计报表状态列使用它。结论：对照表里那条缺口已闭合，
**有实样**。Swift 侧零业务改动（只改了版本号）。

## 可核验的证据

- **端到端（本机实测）**：退掉 Swift 本体让出 41999 后启动 Rust 端，`curl` 四条：
  ① 无令牌 → `401 {"bound":false,"reason":"noToken"}`；② 带令牌 → `200 {"bound":true,"expiresAt":1790511107}`；
  ③ `state` 认不出 → `400 unknownState`（带一句人话）；④ 未知 agent → `400 unknownAgent`。
  随后截图实样：`DimAgent / 工作中 · 自报 · 端到端验证`——自报被采信（显示档从「待机」变「工作中」）、
  后缀由 Rust 拼、自报的句子进了动作行。**验证后已重新启动 Swift 本体**。
- **反向验证五处**：① 冲突时改成采信自报 → 红（「冲突时状态必须按观测走」）；
  ② 去掉 TTL 上限 → 两条红；③ 过期改成删记录 → 红（「过期后记录必须留着」）；
  ④ 报表丢掉出处 → 红；⑤ 沙箱同名相撞 → `testutil` 的用例直接守。
- **测试** Rust 273 → **295**；编译警告 14 → 17（新增的是尚无消费方的公开面，如实留着）。

## 抓到一个会骗人的失效（本轮最值得记的）

Rust 的本地入口在 41999 **绑定失败时静默退化**成空实现，而 Swift 本体用同一个端口。
先启动的占住，后启动的本地入口就没了——**所有请求还是「正常返回」，只是答话的是另一个进程**。
我第一次端到端测试就被它骗过：那两条响应的文案（「落回通道也因此没走」）是 Swift 的措辞，
不是我的代码写的。**如果我当时只看「有没有 200」，就会得出「我的实现通过了」这个错误结论。**
现在绑不上会写一行明确日志。这也是「同一台机器上两个同类应用抢一个端口」这件事第一次被记下来。

## 另一处收口：沙箱命名

「测试沙箱名必须带序号」此前散在 6 个文件，其中 3 个漏了。`as_nanos()` 在 macOS 上分辨率粗，
并行用例会撞名、共用目录、互相删文件，症状是「偶发挂几条」——本轮有一次单条失败没能复现，
按这个机制收口（不明说成「已确诊」，因为没抓到那条失败的名字）。现在规则只在 `testutil.rs`，
并有用例直接守它。

## 边界与后续风险

- **Rust 按 agent 存一条自报**（后报覆盖先报）；Swift 的记录可按 `(agentID, sessionID)` 查。
  「同一 agent 两个会话同时自报显示哪一条」**没有逐行比对**，已写进对照表。
- 撤销的响应形状（`{revoked:bool}`）没与 Swift 核对；`noToken` 的状态码两边不同（Rust 401 / Swift 200），
  但「只回 noToken、不回具体原因」这条防枚举的规则一致。
- 端到端验证要求**先退掉 Swift 本体**（同一个端口），这是迁移期的真实约束，不是临时手段；
  长期要决定两个应用共存时端口怎么办（换端口？只剩一个？）。
- 直连真实自报来源（第三方 Agent 按文档带令牌申报）没有试过——本轮是 `curl` 模拟。
- 同前几轮：同一人既改又审；护栏是五处反证 + 端到端实样 + 那两个**因为去看而不是因为测试**才发现的问题。

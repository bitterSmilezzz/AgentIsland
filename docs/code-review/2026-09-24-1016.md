### P2 — 建议

- **`Tests/AgentIslandTestsRunner/DebtPayoffTests.swift:308`** — `ids()` 的编号后缀白名单只认 `a`/`b`，**窄于文档实际使用的编号约定**。
  - 为什么是问题：判定式是 `tok.dropFirst().allSatisfy { $0.isNumber || $0 == "a" || $0 == "b" }`，两个字母后缀是硬编码的。而文档已经采用「一个编号下挂多个子问题」的写法（`agent-lifecycle-hooks.md:171-172` 的 `V5a` / `V5b`），**V5 恰好把 a、b 两个字母用尽**。下一个子问题（`V5c`，或任何 `V6a`）一旦出现，正文引用与清单行会**双向都抽不到**：`noRow` 与 `orphan` 同时为空，`rows.count` 与 `tableIDs.count` 同时缩小、仍然相等 —— 断言全绿，但那条约定已经失效。这条断言的全部价值就是「新加条目时忘改一处会红」，而它恰好在最需要它的时刻静默失效。
  - 建议：后缀判定放宽为「ASCII 字母」，即 `tok.dropFirst().allSatisfy { $0.isNumber || ($0.isASCII && $0.isLetter) }`。顺带可补一条「清单每行『复核方式』列非空」的断言 —— 文档要求每条都带复核方式，而当前断言只校验了状态列。

- **`docs/research/agent-lifecycle-hooks.md:106` 与 `:227`（对照 `:60` `:150` `:171` `:172` `:186` `:193`）** — 正文括号里的状态词标注 6/8 有、2/8 无，而文档同时新增了「核完要同时改正文状态与本表」的约定。
  - 为什么是问题：文档 `:266-267` 自己写明「任何一条核完要**同时**改正文状态与本表，否则等于没改」。但正文里 `V2`（`:60` 待真机实测）、`V4`（`:150` 未找到出处）、`V5b`（`:171` 待逐字复核）、`V5a`（`:172` 未找到出处）、`V6`（`:186` 待逐字复核）、`V7`（`:193` 待逐字复核）都带了状态词，而 `V3`（`:106`）与 `V1`（`:227`）**没带**。结果是同一份文档里存在两种维护动作：改 V3 只需动表，改 V2 要动两处。而新断言只校验了「编号成对」与「状态属于三分类」，**没有校验两处状态一致** —— 「同时改两处」这条约定目前没有任何守卫，正是它最需要守卫的地方。
  - 建议：二选一。① **正文统一只留编号**（去掉括号里的状态词），状态唯一来源收在本表 —— 与该仓 v0.0.124 立过的「一个事实一个出口」一致，改动最小；② 正文全部带状态词，并加一条断言解析 `**V#**（状态）` 与表内状态列比对。倾向 ①。

# v0.0.417 槽位租约独立审查

## 范围与结论

本轮审查覆盖并发槽位的租约口径（`slot_lease.rs` 新模块）、四类资源注册表的槽位接线
（`agent_resources.rs`）、多机器派发的租约生命周期（`machine_node.rs`），以及两处门禁自身的缺陷。

本片只是**判据层**：不接真实进程编排、不做节点身份认证、不动界面。
真实执行链路仍需可信能力来源与授权策略验证器（ADR 0040 边界），不能以此作为执行授权。

## 修掉的三处真实缺陷

三处缺陷先在**隔离副本**（`/tmp/lease-probe`，复制判据逻辑复现）上观察到，
再回到主仓修改；修改前有复现输出，修改后用例钉住。

1. **迟到释放踢掉当前持有者的租约**（脑裂的根因）
   原实现在释放时只按 `task_id` 删租约、不核对版本。旧机器恢复后补报一次「我结束了」，
   **新**持有者的租约就被删了 ⇒ 任务可再次派发 ⇒ **两台机器同时执行同一个任务**。
   现：释放**必须带租约版本**；版本不符或非持有者 ⇒ 拒绝且**账不动**。

2. **抢占失败却已扣掉旧机器的槽位**（超卖的根因）
   原实现先给旧机器减 1，再检查新机器能否接。新机器满载时直接返回错误，
   旧机器的槽位却被减掉了 ⇒ 它还能再接一个 ⇒ **实际并发超上限**。
   现：**先校验目标再一并提交**，失败路径账完全不动。

3. **重复派发同一任务**（槽位泄漏的根因）
   原实现允许把已派发的任务再派一次：旧机器不再持有该任务，账上却还占着一个槽位
   （永久泄漏），新机器又占一个 ⇒ 账实不符 ⇒ 可用槽位虚高。
   现：已持有租约的任务**不重复派发**。

另修：`agent_resources.rs` 的运行时槽位从**裸计数**换成**版本化租约**——
裸计数不知道「谁持有这个槽位」，迟到的一次释放会减掉别人的占用；
重复派发还会把计数抬高 ⇒ 看起来满了其实没满。

## 能拒错

新增 13 条用例（`slot_lease` 7 + `agent_resources` 3 + `machine_node` 3）。
**变异 7/7 全部被拒**：摘版本核对、摘「先校验后提交」、摘重复派发检查、摘占用幂等、
版本可复用、超限拒绝仍动账、绕过租约表。源码经 `shasum -a 256` 确认字节一致还原。

一处过程记录：第一次做「抢占先减后校验」变异时，变异位置放错（只读校验仍在前面），
用例**没有**变红——这正是「断言存在 ≠ 断言有效」。把变异移到正确位置后用例才拒。

## 门禁自身的两处缺陷

两处都曾把发版卡住，且都与产品行为无关：

1. **VM 复位夹具的路径引号**：`test-native-gates-vm.py` 把解释器路径**未转义**地传给
   `reset_guest_acceptance`，而该函数会把它拼进 shell 命令串。本机 python 位于
   `.../Application Support/...`（含空格）⇒ 命令被切成两截 ⇒ 夹具恒红。
   生产路径本来就用 `shlex.quote` 转义（来宾 python 不含空格），所以只有夹具红。
   现：夹具与生产同口径（先转义再传），并用 `shlex.split` 避免二次解析。
   变异「传未转义路径」被拒。
2. **Ed25519 门禁缺依赖**：`scripts/test-update-signature.py` 需要 `cryptography`
   （`scripts/requirements-test.txt` 已钉版本），本机未装 ⇒ 7 条用例全部报
   `ModuleNotFoundError` 而非真失败。装上后即通过。

### P2 — 建议

- **`Sources/AgentIslandCore/AgentSessionInspector.swift:622`（审查者原文指向 622-622）—
  「认不出来源」的退路仍按当前轮次生成指纹，岛重启后重复弹完成会原地复发**
  - 审查者原文（英文，逐句对应）：*If the app starts after the human-input row has fallen outside
    the tail window, the process-local cache is empty and each system-injected continuation falls
    back to its own new `turnID`. Each `end_turn` then gets a different fingerprint, so
    `ActivityEngine` treats successive continuations as new completions and can repeat the
    notifications this change is intended to prevent.*
  - **症状→后果**：那格备忘是**进程内**的，岛一重启就清零；此时若尾窗里已经没有 `humanInput` 首行
    （长会话必然如此），`humanTurnID` 为空，旧写法退到 `turnID`——而系统注入的续命轮**每轮都是新的
    promptId**，于是每一次续跑都换一个完成指纹，`handledCompletionFingerprints` 的去重就此失效，
    用户报的「一路弹已完成」在重启后的会话里照旧发生。这条正是本轮要治的病，属于**修复没覆盖到的
    同一条路径**，不是新 bug 类。
  - **作者核实**：成立。复现路径写在新增用例里（冷启动 + 两条不同 promptId 的续跑 ⇒ 旧写法给出
    两个不同指纹）。
  - **修法（本轮已落地）**：退路从「当前轮次」改成**会话文件的身份** `sessionKey`
    （`found.file.deletingPathExtension().lastPathComponent`，即 `<会话 uuid>`），
    优先级变成 `humanTurnID ?? sessionKey ?? turnID ?? lastAssistant.id`。
    效果：重启后**第一次**完成照响（宁可响一声），之后的续跑共用一个指纹不再响；
    而真人敲新指令时首行进尾窗、备忘更新 ⇒ 指纹换成新轮次，该响的还是响。
    新增用例 `Qoder: 岛刚重启（备忘是空的）时，续跑要沿用同一个指纹而不是各报一次` 三条断言钉住，
    并补变异 m37（把 `sessionKey` 从退路里拿掉）验证它会红。
  - **能否自动修**：是（已自动修完）。

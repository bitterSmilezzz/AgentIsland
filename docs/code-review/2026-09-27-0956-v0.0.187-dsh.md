## 范围与结论

复核 Phase 1（双形态并存）的**地基与最小侧边栏壳**：设置与窗口、形态分派、侧边栏几何、
`css/sidebar.css` 与 `views.js` 的侧边栏渲染。结论：地基可测、运行时能起来；
**侧边栏的视觉形态未验证**（如实记在下面）。Swift 侧零改动。

## 可核验的行为证据

- **形态解析与回落**：`only_the_known_modes_are_recognised_and_anything_else_falls_back_to_island`
  ——`island`/`sidebar`/大小写/空格都认，`""`/`sider`/`island-2`/`null` 一律回落灵动岛。
  **反向验证**：把回落改成 `Sidebar` → 两条用例红。
- **设置归一化**：`a_hand_edited_shell_mode_or_edge_falls_back_instead_of_breaking_the_window`
  （形态与边沿都回落；侧边栏没有上下两档）；
  `an_absurd_sidebar_width_is_clamped_so_it_cannot_become_a_slit_or_cover_the_screen`
  （`0`/负数 → 下界、`5000` → 上界、`NaN` → 默认、`±∞` → 对应边界、正常值原样）。
- **侧边栏几何**：`sidebar_tests`（5 条）——贴左/贴右、工作区原点非零、`Top`/`Bottom` 一律按右侧回落、
  **宽度绝不超过工作区**（小屏/分屏时以工作区为准）。
  这条测试**当场抓到我实现与自己的注释矛盾**：注释写「窗口比工作区宽会让它有一截永远在屏幕外」，
  而实现里 `.max(MIN_SIDEBAR_WIDTH)` 恰好制造了这个情况（280 > 220 的工作区）。
- **跨文件字段哨兵**：`every_snapshot_field_the_ui_reads_exists_in_the_json` 现在覆盖侧边栏读的字段
  （把渲染回调的参数改名为 `snap.`，而不是 `s.`）。**反向验证**：给 `last_activity_text` 加一个
  `#[serde(rename)]` → 哨兵立刻报 `views.js 读了快照里没有的字段：["last_activity_text"]`。
- **运行时冒烟**：把 Rust app 起起来 6 秒——**启动成功且存活**（两个窗口的配置若写错，
  Tauri 会在启动时直接崩，这条冒烟正是为它准备的）。
- **静态检查**：`node --check` 过 `main.js` / `views.js` / `shell.js`。
- **测试数**：Rust **243 → 252**；编译警告保持 **21**；稳定性：连跑 3 次全绿。

## 设计取舍

- **两个窗口都建好、切换只改显隐**：于是「反复切十次留下十个窗口」在设计上不成立。
- **侧边栏几何不复用灵动岛那套**：一整列 vs 浮在边沿的卡片，共用 `place_with` 只会两边都别扭。
- **`js/shell.js` 单独一个模块**：形态是一种「窗口级事实」，放这里让 `views.js` 与 `main.js`
  都能读而不互相 import（它们本来就有一个方向的依赖，互相 import 会成环）。
- **`?shell=` 查询串而不是 IPC 询问**：窗口创建时就定了形态，没必要启动后再问一次。
- **不进 `SecretStore` 的教训复用到这里**：不给「没人调的 API」，也不给「点了没反应的入口」——
  侧边栏导航里的「待办」「设置」明写**未做**并置灰。

## 如实标注（这一轮没做到的）

- **侧边栏的视觉形态未验证**。几何与代码路径有测试、`node --check` 过、app 能起来，
  但**没有人真正把它切过去看一眼**（要改成 sidebar 就得动用户的 `settings.json`）。
  所以「首层极简」目前只有代码依据，没有实样。**这是本轮最大的未验证面。**
- **计划第 5 条只做了一半**：`renderCard` 还没抽成「不依赖容器尺寸的监控模块」，
  现在是「灵动岛包卡片 + 侧边栏另写列表」，两处各有一套列表标记 ✗ 会漂移
  （数据字段已被哨兵覆盖，但**排版**没有任何东西守着）。
- **`island.css` 未拆分**（计划第 7 条）：目前靠 `.shell-sidebar` 前缀隔离，够用但不干净。
- **「反复切十次无残留」未做运行时验证**（设计上不残留，但没真按十次）。
- **`set_shell_mode` 等命令没有界面消费方**：与之前几轮的命令同一状态；
  换言之今天要切形态得手改 `settings.json` 或调命令。
- 顺带记一条**既有**观察（非本轮引入）：启动日志里有
  `The window is set to be transparent but the macos-private-api is not enabled.`——
  灵动岛窗口的透明在 Rust 侧可能没真正生效。与本轮无关，但值得单独查一次。
- 同前几轮：同一人既改又审；真正的护栏是两处反向验证与那条当场抓到自己矛盾的几何用例。

# v0.0.183 独立复核 · DSH · 2026-09-27 08:29

## 范围与结论

复核派生进程树的迁入（`trees.rs` + `ProcHit.ppid` + `procmon::table()` + 一条命令）。
结论：结构正确、防环有效、深层不爆栈；**一处「因为错误的原因而通过」的用例被反向验证抓出并修好**。
Swift 侧零改动。

## 可核验的行为证据

- **深层不爆栈**：`a_deep_spine_does_not_blow_the_stack`（5,000 层链）。
  这条不是想象出来的风险——第一版实现是递归，这条用例当场用 **SIGABRT** 把测试进程打死
  （即反向验证自己发生了）。改成两步迭代后通过，并逐层走到最深处确认结构真的建出来了。
- **防环与重复挂载**：`a_pid_cycle_is_broken_without_double_counting_or_hanging`
  （PID 环 + 同 PID 挂两个父 ⇒ 只算一次、合计不翻倍）。
- **根不算自己的后代**：`the_root_itself_is_never_included_even_if_the_table_claims_it_is_a_child`
  —— 两种形状：`pid == ppid == root`、以及 `5 → 6 → 5` 环回根。
  **反向验证**：去掉「根预先标为已访问」→ 红。（**第一次做这条反证时它没红**——
  原用例的表里没有 `ppid == root` 的项，所以它此前是「因为错误的原因而通过」。已修好。）
- **没读数不是 0**：`an_unmeasured_child_makes_the_cpu_total_absent_rather_than_zero`
  —— `total_subprocess_cpu == None` 且文本是「本拍无差分窗口」。
  **反向验证**：改成恒 `Some(sum)` → 红（`left: Some(0.0), right: None`）。
- **部分读数要能说清**：`a_partially_measured_tree_reports_how_many_children_were_counted`。
- **零根早退**：`a_zero_or_negative_root_returns_an_empty_tree_instead_of_the_whole_table`
  —— 不早退的话，`ppid=0` 的**整机进程**都会被当成某个 Agent 的派生工具。
- **顺序与合计**：`a_multi_level_tree_is_ordered_and_totalled`（先子后孙、同层按表序）。
- **文本规则**：`0.01%` → `0%`、`0` 字节 → `—`、空名 → `unknown`。
- **测试数**：Rust **211 → 220**；**编译警告 23 → 22**（`ProcHit` 的 `name`/`exe_path`
  因进程树而第一次被读）。稳定性：连跑 3 次全绿。

## 本轮最该记住的一条

第一版我写了**递归**，注释里却写着「显式栈而不是递归」，而且随手写下的深层用例
立刻把矛盾变成了 SIGABRT。这说明两件事：
① 用例写得对，它就会替你把「注释与实现不一致」变成一次可见的失败；
② 反过来，**没被用例覆盖的注释就是一条假线索**——如果我只写了实现没写那条深层用例，
这段代码会带着一句「全程不递归」的谎话留下去。

同一轮里还出现了第二种「假通过」：`the_root_itself_is_never_included_...` 名字说的是
「表里把根写成自己的子节点」，而表里根本没这种项——它靠**没有触发条件**而通过。
两者都是靠反向验证（改坏实现看它红不红）暴露的，不是靠读代码。

## 边界与后续风险

- **`agent_process_tree` 现场扫一拍进程表**：每次调用都新建 `ProcessMonitor` 并 refresh，
  拿不到 CPU 差分窗口 ⇒ 首屏的 CPU 全是「本拍无差分窗口」（内存与结构照常有）。
  这是有意的（树是当下结构），但**界面必须先显示内存/结构，不要先显示 CPU**，
  否则用户第一次点开只会看到一列 `—`。这条写进了命令注释。
- **`procmon::table()` 摘的是全表**，没有上限；进程数千的机器上每次调用都会分配一份。
  当前只有「用户点开某个 Agent」触发，量可接受；若将来做成轮询，这里要先收上界。
- **`ProcHit` 现在带 `ppid`**：`match_profile` 的结果里也填了，但除了进程树还没有别的消费方。
- **命令无 UI 消费方**：与 `remote_status` / `token_forecast` / `audit_report_*` 同一状态。
- 同前几轮：同一人既改又审；真正的护栏是两处反向验证的红、以及那条 SIGABRT 留下的教训。

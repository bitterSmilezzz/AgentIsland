# v0.0.278 分析页报告取数审查

审查者：Codex。基线：v0.0.277。范围：hydrateReport 的分析页数据源。

## 发现与修复

分析页按在线快照首个 ID 请求 get_report。首个工具没有本地明细时返回 None，页面错误显示空态，即使其他工具及概览已有数据。后端已有空 ID 聚合全部启用档案的约定，前端改用该入口；详情页仍按页面 agentId 取数。无新增聚合算法、扫描源或监控口径。

## 验证

- Node 行为回归调用实际 hydrateReport，夹具模拟首个在线工具无明细而汇总及指定详情有数据；旧实现准确失败于请求序列错误。修复后两个分析容器请求空 ID，独立详情请求 codex，并显示各自的模型数据；没有在线快照时仍请求汇总。
- Rust 全量回归：548 通过，5 忽略。原有冷启动与运行期导航模式继续通过。
- 构建后执行 restart-app.sh，通过 CLI analytics 打开实际页面；原生工作台与灵动岛的辅助功能树均显示汇总用量、趋势与模型明细，未出现错误空态。
- 工作区脱敏与 diff 空白检查通过；发布脚本继续检查版本、全历史脱敏、原生 UI 冒烟及单实例。

## 边界与结论

沿用后端全部启用档案的汇总语义，详情仍为单档案。多容器注水、响应过期保护与现有布局保持原逻辑。原生检查确认显示内容，不作为像素布局证据；没有采集或提交个人会话数据。范围内无阻断问题，可发布。

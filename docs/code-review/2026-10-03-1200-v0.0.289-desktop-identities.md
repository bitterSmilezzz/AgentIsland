# 豆包工作与 Trae 桌面身份审查

本机证据：DoubaoWork.app 主进程 DoubaoWork、bundle com.work.pc.doubao；Trae CN.app 主进程 Electron、bundle cn.trae.app；TRAE SOLO CN.app 主进程 Electron、bundle cn.trae.solo.app。采样发现豆包工作和 SOLO 正在运行，旧 Trae 主进程已关闭。原 Trae 档案只认 Trae 进程名，因此 SOLO 的安装记录不能替代运行识别。

Trae CN 保留 trae id，SOLO/TraeWork 单独使用 traework id。Electron 识别必须同时命中对应应用包路径，避免认领无关 Electron；豆包工作仅匹配主应用包的 MacOS 可执行文件，排除普通豆包和浏览器辅助宿主。正式产品分开显示，CPU 与运行状态独立。豆包工作和 TraeWork 没有已验证会话或 Token 本地读取契约，相关源留空，不拿浏览器缓存或虚拟机文件变化冒充任务进度。

官方 https://docs.trae.cn/work_changelog 声明 TRAE SOLO 升级为 TraeWork；本机仍使用 SOLO 名称。用户要求 Trae CN、TraeCode、TraeWork 三者区分，已提出第三个应用身份/位置问题；本机应用清单及 Spotlight 仅找到两个 bundle，不凭展示名猜测第三个程序的身份。第三项接入待核对，不宣称已经完成三项支持。

官方包图标转换为本地 PNG，记录版本与哈希，不改变 artwork。身份资源五处显示守护与 7 项身份边界回归通过。回归包括 CN/SOLO 分别归属、普通豆包与浏览器辅助进程不归属、无关 Electron 和路径含 trae 的临时目录不误认。

最终构建、完整回归、扫描和重启结果在提交前补记，发布仍受原生隔离会话门禁约束。

提交前补记：600 项 Rust 回归、工作区与历史扫描、打包和签名通过；原生 UI 因隔离会话门禁退出 2，未提交、tag 或发布。scripts/restart-app.sh 已核实新版启动。正式 CLI status --json --all 的脱敏字段确认：TraeWork processRunning=true，豆包工作 processRunning=true，Trae CN processRunning=false，与当前桌面应用进程清单相符。单拍状态 idle 不等于已验证任务执行；CLI 单拍没有 CPU 差分窗口。

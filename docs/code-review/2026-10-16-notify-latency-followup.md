# hook 入队延迟：独立复审与修正跟踪

审查者：周衡（独立只读 agent）；作者：主 agent / 李明 / 王强。检查对象为当前未提交的 NOT-01 入队延迟功能。审查没有运行测试，执行证据由交付验收另行记录。

## 第一轮复审

发现两项 P2，无 P1：

| 级别 | 位置 | 发现与触发条件 |
| --- | --- | --- |
| P2 | webhook.rs 接受循环的 received_at_ms | tiny_http 已先解析 header、小正文并排入 messages 队列，应用取出请求后才开始计时，漏掉库内部等待。前序慢请求阻塞时，后续已排队 hook 可能等待超过1秒却被计为近零。20条逐条等响应测试不能验证此情形。 |
| P2 | webhook.rs LocalEventServer::drop | Drop 无条件 join，而 read_to_string 无读取期限。客户端声明较大 Content-Length、只发部分正文后保持连接，会阻塞 server 读取和销毁；50ms recv_timeout 只约束取下一请求。 |

确认的其他部分：容量1唤醒且事件先发送、信号后发送，没有发现丢信号/空转或锁反转；20条真实HTTP测试运行生产 HookScheduler/consumer，关闭唤醒时同路径会等待5秒；来源隔离、nearest-rank、20样本资格、负样本未知及camelCase/null序列化符合约定。

两项 P2 已交回作者修复，尚未定案。不得把当时“生产等待验收通过”扩展成整个服务接收链路已经覆盖，也不得用文案收窄指标来代替修正。

## 第二轮复审：两项 P2 已解决

审查者：周衡。结论为原 2 项 P2 均已解决，无必须修的 P1/P2，并逐项核实：计时起点已前移到 accept/解析前，覆盖库内部排队与慢 header/正文预读；keepalive 后续请求重新取点，不产生虚假近零；Drop 走 stop → 主动关闭连接 → join，连接表用 Weak，无悬挂也无死锁；`/session` 令牌与 `notify_route` 三条 400 判据保留，另有收紧（正文字节失败改判 400、非 unix 平台不再产出令牌文件）；新测试能拒原缺陷。

单列边界（非缺陷）：长连接首请求前的闲置计入首样本（保守高估）；2 秒读写超时使空闲 keepalive 连接被断开；`vendor/tiny_http/` 未跟踪须入库；`Cargo.toml.orig` 需过脱敏。作者据此删除了仅含上游作者邮箱、不参与构建的 `Cargo.toml.orig`，扫描通过。


## 通知页只读复核（陈晨）

按当前后端字段契约，没有发现UI误宣达标、离页响应污染其他页面或按钮无法复位。浏览器检查执行成功，额外验证离页完成后返回缓存页还能刷新。发现2处测试P2：未知状态负断言没覆盖实际分隔格式；等待数字会被旧摘要/固定目标说明提前满足。作者改为完整摘要精确比较和按钮恢复可用，并加入100ms异步延迟，修订后的浏览器测试通过。没有修改后端字段、产品阈值或安全门槛。

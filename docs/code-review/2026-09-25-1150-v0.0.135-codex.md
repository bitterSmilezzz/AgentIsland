### P2 — 建议（三条，全部本轮修掉）

- **`Sources/AgentIslandCLI/Commands/StateCommand.swift:18-20` — `--port` 是最后一个参数时静默改用默认端口**
  - 审查者原文：*When `--port` or `-p` is the final argument, this condition skips the option and
    leaves `port` at its default, so the command may successfully query the wrong endpoint instead of
    reporting invalid usage.*
  - **症状→后果**：调用方显式写了 `--port`，命令却去查了另一个端点，还回一句「连不上」——
    把一个用法错误报成网络问题。非数字那条已经会出声，缺值这条漏了，两条本该同一条规则。
  - **修法（已落地）**：参数解析整体搬进 Core 的 `AgentStateClient.parseArgs(_:)`
    （CLI 那一侧链接不到测试，留在原地就只能靠书写形态守），缺值与非数字都返回一条用法错误，
    退出码 2。新增用例 `state: 参数解析（在 Core，所以测得到）——缺值与错值都要出声` 钉住
    五种形状（无参、缺值、非数字、0、`--json --port 8080`），变异 m93 验证它会红。
  - **能否自动修**：是。

- **`Sources/AgentIslandCore/AgentState.swift:118-120` — 服务端明确的 503 被归进 `malformed`**
  - 审查者原文：*If the server returns the explicit 503 from `AgentStateEndpoint.noEngineReply`,
    this default classifies it as malformed; the CLI then tells users the response shape is
    incompatible and emits `reason: "malformed"`.*
  - **症状→后果**：503 的意思是「等一等就有」，`malformed` 的意思是「CLI 与 App 版本不匹配、要升级」。
    把前者折进后者，用户会去做一件不需要做的事（升级），而真正该做的（再读一次）没人告诉他。
    这正是本仓反复处理的那类「多种原因折成一个布尔」。
  - **修法（已落地）**：新增第五种结论 `engineNotReady`（自己的那句话 + 自己的 `reason` 枚举值），
    `classify` 显式处理 503；用例 `state: 503 是「引擎还没就绪」，不是「形状不兼容」` 与
    「五件事各有自己的一句话」一起钉住（断言五条句子互不相同）。变异 m91/m94 验证两处都会红。
  - **能否自动修**：是。

- **`Sources/AgentIslandCore/AgentState.swift:154-155` — 失败句承诺了一份永远不会出现的输出**
  - 审查者原文：*When the request is unreachable, `StateCommand.run` prints this headline and exits
    without producing an independent sample. The message therefore promises results "below" that
    never appear, and its JSON failure message makes the same misleading claim.*
  - **症状→后果**：原文写「下面这份是本 CLI 独立采样的结果」，而 `state` 失败时**什么都不打印**、
    直接退出码 1。让用户以为屏幕下面有一张表，是比措辞不雅更严重的错——**承诺一份不存在的输出**
    与「把没看到讲成没有」是同一类：话里没有一句能对上事实。
  - **修法（已落地）**：句子改成陈述事实（「这次没有状态可读」+ 指路 `agentisland status` +
    那条命令读不到自报），并加一条**反向断言**：五种失败句里任何一条都不许出现「下面这份」。
    变异 m92 验证它会红。
  - **能否自动修**：是。

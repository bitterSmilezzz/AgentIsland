## 实现与边界

保留系统argv边界，解析Node/Bun/Python受支持启动形式，内联正文、预载参数及业务参数不作为入口。裸提示匹配入口文件名及已知脚本扩展，路径提示按带边界的完整后缀匹配，避免项目目录和部分词命中。原生名字精确/空格前缀族、路径必需锚定、路径排除和僵尸规则保持。未知启动选项不猜测入口，这意味着非标准包装仍需独立核实，不能为提高在线数恢复全文搜索。

Node修改argv0报告名称时以完整别名匹配，不从名称中拆词；避免OS读取器保留旧argc时用后续非入口项推断脚本。默认node/nodejs/bun的大小写及Windows `.exe`路径先归一，避免把运行时自身认作别名。Claude的npm脚本入口与原生命令、MiniMax主CLI及npm别名由档案声明，辅助工具入口不因同属一个包而自动算作主智能体。自定义提示存储字段保持，裸目录关键词的宽泛认领行为明确收紧。

PID可保持而程序发生exec。每拍更新exe/cmd，优先使用当前可执行文件名，避免库缓存名字保持旧所有者；CPU差分监控器不重建。入口每拍解析一次并供档案复用，匹配层不另存拼接后的参数全文；sysinfo内部原始参数仍存在并随刷新覆盖，不声称零参数驻留。

隔离原生CLI门禁先要求Codex/Claude/MiniMax清洁基线，再启动内联及普通参数诊断进程，对正式程序的只读status检查；进程检查期间必须存活，结束后回收并再次检查。已有真实智能体会拒绝前置条件，不能掩盖误报后仍判通过。设置使用独立HOME且前后文本一致；门禁不发送模型请求。

## 可失败证据及修正

- `red.log`：真实Python只读脚本同时被Claude和Codex认领，单例失败。原始表现与原生验收中0→2→0在线数现象相符。
- `path-red.log`：仅删除正文匹配仍不能排除`codex`项目路径。收紧入口提示及包内路径声明后通过。
- `exec-red.log`：Python在相同PID exec为Node入口，3秒内始终保留旧身份，失败。刷新身份后新工具可见；另补原生别名exec为普通进程，旧所有者消失。
- 自检发现Node自报名称及Windows运行时argv0兼容回退遗漏，分别保留失败日志并修正；Windows仅纯argv夹具，不抵扣真实Windows验收。
- 并行夹具曾因墙钟时间戳碰撞、系统shell复制后的签名/文件元数据而失败。现目录使用独立UUID，临时原生夹具仅复制内容并单独签名，所有子进程由退出守卫回收。上述夹具失败不冒充产品反例。诊断不输出真实参数或继承环境内容。
- `before-receipt.json`：正式已发布独立CLI SHA256 `2b54261b88b363ebd5c70389b4f59c4e41f8de3e0602ae4b1a6815b6603ca4d6`，对应应用SHA256 `3434bdc811244f43a6b2c4d205ec50a12e5a1d6ed2fb00c3654dd0e186951d1f`。同系统隔离VM、代码/产物哈希核实，基线清洁，首个诊断进程即触发正式CLI误报，来宾退出3，为预期复现，不计为通过。首次未登录及把bundle主二进制脱离bundle后校验签名失败，均未进入产品判定；后使用正式独立CLI完成复现。

### P2 — 建议

- **`Sources/AgentIsland/LocalEventServer.swift:172-173` — 终态响应不回收按连接存的请求缓冲与连接名额，反复请求会让内存无界增长**
  - 审查者原文：*For requests handled as `.reply`—including repeated `/health` checks, malformed
    requests, and oversized bodies—this branch sends a response without clearing the new `buffers`
    entry or dismissing the connection; `sendResponse` only cancels it. The request data therefore
    remains stored indefinitely, so repeated local requests can grow the app's memory usage without
    bound. Ensure all response and timeout paths remove the buffer and connection.*
  - **症状→后果**：两条，而且第二条比第一条严重。① 每条被 `.reply` 答掉的请求都把它的字节留在
    `buffers` 里（上限 64KB × 请求数）；② 更要紧的是 `liveConnections` 的名额不还——
    `maxLiveConnections` 只有 **16**，跑满 16 条请求之后 `admit` 就开始拒绝新连接，
    也就是**这个本机 notify 端点自己把门关上了**。旧代码不会，因为 `receiveNext` 在
    `processHTTPPayload` 之后统一 `dismiss`；本轮把处理改成异步分支后那条兜底没了。
  - **修复时间线（如实记）**：审查者看到的是**修复前**的快照。作者在收到报告之前几分钟
    自查同一处时已经发现并改掉了——两处独立指向同一个缺陷，说明这条改动的风险面确实窄。
  - **修法（本轮已落地）**：把回收挂在**唯一的写响应出口**上：`send(connection:status:text:)`
    先 `dismiss(connection)`（它同时清 `liveConnections` 与 `buffers`）再写；
    `answer` 的 `.needMoreData` 分支（生产不可达那条）也补了 `dismiss`。
    再加两条书写棘轮：`connection.send(content:` 在服务端**只许出现一次**，
    且 `private func send(connection:` 的那一段里必须出现 `dismiss(connection)`——
    因为这段胶水在 executable target 里，链接不到行为级测试。
  - **能否自动修**：是（已自动修完）。

## 作者自查补上的两条（审查者没拿到重点清单）

- **`/notify` 的 `type` → 事件类型这张表有两份**：一份在本轮下沉的 HTTP 里，另一份在
  `URLSchemeRouter` 的深链里（`agentisland://notify?type=…`）。今天两格抄得一样，
  但「一样」不是不重复的理由——下一格只改一边，就是同一个 `type=alert` 在深链里红着叫、
  在 curl 里绿着收。表统一到 `AgentTaskEvent.externalType(from:)`，两处都问它，
  并加棘轮：深链与服务端都不许再出现 `"costspike"` 字面量。
- **原因短语表会把新增的码降级**：`default: "Bad Request"` 意味着新加一格状态码忘了跟着加，
  客户端拿到的是**一句错话**。本轮的 413 正好是这一格。表搬进 Core 逐码给，
  认不出的按类别给（4xx ⇒ Client Error、5xx ⇒ Server Error）。

## 不采纳及理由 / 无法确认

- **未支持 `Transfer-Encoding: chunked`**：这条回环链路上的调用方（curl、各家 hook、自带 CLI）
  都带 `Content-Length`；在没有需求时加分块解码，等于留一条没人验的路径。
  判定「收完没有」的逻辑已经可以测，真要接分块编码时在那一层加即可。
- **`LocalEventServer` 没有整体搬进 Core**：它需要 `NWListener`/`NWConnection` 与一次
  `@MainActor` 引擎跳转；搬过去只是把不可测的东西换个地方。本轮只搬**判定**。
- **未做真 socket 测试**：41999 被正在运行的实例占着，测试里再起一个服务会跟用户的 App 抢端口。
  剩下的「只连不发被 5s 超时回收」「并发上限 16」两条仍在 03 号票里。

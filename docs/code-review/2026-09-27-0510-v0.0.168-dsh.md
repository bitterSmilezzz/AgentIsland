# v0.0.168 独立复核 · DSH · 2026-09-27 05:10

## 范围与结论

复核 M3「token 明细」这一组：新增 `sqlite.rs` 只读层、`tokens.rs` 接入两类 SQLite 方言、
`AgentProfile` 增 `session_database`、registry 补 `dim`/`mimocode` 并给 6 处声明库、
`cost_estimated` 从「非零即估价」改成逐来源记账。结论：**能力真实增加且口径与 Swift 逐条对齐**；
未与真实第三方库对拍，这条明确留给下一轮。Swift 侧零改动。

## 可核验的行为证据

- **只读契约是测出来的，不是写出来的**：`sqlite::tests::read_only_connection_really_cannot_write`
  真的对只读连接执行 `INSERT` 与 `CREATE TABLE`，两条都必须被挡回；同一连接读同一张表必须成功。
- **净 token 口径逐条对照 Swift 的 SQL**：
  - OpenCode：`cache.read: 999` 不计（10+20+5 = 35，不是 1034）、`role='user'` 的 50000 不计、
    窗口外那行只进累计 → `tokens24=35 / tokens_total=235`；
  - DimAgent：`promptTokens 1000 / cacheReadTokens 1200` 必须钳成 0 而不是负数；
    `(100−40)+50=110`。
- **动态类型不许吞掉统计**：一列里有一行 REAL 时 `SUM` 整体变浮点，
  `real_typed_token_columns_do_not_erase_the_whole_statistic` 钉住「仍要读到 30」——
  这正是 Swift 侧「经 Double 中转」防的同一件事。
- **两种成本来源分得开**：`monitor_merges_the_sqlite_source_and_keeps_recorded_cost_unmarked`
  断言 SQLite 成本**不**带 `cost_estimated`；`jsonl_cost_stays_marked_as_an_estimate`
  断言 JSONL 成本**带**标记（含按模型那一层）。
- **「读不到」与「没数据」分开**：库缺失、表形漂移（第三方升级换表）两条都断言返回 `None`
  而不是空库、也不 panic；`statusIndex` 即便库存在也贡献 0。
- **口径归属查得出**：`sqlite_backed_profiles_pair_each_database_with_the_right_dialect`
  逐档案钉「方言 ↔ 库」配对，并要求走 OpenCode 库的档案**不得**再有 `token_roots`
  （否则同一笔用量两处各算一遍）。`iso_utc_from_ms` 钉住与 `parse_iso_ms` 的往返、
  闰年与月末边界（dim 靠字典序比较，形状错会静默错位）。
- **测试数**：Rust **74 → 86**、Swift 550（未动）。`cargo test --locked` 0 失败。
- 写用例时**我自己的两条期望先红了**（`parse_iso_ms` 不解析小数秒；`time_created=5000`
  其实在 1970 年），按实现的实际口径改正后转绿——记在这里是因为它说明断言真的在校验行为，
  而不是在复述实现。

## 边界与后续风险

- **未与真实库对拍**（本轮最大的缺口）：所有 SQLite 用例都是**现造夹具**，没有在本机真实的
  `opencode.db` / `dimcode.sqlite` 上与 Swift 侧读数逐项比对。已写进 23 号对照表 §7 的待核实项 7。
  下一轮应做：同一时刻跑 Swift `agentisland tokens` 与 Rust 侧读数，逐项对拍。
- **`dim`/`mimocode` 只接了用量**：会话状态与动作解析仍未对齐（`session.rs` 只有
  claude/codex/cline/zcode 四个 probe）。这两家现在会**多出两行**在 Rust 侧（有进程时），
  而状态可能比 Swift 浅——属于「能力增加但未对齐」，不是回归。
- **`StructuredTokenUsageIndex` 未迁**：Swift 的 70 天折入保留窗口（ADR 0007）在 Rust 侧
  没有对应物，Rust 仍是每次简单扫描。数据量大时 Rust 的耗时曲线会与 Swift 分叉。
- **两个新档案的 glyph 码位未目视核对**（Rust UI 只渲染 `glyph`，`emoji` 字段该 UI 未用）：
  `dim` 取 `E734`（星形）、`mimocode` 取 `E774`（地球，且与 demo 数据里的 workbuddy-ai 撞码位）。
  显示不对的话改 registry 一处即可，但**这是未经真机确认的视觉假设**。
- **`mimocode` 的进程名沿用 Swift 的推断**（Swift 档案自己注明「按 CLI 命名习惯推的，
  真实进程名待跑过一次编码会话核对」）。Rust 照搬以免两边再分叉，但推断本身仍未核实。
- **`rusqlite` + `bundled` 的取舍**：绑定 SQLite 3.53.2（> 3.51.3，含 WAL-reset 修复），
  换来跨平台确定性；代价是构建时要编译一次 SQLite（本机实测 +18s）。`Cargo.lock` 已更新，
  `--locked` 仍可复现。
- 同前几轮：同一人既改又审；真正的护栏是上面那些会反向变红的用例，不是这份文档。

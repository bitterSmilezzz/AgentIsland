## 结论

最终改动通过规格与工程规范两项独立复核，没有剩余 finding。审查与实现过程中发现并修复：

1. 自依赖初次被整图校验报告为循环；增加独立自依赖判定，错误码恢复为 `self_dependency`。
2. 初次改写 `check_dependency` 改变了旧纯判据“只判新增边”的语义；保留原有判据行为，生产 Store 使用新的整图校验路径。
3. 项目依赖草稿未保存时，新建项目会推进共享 revision 并强制重绘；现在新建项目前拦截，并断言命令未调用、revision 未变、草稿保留。
4. 依赖编辑器重绘时会累积事件监听器；改为覆盖式处理器，并在空项目或单项目分支清除旧处理器。
5. `.task-project-delete { display: flex }` 会覆盖隐藏状态；增加管理区隐藏规则，并在浏览器中验证无项目时删除和依赖编辑控件确实不可见。

完整依赖图由 Store 在读写校验时使用拓扑遍历，时间与空间复杂度为 O(项目数 + 依赖边数)，避免对最大 8 MB 任务文件重复线性查找或递归遍历。旧项目记录没有 `dependencies` 时继续按空列表读取；失败写入、过期 revision 和无效图不会覆盖原快照。

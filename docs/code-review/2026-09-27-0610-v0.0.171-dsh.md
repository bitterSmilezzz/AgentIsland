# v0.0.171 独立复核 · DSH · 2026-09-27 06:10

## 范围与结论

复核判定增强组的第一个模块：迁入 `AgentHealthEvaluator`，并把它依赖的**卡死三态**一并搬
（Rust 此前 `grep -i hung` 零命中，这个判定根本不存在），阈值收敛到一处，界面接分数徽标。
结论：**口径逐条对齐、测试可判别**；顺带发现并修掉一处「界面读了后端从不输出的字段」的哑火，
并为这类错配加了跨文件哨兵。Swift 侧零改动。

## 可核验的行为证据

- **扣分表与分级**：`cpu_and_memory_deductions_use_the_same_thresholds_as_swift` 逐档钉住
  （80/79.9、50/49.9、2GB/1.5GB），`grade_boundaries_follow_the_same_ladder_as_swift`
  钉住 85/70/50 三条线**恰好落在线上时取更严重档**（85→健康、70→需留意、50→异常、40→危急）。
- **「健康」是全清结论**：`unevaluated_dimensions_block_a_clean_bill_but_never_mask_real_trouble`
  同时验两侧——判不出卡死且其余干净 → 100 分但降级「观测不全」；
  **内存已经扣分时不许被「观测不全」盖掉**（断言仍是「需留意」+ 摘要「资源占用略高」）。
- **判不出的维度不扣分**：上一条里同一断言 `score == 100`。
- **卡死三态的资格**：`is_hung_needs_a_sustained_observation_window_not_just_high_cpu`
  六个分支——观测不够返回 `None`（不是 `false`）、观测够了但高 CPU 刚起来返回 `Some(false)`、
  两者都够返回 `Some(true)`、从没观测过返回 `None`、边界差 1ms 不算够。
  这条区分是这轮的核心：`false` 与 `None` 混同会让「没测」被讲成「没有」。
- **分数钳制**：叠加成 -5 分时钳到 0（`score_is_clamped_to_the_hundred_point_scale`）。
- **跨文件字段哨兵**：`every_snapshot_field_the_ui_reads_exists_in_the_json` 解析
  `views.js` 源码里的 `snap.<字段>`，逐个比对真实序列化出的 JSON 键。
- **测试数**：Rust **97 → 105**（+8）、Swift 550（未动）；编译警告保持 **26**（不多不少）。

## 反向验证

把 `views.js` 改回 `snap.isHung`（原 bug 的字面形态）→ 哨兵红并点名：

```
views.js 读了快照里没有的字段：["isHung"]（静默失效，不会报错）
```

还原后 105 全绿。这条证明哨兵抓的是真错配，而不是在复述实现。

## 边界与后续风险

- **新加的 `Grade::glyph()` 因无人调用而产生一条新警告**：我一度按「SF Symbol 的等义码位」
  补了五个 MDL2 字符，但那些码位是**按名字类比猜的**，没有任何目视核对——正好是上一轮
  已记录过的同类风险。处理方式是**删掉**而不是留着猜：界面用分数表达同一件事，
  枚举上留注释说明为什么不搬 Swift 的 `icon`。警告数因此回到 26。
- **卡死判定只在有 CPU 差分窗口时才可能为真**：`is_hung` 依赖 `high_cpu_since`，而后者只在
  采样到 CPU 时维护。**没有任何引擎级用例**覆盖「跑满 5 分钟后 `is_hung` 变 true」——
  纯函数那六条分支覆盖了规则，但「引擎真的把资格与事实喂对了」没有端到端用例
  （engine 的 tick 用真实时钟，注入时间需要先做时间接缝）。这是本轮最大的测试缺口。
- **`observed_running_since` 的作废时机只跟了进程消失与时钟回拨**：Swift 还有 `resetTracking`
  一族路径。Rust 的清理点比 Swift 少，长时间运行后是否有「资格被错误保留」的情形，未核。
- **界面表达不同**：Swift 在详情页展示（图标 + 「N分 · 等级」+ 摘要），Rust 没有详情页，
  只在列表行上于非「健康」时显示分数徽标。这是显示策略差异，不是口径差异，已写进对照表。
- **`AgentHealthEvaluator` 之外的依赖**：Swift 的 `AgentCleaner.hungNotEvaluatedNote` 从配置读
  阈值文案；Rust 侧建议文案不含数字（与 Swift 的取值同口径），但那条 note 本身没有对应实现。
- 同前几轮：同一人既改又审；真正的护栏是反向验证的那条红与三条判别性用例，不是这份文档。

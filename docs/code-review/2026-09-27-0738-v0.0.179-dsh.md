# v0.0.179 独立复核 · DSH · 2026-09-27 07:38

## 范围与结论

复核 SMTP over 465 会话（`smtp.rs`）：协议对话、消息组装、失败也关连接、端口收窄。
结论：**协议逻辑离线逐条验证过，三处关键细节各有判别性用例**。Swift 侧零改动。

## 可核验的行为证据

- **完整命令序列**：`a_full_session_walks_the_documented_command_sequence`
  —— 脚本化会话走完 220 → EHLO（多行）→ AUTH LOGIN → 用户名/授权码 base64 →
  MAIL FROM → RCPT TO → DATA → 头部七行 → 正文 → `.` → QUIT，并**逐行断言写出去的内容**
  （不是只断言返回枚举）。
- **点号加倍**：`a_body_line_starting_with_a_dot_is_doubled`。
  **反向验证**：去掉加倍 → 红（`assertion failed: lines.contains("..隐藏的一行")`）。
- **失败路径也关连接**：`every_failure_path_still_closes_the_connection`（五条失败路径）。
  **反向验证**：只在送达时关 → 红（`left: 0, right: 1`，理由是「不关就会留下活的 TLS 连接
  与已解密的授权码」）。
- **多行续行**：`multiline_replies_are_consumed_whole_or_everything_after_desyncs`。
  **反向验证**：续行循环关掉 → 红，且报出的正是错位结果（`EHLO：回复异常 220`）。
- **5xx 永久 / 4xx 可重试**：`five_hundred_series_is_permanent_and_four_hundred_series_is_retryable`
  —— 与上一轮的重试逻辑正好按这一位分叉。
- **`smtp_line` 折行**（欠了两轮的账）：`headers_fold_bare_newlines_so_one_message_cannot_become_two_commands`
  —— 并有一条「收件地址里混进 `\r\nRCPT TO:<...>` 不许变成第二条命令」的用例。
- **测试数**：Rust **167 → 176**、Swift 550（未动）；编译警告保持 **26**。

## 顺手收紧的一条判据（上一轮留下的松动）

上一轮的 `dispatch_returns_immediately_even_when_the_transport_is_slow` 写成
「传输 300ms、上限 100ms」，在刚编译完的负载下**飘过一次红**（172 轮全量里唯一一次）。
改成「传输 500ms、上限 150ms」：宽到不受负载影响，窄到仍能把「同步跑」钉死
（反向验证实测 510ms）。改完连跑 8 次全绿 + 判据复验通过。

**这条与上一轮的端口竞争是同一类病**：判据的余量选得比环境噪声还小。凡是用时间做判据的用例，
余量要按「负载最坏情况」选，不是按「空载实测值」选。

## 边界与后续风险

- **SMTP 通道今天在真实运行里走不到**：`has_secret` 恒 false（钥匙串未接入），
  所以配置了 SMTP 的通道会在**闸门**的「配置检查」被拦下，连传输都到不了。
  这一轮交付的是「会话本身正确」，不是「邮箱通道可用」。**钥匙串是最后一块**。
- **真实 SMTP 服务器没有实样**：全部用例都是脚本化会话；`TlsSession::connect` 的真实
  465 握手（含证书校验）与 `native_tls` 的 HTTPS 路径同源，但**没有对真邮箱跑过**。
  这是本轮最大的未验证面。
- **`TlsSession::read_line` 的行缓冲是「攒到换行为止」**：遇到服务器发超长行（无换行的
  大块数据）会一直攒在内存里。SMTP 回复不会这样，所以没设上限——但**没有上限就是没有上限**，
  已记在此处。
- **`TlsSession` 未 join / 未设连接复用**：一次会话一条连接（与 Swift 一致）。
- 同前几轮：同一人既改又审；真正的护栏是三条反向验证的红与上面几条判别性用例，不是这份文档。

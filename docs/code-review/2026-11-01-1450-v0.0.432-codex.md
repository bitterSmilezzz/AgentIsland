## Standards

- `seal` 把头、正文与 AEAD tag 写进单一 envelope 缓冲区；不再额外创建整份 ciphertext `Vec`。
- `open` 只复制一次密文区，在同一缓冲区内认证解密，并以 `Zeroizing<Vec<u8>>` 返回。认证失败时该缓冲区也会在 drop 时零化；调用方不能在认证前取得正文切片。
- 测量回归仅在 macOS test target 编译，并明确 `#[ignore]`。它生成随机临时数据密钥和合成重复字节，只能写入全新临时目录；输出不含正文、身份 ID 或目录路径，离开作用域清理临时树。
- 测量调用当前生产 AEAD 与原子文件创建 helper；文档准确说明 `st_blocks` 口径、未同步父目录、未测 RSS/索引/备份，也没有据此开放产品写入。
- 没有发现违反现有通知凭据、来源只读、原子发布或授权边界的改动。

## Spec

- 首轮合成结果用于指出密文小文件粒度和逐文件同步的成本；它没有 TASK-03 实际 Run 频率、事件分段、索引和备份占用模型，因而没有把容量/期限数字写进策略或 UI。
- 解密返回区的零化和缓冲复制减少是代码路径事实；本轮没有 RSS/分配器测量，不把它换算成进程内存降幅。
- 当前没有将加密代码连接到任务 JSON、Tauri 命令、钥匙串写入或受管理运行。macOS Keychain 原生创建/读取/冲突/删除验收仍未执行；非 macOS 仍拒绝。
- 未发现需阻断该基础设施分片的范围偏差。TASK-05 仍是 partial。

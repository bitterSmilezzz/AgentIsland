# 复盘触发契约（AUTO-02）

> 回答一个问题：**复盘（错题→账本）在什么时机、以什么权限、失败时是什么语义地发生？**
> 需求只授权**设计触发契约**，明确排除定时任务类触发器（不建 cron、不建守护进程）——
> 这份契约就是被授权的交付物。它由 `scripts/test-retro-contract.py` 逐条核对：
> 契约里指名的每个入口必须真实存在，指名的禁止事项必须真的没有。

## 现状（契约的地基，先说清楚）

复盘记录**已经附着在 run 上**：`pipeline.py` 的 run 收尾段会（当操作者以
`--lesson <规则>` 显式给出错题时）调用 `add_lesson` 把规则写进账本，**证据自动绑
本轮 run_id**（不需要人抄），随后用 `promotion_candidates(load_lessons())` 计算
跨日期晋升候选并落盘到本轮证据目录。缺口从来不是「没有挂点」，而是**内容要人打**。

## 触发契约

- **唯一附着点：管线 run 的收尾**（run 的 outcome 已定、证据已落盘）。
  复盘吃的是**这一轮已定案的 run 事实**：失败检查的名字、重试/返工轮数、
  审查否决、暂停记录——候选条目以 run_id 为证据，自动绑定，不靠人抄。
- **不存在其它触发器**：没有定时器、没有 cron、没有守护进程。复盘只附着在
  真实发生的 run 上——没有 run 就没有复盘。
- **显式路径保留**：操作者随时可以 `lessons.py add`（或 run 上的 `--lesson`）
  直接写账本；契约不接管人工复盘。
- **由 run 事实自动生成候选条目**（把「要人打」变成「从证据里来」）是契约允许的
  唯一自动化方向；实现时必须走 `add_lesson` → `append_entry` 的幂等单点。

## 权限边界（复盘能做什么、不能做什么）

| 动作 | 契约 | 现有实现锚点 |
| :--- | :--- | :--- |
| 记录错题/回归/假验证证据 | **允许**，只能经 `add_lesson` → `lesson_ledger.append_entry` 幂等追加（同身份同内容 no-op，同身份不同内容拒绝） | `append_entry`（(key, seen_date, evidence) 幂等） |
| 跨日期聚合与晋升候选 | **允许**（只读计算，候选落到本轮证据目录供人查看） | `promotion_candidates(load_lessons())` |
| **把候选升级成硬规则** | **不属于自动复盘**——晋升是「validate 阶段」的显式动作，复盘只把原料放进账本 | `lessons.py validate` |
| 撤销规则 | **禁止**——`revoke_key` 是人工撤销入口，复盘永不调用 | `revoke_key` |
| 自增权限（改 registry、改门禁、放宽判据） | **禁止**——复盘产物只有账本条目，「恶意规则不自增权限」由 `automation.lessons` 已有用例钉住 | `test-automation-lessons.py` |
| 绕过幂等单点直接拼账本字节 | **禁止**——pipeline 里对账本的引用只允许「路径常量 + lesson_ledger 函数」 | `pipeline.py` 的 `add_lesson` |

## 失败语义

- **复盘失败不改变 run 的 outcome**。复盘是旁路证据记录，不是门禁：它读不到、
  写不进、算不出来，run 该通过还是通过、该失败还是失败——复盘的失败只留下
  自己的 step 记录（现状即如此：`lesson.record` failed 只记 step），绝不回头
  改判据、不重跑检查、不阻塞发布链。
- 复盘写入走账本既有的原子发布（flock + 独占临时文件 + os.replace，0600），
  坏账本保留原字节、明确报错——不静默清空，不覆盖重写。

## 显式排除（本轮不做，也是需求划的界）

- **定时任务类触发器**：不建 cron/LaunchAgent/守护进程。将来若要加，必须先修订本契约
  与它的形状门禁，不能悄悄长出来。
- **自动晋升**：跨日期聚合的候选只呈现、不自动转正。

## 形状门禁核对什么

`scripts/test-retro-contract.py`：①契约指名的入口（`add_lesson`、`append_entry`、
`revoke_key`、`promotion_candidates`、validate 子命令）都真实存在，且 pipeline 里
对账本的引用走的是「lesson_ledger 函数」这一条路；②禁止事项真的没有（pipeline 里
不存在 lessons 相关的定时器/cron 挂点）；③契约与门禁互相指认。任何一侧漂了就变红。

# 扩展适配矩阵（GW-10）

> 回答一个问题：**每个扩展点（Instructions / MCP / Skills / 媒体 / 预热），
> 在每个受管工具上能不能配？** 与 [入口能力矩阵](入口能力矩阵.md) 同型：
> 让「某个工具缺某项扩展支持」成为**可核对的事实**，而不是靠人记。
> 每一格由 `scripts/test-extension-matrix.py` 逐条核对：声称有的必须能在代码里
> 找到实现锚点；声称「不具备」的必须真的没有管理锚点。

## 矩阵

| 扩展点 | Codex | Claude Code |
| :--- | :--- | :--- |
| Instructions（用户级指令文件） | `AGENTS.md`（`~/.codex/AGENTS.md`） | `CLAUDE.md`（`~/.claude/CLAUDE.md`） |
| MCP 服务器（本地配置管理） | `.codex/config.toml`（transport 校验/预览/应用） | —（无管理锚点） |
| Skills 包 | `~/.agents/skills`（共享根，`.claude/skills` 为软链） | 同左 |
| 媒体（搜索/图像/视频适配器） | — | — |
| 预热（会话/缓存预热） | — | — |

## 口径

- **Instructions**：`prompts.rs` 写入与备份的是**用户级指令文件**；它明说
  「项目规则可能覆盖，新会话加载后需核对」——写入≠生效，生效验证属官方客户端层。
- **MCP**：`mcp_config.rs` 只做**本地配置管理**（transport 校验、原子应用、
  预览/恢复），不启动服务器、不碰认证。Claude 侧没有管理锚点：Claude 的 MCP
  配置形态（`.claude.json` / 桌面版）未被本仓管理——写「不具备」而不是「待补」，
  接入前需按其契约另立（ADR 0040 边界）。
- **Skills**：共享根 `~/.agents/skills`（`.claude/skills/<name>` 是指向它的
  软链——见根 AGENTS.md「两条安装路径互斥」）。同步（`skills_package.rs`）面向
  Codex（`.agents`）与 Claude（`.claude`）两个目录，`synced`/`anthropic-skills`
  两个名字对 Claude 禁写。
- **媒体 / 预热**：整个仓库都没有对应适配器——这一格是「没有」，不是「忘了写」。

## 未覆盖（如实登记）

- 本矩阵只管「能不能**配**」；「配了之后工具真的加载」属官方客户端/真实工具层
  （与 GW-02 档位、GW-07 工作区的同款边界）。
- 媒体与预热是**未开始的功能面**，不是已实现但缺文档——需要时按需求另立切片。

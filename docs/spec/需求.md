# AgentIsland 需求基线：Agent 的监工台

> 2026-10-14。本轮固定产品目标与验收范围，不实施产品、测试 runner、云服务或付费发送。
> 用户确认：Mag Pad 指 Magpie（yetone/magpie），To-Do 指 Todos（todos.dev）；两者完整能力纳入目标。本机优先，完整能力可自托管或接入服务，不要求自营云套餐/支付。
> 此基线取代 ADR 0039 中“无网关/无智能路由/仅只读任务”的范围收窄。存量安全规则在新子系统正式设计前仍有效，需求纳入不等于已经授权当前会话读凭据、发短信、运行任务或部署服务。

## 1. 定位与完整性

AgentIsland 是 **Agent 的监工台**：观察全部可接入 Agent 的工作与异常，及时把需人处理的事项送达，并统一提供模型路由和任务执行管理。灵动岛是即时状态入口，工作台承载完整配置、对话、方案、代码审查、历史和管理。

三条并列产品目标：

1. 监控准确、即时通知、界面清晰美观，重点维护。
2. 完整覆盖 Magpie 的模型接入、协议网关、路由、配置、账号与用量等能力，不以打开外部软件代替内建能力。
3. 完整覆盖 Todos 的任务组织、Chief 编排、运行、审查、版本、多机器、移动与协作等能力，不再把待办清单或只读来源当完整移植。

“全部功能”以 [能力对齐清单](功能对齐清单.md)的上游快照为验收对象。核心本地能力内建；云机器、远程同步、推送、搜索/媒体等可由本产品适配自托管/第三方服务。对齐的是用户能力与结果，不要求复制上游品牌、价格、配额数、视觉或全部内部技术。未核实细项登记为 open，不能悄悄排除。

“监控所有 Agent”是开放接入目标，不承诺未知工具自动获得精确语义。维护工具×版本×OS×信号能力矩阵；未接入、不可读、未知、真实空闲明确区分。接入一个工具必须验证真实身份、来源格式与正反例。

## 2. 平台与界面

主要平台：Mac、Windows、移动端；移动端 Android 首发、iOS 后续。Web 倒数第二、Linux 最后。近期 Mac 定需求与技术方案 → 用跨平台技术完善 Mac → Windows；移动/Web/Linux 保留需求位置，到对应阶段验证技术和交互。

Mac/Windows 提供监控、路由与执行工作台；手机首先承担完整任务查看/交互、审批、通知与远程监工，不默认认为可扫描电脑进程或在手机本机执行所有桌面工具。独立移动壳/PWA/推送服务技术仍待设计。已有窄条、侧栏和工作台保持可用；保持窄条优化的原选择未被本轮推翻，四态改造仍属独立未统一项，不阻塞功能基线。

### 即时通知指标（建议初始目标，须实测后锁定）

正常本机负载下，从受支持来源产生可观察事件到桌面提醒 p95 ≤5秒；结构化hook进入服务到通知入队 p95 ≤1秒；外发从入队到首次发出 p95 ≤5秒（网络正常，未静默/限流）。邮件、SMS、手机最终到达受供应商与设备影响，单独测量并展示超时/失败，不承诺绝对即时。各工具采样能力和抑制策略会影响覆盖，指标不适用时须明确理由。

短信费用/发送预算、号码地区、供应商；手机推送供应商与后台方案；路由重试预算；资源上限均须在实施对应能力前定值，不能把空阈值当通过。

## 4. 自有执行与外部监控的两种内容契约

- 外部 Agent 只读监控：继续按来源身份和事件版本读取；源只有单版本就说明，私密正文不复制自建历史。
- AgentIsland 自己发起的受管理执行：为了完整 Todos 版本能力，按项目内容策略保留自有方案、diff、对话与产出；访问、加密、保留/删除、备份恢复另定契约。不得把执行产物条款拿去复制未经授权的日常会话。

监控、执行、路由是三个能力域：单独启停、授权、资源预算、日志与账目；网关出故障不能使监控失明，通知失败不能触发任务重复执行。

## 5. 全自动开发采用的参考与权限边界

用户指定参考 Magpie 作者的自动维护做法。知识库已找到 [错题本研究](../../../01-学习备考/ai-note/notes/39-magpie的错题本-一条规则犯满三天就自动变硬.md)：AGENTS路由、子系统文档、LESSONS、Red check / Break check / Not run、独立审查SHA绑定、CI完成再tag、跨3个不同日期的重复教训升级规范。本轮采用机制，不把文章里的发版数量当质量保证，也不假设未公开的夜审触发器已知。

提供三种项目策略：人工关口、半自动、预授权全自动。用户选择借鉴流程尚不等于授权任意项目自动推送/部署/发短信：默认沿现有需求/发布人工门；显式预授权记录项目/分支/路径/执行工具/密钥/预算/有效期/合并发布条件后才自动推进。所有模式保留暂停、撤销授权、预算熔断、失败通知及审计，Agent不能自行扩大权限。

正常检查自动运行；新缺口、冲突需求、授权外操作、关键门禁失败均暂停对应阶段并通知。复盘在任务结束/事故/候选发布后触发，夜间批处理只设计触发契约与幂等，不在本轮创建定时任务。

## 6. 完成标准和待定项

功能目录已入基线不代表实现完成。每项需求须拥有上游来源、可执行验收场景、负例/故障例、平台、测试ID与门禁、当前证据状态；全部对齐才能称完整覆盖某上游快照。

仍需具体方案决策：各运行时/协议/provider的兼容版本，云部署/同步方案，SMS供应商与计费阈值，移动推送与UI技术，执行内容保留与团队安全，预算/资源/延迟阈值，以及项目预授权策略。本轮不挑供应商，不付款、注册或配置真实凭据。

执行优先级：先完成需求/测试资产清单；监控与即时通知先建立可靠基线；Mac上分别打通网关和受管理任务闭环；完整能力分批补齐且不删除剩余需求；随后迁Windows，再按既定优先级推进移动/Web/Linux。

测试设计见 [测试框架](../testing/测试框架.md)，逐项映射见 [需求测试矩阵](需求测试矩阵.md)。旧方案状态见 [ADR 0040](adr/0040-supervisor-full-integration-requirements.md)。

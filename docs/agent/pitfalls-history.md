## 一、诊断方法：错误的结论几乎都出在测量上

这一族的坑最多、代价最大。共同形状是：**观察面本身不可信/不干净，于是结论错得理直气壮。**

### 1.1 日志按运行累积，于是「没出现」不等于「没发生」

- **现象**：连续三个版本报告「换 SDK 后 `[page]` 从 0 变 6」「改 CSP 后 `[webview]` 从 0 变 3」，
  并据此宣布修好了白屏。实际那几行是**更早运行留下的**，当次一行都没产生。
- **根因**：`log_line` 写固定路径文件、纯 append，多数运行前没清空 ⇒ 历史行被当次证据。
- **规则**：**每次启动先写一行运行标记**（`[run] pid=…`），此后一切「某类日志没出现」的判断
  都必须在该次运行的切片内成立。后来这条还演化成「启动时按 2MB 封顶清空」，理由相同：
  排障要的是**这一次运行**从头到尾。
- **更正链**：v235 报 SDK 错配、v236 报 CSP，v237 还为这两个错误因果建了守护；v238 因运行日志混用撤回，v242 才定位 AB-BA 死锁。配置改动保留有其独立理由，但不能作为「白屏已修」证据。
- **证据**：[CHANGELOG](../../CHANGELOG.md) v235～238、v242、v265；[主线程 ADR](../adr/0014-no-main-thread-dispatch-while-locked.md)。

### 1.2 「权威」访问器是名字给的，不是事实给的

- **现象**：据 `window.outer_size()` / `outer_position()` 判定「窗口从来没被缩到窄条」，
  并把它当成白屏的第二个原因发版。实际这两个访问器**恒等于 `tauri.conf.json` 的配置值**，
  从不随 `set_size` 变化——窗口真的被缩到 18×132 贴到右沿时，它们仍报 372×520。
- **根因**：Tauri + WKWebView 这条路上，配置类/宿主类访问器不反映真实几何；
  而**没有任何测试会告诉你这件事**。
- **规则**：**几何结论以截图为地面真相**，且必须做对照实验（杀掉进程再拍同一块区域，
  图应变且目标消失）。同一类错误在 JS 侧（`outerWidth` 恒 0）与 Rust 侧各犯过一次 ⇒
  这不是「知道规矩」的问题，是**每次下结论前都要先证明观察面可信**。
- **同族第二条（跨时点错配）**：原生窗口落位完成与 WebView viewport 更新是**两个时点**。
  在 viewport 还没匹配时读出来的几何是**过渡态**，拿去判定「缩没缩」会得到另一个错误结论。
  正解是保持最终固定几何、等 viewport 匹配并**经过下一次绘制**后才清理过渡与恢复采样布局，
  且等待要有界（平台不反馈时不许永久锁死）。
- **证据**：`CHANGELOG.md` v0.0.255、v0.0.256（后者为撤回）；
  [ADR 0017](../adr/0017-compact-island-layout.md)（两个时点与有界等待）。

### 1.3 被测对象自己报告，就没有竞态

- **现象**：UI 冒烟偶发假红（4 次里 1 次）。日志显示读回时灵动岛还是 `"state":"running"`。
- **根因**：**定时读回和被测对象赛跑**——固定时刻读一次，而驱动耗时可变；机器一忙读回就落在跑完之前。
- **规则**：正解不是「多等一会儿」，而是让驱动在收尾处**自己上报结果**
  （`invoke('log_from_ui', 'SMOKE_RESULT …')`），固定读回只留作诊断。
- **证据**：`CHANGELOG.md` v0.0.259。

### 1.4 别从局部输出下结论

- **现象**：连着两次据 `tail -6` 的截断输出判断「某检查没跑」，实际是它正常跑完、
  只是被截掉了。三次子条件单独跑全成立。
- **规则**：判断「有没有发生」时读**完整**输出或读退出码，不读片段。
- **证据**：`CHANGELOG.md` v0.0.261。

### 1.5 诊断探针必须只读

- **现象**：白屏排查中，探针自己动了一点被测状态（补发 `tray://toggle`「保险一下」、
  顺手调 `place_island`「验一下通不通」），结果两次测到「明明展开了却是 0」。
- **规则**：**探针动了一点被测状态，它测出来的就不是原来那个东西**。需要驱动状态变化时
  走**产品自己的入口**（启动参数 / 真实事件），不另开旁门。
- **证据**：[ADR 0014](../adr/0014-no-main-thread-dispatch-while-locked.md)、`CHANGELOG.md` v0.0.245。

### 1.6 换一个不会被故障波及的观测面

- **现象**：白屏查了十几个版本。`on_page_load` 与 `[webview]` 日志**都长在事件循环上**——
  事件循环死了它们当然沉默，于是「零日志」既可能是「没发生」也可能是「发生不了」，
  用它们判断「前端坏没坏」是**循环论证**。
- **规则**：主观测面与故障面重叠时，**换一条独立的观测面**（`eval_with_callback` 直接问 webview；
  外加一条不走 Tauri IPC 的 `fetch` 兜底），并先做范围切割对照（纯 WKWebView 在同一台机器
  上 JS 正常 → 问题只在 Tauri/wry 链上）。
- **证据**：`CHANGELOG.md` v0.0.234、v0.0.236、v0.0.242。

### 1.7 试验必须确认真被测的二进制/资源是当前的

- **现象（三处同族）**：① 改 `tauri.conf.json` 后只重建了发布包，跑的却是 debug 二进制
  （`generate_context!()` 在**编译期**嵌配置），于是「`resizable` 无效」这个结论本身无效；
  ② `cargo build` **不跟踪 `app/ui/`**，只改前端再 `cargo build`，资源不会重新嵌入——
  前几次「变异没让测试变红」其实是变异没进二进制；
  ③ 冒烟可能拿着**旧资源**去验，「验的东西不是当前代码」。
- **规则**：① 配置类实验必须先确认被测二进制重编过；
  ② 改 `app/ui/` 必须走 `cargo tauri build`（即 `scripts/build-app.sh`）；
  ③ `ui-smoke.sh` 内置「二进制必须比 `app/ui/` 下最新文件新」的闸，否则拒绝跑并说清原因。
- **证据**：`CHANGELOG.md` v0.0.255、v0.0.264。

### 1.8 环境缺件会伪装成代码 bug

- **当时现象（v243～244，迁移期）**：构建旧 Swift 应用时，不传 `SKIP_SWIFT=1` 会失败，下游报错是
  「cannot find `$state` in scope」「cannot assign to property: 'self' is immutable」，
  第一条甚至精确落在某个闭包里，看着像标准的「闭包捕获 self 变只读」真 bug。
  真因是 `SwiftUIMacros` 是 **Xcode 闭源插件**，本机只有 CommandLineTools。
- **规则**：工具链缺件的报错会**精确落在你的源码行上**。构建脚本因此加**前置检查**：
  进 Swift 段之前先看插件在不在，缺就立刻停并给出路（并明说 `SKIP_SWIFT=1` 的代价）。
  同类还有一条更省事的判别法：遇到「webview 不动」先用**纯 WKWebView** 测同一台机器。
- **证据**：`CHANGELOG.md` v0.0.243、v0.0.244（更正「从来编不出来」这句过头话）。

## 二、测试与门禁：门禁自己也会坏

### 2.1 管道会吞掉退出码

- **现象**：`runner | tail` 让 runner 的非零退出码被 `tail` 的恒 0 吞掉，
  **带失败用例的提交进了历史**；同一形状还导致一次带编译错误的提交。
- **规则**：管道里的退出码一律显式取（重定向到文件后读文件 + 检查 rc），
  构建 rc 与测试 rc 都要显式检查后再提交。
- **规则**：**变异必须保持可编译**——用 `u64::MAX` 时夹具那行 `+ 1` 直接溢出，
  响是响了，但响在编译器上，**不证明那条测试能抓**。
- **证据**：`docs/validation/2026-09-12-round-05-inspect-gating.md`、
  `2026-09-12-round-06-sqlite-layer.md`；`CHANGELOG.md` v0.0.265。

### 2.2 用负例或变异证明判别力；等价变异要认出来

- **现象 A**：守护「改了三次才真正有效」——① 只看生产代码字面量，`cfg(test)` 里被间接调用的
  取时钟隐形；② 「生产段」边界取错，实际只剩 7 行，**结构上抓不到任何东西、永远不会红**；
  ③ 把注释散文当成调用点。每一版都是「写完、跑一遍、看见绿」就当成完成。
- **现象 B**：变异脚本只替换了同名条件的**第一处**，有效的那处没动过，于是把
  「我没改到」误报成「这条断言是假的」。
- **现象 C**：变异首次幸存，原因是**用例写错了形状**——
  测「首行滑出尾窗」却写了一个仍留着关键标记的尾窗，那条机制根本没被用到。
- **现象 D**：真正的**等价变异**（把 UTF-8 解码改回整包，在任何输入上都不可观察）不该被判成断言假；
  功劳要记给真正挡住它的那一步。
- **规则**：① 变异脚本必须报**锚点命中数**，命中 >1 处要么全替要么拆成两条；
  ② 先量一次干净基线，逐条列出红在哪一个用例；③ **测一条机制，就要把别的来源堵掉**；
  ④ 断言要带自检——边界找不到或落得太靠前，守护先报自己失效。
- **证据**：`CHANGELOG.md` v0.0.133（m42/m47b）、v0.0.132（m36）、v0.0.259、v0.0.263。

### 2.3 证不了失败的门禁，比没有门禁更糟

- **现象**：搜索过滤的门禁两次都是假阳性——① 判据里 `indexOf('empty')` 会匹配 HTML 里任何含
  `empty` 的子串，**不派发输入事件也能过**；② 收紧后仍过，因为**这台机器上没有正在跑的 Agent**，
  空态本来就渲染，「打了什么字」不可区分。
- **规则**：缺的是**数据**不是判据时，**降级成诚实的边界**：驱动照跑（崩溃仍抓得到），
  脚本输出显式写「过滤是否生效未验」，不假装覆盖。
- **证据**：`CHANGELOG.md` v0.0.252。

### 2.4 门禁里的洞：测试从没进过门禁，于是红了也没人知道

- **现象（两代）**：① 一批 UI 回归（3 条 Playwright 浏览器用例 + 18 条纯数据用例，
  其中 8 条连文档都没提过）**从未进过任何门禁** ⇒ v0.0.321 起 committed 测试对 committed 产品
  就是红的（窄窗口隐藏任务列表让旧断言超时）却无人发现。
  另一时期新增 Windows CI 首跑即红，是平台依赖范围错误（见 4.2），不是同一批 UI 用例的后续。
  ② `test-functional-ui.mjs` 在 workbench 壳下一直崩——坏在**夹具**（桩 DOM 只认岛/侧栏选择器）。
- **规则**：**每条测试都要说清它在哪个门禁里跑**；需要外部环境的（真机 VM、真实客户端）
  明列「不进自动门禁及其理由」，缺依赖时**明确失败而不是静默跳过**。
- **证据**：`CHANGELOG.md` v0.0.323、v0.0.264；`scripts/release.sh:146-178`。

### 2.5 断路器式断言优于存在性断言

- **现象**：两条守卫写成 `contains(...)` 与 `expectFalse(contains("…"))`——
  前者只要文件里出现过一次就绿（另一侧的回退测不出来），后者只挡一种拼写
  （限定名或本地别名都能绕开）。改成计数式（某标识符**恰好出现 2 次**）后，
  第一次跑就抓到了 `contains` 挡不住的两种回退。
- **规则**：把常量改回**同值字面量**这种事行为测试原理上抓不到（值一样），
  能抓的只有书写层面的计数/禁字面量断言；**更好的处置是改掉形状，让第二出口无处存在**。
- **证据**：`CHANGELOG.md` v0.0.131。

### 2.6 测试隔离：旁路读真实数据会污染判定

- **现象**：一次全量回归中，14 个既有状态机用例被误判 `completed`——
  测试**旁路读取了本机真实的会话库**。
- **规则**：只在「本轮扫描确实命中文件」时才启用生产解析，测试 hook 保持**显式可注入**；
  夹具路径不得指向用户真实数据。
- **证据**：`docs/validation/2026-09-15-round-38-attention-routing.md`。

### 2.7 测试卫生：残留物要有人清

- **现象**：进程内删除 + 断言通过，**退出后 `cfprefsd` 又把偏好文件 flush 回来**——
  连跑两轮冒出 28 个残留。
- **规则**：测试套件改用**登记制 + 退出后循环重试清扫**，残留即 runner 失败。
- **证据**：`docs/validation/2026-09-12-round-16-test-hygiene.md`。

### 2.8 夹具错 vs 功能错：先怀疑夹具

- **现象**：某解析函数被判「不是这一族的库」而拒绝，看起来是功能缺陷；
  实际是夹具只建了 `message` 表、没建 `session` 表。
- **规则**：**先怀疑夹具，别急着怀疑功能**。夹具形状要照**本机实拍**抄（例如时间戳形状、
  空数组这类真实常见值），自造形状会让「该响时响」的分支永远走不到。
- **证据**：`CHANGELOG.md` v0.0.258、v0.0.240。

## 三、数据口径：把「没看到」当成「没有」是同一个家族

### 3.1 「没查到 ≠ 0」是本仓最反复的一条

- **现象（三代）**：① 先 `open` 预检通过、聚合 SQL 仍失败，却返回零值并更新文件戳，
  缺失源被直接从汇总移除；② 汇总把缺失字段当零（隐含 COALESCE），详情页直接相加，
  整组 token 变零且与汇总不符；③ `Int("301.0")` 解析失败后**静默**显示 0。
- **规则**：失败与「成功零值」必须可分辨（可选值 `nil` = 没查、`0` = 查了确实是零）；
  `—` 这个记号被「没查」独占，任何出口都不许拿它兼表示「查了、确实是零」；
  数值解析统一口径、**禁止静默失败**。
- **证据**：`docs/validation/2026-09-09-optimization.md`、`2026-09-10-token-refresh.md`；
  `CONTEXT.md`「Token 数据覆盖」；[ADR 0009](../adr/0009-credential-boundary-borrow-dont-hold.md)、
  [ADR 0011](../adr/0011-local-state-storage-and-migration-triggers.md)。

### 3.2 一次扫描失败的宽限：派生字段必须同进退

- **现象**：读不到会话目录（stat 失败/枚举器建不起来）被折算成 `activeSessions = 0`，
  而同一份快照里活动日期却保留上一份 ⇒ 「刚刚还在写」与「0 个会话」同时成立，
  下游据此翻成「无本地明细」（虚假失明）。
- **规则**：「读不到」不是「没有」。同一次失败里**所有派生字段同进退**（保留就都保留），
  保留有终点（连续 3 趟仍读不到即终态清零，吸收原子替换/迁移的空窗），
  且收尾必须排在缓存整表替换**之后**。反过来，**扫完了确实没有信号文件**是正常终态，
  计数照实取。旧记录中「空会话目录」的回退计数不能套用于现行 Rust 的受支持信号文件计数口径。
- **证据**：`CONTEXT.md`「一次扫描失败的宽限」；`docs/validation/2026-09-12-round-33-file-monitor.md`。

### 3.3 五态活动与三态观测资格分开，一次采样不足以评级

- **现象**：只有 `offline/idle/working` 时，「等用户确认」CPU 与写入双沉寂必被压成 idle，
  「刚完成」又被 working 窗口顶成 working；`isHung == false` 被当成「查过且没有死锁」。
- **规则**：**判不出是第三种答案**，下游一律按三态说话（`null` 而不是 `false`；
  健康分在「判不出」时只说「观测不全」）；**资格**由引擎按 profile 记在快照里，
  不交给调用方自报（一个可以说谎的参数，漏传一处的症状是静默谎报）。
- **证据**：`CONTEXT.md`「死锁判定的三态」「CPU 差分窗口」、
  `docs/validation/2026-09-15-round-38-attention-routing.md`、`2026-09-12-round-37-status-truthfulness.md`。

### 3.4 纯 CPU 尖峰不是「任务完成」

- **现象**：桌面应用启动/后台尖峰（实测 20.6%–93.1%）被当成本轮完成并响铃。
- **规则**：**完成事件需要写入证据**；只看「信号消失」不看「信号来源」会一路误报。
  纯 CPU 区间仍显示 working 但静默收尾。另外，一条证据新增后必须在**所有清理点**同步清除，
  否则证据跨区间泄漏、下轮误报（离线/睡眠断点/停止/终止清理/启用集裁剪都要清）。
- **证据**：`docs/validation/2026-09-12-round-37-status-truthfulness.md`。

### 3.5 指纹是去重语义的一部分，不是随手取的 hash

- **现象（两处）**：① Cline 的 attention 指纹由 `ask + 消息字节长度` 组成，
  而 `alerted_fingerprints` 是**近乎永久**的全局去重集 ⇒ 同一文件里两条**长度相同**的提问，
  第二条被永久静默（「重试」「继续」「好的」俯拾皆是）。② Qoder 每次模型调用换 id，
  完成指纹取「最后一条 assistant 的 id」⇒ 一个长任务里 `end_turn` 很多次，一路弹「任务完成」。
- **规则**：换一个「看起来更唯一」的字段之前，先确认去重那一侧拿它做什么；
  指纹要挂在**结构事实**上（Cline 用消息在数组里的下标、Qoder 用「最近一次人类输入那一轮的
  promptId」），且必须**成对**守护：新问题必须穿透去重 / 同一条问题不得重复提醒。
  拿时钟当语义（时间节流）被明确否决。
- **证据**：`CHANGELOG.md` v0.0.246、v0.0.132。

### 3.6 同一口径两处实现 = 迟早漂移

- **现象（反复出现）**：`dimcode.sqlite` 路径散在 4 个文件；`LIMIT 200`、复核窗口 0.8s 各写两处；
  「只显示在线」散成三种拼法（`process_running` / `level !== 'offline'` / `filter(\.processRunning)`）；
  「最近活动」在岛上写「2分钟前」、侧边栏写「2m 前」；守护里 `covered_by_rust` 是照引擎逻辑
  **重写的一份**，两处编码同一条件、**可以一起漂**。
- **规则**：收成一处，并配**不变式守护 + 反向守护**（例如：前端过滤谓词里不许再出现
  `process_running`；`isVisible` 只许定义一次且必须真的被用到 ≥4 处）。
  冗余不是保险，是**伪装成有意为之的隐患**。这条也是
  [ADR 0008](../adr/0008-calendar-day-buckets-and-rolling-24h-budget.md)、
  [ADR 0010](../adr/0010-swift-freeze-and-rust-prerequisites.md) 的否决理由。
- **证据**：`CHANGELOG.md` v0.0.249、v0.0.258；`docs/adr/0004-…`（能力以档案声明、
  不按 id 反查，根因正是「同一事实被到处重述」）。

### 3.7 通用检测器不能直接移植到它没设计过的形状上

- **现象**：推测「把 Swift 的通用事实收集器搬到 Rust 就能覆盖那 16 个缺口」，
  用**真实会话文件**对拍后推翻：zcode 3 个里 1 处假阳——`request.body.tools[].function.name`
  里的工具目录（schema）被读成「正在等你批准」。
- **规则**：移植前做**真数据对拍**；覆盖面声明要写清边界（「通用收集器只被用在 `genericTail`
  那一族档案上」这类），不要把「没验过」说成「已覆盖」。
- **证据**：`CHANGELOG.md` v0.0.247、v0.0.248。

### 3.8 时间：可回拨的墙钟要重锚，且非法值先归位再钳制

- **现象**：墙钟回拨后，`workingSince/lastSignalAt` 等观测锚点落在本拍之后，可能卡住 working；
  配置里的 NaN / 越界值也曾直接进内存。文件留档则要区分「文件被修改时刻」与「发现损坏时刻」。
- **规则**：采样时钟由引擎盖章、探测层不自取当前时间（否则那族没法用受控时钟测）；
  对回拨造成的未来观测锚点按具体状态规则重锚，正常历史时间不能每拍改写；`normalized()` 全字段钳制（NaN 先归位再钳）；
  测试改用**固定时钟**（时间相关断言依赖「跑测试的那一刻」会在慢机器上偶尔变红，
  而那与代码对错无关）。
- **证据**：`docs/validation/2026-09-12-round-02-engine-time.md`、`2026-09-12-round-03-dirty-persistence.md`；
  `CHANGELOG.md` v0.0.258、v0.0.259、v0.0.130（TTL 重锚）。

## 四、构建、打包与发布链路

### 4.1 「加进脚本」和「跑过」是两件事

- **现象**：把 UI 冒烟加进 `release.sh` 之后一直**手工分步**发版，那条路径从未被真正执行过。
  去看时发现它**根本跑不完**：`release.sh` 调 `build-app.sh` 没带 `SKIP_SWIFT`，
  而本机缺 `SwiftUIMacros` ⇒ 在 `set -euo pipefail` 下**后面所有步骤都到不了**。
- **规则**：加了步骤就要有东西能证明它**真的执行过**；脚本内部的前置探测要么带齐条件、
  要么明说代价（缺件时导出降级开关并打印「产出不了回退产物」）。
- **证据**：`CHANGELOG.md` v0.0.260。

### 4.2 平台专属依赖挂在共享表里 = 另一个平台死在依赖自己的源码上

- **现象**：补了 Windows CI，**第一次跑就红**，而报错落在 `core-foundation/src/filedescriptor.rs`
  ——**不是本仓任何一行**。链条：`security-framework`（钥匙串）拉进纯 macOS 的
  `core-foundation`，而它挂在共享 `[dependencies]` 里、没有 target 门控。
- **规则**：平台专属 crate 一律进 `[target.'cfg(target_os = "macos")'.dependencies]`，
  并配**双向**守护（共享表里不得出现这些名字 / 它们必须**还在** macOS 表里——
  否则「不在共享表」会被「全删掉」满足，钥匙串在 macOS 上悄悄没了）。
  另记一条方法教训：上一版写的「本机验不了」**只对了一半**——
  `cargo check --target` 会被 bundled C 挡住，但**依赖解析**不需要 C 工具链
  （`cargo tree --target … -i <crate>` 就能验），而这次真正的故障面恰恰是依赖解析。
- **证据**：`CHANGELOG.md` v0.0.267、v0.0.269。

### 4.3 发布链的顺序是钉死的

- **现象**：v0.0.81..v0.0.118 共 **38 个版本**提交推上去了、**tag 与 release 却没建**；
  另一处：`--release` 扫描跑在提交**之前**，于是本次新增的 blob 还没进历史 ⇒
  「工作区靠 nosec 放行、历史这一关却要按对象备案」的差异要到**下一轮**才暴露
  （v0.0.174 真发生过：发版成功，下一次冷扫描才发现 1 个未核准 blob）。
- **规则**：`scripts/release.sh` 把顺序钉死，**任何一步失败即停**：
  扫描 → 测试与打包 → 提交 → **再扫一次 git 对象**（在 tag/push 之前）→ tag → push → Release。
  首轮扫描必须早于 commit：**commit 一旦落地，泄漏内容就进了 git 对象，删文件也拿不回来**。
- **显式文件清单**：`RELEASE_FILES_FILE` 必填（每行一个仓库根相对路径，含删除；
  空行/目录/重复/`..`/`.`/`//`/`.git` 一律拒绝），**禁止自动收取工作区改动**。
  暂存走 `git --literal-pathspecs`，防 `*`、`?`、`[` 或 `:(...)` 扩大到清单外；
  不用 `git check-ignore`（它不接受 `--literal-pathspecs`）；**禁用 rename 合并**
  （改名涉及的旧路径与新路径都要在清单里）。预检后**冻结内存清单**——
  构建期间有人改写清单不改变本轮范围。
- **附件复核只重试「读」不重传**：`releases/tags/…` 端点会短暂返回空 assets，
  重传会撞 already exists，**把一次正常发版报成失败**；读不到只打警告，人去看一眼更靠得住。
- **证据**：`scripts/release.sh:1-6, 10-13, 32-55, 85-88, 227-232, 269-281`；
  `scripts/test-release-staging.sh:40-55, 123-167`；`docs/agent/desensitization.md` 第四节。

### 4.4 版本一致不能靠手工同步

- **现象**：R25 先发 release 提交后占号、README bump 用了旧目标串漏改；
  `tauri.conf.json` 的 `version` 写死 `0.1.0` 而它是 `CFBundleShortVersionString` 的来源——
  三处版本号里**最容易漂的一处反而没被钉住**。
- **规则**：建版本哨兵（`scripts/check-version.py` + `scripts/test-version.py`）：
  Cargo / 锁文件 / Tauri 配置 / CHANGELOG 首条 / README 五处一致，**漂移即拒绝**；
  `build-app.sh` 从 CHANGELOG 自动抽取版本。哨兵上线后**首次就在真实发布中拦下缺陷**。
- **证据**：`CHANGELOG.md` v0.0.233、v0.0.322；`docs/validation/2026-09-12-round-17-tests-sentinel.md`。

### 4.5 「重启应用」曾经是一次也没发生过的假保证

- **现象**：`AGENTS.md` 与 `release.sh` 都写 `pkill -x AgentIsland`，而 bundle 里的二进制叫
  **`agentisland`（小写）** ⇒ `pkill -x` 一个都没打中（退出码 1），脚本照常打印「重启应用」并返回 0。
  应用看起来更新，是 `open` 撞上被改过的 bundle、Launch Services 自己重开的。
- **更值钱的教训**：`AGENTS.md` 原本给这条命令的理由是「按进程名精确匹配，不会误伤
  `AgentIslandTestsRunner`」——**这个理由方向就是错的**：正因为它按进程名匹配，它才打不中真正的应用。
  **一个为「避免误伤」而写的理由，恰好解释了它为什么没用。**
- **规则**：收进 `scripts/restart-app.sh`：可执行名**从 Info.plist 的 `CFBundleExecutable` 读**、
  用 `pkill -f` 匹配**应用内完整路径**（不用 `pkill -x agentisland`——用户自己跑的 CLI 同名会一起被杀）、
  杀完等旧实例消失、打开后等新实例出现，**任一步不符即非零退出**。
- **证据**：`CHANGELOG.md` v0.0.268；`scripts/restart-app.sh:1-20, 40, 55`。

### 4.6 只存在于 Windows 的死代码，编译器一辈子看不到

- **现象**：`placement.rs` 的三个 `#[cfg(windows)]` 函数从未被编译器看过一眼；
  `main.rs` 里 `use std::os::windows::process::CommandExt;` 导入后全文件零引用。
- **规则**：能验多少就只写多少（那段 FFI 逐字抄进临时 crate 对 Windows 目标 `cargo check` 通过 ⇒
  只能说「那段 FFI 编译通过」，**不能**说「应用在 Windows 上能跑」）。
  **为了让徽章变绿而只留 `cargo check`，等于造一个假的保证。**
  棘轮：这层缺口只能变少；CI 改成**不阻塞但持续报告**。
- **证据**：`CHANGELOG.md` v0.0.267、v0.0.270。

### 4.7 别人的钩子会静默吞掉你的门禁

- **现象**：`install-git-hooks.sh` 早先是「检测到已有 pre-commit 就 `exit 1`」。本机
  `.git/hooks` 里已有 Qoder 的钩子 ⇒ 在 `set -e` 语义下，前一个钩子只要 `exit 0`，
  我们的扫描就被吞掉——**提交照样过，门禁看起来装着，其实一次都没响**。
- **更隐蔽的一处**：扫描段包在子 shell 里，而**子 shell 的退出码不会自动让 git 拒提交**
  ——实测：扫出假 `sk-proj-` 凭据、打印了拒绝文案、**提交却成功**。失败必须**显式 `exit 1`**。
- **规则**：改成 **marker 环绕 + 置顶插入**，我们的整段包在子 shell 里（自带 set 与 cd），
  别人的部分一字符不动；重复执行只重写 marker 之间的内容，段数异常即拒绝。
  验证方式是真去提交一次，看它是否**真的被拒**。
- **证据**：`scripts/install-git-hooks.sh:10-21, 38-71, 109-114`。

## 五、并发、锁与主线程

### 5.1 AB-BA 死锁：持锁期间不许调会同步派发到主线程的 API

- **现象**：界面全白查了十几个版本，真因是启动阶段**必然发生**的互等：
  引擎线程持锁等主线程写托盘徽标，主线程要引擎锁等它放锁 ⇒ `setup` 永不返回 ⇒
  Tauri 不进事件循环 ⇒ WKWebView 从不发起导航。先前怀疑过的资源没嵌入、URL 格式、
  查询串、资产协议、模块循环依赖、注入时序、bundle id 冲突**全都不是**。
- **规则**：**持锁期间不得调用任何会同步派发到主线程的 Tauri API**；临界区里只做纯计算，
  写操作一律挪到锁外。落地形状：`锁内算出 badge 文本` → `出锁` → `apply_tray_badge(&app, badge)`。
  配 `main_thread_dispatch_sentinel` 扫源码守住（**变异验证过**）。
  另一条容易漏：**命令侧一直没踩这个坑**——它们早就用 `{ let e = state.lock()…; }`
  作用域块把锁放在碰窗口之前 ⇒ 这不是「没人知道规矩」，是**规矩没守到点子上**，
  而这正是一条 ADR 存在的理由。
- **证据**：[ADR 0014](../adr/0014-no-main-thread-dispatch-while-locked.md)；
  取证 `ui-research/2026-09-29-blank-ui-deadlock.md`（已迁出本仓）；`CHANGELOG.md` v0.0.242、v0.0.253。

### 5.2 「调度即已热」与递归刷新死锁

- **现象**：扫描刚安排就写 `lastRefreshAt` ⇒ `isWarmed` 在结果未发布时返回 true，
  后加入的调用方拿不到完成通知，错过启用集重放（异步刷新死锁只是注释约束，注释不会报错）。
- **规则**：冷态/缓存年龄/在途判断合并进**同一临界区**；在途请求**共享完成回调**；
  仅扫描完成才更新时间戳；把注释约束升级为**运行期检查**（`refreshingThread` + 断言）。
- **证据**：`docs/validation/2026-09-10-installed-cache.md`、`2026-09-12-round-28-core-hardening.md`。

### 5.3 迟到的异步结果不许写回

- **现象**：`stop` 后仍在飞的连接重建污染缓存；尾读旧回调覆盖新结果；sink Task 乱序让过期事件回写。
- **规则**：给资源加**代际**（`dbGeneration`）或取消窗口守卫，迟到结果一律丢弃；
  过期回调不许重启入场动画。
- **证据**：`docs/validation/2026-09-12-round-34-data-plane.md`、`2026-09-10-log-refresh-coalescing.md`、
  `2026-09-12-round-32-state-machine.md`。

### 5.4 只读库的锁争用是瞬态，不是「读不到」

- **现象**：读第三方 Agent 的 SQLite 时，`SQLITE_BUSY` 被当成「这个源读不到」。
  官方 WAL 文档列出只读方仍会撞上它的三种情形（对方 exclusive locking、清理 WAL 的那一瞬、
  崩溃恢复期）。
- **规则**：只读连接一律带 `busy_timeout`，且**秒数只在一处**（两条打开路径与 token 统计共用）——
  各处自己写一个超时数字，同一类争用在两个出口会给出两种结论。
- **证据**：`CONTEXT.md`「只读库的锁争用」；[ADR 0011](../adr/0011-local-state-storage-and-migration-triggers.md)。

## 六、文件与 IO

### 6.1 尾读切在多字节字符中间 = 整段中文日志消失

- **现象**：按字节偏移（16 KiB / 64 KiB）切尾，正好落在 UTF-8 多字节字符内部 ⇒
  整块解码失败被视为空日志。
- **规则**：抽共享 `LogTailReader`：**先定位完整行边界**（回读前一字节）再逐行解码，
  丢弃被截断的首行，末行未写完不遮蔽前面记录；读量必须有上限（最多「预算 + 一个边界字节」，
  防文件持续增长时读到 EOF），并对文件**符号链接**的 `skipDescendants()` 加 `isDirectory` 守卫
  （对符号链接调用会毁掉枚举器，丢弃后续所有条目，实测复现）。
- **证据**：`docs/validation/2026-09-10-file-io.md`、`2026-09-12-round-05-inspect-gating.md`。

### 6.2 打开数据库（即使只读）会刷新 `-shm` 的 mtime

> Swift 主线期（2026-09-12）发现。当前 Rust 的 `filemon.rs:250` 按 `jsonl|json|db|sqlite|log` 过滤，`*.db-shm` 与 `*.db-wal` 均被排除；旧版「保留 WAL 活动证据」未按此形式迁入。是否由各数据库语义链充分覆盖须另行验证，本次不据此改业务或宣布缺陷成立。

- **现象**：Antigravity 空闲时 10 个会话库的 `*.db-shm` 在**同一秒**被批量触碰、size 恒为 32768，
  而**主库 mtime 停在 22 小时前** ⇒ 引擎判「刚刚写入 → working」。
- **规则**：噪声名单剥离 `-shm` 侧车（以及 Sparkle appcast、账号/状态文件、内核状态文件名），
  但 **`-wal` 必须保留**——真实写入才落 `-wal`；以任务产物
  （`transcript.jsonl` / `state.json` / `session.sqlite` / `*.db-wal`）做**反例守卫**。
  同类：忽略清单只写复数 `caches` 时，单数 `Cache`、`Code Cache`、`GPUCache`、
  `Session Storage`、`Local Storage` 全部漏网，还虚报「活跃会话」⇒ 按内核子树枚举扩充。
- **证据**：`docs/validation/2026-09-12-round-37-status-truthfulness.md`、`2026-09-12-round-07-hotpath-perf.md`。

### 6.3 「扫描成功但无信号」与「枚举失败」必须可区分

- **现象**：空目录返回 nil 被当失败，**忽略文件反而顶起了 `newest`**；
  终态计数写成 `runScan` 的局部变量，无法跨扫描累积。
- **规则**：结构里显式带出 `signalFiles`；`newest` 只由非忽略非噪声的常规文件聚合；
  跨扫描状态必须**实例级持久**。
- **证据**：`docs/validation/2026-09-12-round-33-file-monitor.md`。

### 6.4 配置变更必须失效缓存

- **现象**：改活跃窗口后，计数、扫描节流、快跳过缓存仍用旧口径；新增监控目录也不触发首扫。
- **规则**：配置变更即清计数并整体失效；扫描结果/根时间戳/全扫时间统一在**扫描结束**提交，
  代次校验阻止在途旧配置结果写回。
- **证据**：`docs/validation/2026-09-10-file-io.md`。

## 七、持久化与数据安全

### 7.1 坏掉的 JSON 会被静默覆盖成出厂值

- **现象**：`Settings::load()` 解析失败时只 `if let Ok(..)` 一笔带过、落到 `default()`；
  而 `save_to()` 写得很稳（原子替换 + 写前校验）。两件事凑起来：
  **一份解析不回来的 `settings.json` 会被下一次落盘干净利落地覆盖成出厂值**，
  用户设置整份消失，**没有留档、没有日志、没有提示**。
- **最刺眼的一点**：同一份代码库里 `todos.rs` **把这件事做全了**
  （读时检出坏文件 → `stash_broken` 改名留档 → 写失败往上抛）。**同一件事，两种待遇。**
- **当时修法**：读时报、写时防，共用 `stash_broken`，回落前先留档；目标存在则改用序号，
  时间戳取文件自己的 mtime。它减少同进程重复留档覆盖，但 `exists` 后 `rename` 仍有竞态，不能当成原子防覆盖保证。
- **长期规则**：损坏原字节保留；需要不可覆盖的备份时使用独占发布机制，见 §7.3 / ADR 0033。
- **证据**：`CHANGELOG.md` v0.0.266。

### 7.2 一条坏元素不该拖垮整张档案表

- **现象**：整表解析失败即丢全部；解析失败后走 save 路径**覆盖了损坏原件**。
- **规则**：逐元素容错（坏元素丢弃 + 记日志，但**合法空数组不打日志**——日志要保真）；
  `LoadState` 三态、corrupt **只读降级**、提前 return 不走任何 save，损坏档案原字节留证。
- **证据**：`docs/validation/2026-09-12-round-21-data-loss.md`。

### 7.3 原子写与「不覆盖历史」

- **做法**：同目录独占暂存 → 写入/sync → 调用方校验 → 以 `hard_link` 原子占用目标名。
  目标已存在或被并发创建时**失败**，不删除、不覆盖目标；文件系统不支持 hard link 就**明确失败**，
  不回退覆盖式 rename。发布完成移除暂存别名，权限 0600。
- **证据**：[ADR 0033](../adr/0033-configuration-backup-publication.md)、
  [ADR 0036](../adr/0036-local-skill-package-publication.md)、`atomicfile.rs`。

### 7.4 凭据边界：只借本机既有登录态，不向厂商索取

- **监控与用量边界**：读取 Agent 本机文件，不调用厂商用量/账单 API，不碰 OAuth 刷新。
  配额没有已核实来源时明确未知，不显示成 0。ADR 0038 已授权手动读取已保存接口的模型清单，
  包括厂商官方 HTTPS 地址；不能把旧版「全面禁止厂商 API」复制成当前规则。
  通知密钥只进钥匙串，条目名由通道唯一决定、**不做成可配字段**——
  「存了但条目名对不上」是界面全绿、每次发送都失败且永远查不出来的失效。
  手动读取已保存接口的模型清单是**窄例外**（只 HTTPS 或字面回环、禁止重定向/代理/自动重试、
  凭据只从该档位声明的环境变量临时读取）。
- **证据**：[ADR 0009](../adr/0009-credential-boundary-borrow-dont-hold.md)、
  [ADR 0038](../adr/0038-manual-interface-model-read.md)、[ADR 0005](../adr/0005-email-outbound-465-only.md)、
  [ADR 0006](../adr/0006-no-unverified-channel-fields.md)。

### 7.5 未见过的字段不许猜

- **现象**：早期版本在模板留空时**自带一套 `title`/`body`/`content` 字段名**，
  后果不是发不出去，而是**发出去且界面显示「已送达」**——中转服务收到不认的字段照样回 200，
  用户端什么也没收到，排查方向还指向网络。同类：留下永远走不到的 STARTTLS 分支，
  代价不是死代码，而是**让「支持 STARTTLS」在代码里看起来成立**。
- **规则**：不预置未核实的形状，交给用户模板（出错面从「我们猜错且看不出来」变成
  「你粘的对不对，点『发送预览』当场能看到实际会离开本机的原文」）；
  不可达的分支**删净**而不是留着。
- **证据**：[ADR 0006](../adr/0006-no-unverified-channel-fields.md)、[ADR 0005](../adr/0005-email-outbound-465-only.md)。

### 7.6 脱敏扫描器自己的坑：棘轮的实现纪律

> 这一节读的是 `scripts/scan-secrets.sh` 的头部注释与关键分支（它把踩过的坑写在脚本里）。

- **「什么都没扫」不等于「零命中」**：baseline 缺失是**独立失败**而不是空核准集；
  git 失败、文件列表为空、命中集初始化失败一律 `exit 3` 不放行。
  这两点各有回归用例，因为它们的症状都是**门禁绿了而其实没扫**。
- **中间文件先写临时再改名**：对同一文件 in-place `sort` 曾是「静默产出空文件」的那一步；
  而**空文件在这里是「扫描没跑完」的信号**，两者混起来门禁就废了。
- **刻意不用「/tmp 文件是否存在」当记忆**：那等于跨进程复用上一轮对象流，
  新提交的 blob 永远扫不到——v0.0.163/164 新增的 27 个 blob 就这样**一次没进过历史扫描**。
- **一条规则只启动一次 grep**：macOS 27 的系统 Bash 在逐文件密集 fork 时会触发 SIGTRAP；
  批量扫描也让 grep 的失败码不再被 process substitution 吞掉
  （与 §2.1「管道吞退出码」同族）。
- **命中内容一律截断 + 打码后才打印**；本机用户名走环境变量注入——
  写死等于把开发者代号放进被扫描的仓库。
- **豁免两种粒度各有代价**：`path:` 前缀放行的代价是「真凭据提交在该前缀下，历史这关会放过它」；
  假邮箱/假口令在历史里成百上千条，逐条备案没有意义。
- **`.gitignore` 的 `*secrets*` 会挡住门禁自身**，必须留 `!` 例外（v0.0.119 首次发版就这么漏的）；
  `node_modules/` 必须忽略——Playwright 装在项目根，其自带示例邮箱/密码会被扫成新命中，
  **v0.0.323 发布真被自己的闸拦下**，并补了「第三方依赖文字不在扫描范围内」的回归。
- **证据**：`scripts/scan-secrets.sh:3-8, 17-21, 39-45, 58-73, 86-101, 114-141, 156-200, 231-235`；
  `.gitignore:29-45, 60-63`；`scripts/test-scan-secrets.sh:60-136`。

## 八、可观测性与降频：省一次要按下游计价

- **口径**：任何「节省」（降频、缓存、跳过一轮扫描、复用上一份读数）的代价不是这次省下的账面值，
  而是**它可能漏掉的那次状态转移的下游成本**。评审降频/缓存/采样类改动时，**必须回答
  「漏一次的代价是什么」**。
- **实例**：滞回、会话定位缓存（**只缓存定位不缓存信号**，TTL 要**错开** 2s 采样节律——
  3s 会与「每 2 拍一次」打拍，等于一半的拍仍在付遍历成本）、扫描宽限、明细保留折入。
- **反例（正确形状）**：`-shm` 那类噪声不是「省一次」，而是**判定本身错了**——
  两者的修法不同，不要混。
- **代价写法**：`detail retention` 折入（折成合计而非丢弃）保住累计口径；
  若真按窗口丢弃，症状是**累计静默变小而界面上毫无痕迹**。
- **证据**：`CONTEXT.md`「省一次要按下游计价」「会话定位缓存」「明细保留窗口」；
  [ADR 0007](../adr/0007-token-detail-retention-folds-not-drops.md)。

## 九、性能与资源（含「测量方法本身是坑」）

表中 round-07、round-23–26、round-05、round-35 均为 Swift 主线时期记录；NSLock、10s TTL、512 项清理等是当时实现，不是当前 Rust 必须照搬的参数。迁移复查应按当前调用链与同输入测量确认。

| 坑 | 现象 / 根因 | 规则 | 证据 |
| :--- | :--- | :--- | :--- |

| 每拍 ~500 次 `proc_pidinfo` | 逐 pid 取 ppid | 合并为单次 `sysctl(KERN_PROC_ALL)`（实测 2.4µs），加缓冲重试 | round-23-26 R25 |

| 资源采样归属误判 | 已退出的僵尸 PID 被反复计为「归属未知」 | 只排除**明确**的僵尸条目；枚举格式异常返回结构化失败（不静默漏过、不输出原始进程文本）；旧样本不回填 | `CHANGELOG.md` v0.0.303 |

## 十、UI、可访问性与几何

### 10.1 落在窗口矩形内 ≠ 落在造型内

- **现象**：右侧停靠时正文上下内缩 10pt，按**矩形边界**写的布局测试全绿，
  用户截图才暴露内容被裁。
- **规则**：加进布局测试一条「用真实视图量测 + 检查正文下沿是否在 CGPath 内」的检查；
  卡片外壳留安全留白、高度与列表剩余空间同步。
- **证据**：`docs/validation/2026-09-10-token-clipping.md`。

### 10.2 浮层/窗口类名不能靠猜

- **现象**：猜的浮层类名漏了 `MenuBarExtraWindow`，注释里的时序模型也写反（首轮验收 FAIL）；
  `NSStatusBarWindow` 只是状态栏宿主、frame 可能大于实际图标，被当交互浮层 ⇒
  自动收起复核被持续取消（「不能自动收起」）。
- **规则**：**活体枚举实证**（`_NSPopoverWindow` / `MenuBarExtraWindow` / `NSStatusBarWindow`）；
  状态栏宿主**显式排除**；面板层只提供 AppKit 窗口状态。
- **证据**：`docs/validation/2026-09-12-round-09-popover-conflict.md`、
  `2026-09-15-round-43-four-edge-dock.md`；[ADR 0003](../adr/0003-draggable-snap-dock-and-sliver.md) 修订。

### 10.3 热区无上界 → 在菜单栏内振荡

- **现象**：展开热区 y 无上界 ⇒ 菜单栏内整条 x 跨度反复「展开→收起」。
- **规则**：热区必须有上下界；同类陷阱还有「细条判定误用整卡 frame」（恒 no-op）
  与「唤醒通知挂错 center」（死代码）——这些都要**活体定位**，读代码看不出来。
- **证据**：`docs/validation/2026-09-12-round-11-panel-state-machine.md`、`2026-09-12-round-23-26-ui-details.md`。

### 10.4 单行竞争宽度 → 标题接近零宽

- **现象**：稳定身份 + 长度不可控的动作名 + 计数 + 固定按钮挤一行 ⇒
  视觉上只看到 `Antigravity · 查看: DeckSc...`（而 AX 树里有全文）。
- **规则**：双层层级（第一行身份/状态，设最低可读宽度，例如 96pt；第二行动作）+
  统一中间省略、help 与 VoiceOver 标签。
- **证据**：`docs/validation/2026-09-15-round-40-title-readability.md`。

### 10.5 可访问性与对比度不能靠感觉

- **现象**：起初想用 `.contain` 合并行 —— 那会让点击主路径对 VoiceOver **不可达**；
  徽标双值动态色需按底色混合**实算** WCAG（thinking 5.79:1、toolCall 4.54:1）。
- **规则**：行按钮 + 内嵌按钮显式 label（显式 label 覆盖合并内容）；对比度实算，
  不靠肉眼；`<9pt` 字号统一这类改动依赖可视化验收，不以代码层论证替代。
- **证据**：`docs/validation/2026-09-12-round-14-accessibility.md`、`2026-09-12-round-12-theme-deadcode.md`。

### 10.6 字号/几何类结论必须先看清再改

- **现象**：截图里工作台左栏看着是空的，两种可能（空态没进 DOM = bug；太暗 = 观感）**修法完全不同**。
  直接问 DOM：元素在、52px 高、文案正确 ⇒ **不是缺陷**，是截图看不清。
- **规则**：**不猜着改 CSS**；先把观察变成**可证伪的判据**（该形态下必须有空态文案 + 打印量测值）。
  另记：判据写宽与写错结论一样，都是在造噪音（三个窗口一起判失败，而只有工作台有监控栏）；
  第一版把高亮项快照放在点击循环**之后**，观察不到启动落点，短路掉照样报「生效」。
- **证据**：`CHANGELOG.md` v0.0.257、v0.0.264。

## 十一、文档与口径漂移

### 11.1 过期状态声明比全错更坑

- **现象**：三处「尚未迁」实为过期（`SessionProbeFailure` 有 39 处引用、三个窗口俱在）；
  第三处**半对半错**——「没有这两个档案」已过期，但「JSONL token 用量读不到」**仍然成立**。
- **规则**：**半对半错的文档比全错的更坑**——整句标成「已完成」会把仍然缺的那半一起盖住。
  只改错的那半，并在原文旁写明核实方式。README 里的已知限制必须**逐条对着代码核实**再留着。
- **证据**：`CHANGELOG.md` v0.0.262；`AGENTS.md` README 一节。

### 11.2 入口文档说错形态，传播速度比 bug 快

- **现象**：`docs/workbench/README.md`（改造入口文档）写着「Rust 端是 island + sidebar 双形态」，
  而第三个形态（工作台）早已落地；根 README 同一份文档前后也不一致。
- **规则**：入口文档的「当前状态」句必须改对，历史计划文字**保留原样但标注**
  「其余字样是当时的计划记录，当前以本节与根 README 为准」。
- **证据**：`CHANGELOG.md` v0.0.254。

### 11.3 注释描述的失效模式必须真的会发生

- **现象**：review 报告里「注释写的失效面压根不发生」被判为**第三次踩同一类**；
  另一处注释声称「编号列前插一列会指错列」——拿原码跑同一变异，它**先红在定位条件**，
  报的是正确那句（因为定位条件本身已把「编号必须在第一列」写进约定）。
- **规则**：注释里的因果与失效面要**实测**；发现不成立就改写正文，不照抄。
  文档与注释都要能自证（本轮把定位改成认列名之后，那句注释第一次成真）。
- **证据**：`docs/code-review/2026-09-24-1752-v0.0.130-fallback-subagent.md`、
  `2026-09-24-1335-v0.0.129-fallback-subagent.md`、`CHANGELOG.md` v0.0.129。

### 11.4 声明必须真是那份定义（放行不能靠位置）

- **现象**：「待核实清单」的守卫一度是**一把不校验内容的万能钥匙**——
  任意一段带状态词与判定说法的正文包进声明块就全绿；两份文档里 272/292 行删掉也不响。
  触发条件还只有一个出口 `contains("待核实")`，而**那恰好是清单的列名**——
  把列名改成「未决项」整份文档静默进 skipped。
- **规则**：① 放行靠**声明**（白名单标签）而不是位置，且声明本身要被审（必须逐字给出定义、
  不许空块、≤N 行）；② 触发条件是多个出口的**并集**；③ **否定陈述不算欠项**——
  「本文档暂无待核实项」判红的话，最省事的修法恰是把触发词删掉，那才是让守卫永久失效的动作。
  **激励方向必须对着判据。**
- **证据**：`CHANGELOG.md` v0.0.128、v0.0.129。

### 11.5 审查者不一定对

- **现象**：审查者说 `|**V4** |`（编号格少一个空格）会静默漏网，实测是**绿而且应该绿**
  （合法 markdown，单元格内容仍是粗体 `V4`）；review 还推翻过作者两处自述。
- **规则**：**不采纳要写理由**，记在 review 报告的「不采纳及理由」里；
  报告是**时间点证据**，不改写已提交的报告。
- **证据**：`CHANGELOG.md` v0.0.128、v0.0.129。

### 11.6 多会话共享工作树的纪律

- **现象**：v0.0.130 的 tag 与 release 是**同仓库另一个会话**推的，而 `release.sh` 当时用
  `git add -u` 暂存 ⇒ 另一个会话未提交的一部分修复跟着进了那版，代价是分两版发。
  另一次：原地做变异 + `restore()` 等于**拿自己的快照盖掉另一个会话的未提交工作**。
- **规则**：变异与实验在**仓库副本**里跑（`rsync` 排除 `.build`/`dist`/`.git`，
  且副本目录名**含项目名**——否则那条按 cwd 判的断言会凭空红一条）；
  只暂存本任务明确修改的文件。本仓当前形态：`release.sh` 要求
  `RELEASE_FILES_FILE` 显式列出本轮文件（含删除），**拒绝自动收取工作区改动**。
- **证据**：`CHANGELOG.md` v0.0.131；`scripts/release.sh:59-60`。

### 11.7 假保证待在 dist 里比没有回退物更糟

- **现象**：`dist/AgentIsland-Swift.app` 是几天前的产物，而 `SKIP_SWIFT=1` 既不刷新它、也不提它——
  任何人打开都会以为「随时可以退回去」。
- **规则**：`build-app.sh` 显式提示「它**不是**当前源码构建出来的，拿它回退等于回到几天前的行为」。
  「一个不留退路的切换不是切换，是砸东西」，但**过期、没人提醒的回退产物比没有更糟**。
- **证据**：`CHANGELOG.md` v0.0.261、v0.0.233。

## 十二、验收与证据（当前阶段最活跃的一族）

### 12.1 静态审查 ≠ 原生验收；暖重放 ≠ 最终门禁

- **现象**：首轮完整发版的 native 回执 `passed=false`（CLI 门禁退出 2），
  而**原输出未区分失败阶段** ⇒ 无法认定为应用缺陷或环境原因。
  同一脚本与同一签名二进制**原样暖重放通过**，随后冷启动前缀连续重放 5 次全通过。
- **规则**：① 失败时记录**固定阶段与异常类型**（便于定位），但**不改变断言、超时、顺序、
  退出码、重试或清理**；② 5 次未复现**不足以**认定偶发问题已修复；
  ③ **暖重放或多次诊断不能替代最终验收**——首次失败根因未定时如实写明。
- **证据**：`docs/code-review/2026-10-13-1930-v0.0.322-codex-gate-diagnostics.md`。

### 12.2 「不宣称完成」是一种交付物

- **做法**：每轮 review 都显式列出**仍开放**项（实际跨原生窗口失效、完整 macOS/M0–M4、
  历史接口归属/预算、服务账单、真实负载资源验收），并写明
  「本报告核实最终候选，**不宣称**提交、tag 或 Release 已发生」。
  保留 `feature_acceptance_passed=false` 原字段，不伪称驱动自动判定；
  主审视觉核对与不变量通过就明说是**主审结论**。
- **规则**：`PASS` 要么来自驱动回执，要么明说是主审核对；两者不混写。
  「代码接上了、数据没通」这类**只见于跨进程的断点**要单列（例如 CLI 侧读不到自报，
  因为自报记录活在 App 进程的引擎里）。
- **证据**：`docs/code-review/2026-10-13-1900-v0.0.322-codex-final.md`、
  `2026-10-12-2140-v0.0.322-codex-independent.md`；`CHANGELOG.md` v0.0.134（「代码接上了，数据没通」）。

### 12.3 清理失败不能被「协议完成」掩盖

- **做法**：资源长测的清理**逐项验证**（自有应用、保持唤醒进程、独占锁、配置/任务基线），
  任何一项失败即非零退出；分析器**拒绝失败或残缺的清理回执**；
  旧回执仍可验证采样协议，但明确**没有**清理证明。
- **规则**：不按进程名杀应用（精确路径与启动身份保护）；已有应用或租约阻止开始；
  没有资源预算或平台整体完成声明。
- **证据**：`CHANGELOG.md` v0.0.323；`scripts/resource-soak.py` / `test-resource-soak.py`。

### 12.4 「仍是红的就让它红」优于造一个假绿灯

- **做法**：CI 里 Windows job **跑真测试**而不是只 `cargo check`；
  「为了让徽章变绿而只留编译检查，等于造一个假的保证」。Swift 测试需要 Xcode，
  runner 镜像不保证一致 ⇒ **宁可少一条，也不写一行假装它跑过**。
- **证据**：`CHANGELOG.md` v0.0.267。

### 12.5 前台动作数为 0 也要证明

- **做法**：原生专项验收核对读回不变量（`inspection_invariants_passed`、
  `baseline_unchanged`、请求数与目标地址、`host_foreground_actions=0`），
  并保留 cleanup 的 hash/bytes/mtime/inode 不变证据。
- **规则**：「没动过」是**要被证明**的，不是默认的；请求数与地址要核对，而不是只信「发过一次」。
- **证据**：`docs/code-review/2026-10-13-1900-v0.0.322-codex-final.md`。

## 十三、近期业务改造中需要保住的契约（v281～322）

### 13.1 不同用量来源不能共用 input−cache 公式

Claude/OpenCode/MiniMax 的 input 已排除缓存读取，再扣一次会少算；Codex 等 inclusive 输入才需要扣。v288 同时修正 TTL 缓存创建分项、内容块与流式修订的重复记录；ZCode 后来改为 canonical message SQLite 账本优先于 rollout 镜像，两者不相加。v323 工作树另补重叠声明根的跨路径去重，避免主报告与上一周期出现不同数字。

**长期规则**：净消耗、缓存创建/读取、响应去重、费用估算按来源契约建立对拍；当前配置、请求模型、响应模型和真实账单分开。数据源缺失不能用零补齐。

证据：[v288 调研](../research/2026-10-02-vibe-usage-token-contracts.md)、[v289 ZCode 审查](../code-review/2026-10-06-1949-v0.0.289-zcode.md)、[当前用量口径](../../CONTEXT.md)、CHANGELOG v288、v306、v323（工作树）。

### 13.2 进程名、PID 存活和工具名出现在参数里，都不等于身份正确

v281 的 Codex 日期目录曾被扫描深度挡住，首拍 CPU 被伪报为已测；v283 补宿主 CLI 命令行后，v312 又发现 Python/Node 内联正文、提示词和普通参数里的工具名会被认成在线 Agent。同 PID 还可能 exec 成另一程序，读取库缓存的旧名字会延续错误身份。

**长期规则**：保留 argv 边界，识别可执行文件/运行时真实入口，不全文搜工具名；每拍刷新身份，CPU 差分保持独立。档案识别、会话目录覆盖和资源测量目标都要用正反例核对。

证据：[v312 Codex 审查](../code-review/2026-10-10-1501-v0.0.312-codex.md)、[v281 审查](../code-review/2026-10-01-1049-v0.0.281-codex.md)、CHANGELOG v281、v283、v312。

### 13.3 销毁 WebView 不等于底层原生窗口已释放

v294 原生验收定位到 Tao macOS 创建窗口重复 retain 已拥有指针、视图与委托销毁遗漏父类清理。仅隐藏/销毁工作台或缩短回收延时不能处理底层所有权缺陷；补丁最终固定在仓库 vendor 源码，而非临时改本机 Cargo 缓存。

**长期规则**：资源结论核对原生对象生命周期及连续创建/回收；优化不能撤掉草稿保护换取更早销毁。共享、静态和私有内存分别取证。

证据：[v294 Codex 审查](../code-review/2026-10-08-0908-v0.0.294-codex.md)、CHANGELOG v294；[vendor 说明](../../vendor/README.md)。

### 13.4 窗口操作成功需要逐步读回，历史只说明当时结果

v296 真实 VS Code 右半屏窗口先放大再移回时，尺寸受工具限制，撤销只恢复位置；后续加入先收缩、移动再扩展、有界读回与完整临时计划，覆盖同尺寸互换。v305 又发现 JSON 浮点读回一位差异把实际成功误判成意图改变。

**长期规则**：核对原生身份、屏幕坐标、每步实际几何和最终读回，不在等待时反复写入；浮点往返问题不能靠放宽意图比较掩盖外部改动。持久历史不等于当前窗口身份，重启恢复需重新选窗与预览。

证据：[v296 审查](../code-review/2026-10-08-1549-v0.0.296-codex.md)、[v305 审查](../code-review/2026-10-09-1600-v0.0.305-codex.md)、[ADR 0037](../adr/0037-window-operation-history.md)、CHANGELOG v296、v298–299、v305。

### 13.5 焦点恢复错一格，就可能把导航变成配置写入

v304 快捷导航在配置预览期间错误恢复焦点，把取消转成确认，紧接回车可触发写入。v308 还修正迟到结果抢走已转移的焦点；v313～314 区分干净详情与已修改草稿，避免旧表单借新 revision 保存或控件有焦点就永久冻结来源更新。

**长期规则**：确认期间守住导航、取消和背景 inert；异步回执属于发起时目标，不借用户当前页面或新版本。保存失败保留输入，后台刷新按任务/表单身份恢复焦点、选区与滚动。

证据：[v304 审查](../code-review/2026-10-09-1002-v0.0.304-codex.md)、[v308 审查](../code-review/2026-10-09-2125-v0.0.308-codex.md)、[v313 审查](../code-review/2026-10-10-1651-v0.0.313-codex.md)、CHANGELOG v304、v308、v313～314。

### 13.6 正文不能跟着页面缓存、动画副本或迟到请求留下

v317 发现离开任务页后来源正文可能仍随页面缓存和退场副本保留，快速离开再回来也会被旧请求回填。v316 独立 Standards 审查还发现 `get("isSecret").or_else(...)` 让一个 false 遮蔽另一别名的 true/null。

**长期规则**：正文按需读，只保存版本引用；离页先清正文再生成缓存/副本，失效请求不可回填。文档、message、内容块的各隐私字段独立核对，已出现且非明确 false 的值拒绝正文。

证据：[v316 Standards 审查](../code-review/2026-10-11-0116-v0.0.316-standards.md)、[v317 审查](../code-review/2026-10-11-2044-v0.0.317-code-review.md)、[ADR 0029](../adr/0029-source-artifact-content.md)、[ADR 0030](../adr/0030-claude-attention-artifacts.md)。

### 13.7 拒绝 ACK、计数增量与转录可读，不能拼成采集成功

v318 发布文字曾将无正文投递解释为私密拒收，并用计数、身份条目与普通转录读取支持连续采集通过。v319 更正：缺失/空白 plan 在解析阶段是 Invalid，不能推成 Private；拒绝 ACK、放宽的 `private_bodyless` 回执和转录正文不证明临时缓存存在。事件日志被覆盖、截图无独立运行身份与哈希时，也不能拼成精确身份和 180 秒时序通过；沙箱写入例外须如实记录。

v320 则修了另一条真实时序问题：官方客户端可能先调用钩子、稍后首次落盘。只对可信来源 ENOENT 在原交换期限内有界等待，父目录替换立即拒绝；这项修复不关闭其他官方客户端和平台验收缺口。

**长期规则**：先核对协议的成功/拒绝语义，再选择证据；保留原失败与更正。就绪等待只覆盖已核实的短暂竞态，不放宽来源身份、隐私或授权边界。

证据：[v319 审查](../code-review/2026-10-12-1101-v0.0.319-codex.md)、[v320 审查](../code-review/2026-10-12-1750-v0.0.320-codex.md)、[方案采集实施记录](../workbench/implementation/13-claude-plan-capture.md)、CHANGELOG v318 更正块及 v319～320。

### 13.8 普通网络失败与目标失效，需要不同缓存行为

v322 独立 Codex 审查复现：服务模型第一次成功后，另一窗口修改/删除档位，后端拒绝旧目标，但前端把它当普通错误继续保留旧模型及可选择按钮。改为受控 `target_invalidated` 错误后清除结果；瞬态网络失败仍保留带时间的上次成功。另一个 P2 是配置模型名匹配让无关服务模型行全部保留，原夹具只测远端模型，没覆盖名称交叠。

**长期规则**：缓存绑定完整目标与代次；失效和暂时失败分型。搜索与身份规则用交叠、变更、删除重建、晚到响应等反例验证，不仅测各自独立成功。

证据：[v322 独立 Codex 审查](../code-review/2026-10-12-2140-v0.0.322-codex-independent.md)、[ADR 0038](../adr/0038-manual-interface-model-read.md)。

### 13.9 配置保存、存在目录与客户端已加载是三个状态

MCP、Skills、提示词管理容易把「写入完成」当「能力生效」。Codex 用户级 `AGENTS.override.md` 非空时优先于 `AGENTS.md`；未核实启动目录、专属 frontmatter、项目/插件作用域都不能自动补推成支持。完整包复制也不能只复制 SKILL.md 丢掉资源及用户执行位。

**长期规则**：沿目标工具官方契约逐层核对读取、预览、写入、备份、恢复与新会话加载；未知格式保留只读。原生受控客户端验证与日常账号能力分别报告。

证据：[ADR 0025](../adr/0025-native-mcp-configuration.md)、[ADR 0027](../adr/0027-user-skill-activation.md)、[ADR 0034](../adr/0034-native-prompts-and-user-instructions.md)、[ADR 0036](../adr/0036-local-skill-package-publication.md)、CHANGELOG v293、v295。

### 11.2 跨进程去重（dedup.rs + dedup_tests.rs，9 项）

重启后重复打扰的修复。关键实现事实：

- **身份是 SHA-256 摘要，不是原文。** `identity(agent, kind, raw)` 用长度前缀分隔三段

  仅常驻 GUI 在 `main.rs:4358` 调 `enable_dedup_persistence`。CLI、`--memory-core-probe`、
  `--selftest`、demo、隔离实例都不启用。**只读消费者不会消费通知身份或写共享历史。**
- **schema 从 1 升到 2，旧版拒读。** 版本 1 存的是未验证的原始字符串，不能按哈希身份解释；
  读失败保留原文件并**永久禁用该实例的写入**（`disk.blocked`），监控退化为内存去重继续运行。
- **写前写后双重 revision 校验**（内容摘要 + mtime + Unix dev/ino），已有文件另加
  `try_lock` 非阻塞写锁；absent 走 `atomic_create_validated` 独占创建。发现外部变更即
  停止写入，不做合并——本项目当前只有一个写者（常驻 GUI）。

接入点（`engine.rs`）：`:622` `!dedup.attention_seen(&key, &fp)`、
`:634` `note_attention` + `:635` persist；`:659` `!dedup.completion_seen(&key, &fp)`、
`:684` `note_completion` + `:685` persist。**旧的 `alerted_fingerprints` HashSet 与
`last_completed_fp` HashMap 已删除**，由同一个有界 Store 统一承担。

**短完成不落盘**（`engine.rs:659-672`）：`seconds < MIN_TASK_SECONDS(3.5)` 时既不推事件
也不 `note_completion`，直接返回。否则"保存成功后、入队前进程退出"会永久抑制一条
从未送达的事件。

### 11.3 已知限制（未修，如实记录）

1. **重启测试是同进程二次装载**，不是跨 OS 进程重启（`state_tests.rs` 用临时文件 +
   `Store::open_at` 重新读）。覆盖了"落盘→读回→新引擎"链路，但没验两个真实进程。
2. **`disk.blocked` 后不可恢复**，且当前用 `eprintln!` 报告——GUI 由 LaunchServices 启动时
   stderr 不进 `agentisland-tauri.log`，"持久化已放弃"这个退化在取证链上不可见。
3. **不遵锁的外部写者**在 revision 校验到 rename 之间仍有极短竞态；现有机制是
   stale 检测，不是跨任意外部写者的文件系统 CAS。
4. **Windows 运行行为未验**（`try_lock`、`O_NOFOLLOW` 路径）。

# ⚠️ 已撤回：灵动岛窗口「从来没被缩到窄条」是测量错误

> **本文的结论是错的**，v0.0.256 撤回。保留正文作为时间点证据，
> 并在这里写清错在哪、以及正确的验法。

## 当时声称的结论

> `place_island` 的 `set_size` / `set_position` 都返回 `Ok`，
> 而窗口几何**一像素没动**（保持配置尺寸 372×520、摆在屏幕中部）。
> 这是「界面空白」的**第二个、与死锁无关的原因**。

## 错在哪

我把两个 Tauri 访问器当成了**权威几何**：

```rust
window.outer_size()       // 报的是【配置值】，不是真实窗口
window.outer_position()   // 同上
```

它们在这个应用里**恒等于 `tauri.conf.json` 里写的值、且从不变化**——
窗口真的被缩到 18×132 并贴到右沿之后，它们依然报 372×520 与 (1098, 216)。

**正确的验法是截图**，不是访问器：

```sh
# 放置计算会给出目标位置：place_island 内部请求 18×132、算得 (1452, 329.5)
# 屏幕 1470 点宽 ⇒ 1452 + 18 = 1470，正贴右沿。去看那一小块：
screencapture -x -o -R 1420,300,50,200 sliver.png
```

拍到的是**深色竖条药丸 + 绿色边框**，位置与算出来的 `x=1452` 吻合、尺寸 18×132 也对得上。

**对照实验**（决定性）：杀掉进程再拍同一块，那块药丸**消失**（只剩背景）；
两张图的 MD5 不同 ⇒ 那个元素确实是本应用的。

⇒ **岛窗口一直是对的、可见的。** 自 v0.0.242 起应用就是好的。

## 教训

1. **「权威」是要证的，不是名字给的。** `outer_size()` 听着权威，
   但它在这个项目里恒等于配置值——与 JS 侧的 `outerWidth` / `screenX`
   报 0、报默认值是**同一类问题**：配置类/宿主类访问器在 Tauri + WKWebView
   这条路上不可信，**没有任何测试会告诉你这件事**。
2. **同一个应用里已经出现过一次同样的错**（JS 侧窗口几何报 `y=956, w=0`），
   我当时识破了并写下「拿不可靠的观测面下结论会踩空」——
   然后**转头在 Rust 侧踩了同一个坑**。写下来的教训没有在自己身上生效。
3. **结论要能承受对照实验。** 「窗口没缩」这个结论只要做一次
   「杀掉进程再拍同一块」就能推翻；我没做，就发版了。

## 因此作废的排除表

原文据「访问器显示窗口没动」而排除的这些，**结论全部作废**：

| 当时声称 | 实际 |
| :--- | :--- |
| `resizable: false` 挡住 `set_size` | 改 `true` 后访问器仍报旧值——**因为它本来就不反映真实窗口** |
| `transparent: true` 同上 | 同上 |
| 「窗口保持 372×520 摆在中���」 | **假的**，那是配置值 |

`generate_context!()` 是编译期嵌入配置的。

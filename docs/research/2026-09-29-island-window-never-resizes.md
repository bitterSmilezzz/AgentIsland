# 灵动岛窗口压根没有被缩到窄条（死锁之外的第二个原因）

> 2026-09-29。v0.0.242 修掉死锁之后界面**内容**确实渲染了，
> 但**窗口**从来没落到窄条尺寸——于是从外面看仍然「什么都没有」。

## 现象

页面在渲染（`rootHtmlLen` 非零、零未捕获错误、冒烟点得动每一页），
可岛在屏幕上表现为「没有东西」。差别在**窗口**这一层。

## 硬证据

在 `place_island` 内部量前后：

```text
[place] 请求 18×132 算得 (1452,329.5)；改之前 Ok(PhysicalSize { width: 744, height: 1040 })
[place] 改之后 Ok(PhysicalSize { width: 744, height: 1040 }) / Ok(PhysicalPosition { x: 1098, y: 216 })
```

对照 1.2 秒后的权威落位（Rust 侧 `outer_size` / `outer_position`）：

```text
[boot] 落位 island：pos=(1098,216) size=(744,1040) visible=true
```

**三件事同时成立：**

1. **放置算得对**：请求 18×132，算得 `(1452, 329.5)`——`1452 + 18 = 1470`，
   正好是屏幕宽度。贴右边沿，完全正确。
2. **`set_size` 与 `set_position` 都返回 `Ok`**，而窗口几何**一像素没动**。
3. 窗口保持**配置尺寸** 372×520 逻辑，摆在屏幕**中部**（x=549 逻辑），
   而形态是 `edge-right`（该在右沿）。

于是最终画面是：**一个 372×520 的透明窗口摆在屏幕中间，里面只有一条 18×132 的窄条**。
从用户角度看，这与「什么都没有」**完全无法区分**。

## 已排除

| 假设 | 实测 | 结论 |
| :--- | :--- | :--- |
| 放置计算写错 | 算得 `(1452, 329.5)`，贴边正确 | ❌ |
| `resizable: false` 挡住 `set_size` | 改成 `true` 重建后**仍然无效** | ❌ |
| JS 没调 / 调用失败 | `[webview] island boot：place_island 已返回` | ❌ |
| 窗口不可见 | `[boot] 落位 … visible=true` | ❌ |
| 主线程被占 | `eval_with_callback` 回调照常返回（它也走主线程派发） | ❌ |

⚠️ `resizable` 那一次实验**第一遍是无效的**：改完 `tauri.conf.json` 后只重建了发布包，
跑的却是 debug 二进制——而 `tauri::generate_context!()` 是在**编译期**把配置嵌进去的，
debug 里还是旧的。重建 debug 后重跑才得出「不是它」这个结论。
**配置类的实验必须确认被测二进制真的重编过。**

## 还没查的

- `transparent: true` + `macOSPrivateApi`：wry 的私有 API 路径可能给窗口套了容器视图，
  改 frame 不往下传。**这是推断，未实测。**
- 同一现象在 `sidebar` / `workbench` 上是否存在——它们是 `visible: false`，
  几何照样可读，但**本轮没有逐个查**。

## 为什么值得单独记

死锁（v0.0.242）与本条是**两个互不相干的原因**，而症状一模一样。
修掉前者之后，冒烟能证明「内容在渲染」，却**证明不了「窗口在正确的位置与尺寸」**——
后者是冒烟在原理上够不到的层（本该由人眼看，而本机每扇窗都盖在它上面）。
两件事凑在一起，才让「界面空白」这个症状一直没有被彻底关掉。

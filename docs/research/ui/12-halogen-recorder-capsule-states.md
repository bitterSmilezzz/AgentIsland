# Halogen：一个常驻悬浮录屏小部件的四种形态（同一条胶囊的伸缩）

> 目的：sasha birukoff（[@sashabirukoff](https://x.com/sashabirukoff)）2026-09-25 发的
> "Halogen case study otw"，视频 11.5 秒、1080×1080、30fps、344 帧，**是动效视频（非静态稿）**。
> 对 AgentIsland 的价值极高：**它演示的正是我们 `shell_mode` 要做的事——
> 同一个常驻小部件，在 idle / 可选 / 工作中 / 收起四个形态之间切换，
> 而四个形态共用同一个容器、同一条呼吸点、同一套边框。**

素材文件：`.scratch/ui-material/11-halogen.mp4`（不入库）。

## 一句话结论

**它不是四个控件，是一个控件的四种高度。** idle 时是一枚只有图标点的竖胶囊；
展开是两个可选动作（Record / Screenshot）；录制中塌缩成**单行计时胶囊**；
收回后又回到 ididle。整段切换里，**图标（点阵）与边框从头到尾是同一份东西**，
变的只有容器高度、行数与显隐。

## 它是什么

黑底（纯黑背景）上的一枚悬浮小部件，四态：

| 态 | 外观 | 内容 |
|---|---|---|
| **idle（闭合）** | 竖长全圆角胶囊，细浅灰描边，**无文字** | 上下两个点阵图标：红点阵圆（Record 在上）、白点阵方框（Screenshot 在下） |
| **expanded（可选）** | 展开为横向两行，每行整宽大圆角条，行间仅极弱分隔 | 上行：红点阵圆 + 白字 `Record`；下行：白点阵方框 + 白字 `Screenshot` |
| **recording（工作中）** | **单行计时胶囊**（最矮） | 左：红点阵图标；右：计时 `00:00` → `00:01` → … |
| **recording + menu（工作中展开）** | 视频中段出现过三行菜单态 | `Restart`（白点阵）、`Delete`（灰点阵）+ 计时 |
| **回落** | 直接回到 idle 闭合竖胶囊 | 同 idle |

注意视频的时间轴顺序：idle → 展开两选项 → 开始录制（计时 00:00）→
**塌缩成单行计时胶囊**（多行菜单淡出）→ 计时进行 → 回到 idle。

## 手法一：四种形态共用同一份「身份」

这是全片最值得抄的一点。红点阵圆（Record）与白点阵方框（Screenshot）
这两个图标在**四种形态里都以同样的点阵风格、同样的尺寸、同样的颜色出现**：

- idle：上下排列，无文字
- expanded：与文字同行
- recording：只剩红点阵（Record 的），白点阵（Screenshot）**整个消失**
- 回到 idle：两个都回来

也就是说，**`Screenshot` 在录制中不是"变灰"或"禁用"，是直接不在场。**
而我们今天更常见的做法是把不可用选项置灰——这会在常驻 UI 上长期留着一个
用户点不动的视觉元素。

> 对我们：灵动岛的「截图」或某个 agent 动作不可用时，可以考虑**让它不在场**，
> 而不是置灰。这条与案例库 05/06 篇 Farhan 的"收敛"是同向的，但更狠一层：
> 不是降低权重，是移除。

## 手法二：塌缩靠「行淡出」，不靠整体缩放

从三行菜单塌缩到单行计时胶囊的过程，逐帧读到的顺序是：

1. 起始：三行菜单（Restart 亮白 / Delete 灰）
2. 中间：出现 `…·` 省略号分隔，下方 `Restart` 整行**图标与文字一起变暗为灰**
3. 结果：多行全部消失，只剩单行胶囊 + 红点阵 + 计时；计时数字**只在塌缩完成后才出现**

**关键：计时数字 `00:00` 是在塌缩完成后才出现的，不是从展开态渐变过来的。**
多余的行是"逐行暗下去再消失"，而不是把整个容器做 scaleY 压缩。

这条对 SwiftUI 很直接：`withAnimation` + 条件渲染移除行，比
`scaleEffect` 整体缩放更干净，而且是**语义正确**的——消失的那些行本来就是不该存在的。

## 手法三：点阵图标是「低分辨率风格」，不是圆角实心图

两个图标都是**点阵/像素风**：由许多小圆点拼成，点与点之间有黑色缝隙。
红点阵圆是实心点阵圆，白点阵方框是**只有边缘亮的点阵方框**（中间露黑）。

这个选择在**黑底 + 细描边**的组合下是有理由的：点阵天然带"像素感"的边缘，
不需要抗锯齿就能在小尺寸下保持清晰；同时点与点之间的黑缝让图标**不会糊成一团**。
它也是一贯的视觉签名——四态里同一个图标不会因为尺寸变化而走样。

> 对我们：微细条/状态点若要缩小到 8–12pt，实心圆角图容易糊，
> 点阵是一个已经被验证的小尺寸方案（代价是要做点阵版位图，不能用 SF Symbol 缩放）。

## 手法四：边框只做「细灰描边 + 大圆角」，起分隔作用的不是边框

整枚小部件只有**很细的浅灰描边**（约 1–2px）和**很大的圆角**。
展开成两行时，两行之间**没有 divider 线**，只靠极弱的间距分行。

也就是说：**它不靠边框表达边界，靠圆角 + 间距。**
对照 02 篇 Slingshot Lamp「把光挖出来而不是叠上去」、05/06 篇 Farhan
「选中态要扫到不要注意到」——这是第四条同向证据：**容器的边界应该由形状和留白决定，
不由线条决定。** 线条越少，越不需要考虑改主题时线条颜色怎么调。

## 手法五：时间显示与图标的颜色关系

计时数字 `00:00` / `00:02` / `00:03` 是**白色文字**，不是红色。
红色只留给红点阵图标（Record 的身份色）。

**计时本身不是告警，不用颜色强调；红色图标才是"这是录制"的信号。**
这条很细但值得记：常见的错误是把进行中的计时器做成红色/闪烁，好像"在跑"本身就是异常。

从抽帧读到的、本文引用的事实：

| 项 | 读到什么 |

| 态数 | 至少 5 种：闭合 / 两行展开 / 录制单行 / 三行菜单 / 回落闭合 |
| 图标 | 点阵风（`…·`点阵），红点阵圆 + 白点阵方框；点间有黑缝 |
| 边框 | 细浅灰描边约 1–2px，大圆角（胶囊）；两行间**无 divider** |

> 本文不推测这些。

## 可迁移的决策规则

1. **同一个常驻控件做成一种形态列表，而不是多个控件。** idle / 可选 / 工作中 / 收起
   共用容器、图标、边框——变的只有高度、行数、显隐。
2. **不可用的选项让它在场外，而不是置灰。** 常驻 UI 上长期放一个点不动的元素是负债。
3. **塌缩用行淡出，不用整体缩放。** 语义正确且不需要处理 scaleY 带来的内容变形。
4. **状态数字用中性色，身份色留给图标。** 计时是白字，红色只属于 Record 图标。
5. **容器边界靠圆角与留白，不靠 divider。** 线条越少，主题适配越省事。
6. **小尺寸图标用点阵。** 天然不糊、自带签名感；代价是要做点阵资产。

## 应用建议清单（与实现解耦，尚未排期）

1. **把 `shell_mode` 的两个壳重新理解成"一个控件的两种形态"**：
   灵动岛 = idle/收起态，侧边栏 = 展开态。这样切换逻辑从"两套 UI"变成
   "一个容器的两种高度"，与 `02-goals.md` 的双形态决策一致但实现口径更省。
   这是本篇对我们最有价值的一条，值得在 Phase 1 动手前过一遍。
2. **灵动岛「截图/某动作不可用」时考虑让元素不在场**，而非置灰。
   需先看 02 篇 Farhan 与 05/06 篇的收敛共识，确认不需要保留"可发现性"。
3. **微细条呼吸灯若缩到 <12pt，评估点阵版**：需先核实现状尺寸与位图资产，
   未核实前不动。
4. **壳的边框改为"细描边 + 大圆角"，去掉 divider**：需核实现状 CSS 是否需要 divider
   做分组分隔（信息密度高的侧边栏可能仍需要），做前先读 `sidebar.css` 现状。

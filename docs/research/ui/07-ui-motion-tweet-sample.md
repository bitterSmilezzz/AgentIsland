# 一周 UI 动效推文抽样：静止封面上能证明什么、不能证明什么

> 目的：2026-08-18 至 08-24 一周内，一批设计账号集中发布动效 demo。本文把 19 条推文当作**一次抽样**来读，
> 而不是逐条吹捧。核心问题是：**从一张静态封面，我们究竟能引用这个动效的什么？**
> 一手证据：19 条推文的元数据与原文（fxtwitter API 抓取）、10 张视频封面的逐张视觉分析、
> 20 张推文配图的视觉分析。全部抓取与分析于 2026-09-26 完成，方法见文末。

## 一句话结论

**这批推文里，胶囊（pill/stadium）形状占了 7/10，声音在 3 条推文里被显式提起，而"作者命名"与
"画面可证"经常不符——最典型的一条自称 gooey toggle，三次定向读图都确认该帧没有任何 metaball 特征。**
对本项目的实际结论：可迁移的是**静态规格**（形状、圆角、错位比例），不是手法；
手法只能从视频本身取，而视频我们拿不到逐帧。

### 关键判定一：命名是作者的，特征是画面的

`2090597932122677248` 推文自称 **gooey toggle**。gooey 的标准视觉证据是两个色块靠近时长出熔化般的"颈"再合成一滴，伴随边缘模糊。**三次定向读图都返回：只有一个连续形状、无 blur、无 neck、无 second blob。** 也就是说这一帧最多支持"圆角极大的胶囊开关 + 挖空滑块"这个基础形态，把它归为 gooey 是作者命名，不是画面可证的技术特征。

反过来，`1932179564471689216` 自称 liquid glass，而**这一帧的折射证据确实在场**——右侧深色弧带被玻璃拉扯弯折。这是 10 张里唯一"命名与特征对得上"的材质案例。

**这条规则对写文档的意义**：引用一个动效时，能引用的是画面能证的那部分；作者怎么叫它，是另一回事。本案例库前几篇都拿到源码或可复现实样，所以没有这个问题；这批只有封面，就必须把这条规则摆到明面上。

### 关键判定二：交互暗示高度依赖"光标入镜"

半数的封面把手型/箭头光标放进画面标示"这里可点"（kail 的指尖加载圈、Swami 的光标压在 `+`、Imran 的手指压在卡片上、arknow 的光标在开关下方）。**这条对 macOS 常驻 UI 不适用**——macOS 浮层不暴露光标改绘制，做示能只能靠视觉态（hover 高亮）本身。

## 20 张配图：五态配色在这批有 3 组独立证据

推文配图（photo 类型）20 张，分属 8 位作者。它们与视频封面不同——**这些图就是最终设计稿**，所以可引用的规格更实。分析方式同样是 OCR 取确切文字 + 语义读图取画面结构，色值均为读图估算（未做像素采样），快捷键组合等属推断并已标注。

### 本批最有参考价值的一组：@Griveau 的 Linear 组件（1288 赞，本批最高）

OCR 逐字确认（含置信度）：`Send to agent`(0.9981)、`4 files +232 -17`(0.918)、`Approved`(0.99998)、`High risk Codex-5.6 SOL`(0.993)。

三行水平排列、**胶囊形为唯一形状语言**的组件快照：

| 行 | 内容 |
|---|---|
| 一 | 7 个圆角图标按钮 + 1 个宽胶囊（缩放宽胶囊内 `+` `−` 夹一条细轨道，**实心白色圆形滑块**）：搜索、`</>`、图片、括号、对比度、复制、下载 |
| 二 | 左：**纸飞机 + `Send to agent` + 一条细分隔线 + 两个小图标**；右：**分支图标 + `4 files` + 绿 `+232` + 红 `-17`** |
| 三 | 左：**三个重叠真人头像 + `Approved` + 蓝紫对勾**；右：**靶心图标 + `High risk` + 两个更小次级标签 `Codex-5.6` / `SOL`** |

三条手法，画面直接支撑：

1. **用明度差代替阴影分层。** 深色下投影几乎不可见，作者改用「组件底比背景亮一档 + 1px 半透明白描边」。整组组件因此像**贴在**背景上，而不是散乱地**浮**着。
2. **彩色只编码状态，绝不装饰。** 绿 `+232`、红 `-17`、蓝紫对勾，三个颜色全部承载语义。
   → **本仓今天没有做到这条**：五态色是 `Theme.statusWorking` / `statusIdle` /
   `statusOffline`（Theme.swift:171–173）那套语义名，但彩色不止五态在用——
   `Theme.sydedockCyan` 有 64 处引用，用在详情页数据单元格（如「工作总耗时」）当数据色；
   `actionBlue` 31 处、`focusBlue` 9 处。所以这是**待判问题**（数据色要不要让位），
   不是已达成的事实。
3. **单胶囊内做多信息复合。** `Send to agent` 胶囊里装了图标 + 文字 + **分隔线** + 两个次级图标；`High risk` 里装了图标 + 主词 + 两个更小的次级词。**胶囊不是"圆角按钮"，是一个能塞分层信息的微型容器。**

第 3 条对常驻 UI 是决定性的：**灵动岛宽度极窄，只有"一胶囊多层信息"能塞进足够上下文。**

### 五态配色在三个独立来源上收敛

| 状态 | 本批证据 |
|---|---|
| 完成 / 通过 | **绿**（Linear 的 `+232` 与对勾） |
| 进行中 / 处理 | **蓝** |
| 危险 / 高风险 | **红**（`High risk`；byJWXN 的 Logout hover 整行染红） |
| 排队 / 禁用 | **灰** |
| 离线 | 本批无直接对应；分析建议用**更暗的灰或仅文字** |

### 选中态的正确做法：状态用颜色，选中用明度

Griveau（Linear）与 heysimplycraft（Nav）**都不用高饱和色做选中**，而是"比容器亮一档的圆角矩形 + 文字提亮"，把彩色配额全部留给状态编码。**这条直接修正了一个常见误区**——把选中态也涂成彩色，会让彩色失去语义。

### `N of M + Est. X mins` 比进度条更省空间

@lucadefreitash 的 File upload screens（4 帧）在三帧中重复使用这个形式；他的文件列表退回 **20–24px 圆角矩形**而非胶囊。

**推论：形状半径跟随信息密度**——标签/状态用 999px 胶囊，信息列表用普通圆角矩形。不是"全胶囊"更好，是看那一格塞了多少东西。

### 其余各组

- **@byJWXN 的 profile menu dropdown**（3 帧）：不是用户菜单，而是「任务快捷入口 + 用量进度 + 账户」三合一控制台。**Logout hover 时整行文字与图标变红**——把不可逆操作的危险做成即时可见的信号，而不是等弹确认框。三段式用量条比百分比文字更适合窄面板。
- **@abid_led_design 的 Components UI card**（4 张）：大数字 + 趋势徽章、堆叠通知卡、设置开关组、**唯一的黑色主按钮**。适配度同为高。
- **@omererdgan 的 empty state**（2 张）：居中四层结构（图标 → 标题 → 说明 → CTA），标题用**拟人化句式**（`Your notes are waiting for a first entry` 而非「暂无笔记」），且**刻意只用一枚几何图标而不是场景插画**。
- **@Iconlypro 的 Smart Home App**（3 张）：玻璃拟态明确**不建议搬**——常驻面板的性能与 HIG 双重不利。
- **@colmtuite 的 42 new icons**：**该图标集许可协议未核实，不可直接商用**（记录在案，用前必查）。

## 横向观察

### 1. 胶囊化是这批作者的共同默认，不是个人风格

10 张视频封面里 7 张主体轮廓是胶囊（胶囊导航、胶囊 loading、胶囊按钮 ×2、胶囊开关轨道、半透明胶囊、滑杆轨道两端全圆同源）。剩下的是圆钮组、squircle 网格、圆角卡片堆叠。

**推论**：胶囊在"小控件"尺度上已成默认答案。这与 [03 篇](03-libraries-dev-where-effects-belong.md) 的克制原则一致——胶囊不抢注意力、边界清楚、深浅色都成立。

### 2. 声音被反复带进视觉设计

3 条推文显式写声音（`more interactions, sound on`、`gooey toggle - sound on`、Albia 引用的液态玻璃演示），
其余几条虽未提，但 `Thinking...` 胶囊、铃铛这类组件在惯例上也开声。

**这对我们有直接意义**：AgentIsland 今天的声音策略是"按提醒分级"（README 有载），
而这批样本显示动效的验收标准本身包含声音。**本项目已有提示音，但"动效 + 声音"成对设计的意识缺位**——
目前没有任何一处按"这个动作要不要配一声"来设计。这与 [02 篇](02-slingshot-lamp-handwritten-pendulum.md)
Slingshot Lamp 的全部音效现场合成是同一个方向：声音是运动量的自然读数，不是装饰。

### 3. 两种材质语言几乎对半，且"glass"被用得比"折射"宽松得多

- **液态玻璃路线**（半透明 + 高光边 + 折射）：10 张里只有 1 张五项特征齐全。另有两张被描述为 glassy/frosted
  但**没有折射**——深度来自卡内 glow。
- **实心扁平路线**（实心、无渐变、无投影或仅 1px 抬升）：另 4 张。

**推论**：叫"glass"的大多没有折射。要谈 glass 就谈折射那一项，其余是"半透明 + 高光边"。

### 4. 深色样本几乎不用彩色，浅色样本敢放饱和色

深底的两张几乎只用中性灰阶（一张零彩色强调、一张只靠胶囊内渐变发光）；浅底样本敢放 iOS 蓝、azure。

**推论**：深色模式下的彩色要更谨慎。这与 `Theme.swift` 已有语义色不冲突，但是一条可核对的约束。

### 5. "亮环境包暗卡"是值得偷的一条

Imran 的 bento 与 Raul 的卡片组都用**浅色画布 + 深色/饱和卡片 + 白字**。
其中 `AI Usage / 84.5K Tokens`、`Team / 14 Members` 的结构与本机监控卡片**高度同构**。

### 6. 信息架构直接可抄的一处

Imran 的 2×2 bento：Workspace / Automation / AI Usage / Team，每卡"线性图标 + 标题 + 副标数值"。
这正好对应我们的"哪些 agent / 在干什么 / 花了多少 / 状态"。**可抄的是这个结构，不是渐变。**

## 可迁移的决策规则

1. **静态规格可抄，手法要另证。** 封面能给的：胶囊比例、24–28px 卡片圆角、五卡 5–6% 错位、thumb 白环、`+`/线稿图标。这些已被反复使用。**手法不能从一个静态帧引用。**
2. **别把"叫 gooey"当 gooey。** 眼见为实——颈部、接缝、模糊、第二个色块，一条都不在，就说它是胶囊开关。这条适用于任何别人的 demo。
3. **胶囊是小控件的默认起点**，但深色下别写死黑（改用 `Color.primary` 体系跟随系统）。
4. **无文字控件用双端图标定语义**（走/跑 = 慢/快），比带数字的滑杆省空间，含义自解释。
5. **无数字 badge 比有 badge 更安静**——常驻 UI 上，Swami 那枚铃铛容器外不放红点，是比"Always badge"更克制的选择。
6. **动效与声音成对设计**。本项目目前没有"这个动作要不要配一声"的设计环节。
7. **光标入镜式的示能在 macOS 上不可移植**，只能靠视觉态本身。
8. **彩色只编码状态，绝不装饰。** Linear 那组里绿/红/蓝紫三个颜色**全部**承载语义。推论很硬：**五态色是唯一允许出现的彩色，其余一律灰阶。**
9. **选中态用明度，不用彩色。** Linear 与 heysimplycraft 都不拿高饱和色做选中——把彩色配额留给状态编码，选中态靠"比容器亮一档 + 文字提亮"。
10. **深色下用明度差分层，别指望投影。** 「组件底比背景亮一档 + 1px 8% 白描边」比加阴影可靠，且整组看起来是**贴**而不是散乱地**浮**。
11. **胶囊是微型信息容器，不只是圆角按钮。** `Send to agent` 胶囊里用一条 1px 分隔线在内部重新分层。对宽度极窄的常驻浮层，这是唯一能塞进足够上下文的范式。
12. **形状半径跟随信息密度。** 标签/状态用 999px 胶囊，信息列表退回 20–24px 圆角矩形。不是"全胶囊"更好。
13. **危险操作的危险性要做成即时可见。** byJWXN 的 Logout hover 整行染红，而不是等弹确认框才告知。
14. **空状态用拟人化句式，且只放一枚图标。** `Your notes are waiting for a first entry` 而非「暂无笔记」；场景插画在"简单"这个宣称下是自我矛盾。
15. **第三方图标集用前必查许可。** @colmtuite 那 42 枚的协议本次未核实，已记录为不可直接商用。

## 应用建议清单（与实现解耦，尚未排期）

1. **`Thinking...` 胶囊是 attention 态最省的表达**：一条胶囊 + 一段横向流动的渐变 + 一段可注入文案。
   这是本批最直接可用的一条（@tranmautritam 那张）。深色底成立，浅色菜单栏下需按 `colorScheme` 换网格。
2. **中文案必须可注入**：原 demo 写死 `Thinking...`；我们的五态各有自己的措辞，不能写死。
3. **液态玻璃折射是 macOS 26 起唯一"背后总有真实内容可折射"的位置**——常驻浮层悬浮在桌面与其它窗口之上。
   优先用系统材质而非自绘 shader。**风险要记**：强折射在低对比背景下降低可读性，控件内文字不能被拉扯。
4. **别做 gooey/metaball**：SwiftUI 无原生能力，需 Metal/CAFilter 自绘，且本批样本连可证的 metaball 帧都没有。
   性价比最低的一条。
5. **bento 结构可借**：若将来做展开态的多指标视图，"图标 + 标题 + 副标数值"四宫格是现成的好结构。
6. **补"动效 + 声音"成对设计**：目前五态有各自颜色与措辞，但没有各自的声音语义。
7. **微细条/状态胶囊按 Linear 的三行结构重画一遍**（本批最高适配度）：图标操作行 + 统计标签行 + 状态标签行。
   动手前先解决彩色配额问题：`Theme.sydedockCyan`（64 处，详情页数据色）、`actionBlue`（31 处）、
   `focusBlue`（9 处）都不是五态色。若要让状态色成为唯一彩色，详情页需另找区分手段（明度/字重）。
8. **拖拽/危险操作（如终止 agent）的 hover 态整行染红**：与 byJWXN 的 Logout 同法，
   把不可逆操作的危险做成即时可见，而不是只在确认弹窗里说。
9. **`N of M + Est. X mins` 比进度条更省空间**：多 agent 并发时，"3/12 + Est. 4m"一行能表达的事，
   进度条要占三倍宽度。
10. **`offline` 建议用更暗的灰或仅文字**（本批无直接对应，是最弱的一条推论）：其余四态在三个独立来源上收敛为绿/蓝/红/灰。

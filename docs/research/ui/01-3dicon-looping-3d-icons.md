# 3dicon：一句话进，循环动画 3D 图标出（带真透明）

> 目的：在考虑「给 AgentIsland 做一套动画图标」之前，把 [samyost1/3dicon](https://github.com/samyost1/3dicon)
> 这条 pipeline 摸清——它是什么、解决什么、哪些判断可以直接搬、哪些今天不成立。
> 本文引用的 SKILL.md 原文、README 原文与版本号均为 2026-09-25 从上游仓库核实，不是推测。

## 一句话结论

**它不是动画库，是一个 Claude Code skill：一句话 prompt 进去，输出一个带真实 alpha 通道的循环动画 WebP 图标。**
对本项目最有价值的不是它生成的图标，而是它写死在 SKILL.md 里的**动效判断规则**——
尤其「物体静止时在干什么」四分类，与本文另两篇（Slingshot Lamp 的手写物理、libraries-dev 的按等待时长定效果）
构成三套互补的动效决策口径。

## 它到底是什么

| 维度 | 事实 |
|---|---|
| 形态 | Claude Code skill（`/3dicon`），不是 npm 包、不是组件 |
| 安装 | `/plugin marketplace add samyost1/3dicon` → `/plugin install 3dicon` |
| 依赖 | Python + `ffmpeg` on PATH + 一枚 OpenRouter key；首跑下载约 180MB matting 模型 |
| 产物 | 动画 WebP（真 alpha），可直接进 iOS / Android / Web / expo-image，**无需 Lottie 转换、不加 native 依赖** |
| 成本 | 静帧 13 美分；含动画的完整一轮 48 美分、约 4 分钟 |
| 许可 | MIT；生成的图标归使用者，无限制 |
| 数据 | GitHub 424 star（2026-09-25 实测） |

## Pipeline（四段，可中止）

```
prompt ──► still ──► animate ──► matte ──► encode ──► verify
          GPT Image   Seedance   去背景      WebP      逐帧测运动量
          (13c)       (约35c)                       (失败即非零退出)
```

`run` 只是 `still` 加上「停下来问人」。分段的理由是**每一段都是一个可以在花下一笔钱之前看一眼的地方**。

### 无缝循环的关键手法

**同一张静帧同时作为视频模型的首帧与尾帧。** 模型于是回到起始姿势，循环闭合处无缝。
上游明说这一点由 `kling.py` 在两个后端上代劳，**不要删掉它去改做交叉淡入淡出**。

### 真 alpha 的关键手法

静帧先被压到一个**已知的中间灰**底色上再送进去。因为底色精确已知，
matte 阶段可以解出 `C = (F - (1-a)*BG) / a` 求真实前景，而不是估算它——
实测把边缘色误差从 **26.9 降到 15.9**（255 制）。

上游特别叮嘱**不要换成 chroma-key 绿/洋红**：那两种会溅到高光边缘上。
（这条与 Slingshot Lamp 那篇里「光要挖出来而不是叠上去」是同一类手艺：
**把已知量变成可解的量，而不是留给模型猜**。）

## 可迁移的决策规则（本篇核心价值）

### 规则一：先问「物体静止时在干什么」，再选策略

选错策略是结果平庸或千篇一律的主要原因。上游原文表格：

| 问题「它自己会动吗」 | strategy | 得到什么 |
|---|---|---|
| 会——流动、燃烧、呼吸、滴答 | `native` | 源于自身物理的连续运动 |
| 不会，用到才动 | `event` | 执行一次本职动作，然后回到静止 |
| 不会，但有松动/铰接/轻的部件 | `part` | 主体锚定，一个小部件动 |
| 不会，且完全没有可动部件 | `surface` | 光或材质在固定形体上流动 |

原文强调：**人们要的东西大多是 inert（惰性）的**。让一个惰性物体"自然地动"，
正是转台旋转或无目的浮动那种结果的成因——它没有自然运动，模型就只能给一个通用的。
**除非它真的自己会动，否则先伸手拿 `event`。**

> 对我们：灵动岛五态图标全是惰性的——一个灯泡图标不会自己闪。按这张表，动画应该走 `event`
> （表现一次「检测到/完成了」）而不是给它加一个常驻的呼吸浮动。后者就是原文说的 generic bob。

### 规则二：`--energy` 分开管「物体本身动不动」

主体运动不是敌人，**无目的的主体运动**才是。压扁、后坐、急晃、动作前的预备：
这些是让东西"活起来"的大部分语汇，为了避免转台旋转而一律禁掉，等于扔掉整门语言。

| energy | 物体本身 |
|---|---|
| `still` | 完全刚性 |
| `calm` | 倾斜、落定、轻微呼吸 |
| `lively` | 压扁、倾斜、后坐、抖动、回弹 |
| `playful` | 预备、过冲、摆动、原地小跳 |

默认值跟 strategy 走（`native`/`event` → `lively`，`part` → `calm`，`surface` → `still`），
显式 `--energy` 永远优先。**结果显得没有生命力时，先调它，再动别的。**

每级都有且仅有两件事被禁：**整体旋转**与**漂移**。

### 规则三：小而多胜过大而一

单个大幅整体运动是最显而易见的选择、也是最差的一个：会撞画框边缘、读起来很通用、
且什么也没说。**把运动分散到物体自身的细节上**——它出不了画框，且天然只属于这个物体。

同一个元素出现多个时，**必须不同步**。原文用词很重：同步是"某个东西是被动画过的
而不是被观察到的"最响的破绽。

> 对我们：灵动岛微细条上的状态点若要做多颗，绝不能同明同暗；Agent 列表里的多个 ⚡ 后台胶囊同理。
> 这与仓库现有的「每个请求只提醒一次」「每条通知各有自己的措辞」是同一取向：
> 不要让人一眼看出那是批量生成的。

### 规则四：出去的都要回来

任何伸出、升起、展开或抛出的东西，必须收回、落定、被重新吸收或淡出。
原文刻意把它说成**物理事实而不是边界**——理由是"边界"是模型会不经意跨过的东西，
而往返本身正是无缝循环所需要的。

### 规则五：动结果，不动成因

这是"物理正确但结果平庸"最常见的来路：模型去抓那个通常会**引起**运动的东西，
而引起物往往是把物体搬动的某个外力。在图标尺寸上**成因不可见，只有位移读得出来**。
描述效果本身，让重力、热、空气、张力或物体自身的力去做驱动。

### 规则六：反复问人，因为钱已经花掉了

硬规则不是礼貌：静帧 13 美分、完整一轮 48 美分 4 分钟，且**每个后续阶段都继承静帧的
形体、颜色与重量**。动画没被看过的图等于付两次钱。因此：

1. 只生成**一张**静帧（不是一组候选）；
2. 给用户看并问是否满意；
3. 满意了，**再提一个动作方案并停下来问**——动画是第二个决定，是那个要花 4 分钟的。

汇报也规定得很死：**聊天保持几乎空着**。用户在看图，不是在读报告。
静帧后只说三行（Still ready / 图 / Happy with it, or change something?），
动画后只说一行数字加文件名加 contact sheet。**绝不**粘贴 CLI 原始输出、
分阶段进度、合成后的 motion prompt。（附录 B 有理由。）

## 上游的实测数据（可直接引用）

| 结论 | 数字 |
|---|---|
| WebP quality 不是画质杠杆 | 50→90 只把色误差从 2.96 降到 1.84（/255），却多 500KB，肉眼不可见 |
| 真正的画质损失在降采样 | 1440px 渲染降下来才是可见损失。默认 512 master / 384 输出；**先提 `--size` 再碰 `--quality`，且永不高于 master**（那只是放大） |
| 降帧率是毁掉它的头号方式 | Kling 出 24fps；为压体积降到 8fps 会产生 judder，看起来像渲染差、抠像差或播放器差，而其实都不是。缓慢平滑的运动受害最重——**最该被动画化的图标恰恰最怕低帧率** |
| 已知灰底把边缘误差砍掉 41% | 26.9 → 15.9（见上） |
| 会"看起来动了其实几乎没动" | 出现过 121 帧里只有 1 帧在动。所以 `verify` 必须逐帧测运动量并**非零退出**，它说静态就重写 prompt，别直接编码 |
| 时域平滑 alpha 是陷阱 | 看着像最自然的抗闪法，其实会给任何运动物体糊出一圈鬼影环 |

## 它做不到的（上游自述，全部实测而非理论）

见其 `skills/3dicon/docs/limitations.md`，要点：

- **软接触阴影活不过 matting**：抠像模型把半透明阴影一律当背景。3D 图标实测阴影区恢复出的 alpha
  只有 0.03–0.09，而真值是 0.16。后果是**深色底上看不出来，浅色底上静图有落点而动图会飘**。
  图标若放在浅色页面上，要在那里看过再发布。上游留了一个未实现的做法：把静帧的阴影层
  作为静态元素垫回动画下面。
- **文件大小几乎随帧数线性增长**：288px、5 秒循环——122 帧 24fps = 857KB，61 帧 12fps = 429KB，
  41 帧 8fps = 288KB。帧间差分收益很小，因为这类循环里整个物体都在动。
  WebM 小得多（同样 857KB 那条是 254KB）但它是视频、需要播放器而不是 `<img>`。
  对 App 图标而言 WebP 通常仍是对的取舍。
- **没有透明 MP4**：Safari/iOS 上的透明视频需要带 alpha 层的 HEVC，而多数 Linux 发行版打包的
  `libx265` 直接报不支持 alpha 层编码，需要自建编译。`--mp4` 输出因此被压平到纯色。
- **动画 WebP 无视 reduced-motion**：一旦上屏，没有任何东西能让它暂停。
  若你遵守 `prefers-reduced-motion` / `useReducedMotion`，**必须留着静帧并切过去**——
  pipeline 两个都会写。
- **不要把代码动画叠在烘焙循环上**：原文用词很重——烘焙好的循环之上再加一个 spring 或 drift，
  读起来像"烦躁"而不是"有生命"（fidgeting rather than life）。**二选一。**
  如果美术自己会动，就让它自己动。

最后两条对我们有直接约束：灵动岛是常驻 UI，任何动画资产都要提供静态替代路径，
且**不能在代码里再叠一层位移动画**——否则就是上游明说的 fidgeting。

（核实更正，v0.0.137 时写错过一次）：本条初版写的是「本项目目前没有 reduce-motion 处理」，
**那是错的**——当时按 Web 侧拼法 `reducedMotion` / `prefersReduced` grep，而 SwiftUI 的键名是
`accessibilityReduceMotion`。按正确键名核实：`DockedSliver`（2 处）、`AgentRingView`（3 处）、
`ActivityMatrixDots`（1 处）**已接**；`IslandView` / `IslandComponents` / `EventBannerView`
与各列表图表 View **未接**。真实情况是"部分覆盖、两种行为并存"，不是"完全没有"。
教训留在 [06 篇](06-liquid-taffy-goo-engine.md) 第 590 行附近。）

抠像模型选型也给了实测（对将来做任何截图/素材处理有用）：

| 模型 | MAE | 备注 |
|---|---|---|
| `birefnet-general` | 0.0041 | 慢 7–30 倍 |
| **`isnet-general-use`** | **0.0043** | 默认；同等精度下最快 |
| `bria-rmbg` | 0.0045 | |
| `u2net` | 0.0050 | **可见的背景渗漏** |

（`backgroundremover` 被弃用，因为它只打包 u2net 变体。）

## 应用建议清单（与实现解耦，尚未排期）

1. **给五态各画一个惰性图标**，策略按规则一取 `event`（"检测到一次"而非常驻呼吸）。
2. **多图标动画必须错开相位**（规则三）——若做列表内多胶囊。
3. **若做任何动画资产，静态替代是交付项而非可选项**（`prefers-reduced-motion`）。
4. **不要用 chroma-key 做任何扣像**（若将来做截图处理）——已知底 + 解方程。
5. 现在的岛内呼吸灯若改为动画图标，按本文规则仍需保留静态帧。

# Slingshot Lamp：一个可被"玩坏"的单摆灯（Canvas 2D 手写物理）

> 目的：在给灵动岛加任何常驻动效之前，把 [kamran.fyi/lamp](https://kamran.fyi/lamp)（作者 Kamran Ahmed，
> [@nilbuild](https://x.com/nilbuild)）这个案例摸到底——它只用 Canvas 2D 和手写物理，没有任何动画库、
> WebGL 或物理引擎，却是近三年 Web 上最耐看的小交互之一。
> 本文的行号引用来自 2026-09-25 抓到并落盘的页面内联脚本（981 行，见文末取证命令），
> 截图抽帧来自同源视频，均非推测。

## 一句话结论

**一个吊灯 + 一个弹弓 + 一个开关。你被明令"别碰那盏灯"，然后给了你三种碰它的方式。**
技术上的启发不是某个特效，而是三件事：**用单摆方程而不是 keyframe 做钟摆**、
**用 `destination-out` 把光"挖"出来而不是叠上去**、**同一个状态用不对称的速率过渡**。

## 它是什么

深色单页，中央一行大字 **"Nobody touch the lamp."**，可交互元素三样：

| 操作 | 效果 | 代码位置 |
|---|---|---|
| **flip the switch**（右侧竖向拨动） | 开/关灯。灯丝渐亮渐暗、暖机抖动、过热闪烁 | `setSwitch` / `updateLight` |
| **pull the pebble back and let go**（左下木弹弓） | 石子抛物线飞出。打中灯罩 → 灯开始摆；打中灯泡 → **爆碎** | `shoot` / `collidePebble` |
| **grab the shade to swing it** | 抓住灯罩直接甩，松手自由摆动，摆动衰减由阻尼决定 | `step` 里的 grab 分支 |

击中灯泡会炸出 **38 片随机多边形玻璃 + 40 颗火星**，玻璃碎片带初速度、角速度和重力，会落到屏幕底部堆积。
左下角计数 `shots` / `bulbs` 一路累加，`R` 键或按钮换新灯泡。
左上角是终端风状态：`slingshot-lamp · on`，碎后变 `slingshot-lamp · blown (switch on)`。

标题字体 Funnel Display，正文 Bricolage Grotesque，等宽 Geist Mono——全部 Google Fonts，零本地资源。
**除 GA 外没有任何外部 JS。**

## 手法一：钟摆是解出来的，不是摆出来的

`lamp.js:492`（本文最重要的一行）：

```js
let acc = -(G / lamp.len) * Math.sin(lamp.theta) - lamp.omega * 0.3;
```

就是单摆运动方程：`θ'' = -(G/L)·sin(θ) - c·θ'`，其中 `G = 2600`、`lamp.len = 260`、阻尼 `0.3`。
抓住灯罩时叠加一项弹簧力把摆角拉向鼠标方向：

```js
acc += (tgt - lamp.theta) * 170 - lamp.omega * 16;   // 刚度 170，阻尼 16
```

摆角被钳在 ±1.45 rad（约 83°），于是灯永远不会打到天花板或翻过圈。
摆到两端且角速度够大时触发 `sfx('squeak')`——**声音是运动的自然结果，不是写在动画时间轴上的**。

**石子怎么让灯摆起来**（`kickLamp`，`lamp.js:394`）：

```js
lamp.omega += (ry * fx - rx * fy) / (lamp.len * lamp.len);
```

这是二维叉积算力矩，除以转动惯量 `L²`。含义是**打在灯罩顶端的石子比打在底部的让灯摆得更狠**——
符合直觉，而且是白送的（不需要为不同命中点写不同动画）。

**为什么不能换成 CSS keyframe**：这个运动必须能被外部事件**打断、叠加、随时抢占**。
你甩一下它会一直荡；再打一颗石子会**叠加**到当前角动量上；你可以随时抓住它。
CSS 动画一旦起始就无法被外部事件调制——这就是判据：**这个运动需要被外部事件干扰吗？** 需要，就上手写积分解。

**定长步进**：`STEP = 1/120`，用累加器跑（`frame()` 里 `while (accT >= STEP)`），
渲染跟 rAF，`dt` 钳在 50ms 防切标签页回来后炸。高刷屏上物理不会变快。

## 手法二：把光"挖"出来，而不是叠上去

`renderLight()`（`lamp.js:633`）分四步，是全篇最值得抄的一段：

1. **离屏 canvas 降采样画光**：`gctx.setTransform(0.25, 0, 0, 0.25, 0, 0)` 配
   `gctx.filter = 'blur(5px)'`——在 1/4 尺寸上做模糊再放大，模糊成本降到约 1/16，
   视觉上几乎没有差别。光体是**一个梯形**（从灯罩两侧的边缘出发，沿方向矢量延伸
   `far = max(W,H)*2.5` 到屏幕外），不是圆形渐变——所以光有明确的锥形边界。
2. **另做一张 `dark` canvas，先铺满近黑**：`dctx.fillStyle = 'rgba(3,4,5,0.975)'`。
3. **用 `destination-out` 把光从黑层里挖掉**：

```js
dctx.globalCompositeOperation = 'destination-out';
dctx.drawImage(glow, 0, 0);
```

4. 贴回主画布，再以 `globalCompositeOperation = 'lighter'`、`globalAlpha = 0.13` 叠一层做柔光余晖。

**为什么这样更好**：常见写法是层层半透明圆或 `shadowBlur`，光越亮背景越被洗白，最后糊成一团灰白。
"挖空"是**减法**——背景始终是真正的黑，光锥边缘干净、不发灰，且永远不可能过曝到失去黑色。

> 顺带一个通用好处：把第 2 步那层的 alpha 调低（比如 0.4），同一套渲染就变成**亮色模式**——
> 它不是在"加光"，是在"允许光通过"。我们的深浅两套外观可以直接复用这个结构。

## 手法三：光有不对称的性格

`updateLight()`（`lamp.js:603`）——同一个"开灯"，过渡曲线有三种不对称：

```js
const upI = target > light.I ? 34 : 16;      // 亮起来快 (34)，暗下去慢 (16)
light.I = lerp(light.I, target, 1 - Math.exp(-upI * dt));
const upF = target > light.fil ? 14 : 3.2;   // 灯丝跟上更慢，熄灭时最慢 (3.2)
```

- 点亮初期 `light.warm` 生效：目标亮度按 `Math.random() < 0.45 ? 0.12 : 1` 跳 → **钨丝暖机抖动**；
- `light.heat > 2.6`（被打过太多次）后按概率把目标亮度打到 0.3 → **过热闪烁**；
- 碎裂前 `light.popT` 期间目标亮度冲到 **1.6**（过冲）再炸 → 爆裂前的最后一次闪。

**成本几乎为零，收获是全部状态过渡都从"机械"变成"有重量"。**
一行三元表达式换来的是"灯丝有余热"这件事。

## 手法四：声音全部现场合成

Web Audio 生成，**零音频文件、零加载**：开关是噪声脉冲 burst，皮筋拉到阈值有 `creak`
（吱嘎，按拉伸量调音高），摆到两端 `squeak`（锯齿波 + LFO 调制 + 带通 Q=4，1400Hz 附近，
所以是"金属哀鸣"而不是正弦哔声），碎玻璃是 `pop`。
`audio()` 是懒创建的（首次交互时才建 `AudioContext`，浏览器要求）。

## 一手证据：抽帧与状态文案

视频 28.6 秒、1080×720，逐帧核对（构造命令见文末）：

| 时刻 | 状态 | 读到什么 |
|---|---|---|
| 1s | `on`，shots 36 · bulbs 6 | 亮着，静止待机 |
| 4s | `on`，手型光标悬在灯泡旁 | 准备抓灯罩 |
| 7s | `blown`，shots 37 · bulbs 7 | **刚碎**，碎片四散飞溅 |
| 10s | `blown`，碎片已落到屏幕底部堆积 | 碎片有重力，不是喷完即消失 |
| 13s | `blown`，shots 38 · bulbs 8 | **又碎一颗**，旧碎片仍在场景里向右上飘 |

### 一条对我们有直接用处的口径

`blown` 状态下左上角写的是 **`slingshot-lamp · blown (switch on)`**。
也就是：**开关还开着（电还在来），但灯泡已经碎了，所以没有光。它把这件事说出来了，
没有伪装成"已关闭"。**

这和本仓反复强调的同一条口径是同一回事——「读不到 ≠ 闲着」「没看到 ≠ 没有」
（README 已知限制段、`provenance` 的设计、v0.0.135 修的"承诺一份不存在的输出"）。
一个娱乐小页面都做对了：**状态显示不靠控件位置推断，靠实际现象。**
灵动岛上对应的两处：进程在但读不到会话明细（`inferred`）、以及"未接入明细源"——
现在的措辞已经是这个取向，这篇可以作为一个外部佐证留下。

### 另一条：破坏有后果

碎片**留在场景里堆积**，不播完就清空。玩得越久越狼藉，按 `R` 才收拾。
这让"交互"有重量；对照的是那种播完即消失、什么都留不下的动效。

## 可迁移的决策规则

1. **运动需要被外部事件干扰吗？** 需要（可打断、可叠加、可抢占）→ 上手写积分解，
   不要 CSS keyframe。单摆方程一行就够。
2. **纯黑背景上的光，用减法。** `destination-out` 从近黑层里挖光，再 `lighter` 叠一层柔光。
   比叠加半透明图层干净，且天然支持改造成亮色模式。
3. **过渡速率不对称。** `target > cur ? 34 : 16` 一行。一切状态切换都立刻获得重量感。
4. **钝感是攒出来的。** `heat` 累积到阈值才开始闪——不是每次被打都闪，
   是"被打太多次"才闪。这让异常与正常能用同一个系统表达。
5. **声音绑在物理量上**，不绑在时间轴上。摆到端点 `|ω| > 0.35` 才吱嘎，
   于是声音强度天然反映摆动幅度。
6. **把"明明开着却没亮"讲出来。** UI 状态显示实际现象，不显示控件位置。

## 应用建议清单（与实现解耦，尚未排期）

1. **微细条呼吸灯改用不对称速率**：现在的线性脉动改成"快起慢落"（约 2:1），
   一行常量的事。这是全篇成本最低、收益最直接的一条。
2. **五态异常态可考虑"过热"式累积**：`working` 持续过久或反复 attention 时让亮度/频率变化，
   而不是另做一套告警动画。
3. **任何发光效果先审查是不是"叠"出来的**：现在岛内的玻璃卡片与光环若用多层半透明叠加，
   可评估改减法（macOS 上是 `NSVisualEffectView` 而非 canvas，`destination-out` 无法直接搬，
   但"减法而非叠加"的思路仍然适用——先核实现状再决定）。
4. **状态文案沿用"实际现象"口径**（已有，本篇作为外部佐证）。

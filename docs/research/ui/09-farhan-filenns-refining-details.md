# UI_Farhan「Refining the details, one pixel at a time」：一个订阅卡的材质与层次

> 目的：Farhan（[@UI_Farhan](https://x.com/UI_Farhan)）在 2026-09-25 同日发的第二条，
> 配文 "Refining the details, one pixel at a time. What do you think?"。
> 素材是**静态设计图**（原图 1839×1758 PNG，非视频）。
> 这条同属演示稿，展示的是一个深色网盘类界面（"Filenns."）的两个核心组件：
> 侧边栏 + 一个「存储用量 / 升级」卡。
> 对 AgentIsland 的价值：**侧边栏的主导航与用量卡怎么做才不土。**

素材文件：`.scratch/ui-material/05_HTD7CdOacAAbUJL.png`（不入库）。

## 一句话结论

**这张图里最讲究的一处不是任何控件，而是「Upgrade Storage」按钮上那层彩虹渐变——
它是全图唯一的彩色渐变，于是它成了唯一的行动召唤。**
同一张图里其余地方（导航项、用量条、文件表格）全部保持中性。
这是一条可以直接搬的纪律：**渐变是稀缺资源，一个视图只允许一个。**

## 它是什么

左侧大图是应用的一个完整窗口（背景是一张草地山川照片），右侧是拆分出来的两个组件：

| 组件 | 内容 |
|---|---|
| **侧边栏**（左上大图） | Filenns. logo；搜索框（`⌘F`）；`MY WORKSPACE`：My File / Shared with me / Recent / Favorites / Trash；`AI TOOLS`：AI Insight、AI Categories；`STORAGE`：Storage Overview、Backup & Restore、Storage Plans；底部：头像 + 姓名 + 邮箱 + `245.6 GB of 1 TB used` + "Upgrade Storage" 按钮 |
| **账户卡**（右上） | 头像 + Farhan + 一行邮箱地址（脱敏，见文末注）；`245.6 GB of 1 TB used`；一条蓝色渐变用量条；**"♛ Upgrade Storage" 按钮**（蓝青紫渐变） |
| **文件列表**（右下） | My Files 表：Name / Ai Category / Last modified 三列；行有 ZIP/DOC/PNG/PDF 彩色图标 + 文件类型行；可展开的文件夹树（Project Tecniro AI 下挂 4 个文件、Document、Branding Magents 两组） |
| **图标列**（右上边缘） | PDF / ZIP 图标 + Client / Research / Assets 三个文件夹 |

## 手法一：全图只有一个渐变，用在唯一的行动点上

`Upgrade Storage` 是整张图里**唯一使用彩色渐变**的元素：蓝→青→紫的横向渐变 + 圆角。
其余一切（导航选中态、用量条、按钮）都是单色或中性。

值得单独说的是那条**用量条也是渐变的**（蓝色），但它是**冷色单色渐变**
（蓝到浅蓝），与按钮的**彩虹渐变**（蓝青紫三种色相）在性质上不同：
前者是数据可视化，后者是品牌行动召唤。两者都是渐变，但它们不同级。

**这条纪律对我们的适用性很高**：灵动岛/侧边栏里如果今天已经有渐变
（玻璃卡片、光环、微细条呼吸灯），那么任何新的"行动按钮"用渐变就是在抢戏。

## 手法二：选中态靠"颜色微差 + 一组图标"，不靠强色块

侧边栏里 `My File` 是当前选中项。它的处理是：

- 图标是 Filenns 的品牌蓝（其他项图标是灰/中性）
- 文字比其他项稍亮
- **没有背景色块、没有左侧指示条、没有加粗到刺眼**

对照 [08 篇](08-farhan-video-dashboard-info-partition.md)：那份稿子的选中项（`Projects`）
用的是**低对比蓝色背景 + 蓝字**，也不做强色块。

两份独立稿子用了同一种克制：**选中态要被"扫到"，但不该被"注意到"。**
我们侧边栏的导航选中态如果今天用了高饱和背景，这是可以对照的一处。

## 手法三：底部区域是"谁 + 多少 + 让你做什么"，三件事一行闭环

侧边栏底部的账户区是一个完整闭环：

```
[头像] Farhan
       <作者公开的邮箱，此处脱敏>   ← 我是谁
       245.6 GB of 1 TB used
       ━━━━━━━──────                ← 我用了多少
       [ ♛ Upgrade Storage ]        ← 我该做什么
```

**用量条在这里第二次出现**（右上角账户卡里也有一条），与 [08 篇](08-farhan-video-dashboard-info-partition.md)
的 Render queue 双现是同一手法：**摘要态与详情态各自持有同一数据的一份呈现。**

## 手法四：置底区域是侧边栏的信息收尾

侧边栏底部被**账户区占据**，而产品本身的功能导航（AI Tools / Storage）排在它上面。
这条顺序值得注意：**"关于用户的数据"压轴，"关于产品的能力"排中间。**

对我们的映射：侧边栏底部现在是高级设置入口（按 `03-approach.md` 的信息架构）。
这份稿子给出的替代思路是**底部可以放"关于这台机器/这个用户的状态"**——
例如 token 总量、监控中的 agent 数。这条与 05 篇的"汇总态"互补。

## 手法五：文件类型行——三重信息一行说完

文件列表里每个文件都长这样：

```
[彩色图标] Tecniro AI Brief.doc
            Document
            Sept 24 · Sept 15 · 14:00 PM
```

一行给出：**文件名（主）+ 分类（副）+ 两个时间（创建 · 修改）**。
注意两个时间是**同一行里的两个不同语义**，没有用"修改于 x，创建于 y"这种文字标签，
而是靠**顺序**表达。

对我们的映射：agent 列表行今天有 agent 名 + 状态 + token。若要加"上次活跃时间"，
可以用顺序而不是加文字标签——保持行的可扫读性。

> 注：同为**静态设计图**，不含动效，不能作为动效证据使用。
> 图中账户卡有一行邮箱地址，是作者本人公开写在设计稿里的展示信息。**本文已脱敏**——
> 虽然它是公开的，但"公开"不等于"该被本仓转载"：真实邮箱进了这个仓库，
> 就会被下一次 grep 全文的人当成联系方式或种子数据。原文可到原推文核对。
> 同理，任何从外部读到的第三方标识（邮箱、域名、账号）都**不得**进代码或配置——
> 与本仓「源码零硬编码 secret」是同一条红线。

## 可迁移的决策规则

1. **渐变是稀缺资源，一个视图只允许一个。** 全图唯一的彩虹渐变给了唯一的行动按钮。
2. **选中态要被"扫到"，不该被"注意到"。** 图标颜色微差 + 文字微亮，别做强色块。
3. **同一数据在摘要态与详情态各持一份呈现。** 用量条出现两次是有意的。
4. **底部放"关于用户的状态"而不是"关于产品的能力"。** 闭环是：我是谁 / 我用了多少 / 我该做什么。
5. **一行说完三重信息时，新语义靠顺序表达**，不加文字标签。

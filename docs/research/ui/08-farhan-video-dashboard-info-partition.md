# UI_Farhan「Video Editing Dashboard」：深色大面板的信息分区法

> 目的：[Farhan](https://x.com/UI_Farhan)（[@UI_Farhan](https://x.com/UI_Farhan)）2026-09-25 发的
> 视频剪辑工作台设计稿，配文 "Designed a Video Editing Dashboard 🎬 What do you think? 👀"。
> 素材是**静态设计图**（非视频），原图 2262×1758 PNG。
> 对 AgentIsland 的价值：侧边栏主形态要做「首层极简 + 内部信息丰富」，
> 这份稿子示范的是**一个大面板如何同时容纳 4 类信息而不显得吵**。

素材文件：`.scratch/ui-material/05_HTCuOh3aoAA4Qv0.png`（不入库）。

## 一句话结论

**它把「状态」「容量」「队列」这三件本会互相抢注意力的事，装进了同一张面板的
三个不同权重区：中间给内容和进度，右侧给两个固定用途的卡片，左下给一个可折叠的小卡。**
深色 + 有机彩色背景的组合让整张图有了作者签名，但没有让彩色进入信息层。

## 它是什么

深色主题的桌面工作台（应用名 "Outline · Video & Motion Studio"），三栏结构：

| 区域 | 内容 | 视觉权重 |
|---|---|---|
| 左侧导航栏（固定） | Workspace 切换、Home/Projects/All projects/Version history/Review & comments/Favorites、Editor、Templates 312、Assets 1.2k、Exports 3、Analytics；FOLDERS 分类带彩色圆点与计数 | 最弱（低对比、无强调） |
| 中间主区 | Projects 标题 + "48 videos and motion projects across 4 folders"；`All 48 / Mine 16 / Shared 32` 平板筛选；**Pinned 3** 三张大缩略图卡；All projects 列表（8 行，含 OWNER 头像、LENGTH / FORMAT / UPDATED / STATUS） | 最强（内容与进度都在这里） |
| 右上角 | 搜索框 + 通知铃 + `84.2 / 200 GB` 环形用量 | 中（常驻但只占一角） |
| 右侧两张卡 | **Storage**（Team · 200 GB + 84.2 GB 用量条 + Video/Renders/Audio/Images 四色细分）+ **Render queue**（3 active · 9 finished today，三条任务带进度条与百分比） | 中高（有自己的标题层级，但不抢主区） |
| 左下角 | **RENDER QUEUE 3/12** 小卡：一条任务 + 26% 进度 + `4K ProRes · next in queue 02:10` | 低（缩起来的状态条） |

注意：**渲染队列出现了两次**——右下角是完整版（三条任务），左下角是单任务迷你版。
这不是重复，是同一数据在两个层级上的呈现（详见手法二）。

## 手法一：进度有三种粒度，各占一个视觉权重

这是全篇最值得抄的一点。同一个「渲染中」概念，在这张图里有三种写法：

| 粒度 | 长什么样 | 用在哪 |
|---|---|---|
| **徽标级** | 列表行 STATUS 列的 `RENDERING` 药丸（蓝紫渐变） | 让人扫一眼就知道"哪些在跑" |
| **行级** | Render queue 卡片里每条任务下方一条细进度条 + 百分比（`62% · 02:10`） | 单条任务的精确进度 |
| **汇总级** | `3 active · 9 finished today` + 左下角 `RENDER QUEUE 3/12` | 回答"总共什么情况" |

**它们不是同一个组件的三种尺寸，而是三个不同问题的答案。**
我们侧边栏的「看清」页今天是一份 agent 列表；如果也要回答"几个在跑 / 各自到哪了 / 总共如何"，
问题是要不要做成三处而不是把三件事塞进一行。

## 手法二：同一数据在两个层级重复出现，且层级决定详略

Render queue 在右下角（详版）和左下角（缩版）同时存在。缩版只留一条最关键的任务
（当前正在渲染的那个）+ 百分比 + 下一条是什么 + 剩余时间。

对照本仓已有的做法：灵动岛的微细条是**缩版**（一个 agent 一行摘要），
侧边栏监控页是**详版**。这份稿子说明这个双形态不是妥协，
而是**同一数据天然就该有浓缩态与展开态两个出口**。
（这条与 [02 篇 Slingshot Lamp](02-slingshot-lamp-handwritten-pendulum.md) 的
"同一个状态用不对称的速率过渡"一样，都属于"同一事物不只有一种呈现"。）

小细节：左下角缩版左上角有一个**实心小圆点**，右下角详版同位置是**空心**。
用填充/空心区分「这是当前项」，比加颜色或加粗都轻。

## 手法三：状态语义用色相，优先级用「饱和度 + 位置」

四个状态药丸：`RENDERING`（蓝紫）、`IN REVIEW`（黄橙）、`PUBLISHED`（绿）、`DRAFT`（灰）。
它们全部只出现在 STATUS 列——**颜色是状态的载体，不是装饰**。

同时：用得越多、越重要的区，颜色越少。主内容区（大缩略图 + 列表）几乎无彩色，
彩色集中在状态列、FOLDERS 圆点、Storage 用量细分图这几处**本就该被颜色识别的元素**上。

> 这与案例库已收录的克制共识是同向的，且给了一条更细的操作规则：
> **彩色名额有限，只给"需要被颜色识别"的元素；剩下的地方保持中性。**

## 手法四：背景色离开信息层

整张设计稿的背景是一张有机的、蓝橙相间的抽象图（Unsplash 水印可见）。
但**内容全部落在深色近黑的面板上**，背景只负责气质。

这条对我们几乎直接适用：灵动岛/侧边栏后面是用户桌面，背景不可控。
这份稿子的做法是**用不透明度与深色面板把自己与背景隔开**——
即我们已有的玻璃卡片思路，且提示「面板要够深，别让桌面内容透进来干扰状态识别」。

## 手法五：数字的呈现分级

| 数字 | 怎么写 | 回答什么 |
|---|---|---|
| `48` | 导航项 Projects 右侧的计数 | 有多少项目 |
| `312` / `1.2k` / `3` | 次级导航计数（`1.2k` 而不是 `1247`） | 规模感，不追求精确 |
| `84.2 / 200 GB` | 环形 + 精确到小数 | 配额余量 |
| `58.4 GB` | Storage 条目右侧 | 占比构成 |
| `3 active · 9 finished today` | 卡片标题右侧一句话 | 今日态势 |
| `Showing 1 to 10 of 12` | 右下角灰字 | 分页事实 |

**精度跟着"这个数字要被用来做什么决定"走。** 规模感用 `1.2k`，配额判断用 `84.2`。
我们「看清」页的 token 统计也应分辨：摘要行要的是规模感（`12.4k`），
详情页要的是可核对的精确值。

## 可迁移的决策规则

1. **进度分三档：徽标 / 行级 / 汇总。** 三者回答不同问题，不要用一个组件的三种尺寸糊过去。
2. **同一数据做浓缩态与展开态两个出口。** 灵动岛微细条 = 浓缩，侧边栏 = 展开，这是特性不是妥协。
3. **「当前项」用填充/空心区分**，比加颜色轻。
4. **彩色名额有限**：状态、分类、占比这类"需要被颜色识别"的元素才给色相，其余保持中性。
5. **数字精度跟着决策走**：规模感 `1.2k`，配额判断 `84.2`。
6. **背景必须与信息层隔开**：用户桌面不可控，面板要够深、够隔。

## 应用建议清单（与实现解耦，尚未排期）

1. **「看清」页核对一遍我们是否已经在回答三个进度问题**：几个 agent 在跑（汇总）、
   各自状态（徽标/行级）、某一条的细节（展开）。若缺汇总态，可在侧栏图标计数上体现。
2. **Token 统计区分规模感与精确值**：摘要行用 `k` 缩写，详情保留精确数。
   现状未核实，做前先读 `stat` / `session` 相关代码。
3. **「当前 agent」高亮改用填充/空心一类轻量手段**，而不是加背景色
   （加背景色会与玻璃卡片打架）。

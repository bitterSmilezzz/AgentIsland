# 17 · 受管理运行事件与密文存储边界

日期：2026-11-01。领域决定见 [ADR 0042](../../adr/0042-managed-run-event-segments.md)，数据策略见 [ADR 0041](../../adr/0041-managed-history-data-policy.md)。本文确定逻辑事件与物理密文段的边界，不宣称执行、存储或容量功能已交付。

## 当前实现

- `tasks::Run` 是外部来源状态的只读投影；`event_receipts` 用于来源事件去重。它们不是 AgentIsland 创建的执行记录或正文日志。
- `run_lifecycle.rs` 提供计划先行、取消/关闭区别、终态拒绝与认领版本等纯状态机判据；当前没有生产执行器或项目授权链调用它。
- TASK-05 目前只提供身份绑定 AEAD 原语和 macOS 专用项目密钥接口。策略快照、密文内容文件、删除、备份、任务页和原生 Keychain 验收仍未完成。

因此不得将现有来源 `Run`、本地产出正文或 `event_receipts` 当成受管理执行历史，也不得因状态机判据存在就启动执行或接通历史正文写入。

## 目标数据边界

受管理运行是另一个数据域，至少固定项目 ID、任务 ID、运行 ID、执行授权版本、内容策略版本、当前阶段、认领版本和聚合 revision。生命周期字段表达“谁可以做什么、当前在哪一阶段”；它不保存提示词、对话、diff、计划正文或工具输出。

运行正文由不可变逻辑事件组成。每个事件在单一运行中有连续序号和稳定事件 ID；重试使用同一事件 ID 时幂等，身份相同但内容不同则拒绝。事件正文、敏感标题及可识别元数据均属于 ADR 0041 的加密范围。审批、重认领、取消和完成等检查点会封存当前批次，避免一个物理段跨过难以恢复的授权边界。

逻辑事件与物理密文段是两个层次：

- 一个密文段可以包含多条小事件，降低每条消息单独同步文件造成的目录块与 fsync 成本。
- 一个逻辑事件可以跨多个有序内容分片，但读取必须先验证所有片段的身份、顺序、长度和 AEAD，再一次性返回完整事件；不能把部分正文交给 UI。
- 段文件名使用随机标识。段内明文序号用于恢复事件顺序；AEAD 附加数据绑定格式版本、项目、运行、段标识以及首末事件序号。事件 ID、产物/内容版本和内容分片序号保存在密文帧中并随段整体认证。现有 AEAD 原语的上下文还需扩展后才能承载此段契约。
- 段发布不可覆盖旧段。聚合索引只引用已完整写入、同步、验证并原子发布的段；索引更新与段发布间的崩溃恢复协议须在实现密文存储前另行定案。

## 分段压力测量

v0.0.432 的合成微基准显示：相同 1 MiB 内容按 1 KiB 独立文件发布约需 5.9 秒、占用约 4 MiB 文件块；按 64 KiB 分组约需 91–101 ms；按 256 KiB 分组约需 20.8–28.9 ms；单个 1 MiB 文件约需 6.7–11.5 ms。它只测加密文件成本，尚未包含运行事件结构、索引、备份或多段恢复。

后续完整合成轨迹至少要比较 64 KiB、256 KiB、1 MiB 段尺寸，并生成规划、确认、不同大小的消息、工具结果、diff/产物、取消/重认领和完成检查点。每种轨迹需报告：逻辑/实际分配字节、段数、每段事件数、写入同步/认证时间、读取与完整重组时间、索引与加密备份占用、拒写容量的准确性，以及进程内存峰值。合成输入不得读取真实外部会话、任务正文或凭据。

只有合成轨迹结构、索引和备份都固定并测量后，才能讨论项目容量、全局容量、期限范围或默认值。段尺寸是存储实现参数，不能替代用户可见的容量配额。

## 尚未定案的实现前置项

- 执行授权如何签发、撤销并绑定到项目、任务、执行角色及机器；真实 TASK-03 写路径仍关闭。
- 同一运行并发追加时的序号分配、幂等冲突处理及认领版本复核。
- 超过单段目标尺寸的单个事件如何分片、上限如何由完整轨迹推导。
- 段文件、聚合索引、删除意图和备份之间的原子结算与崩溃恢复协议。
- 依据完整合成轨迹选定段目标；容量、期限和清理提醒仍以 ADR 0041 的实测门槛为准。

## 出口

本设计片只关闭“来源观测 Run 与自有受管理执行历史如何区分、事件如何批量封装”的领域边界。它不关闭 TASK-03 的真实执行授权、Run now 流程或端到端验收，也不关闭 TASK-05 的内容存储、容量期限、删除、备份、UI 或平台验收。

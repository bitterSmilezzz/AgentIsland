# TASK-05 · 自有执行历史首轮容量测量

日期：2026-11-01。此文记录首轮合成基准与其边界，不代表产品容量/期限已定案。

## 测量方法

- 以 v0.0.431 为基线，在 macOS 27.0.1 / arm64 上运行 Rust release 测试二进制；正文、身份和数据密钥均为进程内合成值，每次运行只在新建临时目录写入并由测试自动清理。
- 加密测试调用生产 AES-256-GCM `seal` / `open`；每个正文大小重复 15 次，记录单进程中位数。优化前运行 3 轮，原地封套/零化解密缓冲优化后运行 4 轮。
- 文件配置调用相同加密原语与 `atomicfile::atomic_create_validated`；计时包含加密、暂存文件写入/`sync_all`、读回认证及原子创建。每个配置总正文均为 1 MiB，独立随机文件名。已分配字节从文件 `st_blocks × 512` 汇总。
- 基准命令：

  ```sh
  cargo test --release --locked --manifest-path app/src-tauri/Cargo.toml \
    measure_synthetic_managed_history_storage_and_crypto -- --ignored --nocapture
  ```

## 结果

AES-GCM 封套的固定格式开销为每对象 33 字节：4 字节 magic、1 字节格式版本、12 字节 nonce 和 16 字节认证标签。对 4 MiB 合成正文，原实现每轮中位数的跨轮中位数为加密 1.210 ms、解密 1.093 ms；原地封套和零化解密缓冲后为 0.522 ms、0.534 ms。各轮范围分别为：加密 1.010–1.237 ms → 0.509–0.609 ms，解密 0.923–1.102 ms → 0.522–0.615 ms。它是单机微基准，未用 RSS/分配器采样证明进程内存降幅。

相同 1 MiB 正文按不同对象粒度写入的结果：

| 每对象正文 | 文件数 | 文件逻辑字节 | 已分配文件字节 | 写入、同步与认证用时 |
| ---: | ---: | ---: | ---: | ---: |
| 1 KiB | 1,024 | 1,082,368 | 4,194,304 | 5,886–5,967 ms |
| 16 KiB | 64 | 1,050,688 | 1,310,720 | 373–385 ms |
| 64 KiB | 16 | 1,049,104 | 1,114,112 | 91–101 ms |
| 256 KiB | 4 | 1,048,708 | 1,064,960 | 20.8–28.9 ms |
| 1 MiB | 1 | 1,048,609 | 1,052,672 | 6.7–11.5 ms |

单轮中的时间受本机文件同步影响；表中是四次优化后运行观测范围，不是产品延迟承诺。目录内容元数据、索引、备份、项目策略快照与全应用 RSS 未计入。

## 决策与边界

- 33 字节 AEAD 开销不会主导大正文磁盘空间；小正文独立文件的分配与逐文件同步成本明显。受管理运行存储设计必须先锁定消息/产物的持久化粒度，并用有界合成运行重测，不能默认每条很小的消息独立同步为文件。
- 现有受管理运行还没有确定记录频率、消息分段、单正文最大长度、每次运行的对象数量与实际生命周期。此基准不读取外部 Agent 用户历史，也不模拟真实运行流量。
- 因此本轮**不设置项目容量、全局容量或期限范围/默认值**。这些数字要等 TASK-03 的 Run/事件边界和 TASK-05 密文索引、备份占用模型固定后，用完整合成轨迹与磁盘/资源测量计算。
- 本测量不启动/写入系统钥匙串，不验证 Keychain 锁定或权限行为；不证明生产目录同步、崩溃恢复或完整删除协议。

容量与期限配置仍关闭，见 [ADR 0041](../../adr/0041-managed-history-data-policy.md)。当前报告只把“每条小消息一个原子文件”标记为需要避免或重新设计的压力点，不将测量样本外推为推荐配额。

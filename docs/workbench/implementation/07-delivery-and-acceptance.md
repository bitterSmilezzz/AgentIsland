## 2. 每批执行方式

1. 在 `.scratch/<feature>/spec.md` 固定范围、复现、成功信号与非目标；issues逐文件记录执行状态。
2. 核对当前代码与依赖，先建立可失败的行为复现，按风险补必要测试。
3. 修改最小接缝，新增DTO/命令同步注册、序列化、前端调用与能力说明。
4. 运行相关回归与纯数据UI场景，检查截图/焦点/错误/空态；修正后重测具体问题。
5. 构建，按仓库约定自动重启；原生桌面自动化必须满足现有隔离要求。
6. 独立review记录现象、修正、验证与阻塞；文档同步、扫描和release门禁按既有脚本执行。

不得为修UI测试伪造隔离标志、跳过扫描或将未执行检查写成通过。累计工作区改动保留，不在实施前reset或覆盖。

# 06 · 平台适配与后续客户端

## 1. 顺序和共享边界

macOS完整范围通过07验收后进入Windows，Windows完成后进入Linux；之后再设计Web/移动。当前可做接口边界和平台静态检查，不宣称后续平台已交付。共享Rust业务、DTO、组件/token与来源规则，原生操作单独适配。

| 边界 | 当前证据 | 后续实施项 |
| --- | --- | --- |
| 会话导航 | session_navigation.rs macOS /usr/bin/open；其他平台报未接入 | 按工具核实注册协议/应用启动；准确区分精确会话、打开工具、不可用 |
| 外部窗口布局 | 当前尚无模块 | 按平台实现枚举/几何/权限/身份/实际结果，复用纯布局 |
| 凭据 | secret.rs 非macOS写入Refused | 实现OS安全存储，失败明确，不明文降级 |
| 进程/文件 | sysinfo + 工具来源，仍有POSIX表面 | 进程身份/路径/文件锁/编码/原子替换和只读SQLite逐平台验证 |
| 应用壳 | Tauri、macOS原生材质与菜单栏行为 | 托盘、快捷键、自启、DPI/屏幕、关闭隐藏与安装升级 |

API候选只是技术调研入口，不能直接视为承诺。平台能力表由真实适配结果提供，失败原因可见。

## 2. Windows执行包

W0：扫描生产POSIX调用与macOS专属依赖门控；Windows CI改成实际阻塞前先完成目标编译、Rust纯逻辑/契约回归。不得通过全局禁用模块换取绿灯。

W1：Windows原生小探针验证应用/进程身份、托盘隐藏唤回、WebView2、DPI、多屏负坐标、快捷键与自启。UI保持相同语义，不模拟macOS按钮/材质。

W2：实现凭据适配候选（Windows安全凭据能力）及会话导航；由注册工具清单决定启动，不接受前端任意命令。同步验证原子替换与Codex实际配置路径。

W3：窗口布局候选基于Win32窗口能力；核实窗口句柄生命周期、进程启动身份、权限级别、最大化/全屏、最小尺寸与DPI。句柄复用必须拒绝误操作。

W4：安装/升级/卸载、已有数据保留、三形态、任务/配置/通知/窗口端到端验收；明确首发架构和系统版本支持范围，再发布。安装格式、签名与更新渠道在本阶段基于工具链验证决定。

## 3. Linux执行包

L0：确定首批发行版/桌面环境及打包目标，不承诺所有Linux。验证依赖、构建、WebKitGTK与基础启动。

L1：文件/进程/只读SQLite、托盘/通知、自启与快捷键分别验证；缺少桌面能力时显示原因。

L2：核实安全凭据服务是否可用与解锁行为，无服务时相关功能明确不可用。X11/Wayland分别核实窗口枚举/操作与权限；不能用X11通过推导Wayland支持。

L3：目标环境端到端验证、安装升级与迁移；窗口布局受限制的环境明确降级，保留其他功能。不得绕过窗口管理器限制假报完成。

## 4. Web与Android/iOS后置设计包

首先确定数据来源：桌面可信桥接或用户部署服务。定义配对/鉴权/设备撤销、读与写权限、连接中断与离线缓存；既有通知渠道不等于可入站控制。未经具体授权不自动下发执行任务。

Web：评估共享组件与独立导航、浏览器兼容和部署；本机数据不能直接由公网网页读取。移动：独立设计查看进展、人工关口与来源回访，触屏目标、推送、后台/离线、跨设备来源能力重新验证，不缩小桌面页面。

此时才评估Web框架和移动原生/跨平台框架。当前只保留契约边界，不创建空客户端工程，不加入云同步作为桌面前置。

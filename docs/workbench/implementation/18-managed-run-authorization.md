# 18 · 受管理运行的项目授权与执行者身份

日期：2026-11-07。领域决定见 [ADR 0043](../../adr/0043-managed-run-project-authorization.md)；自有历史数据策略见 [ADR 0041](../../adr/0041-managed-history-data-policy.md)。本文记录授权判据、独立策略存储核心与尚未开放的生产链路。

## 当前实现

`app/src-tauri/src/managed_run_authorization.rs` 提供纯授权模型；`managed_run_authorization_store.rs` 提供独立本地策略存储和项目根身份核验：

- 新项目默认不允许运行，也不采集历史。
- project/task/run 身份在绑定时固定；跨项目、跨任务和跨运行替换均拒绝。
- planner、executor、reviewer 分别授权；一个角色不能借另一个角色的项目 grant 执行动作。
- 运行快照绑定项目授权版本、历史策略版本、稳定 runner ID、runner 进程代次与 claim version。权限变更、runner 重启或重新认领会拒绝旧快照。
- 历史写入要额外通过显式 opt-in 与当前策略版本检查；关闭历史不会改变规划/执行授权。
- 版本不能递增时拒绝且保留旧状态。标识符采用受限字符集合；不接受路径、标题或凭据作为身份。
- 项目运行 grant 不包含 Git 推送/合并、发布、通知发送或网关请求权限。
- 独立的 `managed-run-authorization.v1.json` 缺失时无授权、无历史采集；未知字段/未来版本、损坏、符号链接和原子发布失败时拒绝并保留现存字节。
- grant 记录固定 project UUID、规范根路径、卷身份和文件身份；Unix 使用设备号/inode，Windows 使用卷序列号与 128-bit 文件 ID。移动、替换或经符号链接重定向根目录后，旧 grant 不复用。
- grant/角色变化与历史采集策略分别递增版本；撤销保留版本墓碑并清空授权内容，溢出拒写。Unix 策略文件要求仅所有者可访问。
- `confirm_project` 仅是存储层 API；没有生产调用方或用户确认界面。17 条定向用例覆盖默认关闭、坏格式、路径变化、版本和原子写入等边界；隔离去除目录身份相等校验的变异被替换目录用例捕获。

## 安全边界

判据只说明调用方必须满足哪些要求，不负责证明谁是用户或 runner。`VerifiedRunner` 只能由应用内部在核验本地进程/认证会话后构造；当前还没有该启动器。虽然策略存储现已能绑定目录身份，仍没有生产路径调用 `confirm_project`，也不能把前端任意 JSON 当作用户确认。

权限变化会使既有快照失效；实际 runner 尚不存在，因此当前没有撤销后停止进程的实现。存储文件没有抗回滚机制，也没有备份/恢复 API；目录替换有拒绝行为，策略回滚风险仍未解决。尚未接入 Tauri 用户确认命令、授权审计 UI、runner 握手/停止、主机钥匙串、TASK-05 密文写入与生命周期。

## 下一片

1. 将 `confirm_project` 接到本地用户确认 UI/Tauri 命令，并明确策略文件回滚、迁移和恢复规则。
2. 定义本地 runner 注册与启动握手，证明 runner ID/代次来自实际进程，不接受客户端自行声明。
3. 将 Run now、计划确认、撤销停止、迟到结果拒绝接入真实执行服务；外部副作用仍逐子系统授权。
4. 与 TASK-05 密文事件存储、索引、精确删除和生命周期接线；完成原生钥匙串及策略恢复验收后才开放历史写入。

本片没有上述生产接线，也不宣称 TASK-03 授权、真实执行或 TASK-05 历史写入完成。

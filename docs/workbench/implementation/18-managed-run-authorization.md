# 18 · 受管理运行的项目授权与执行者身份

日期：2026-11-06。领域决定见 [ADR 0043](../../adr/0043-managed-run-project-authorization.md)；自有历史数据策略见 [ADR 0041](../../adr/0041-managed-history-data-policy.md)。本文记录当前纯判据与尚未开放的生产链路。

## 当前实现

`app/src-tauri/src/managed_run_authorization.rs` 提供一个不连接 Tauri、文件或执行器的纯授权模型：

- 新项目默认不允许运行，也不采集历史。
- project/task/run 身份在绑定时固定；跨项目、跨任务和跨运行替换均拒绝。
- planner、executor、reviewer 分别授权；一个角色不能借另一个角色的项目 grant 执行动作。
- 运行快照绑定项目授权版本、历史策略版本、稳定 runner ID、runner 进程代次与 claim version。权限变更、runner 重启或重新认领会拒绝旧快照。
- 历史写入要额外通过显式 opt-in 与当前策略版本检查；关闭历史不会改变规划/执行授权。
- 版本不能递增时拒绝且保留旧状态。标识符采用受限字符集合；不接受路径、标题或凭据作为身份。
- 项目运行 grant 不包含 Git 推送/合并、发布、通知发送或网关请求权限。

## 安全边界

该模型只说明调用方必须满足哪些判据，不负责证明谁是用户或 runner。`VerifiedRunner` 只能由应用内部在核验本地进程/认证会话后构造；当前还没有该启动器，所以没有生产路径能生成此身份。调用 `ProjectAuthorization` 的未来服务必须来自本地显式授权交互，不能把前端任意 JSON 当作签发依据。

权限变化会使既有快照失效；实际 runner 尚不存在，因此当前没有撤销后停止进程的实现。生产接线前还需绑定项目目录的文件系统身份、定义已启动进程的停止与确认语义、保存授权审计和策略 revision，并完成主机钥匙串及写入原子性验收。

## 下一片

1. 建立由本地用户确认签发的项目授权存储；授权只作用于经核验的项目目录身份，删除/替换目录后拒绝复用旧授权。
2. 定义本地 runner 注册与启动握手，证明 runner ID/代次来自实际进程，不接受客户端自行声明。
3. 将 Run now、计划确认、撤销停止、迟到结果拒绝接入真实执行服务；外部副作用仍逐子系统授权。
4. 完成策略快照持久化及损坏/未来格式拒写，再开放 TASK-05 事件写入。

本片没有上述生产接线，也不宣称 TASK-03 授权、真实执行或 TASK-05 历史写入完成。

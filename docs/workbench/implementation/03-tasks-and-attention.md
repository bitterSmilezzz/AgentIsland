# 03 · 本地任务与人工关口

## 1. 范围

首版支持项目关联、本地任务看板、来源绑定、运行与产出引用、待回答/确认方案/验收结果。首版不执行编码、不代替来源工具回答/批准、不连接 Todos 服务。打开来源是导航，手动确认自己的记录是本地操作，必须在文案上区分。

旧 `todos.rs` 和 todos_* 命令继续提供简单清单，旧 `todos.json` 不覆写或删除。新增 `tasks.v1.json` 保存 Agent 任务；读旧 Todo 时映射 `kind=manual` 的视图。这样无须立即改变旧ID和done语义，也避免两份可写清单漂移。后续需要统一存储时再单独迁移。

## 2. 目标数据

一个原子聚合文件：`schema_version=1/revision/projects/tasks/runs/attentions/artifacts/event_receipts`。

| 实体 | 字段与约束 |
| --- | --- |
| Project | id、name、可空本机路径；路径不进入远程导出 |
| Task | id、project_id、title、agent_id、source_ref、current_run_id、created_ms、updated_ms、archived_ms（可空）、revision；agent_id/source 可空，但不能伪造关联 |
| Run | id、task_id、status、started_ms、finished_ms、source_run_id、revision；状态 queued/running/waiting/ready/failed/cancelled/accepted |
| Attention | id、run_id、kind=answer/plan_approval/result_review、summary、source_event_id、artifact_id/revision、state=open/resolved/expired |
| ArtifactRef | id、run_id、kind=question/plan/result、title、source_ref、source_revision、available；只保存引用与简短摘要，不复制会话全文或secret |
| EventReceipt | source namespace、event ID、last revision、关联run；用于幂等更新，有界维护 |

Task 的看板分组由 current_run 推导，不能手工再存一份互相矛盾的状态。无run任务放未开始；人工关口放需处理；failed在需处理区显示“执行失败”，与三类人工批准不同。有open人工关口时优先放需处理；已结束包括无open关口的结果就绪/已验收/取消，标签区别；执行结束不能自动 accepted。

## 3. 状态转换

| 输入 | 转换 | 不允许的推断 |
| --- | --- | --- |
| 用户新建任务 | Task，无run | 不自动启动工具 |
| 可信执行开始 | 新建run或同一来源run更新 running | 不能仅按CPU升高新建任务 |
| 可信提问/方案/结果 | waiting或ready + 对应Attention | generic attention只能保存待确认原文，不能推断有方案 |
| 执行完成 | ready，保留run与结果引用 | 不等于验收通过 |
| 来源明确回答/批准/验收 | 只更新匹配run与版本；验收 accepted | 打开来源不能标resolved |
| 用户标记本地已处理 | 更新本地记录，标注manual_resolution | 不发送批准给工具，不宣称来源已批准 |
| 新一轮执行 | 新run、旧人工关口按来源有效性过期 | 不覆盖旧产出，不把旧问题绑到新会话 |
| 来源丢失 | 保留记录，available=false并说明 | 不跳到最近无关会话 |

同一来源事件重复提交不增加计数。只读事件采样不足以建立具体Task时，仅保留现有通知，不自动制造虚构任务。用户可从任务页手动关联经选择的来源，会显示“手动关联”。

## 4. 拟新增命令

- `tasks_snapshot(project_id?)`：聚合视图、revision、来源可用性、manual Todo摘要。
- `task_create(title, project_id?, agent_id?)`：创建本地记录，不启动执行。
- `task_update(id, patch, expected_revision)`：白名单title/project关联；状态不能任意patch。
- `task_link_source(id, source_object_id, expected_revision)`：服务端解析可信来源，不接受任意URI。
- `task_archive(id, archived, expected_revision)`：归档/恢复本地记录，不取消来源执行；无run任务也适用。
- `task_runs(id)`：分页/有界历史引用。
- `task_open_source(id, run_id?, artifact_id?, expected_revision)`：复核身份和有效性后导航。
- `task_mark_handled(id, run_id, attention_id, expected_revision)`：仅本地处理记录，UI明确标识。

聚合revision控制整个文件写入；对象revision用于来源/内容验证，服务返回两者，不能混用。所有用户写命令的expected_revision是聚合revision；自动事件串行合入后同样递增。所有写返回新聚合revision，失败不清输入。来源事件由内部 task_service 接收，不新增对外无鉴权审批接口。

## 5. UI 与落盘

归档默认从主看板隐藏，提供“已归档”筛选和恢复。任务页四组：未开始、执行中、需处理、已结束；首版用列表组，暂不实现拖拽改状态。详情展示运行切换、来源能力、方案/结果引用与动作。灵动岛最多一条需处理加数量；优先待回答/方案/验收，再失败，组内按时间稳定排序。资源异常仍由原通道呈现，不塞进需批准计数。

单进程服务串行写并复核revision，文件整体原子替换；读损坏时保留原文件并进入可见只读错误，不能写空快照覆盖。历史容量、摘要上限与手动清理策略在首批真实规模测量后设定；event_receipts淘汰必须保留活跃run所需去重键，不静默删用户已结束任务。达到 ADR 0011 判据再评估SQLite。

## 6. 验收

旧Todo增删/勾选/清已完成不变、ID不变；重复事件不重复计数；两个来源相同external ID不串任务；run重跑保留旧历史；旧问题过期禁止本地提交；完成与验收分开；缺来源不误绑；revision冲突拒绝；磁盘写失败/坏JSON留存且提示；来源跳转不批准操作。用固定来源夹具测试，不能真实启动用户Agent任务。

## 7. 首批实施状态

已实现 `tasks.rs` 独立聚合存储、单进程互斥写命令，以及工作台任务页：项目、新建/编辑、四组列表、归档恢复、显式记录进度、人工关口、本地处理、运行历史与产出引用。旧 Todo 命令和文件保留。当前用户命令没有任意来源 URI 参数；来源绑定、语义事件合入与历史会话导航已接入真实引擎和工作台；已核实数据库方言的稳定身份已接入；Codex 问题/完成结果引用及按需只读内容已接入；方案引用、其他工具内容和完整原生验收未完成，不宣称 B2/B3 全部完成。

人工处理等待关口后，记录变为 queued，表示没有执行证据；结果处理保持 ready，不自动 accepted。详情未保存输入阻止破坏性重画，切换工作台页面保留整页 DOM。未修改的详情在控件有焦点时仍接收最新关口与运行记录，按逻辑身份恢复焦点和选区；历史展开状态保留，失效动作聚焦详情，不向其他页面抢焦点。项目表单和任务创建表单保存失败保留输入。

存储上限暂为 8 MiB、20,000 个事件去重键；达到上限明确拒绝新写，保留历史，不淘汰活跃 run 所需去重键。此限制是首批保护边界，历史清理和真实规模测量仍待后续实现。来源仅接受工具 ID、64 位会话指纹和可选 UUID，不保存原始会话路径或内容。

### 会话来源同步推进

真实引擎只把带明确语义信号与具体来源文件的会话放入 `task_sources`。绑定命令复核工具与所选会话指纹，UI 不提交 URL 或路径；未绑定的会话不自动创建任务。Active 还须工具运行且来源文件在工作窗口内更新，过旧/退出状态不生成运行更新。Codex 的提问由现有 request_user_input 解析分支产生，归为待回答；未分类工具提醒仍为需要确认，不猜测方案批准。

来源事件在引擎锁释放后由任务写锁批量合入；同拍同来源事件去重，一次原子写入。新增运行保存来源快照；任务先有本地记录再绑定时，本地历史不变、旧本地关口过期，新的来源记录另起运行。任务页订阅变更并更新列表，编辑中的详情保留；恢复缓存任务页刷新观测。

Codex 导航使用绑定时保存的 UUID，通过既有路由构造 URI；其他工具复用注册表的应用入口并明确标注打开工具。不使用最新无关会话替代历史来源。数据库来源按下节的身份规则进入绑定列表；缺少稳定键、过期或无语义证据的来源仍不列出。Codex 问题/完成结果引用已接入；未核实工具来源、方案引用和原生导航验收仍待完成。

### 轻量投影与工作台导航

`tasks_attention_summary` 提供聚合 revision、当前需处理任务总数、人工/失败分项与单条优先事项。`task_show_workbench` 复核任务/当前运行/revision 后投递单窗口导航，lazy 工作台启动后消费同一请求并选中任务。三壳投影、同会话去重和来源动作已接入；已核实数据库来源身份已接入；Codex 问题/完成结果引用已接入；完整原生导航、未核实来源与方案引用仍按批次验收。

长期计数、来源证据和本地处理口径沉淀到 [ADR 0020](../../adr/0020-local-task-attention.md)，此处仅追踪实施状态。

### 历史运行来源入口

`task_open_source` 已支持可空 `run_id` / `artifact_id`：以聚合 revision 复核，运行必须属于所选任务，产出必须属于所选运行。显式选择历史记录时只取运行保存的来源；旧本地运行和缺来源记录拒绝导航，不回退到任务当前会话。未指定历史记录时保留任务来源入口。工作台运行历史按实际能力显示“打开来源会话”或“打开来源工具”，无来源显示“未保存来源”。导航不改变产出、关口或验收状态。带可信 Codex 事件引用的记录可直接只读查看对应版本；手工摘要没有来源正文。打开来源会话不宣称已滚动至某条产出。

### 数据库来源身份

Dim sessionId、OpenCode 新旧表的 session_id、MiniMax session_id 和状态索引的主键从同一条只读语义查询带出。ZCode 使用 workspace_key + task_id 复合键，不能把不同工作区的同名任务合并。内部上下文保留有界键与必要事件时间，不序列化给界面；持久化任务来源仅保存会话指纹，没有库路径或原主键。源文件目录和库路径变化不会猜测迁移到新来源。

状态索引使用更新时间区分事件版本，会话身份保持稳定；现有运行状态与通知指纹不改变。OpenCode/MiniMax 的活动年龄取所选行的事件时间，避免 WAL 写入未更新主库 mtime 导致来源误失效；未知/未来时间和进程退出不提供活动绑定；OpenCode/MiniMax 的未来时间不再报告当前活动，时间差采用溢出保护。探针的正常库年龄、完成态与未知结构边界继续保留。

同拍重复采样零写；新会话只更新显式绑定自己的任务。已终止运行后出现新的等待事件时另建运行，避免错过中间执行采样就覆写上轮历史。完成不自动验收。尚未核实对应 URI 的工具保持“打开工具”或“无桌面跳转”，不会因取得数据库 ID 就宣称精确导航。沙箱查询/任务存储集成及只读本机观察分别记录；本机无当期语义不证明实际绑定全流程。


### 来源内容直接查看

`task_artifact_content(id, run_id, artifact_id, expected_revision)` 复核任务/运行/产出归属，在后台按工具内置目录查找已保存的来源指纹，读取后再次核对聚合 revision。不接受用户路径或 URI，不查询最新会话替代历史来源。Codex 的 `request_user_input` 问题与带 `turn_id/last_agent_message` 的完成事件保存不可逆事件引用及通用标题；具体选项与结果正文按需从同一事件版本读取，任务文件不保存正文、原路径或原始调用 ID。只有完成事件不自动建立验收关口或进入 accepted。

目录查找最多 10,000 项/深度 5，沿用来源尾窗读取上限，正文上限 64 KiB；缺版本、文件丢失、私密输入、已识别凭据形态和超限明确提示回到来源。凭据形态检查是有边界的保护，不保证识别任意敏感文本。临时读取结束清理该线程的来源缓存。工作台使用纯文本展示，关闭/Escape 清除正文并返回入口焦点；草稿保持，过时请求不重开查看区。方案协议与其他工具内容仍需独立核实。长期口径见 [ADR 0029](../../adr/0029-source-artifact-content.md)。


### Claude 人工关口分型

同一尾窗内产生语义信号的 AskUserQuestion/ExitPlanMode 按对应 tool_use ID 复核，分别投影为待回答/确认方案；观测指纹包含关口类型，旧的通用确认去重收据不会阻止正确分型。问题正文、选项及多选提示按需读取；方案只接受该具体 tool_use 内明确存在的非空 plan 字符串。缺少正文仍保留确认方案关口，工作台说明无法提供正文且不显示查看方案按钮，不读取 planFilePath 或最近的计划文件。工具结果只影响既有语义探针收口，不解释为已批准或已验收。原生来源仍按注册表能力降级为打开工具。

多调用消息逐项检查：同批未收口人工关口优先于执行，正文/分型从选中调用取得；只有调用之后的主会话 user/tool_result 能收口。子会话调用、结果和停止不覆盖主状态。多个人工关口仍显示一个当前摘要，处理后再显露同批其余未收口关口；不新增批准或回答动作。顶层/问题私密标志及已识别凭据使用通用摘要与只读拒绝提示。

官方 hooks 文档明确 plan/planFilePath 为 hook 输入注入字段，不能推导所有 transcript 都带正文。当前本机有界取样没有 Claude transcript，因此测试为实际探针/存储沙箱集成与纯数据浏览器流程，未取得本机真实方案记录的端到端证据。相关长期边界见 [ADR 0030](../../adr/0030-claude-attention-artifacts.md)。

### 会话来源目录

工作台会话页集中 task_sources 的当前语义来源与聚合中每个运行自己的 source；不借用任务的最新source代替历史。按工具/会话指纹/线程身份合并，当前来源优先、历史按运行时间排序，支持工具、当前/仅历史及工具/任务标签查找。未保存来源的本地运行不生成会话项，未归属到任务的运行不采用。历史即使保存running也显示历史记录，不冒充当前执行。

session_open_observed 只接受Source DTO，核对当前Choice完整身份再取服务端target；相同GUI两条会话仍须分别核对指纹，失效拒绝。历史复用task_open_source的运行归属与聚合revision。入口不接收URL/路径、不更改任务、不回答关口。无桌面目标的当前来源不回退历史动作；精确能力与打开工具明确分开。

刷新保留现有内容及筛选；失败停用导航直至重新读取。缓存返回只刷新一次，隐藏页迟到结果不更新当前页面；等待中的重复操作阻止，焦点在结果后回到入口（用户已另行移动焦点时不抢回）。浅深/620px、减少动态及模拟失败/冲突/切页流程已验证，原生验收仍单独执行。

当前task_sources每个工具至多一个选中语义来源，任务历史只覆盖已保存运行；Codex默认普通/归档目录另提供手动枚举，其他工具完整会话清单、更多状态/项目筛选与可信来源能力表仍按整体方案实现。此目录是可用入口，不作为全部会话覆盖证明。

来源初始显示50项，手动逐批增加；查找始终针对完整已读取集合，界面区分已显示与匹配总数。每来源的运行历史按需展开，初始50条，记录可逐批完整到达，任务入口绑定具体run的task ID；不只跳转最新关联任务。关闭释放记录控件，重新展开保留已显示数量；筛选/切页/刷新保持展开状态。

无变化刷新保留行DOM；读取等待期间停用导航，后台刷新保持现有计数，手动读取有等待提示。结果后恢复原入口焦点，末批按钮消失时焦点移到新内容。长标题两行显示，完整文字保留在DOM/提示与任务详情。渐进渲染控制初始DOM，不是固定容量虚拟列表；用户逐批展开后节点仍会增加，全部聚合数据仍在内存。原生资源与完整工具会话覆盖另行验收。


### Codex 默认本机目录

手动 `session_catalog_read` 扫描默认 sessions 与 archived_sessions；只解析未压缩 JSONL 首条 session_meta，头记录 UUID 必须与文件名解析目标一致。前端只得到 Source、工具名、mtime、归档标记和服务端能力，正文、账户、工作目录与指令不返回。目录项与当前/保存来源按完整身份合并；没有关联任务的项仍可搜索与打开，不创造任务或状态。支持路径完整遍历，无4,000条静默上限，深度上限4及无法读取/核验、压缩/缺失逐类计数。手动扫描完整元数据仍随文件数增长，不当成内存预算达标。

打开只接受读取代次和完整Source，后端再次核对原文件设备/inode及首条头；正常追加允许，删除、替换、身份变化或旧代次拒绝。Windows fallback尚未原生验证。失效/读取失败保留可见旧内容并停用目录来源动作，当前来源动作独立；成功重新读取恢复。切走时在缓存页面结算读取结果，返回刷新不会永久停留在加载提示。范围仅 Codex 默认未压缩目录，其他工具、自定义CODEX_HOME、压缩格式仍待接入。

协议依据（2026-10-05核对）：[SessionMetaLine](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/protocol.rs)、[实际JSONL记录测试](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/recorder_tests.rs)、[目录定义](https://github.com/openai/codex/blob/main/codex-rs/rollout/src/lib.rs)。上游后续格式变化须重新校验。

### 详情草稿与版本归属

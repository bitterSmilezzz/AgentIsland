# 28 · 功能重规划与定案过程

> 历史范围收敛与纠错记录。用户最新明确完整Magpie/Todos能力及多渠道即时通知，[ADR 0040](../adr/0040-supervisor-full-integration-requirements.md)与 [需求基线](../需求.md)已取代本文及ADR0039中的只读/无网关/无执行收窄。正文保留演进证据，不充当当前排除清单。
> 2026-10-14 复核基线：`61d3fa3` / `v0.0.323`；此前讨论基于 `07c04ec` / v322。当前工作树另有未提交文档与代码，不能混成已发布能力。

## 1. 需求如何收敛

1. 用户希望借鉴 Magpie 的接口、模型与本地路由能力，重点维护 Agent 灵动岛的准确性与 UI。
2. 用户追加 Todo S（调研库对应 Todos）的任务能力。
3. 本会话弹窗明确选择：配置目录 + 只读协议探测；横幅与系统通知不抢焦点；保持窄条优化层级几何；来源单版本就明说单版本，不复制正文维护历史。
4. 平台主要为 Mac、Windows、移动；Android 先、iOS 后；Web 倒数第二、Linux 最后。近期先完善 Mac 再迁 Windows。

因此当前范围不再等于“完整复制 Magpie 网关”或“完整复制 Todos 执行机”。上游产品能力、当前选定范围、实际实现与验收结果必须分别登记。

## 2. 模块与已有资产

| 领域 | 选定方向 | 已有资产与待核查 |
| --- | --- | --- |
| M0 监控内核 | 准确性优先、可信证据和清楚降级 | 注册表、进程/文件/数据库解析、状态与通知已存在；须按当前工具版本重新核对漏报与误报。v247 的“16 个缺口”和旧“25 家/5 家用量”只代表当时样本 |
| M1 配置与能力 | Magpie 的目录、切换、配置快照思路；只读协议探测 | `provider.rs`、`models.rs`、`interface_models.rs` 已有配置及手动读取；跨工具探测范围按已核实配置确定，不能假设档案存在就能判断运行模型 |
| M2 任务工作流 | 借鉴 Todos 的人工关口、版本绑定与历史表达 | `tasks.rs` 已有 Ready/Accepted、三类专门关口及过期状态、Run/Artifact/Receipt。重点是核查真实来源与 UI 闭环、diff/版本覆盖，不重新新增已有枚举 |
| M3 岛内呈现 | 保留现有窄条，改进层级、几何和动效 | 不把旧 Swift 的 6pt 当当前 Rust尺寸；美观与准确性都要维护，不以“只有几何问题”替代审美工作 |
| 提示词与扩展 | 沿现有安全事务继续完善 | 提示词、MCP、Skills 已有实现与 ADR 0025/0027/0034/0036；外部方案中的“新增模块”先对照存量 |

监控状态、配置目标与用量账本相互关联但不是同一证据。未经过内建网关不妨碍读取本机账本；运行状态不产生可靠账单归因。

## 3. 旧稿的事实更正

| 旧稿结论 | 复核结论 |
| --- | --- |
| 方案确认/结果验收尚未独立、缺 Accepted | `tasks.rs:39` 起已具备相关枚举及转换保护；不能据文档错误安排重复开发 |
| 不架网关就只能同厂商多账号切换 | 限制来自协议兼容性。第三方服务原生兼容客户端协议或使用既有网关时，配置可以指向它；本产品不做翻译和无条件可用承诺 |
| UI 问题的原因不在 UI、美观不必单列 | 用户明确重视美观；视觉、几何、动效和准确性分别分析，不用旧故障否定审美需求 |
| 每个新方言都要真库 DDL | 文件方言用格式/schema/结构夹具；数据库方言才需要 DDL；真实来源验证按授权与隔离条件执行 |
| 保持 6pt 且不改几何 | 用户确认保持现有窄条并优化几何，没有锁定 Swift 的旧尺寸，更没有禁止修正几何 |
| 必须先做 Todo S 才能扩监控方言 | 无此技术依赖；监控重点优先，任务缺口核查和测试基础可独立推进 |

旧稿非已提交历史报告，因此在本文件直接修正；既有 code-review、CHANGELOG 与 validation 时间点证据保持原样。

## 1. 已定边界

桌面主线为 Rust + Tauri v2 + 静态 HTML/CSS/ES Modules + Rust CLI，见 [ADR 0016](../adr/0016-rust-only-main.md)。移动端与 Web 的具体技术尚未定案；Tauri 的移动支持不意味着当前桌面模块可以直接运行在手机上。

用户确认的主要平台为 Mac、Windows、移动端；移动端 Android 先、iOS 后，Web 倒数第二、Linux 最后。近期执行顺序为 Mac 定方案 → 跨平台技术完善 Mac → Windows 迁移。业务方向见 [ADR 0039](../adr/0039-feature-plan-and-monitoring-kernel.md)。

目标是减少漏接测试、旧产物假通过、环境缺失和回执误判，不能保证后续自动化永远不出问题。框架本身也需要失败注入与独立复核。

## 2. 已核实的测试资产与真实缺口

| 事实 | 证据与限制 |
| --- | --- |
| Rust 已有大量内联测试和独立测试模块 | 先前 `cargo test --list` 枚举为 973 条；枚举不证明执行通过。工作树仍在变，数量不是长期门禁阈值 |
| JS 脚本含纯数据、桩 DOM、三种壳变体和真实浏览器测试 | [release.sh](../../scripts/release.sh) 同时用直接命令和 `for` 列表执行；不能全文搜完整文件名来断言没接入 |
| 发布中已运行脱敏、脚本自测、JS 和 Rust 回归 | `release.sh:124` 起执行脚本回归，`:180` 执行 Rust；`:186` 构建，`:188` 重启，之后才进行 CLI 与原生门禁 |
| 依赖已入库 | [package.json](../../package.json) / [lock](../../package-lock.json) 已被 v323 跟踪；Playwright 为固定版本开发依赖，不能再写“未跟踪，待决定是否入库” |
| CI 与发布测试覆盖不一致 | [build.yml](../../.github/workflows/build.yml) 的 macOS job 主要执行 Cargo check/test；独立 JS/浏览器/扫描自测没有等量接入 |
| 缺少独立于发版的全套编排入口 | `cargo test` 与 `npm run test:browser` 各管部分；运行完整 `release.sh` 会重启、暂存、提交、推送和发 Release，不能充当日常测试命令 |
| 部分测试依赖隔离 VM / 官方客户端 | 原生动画、官方 Claude 取证等须显式选择环境；不能用普通机器缺环境冒充通过，也不能要求每次快测都准备 VM |

脚本文件数、命令数、测试用例数和执行变体数是四种不同计数。落地时由清单与实际运行结果生成，不沿用旧稿未可靠复核的“45 个脚本”及“7 个零引用”。

`untested-surface.py` 是零引用报告，不是覆盖率工具。它曾失效，不意味着 Rust 的正规覆盖率工具不可用；是否引入覆盖率须评估 Tauri/平台依赖、采集成本和有意义的分支，不能用一个总百分比代替行为验收。

## 3. 编排建议：跨平台 runner + 单份清单

建议复用已有 Python 3 作为编排器，例如 `python3 scripts/test.py <profile>`，命令以 argv 数组交给 subprocess，不经 shell 拼接。Mac 可提供薄包装，Windows 使用 `py -3` 或安装好的 Python。现有 Bash 脚本保持在其支持的环境运行，不能把 Bash 当作全平台原生依赖。

以下文件与命令均为设计示例，尚不存在：

- `scripts/test-manifest.json`：单份清单，登记 test ID、层、argv、cwd、环境键、平台、profile、超时、依赖、输入产物、是否有副作用，以及外部环境测试的理由。
- `scripts/test.py`：预检、执行、超时清理和结果汇总；本地与 CI 共用。
- `scripts/test-runner-tests.py`：验证 runner 自身与清单覆盖，使用临时目录和假子进程，不碰真实 App 或用户数据。

新增测试必须登记；登记重复 ID、缺文件、未知 profile、平台不匹配均明确报错。扫描 `test-*.py/mjs/sh` 检查遗漏；非此命名的原生 probe、客户端检查、诊断脚本也须显式分类，报告工具不冒充阻塞测试。

## 4. 分层与产物先后关系

| 层 | 内容 | 前置与副作用 |
| --- | --- | --- |
| A · 仓库卫生 | 版本一致、工作区脱敏、diff 格式、清单自检 | Git/Python/Bash 等真实依赖；不修改索引或安装钩子 |
| B · 核心回归 | Rust 状态、解析、存储、事务、CLI 规则与契约夹具 | 工具链及系统库；平台专有测试按适配证据运行 |
| C · 前端逻辑 | 纯数据、桩 DOM、三种壳、导航/草稿/异步生命周期 | Node；完整统计 `release.sh` 的直接调用和循环变体 |
| D · 浏览器 | 真实 DOM、键盘、焦点、双栏滚动、正文离页等 | 锁定 Playwright 包与浏览器安装；失败保留可脱敏产物 |
| E · 正式构建与随包 CLI | 新包构建、签名/哈希、真实 CLI 参数与用量 | A–D 通过后构建；CLI 用隔离 HOME/受控命令 |
| F · 原生验收 | UI/Dock/单实例/CLI/窗口释放 | **必须使用 E 产生的同一正式包**及隔离 VM，不拿旧包代替 |
| G · 专项 | 长时资源、原生动效、官方客户端/协议取证 | 独立环境、时长与清理契约；普通快测不包含，变更需要时显式执行 |

发布链保持：扫描 → 构建前回归 → 构建/签名 → 随包 CLI → 同包原生验收 → 明确发布文件清单 → 提交 → 历史扫描 → tag/push/Release。不能用“全部测试前移”破坏原生测试的新包前置。

日常测试不重启宿主 App、不暂存、不提交、不访问真服务。发布脚本的更新/重启策略继续遵循现有约定；编排复用测试阶段，不搬入发布副作用。

## 5. profile 与结果契约

建议 profile：

| profile | 用途 | 包含范围 |
| --- | --- | --- |
| `fast` | 开发反馈 | A 的轻量检查 + 明确选定的 B/C；不称完整验收 |
| `ci` | PR/持续集成 | A–D 中在该 runner 可运行的完整集合 |
| `package` | 候选包验证 | E，显式绑定构建与依赖回归结果 |
| `native` | 正式包原生验证 | F，缺包/VM 为阻塞 |
| `resource` / `client` | 专项协议 | G，环境与负载单列 |

独立、无副作用的层可以失败后继续以便汇总；依赖失败时，下游记为 `blocked`，不能继续测试旧产物。结果分 `passed / failed / blocked / not_selected / not_applicable`，每条都带理由；被选中的必需检查缺依赖是 blocked 并使总退出非零，不能计为 passed。

每次生成独立 run ID，绑定 HEAD、工作树指纹、工具版本、命令 ID、目标平台、时间、退出码和构建哈希。汇总可用 JSON/JUnit；输出不含凭据、个人会话、任意环境变量或未脱敏子进程正文。报告写忽略的产物目录。超时、中断、部分结果、清理失败均不可算成功；重跑保留原失败，不自动放宽断言或重试隐藏 flaky。

## 6. 平台状态与 CI

| 目标 | 当前可宣称 | 后续门槛 |
| --- | --- | --- |
| macOS | 有正式交付和原生分项验收，完整业务/资源验收仍开放 | 现有 Cargo、JS、浏览器和同包原生证据分别保存 |
| Windows | 有编译/测试观察 job，移植未完成 | 先在真实 runner 查依赖和编译，再查测试及 WebView2/权限/DPI；工作完成的层逐步转阻塞 |
| Android → iOS | 用户确定优先级，产品形态和技术尚未定 | 先验证共享核心与目标壳，不假定桌面 Cargo 测试全部适用，也不假定纯原生 UI |
| Web | 低于主要平台，未交付目标应用 | 前端浏览器回归不等于 Web 产品通过；另定 transport、鉴权与部署 |
| Linux | 最低优先级，未交付验证 | 到排期时核实依赖、桌面协议和权限 |

CI 明确安装 Node/Python/Rust、系统依赖和 Playwright 浏览器，复用同一清单；普通 hosted macOS CI 不等于已认证的 Tart 原生验收环境。Windows 现有非阻塞观察先保留，不将 Bash 脚本直接塞进默认 PowerShell job。

平台台账记录能力、证据与阻塞，不用行号/错误数作为唯一主键，也不要求新发现只能减少。保留现有 ratchet 直至新机制能覆盖同样失效面；禁止空台账自动表示全通过。

## 7. 实施建议与完成标准

1. 固定真实清单、profile、执行依赖和产物契约；保留现有脚本。
2. 实现 runner 及有判别力的自测：失败退出传播、超时子进程回收、缺依赖、遗漏/重复登记、坏回执、旧包哈希、部分清理与中断。
3. 先与现有发布回归对拍命令及变体，再接 macOS CI；只有同等门禁得到证明才删除旧重复清单。
4. 让 `release.sh` 分阶段复用 runner，保持“新构建先于随包原生”的顺序；不在本轮梳理中执行。
5. Mac 验收基准稳定后迁 Windows；移动/Web/Linux 在各自阶段新增实际适配与环境证据。

完成意味着：新测试漏登记会失败；被选中检查缺环境明确非零；一次候选包的回归、哈希、原生与清理能串成同一证据链；运行测试不会暗含发版。耗时在首次基准后报告，旧稿“两分钟、零依赖、全平台可跑”的承诺撤回。

# 界面品质基准与验收

以 Awwwards / FWA 获奖作品的完成度为设计目标，落实到常驻桌面控件的克制、清晰、连贯和细节一致。奖项目标不是可自我授予的结论；内部验收记录具体证据，不用“已获奖级”替代验证。

## 一手参照与适用范围

2026-10-03 核对：[Awwwards 官方获奖评分页](https://www.awwwards.com/sites/str8fire)展示设计、可用性、创意、内容及开发奖中的动效、无障碍等维度；[FWA 官方介绍](https://thefwa.com/FWA25/25.html)强调创意、原创性与技术品质。这些是网页奖项参照。下表是针对常驻桌面工具的内部转译，不代表官方评分、参赛资格或获奖结论。

## 必须通过的标准

| 维度 | 验收要求 | 验证方式 |
| --- | --- | --- |
| 连贯 | 一个持久圆角表面，文字不缩放；进入与返回节奏不同 | 实际模块的逐帧几何与截图 |
| 稳定 | Agent 用量返回无尺寸反弹、无结束跳帧；采样不重播导航 | 延迟 viewport 回归、采样高度变化、原生复核 |
| 定位 | 上下左右四边的贴边锚点保持一致；原生窗口只预留/收回空间 | 四边中间帧与落位次数 |
| 异步 | 报告晚到、快速返回和连续跳转不会卡住、留下旧页或覆盖新页 | 延迟报告和中断重放 |
| 简洁 | 设置常用项首屏可见；细项默认折叠，全部字段保留 | 330px 原生尺寸、打开更多设置 |
| 视觉 | 分组、文字、控件对齐一致，浅深色均清晰；无横向溢出或截断 | 两种主题截图和尺寸检查 |
| 操作 | 鼠标和键盘都可访问，焦点回到来源；保存失败回滚并提示 | 现有保存回归、Tab/Enter/返回 |
| 减少动态 | 系统减少动态效果时直接切换，控件停用过渡 | reduced-motion 检查 |
| 交付 | 语法、Rust 回归、版本与脱敏门禁通过，真实新应用重启 | 脚本输出与原生检查 |

## 灵动岛四态几何与编号行为规则

> 2026-10-14 文档复核：本节记录的四态方案与 [ADR 0039](../adr/0039-feature-plan-and-monitoring-kernel.md)及本会话“保留现有窄条、不增加展开档位”的选择冲突。保留并行会话记录，不推断其授权先后；本节几何值与 R1–R12 暂不作为本会话的已批准门禁。前文现有品质标准继续适用。冲突登记见 [文档梳理报告](../agent/project-document-audit-2026-10-14.md)。

原并行记录：2026-10-14 用户拍板，灵动岛不再按「一条窄条」设计，改为**四个有确定几何的态**。
本节是判据，每条须有可执行用例；未列出的行为默认沿用上表。

### 0. 为什么要有编号

上一轮「窄条放什么 / 是否允许改形态」长期停在描述性讨论里，两边都成立。
把状态写成有编号的规则后，「什么时候打扰 / 什么时候安静」才成为可测判据，
「美观度不足」才有可归因的对象。**规则编号一旦公布即成为门禁依据，改规则要先改本节。**

### 1. 四态几何契约

| 态 | 宽度 | 角色 | 次要 Agent |
| --- | --- | --- | --- |
| `hidden` | 刘海自然宽（wN） | 完全不可见 | 不可见 |
| `peek` | wN + p | 主体 Ø≈18，居中 | 不可见 |
| `compact` | wN + c | 主体 Ø≈20，视线跟随 | **网格承载**（2×2，详见 R4） |
| `expanded` | 固定宽度 e | 按视图 | 按视图 |

`p` / `c` / `e` **本轮留空待定**，不得沿用外部项目的数值——
参照项目的偏移量是按它自己的刘海尺寸算的，直接抄会错位。
定值时须同时确定：无刘海屏（面板落到顶部居中）与缩放/旋转显示器的逻辑坐标换算。
主体在 canvas 中占比固定 60%，其余留给粒子、手部与角标。

### 2. 编号行为规则

| # | 规则 | 验收方式 |
| --- | --- | --- |
| **R1** | 无任务运行 → `hidden`，完全不可见 | 静默 10 分钟截图，岛区域无任何像素 |
| **R2** | `hidden` 时指针到达刘海 → 立即 `peek`；停留 650ms → `expanded`；中途离开 → 600ms 后回 `hidden` | 三段定时回放 |
| **R3** | 有任务运行且用户活跃 → `compact`，主体视线跟随光标 | 移动光标截图 |
| **R4** | `compact` 下次要 Agent 收进 **2×2 网格**；1 个居中 / 2 个并排 / 3 个上二下一 / 4 个成方阵；≥5 个折叠为计数角标 | 四种数量各截图 |
| **R5** | `compact` 悬停 200ms → `expanded`；点击主体 → 立即 `expanded` | 定时回放 |
| **R6** | **无鼠标移动达阈值（默认 3 分钟）→ `hidden`，即使有任务运行**；首次移动回来 → 有任务则回 `compact` | 静置计时回放 |
| **R7** | **告警（权限 / 提问 / 错误）自动展开，且不自动关闭，直到被回答**；用户离开期间同样触发 | 静置中触发 + 不回答，持续观察不收起 |
| **R8** | 任务完成 → 展示完成视图 5.2 秒后移除任务并收起 | 完成时序回放 |
| **R9** | 多条告警同时到达 → **排队，一次一个**，按到达顺序 | 注入 3 条并发告警 |
| **R10** | `expanded` 后 60 秒无活动自动收起；**最后 10 秒底部显示倒计时**（160pt→0 的横线，白 35%）；`Esc` 立即收起 | 静置到第 50s 与第 58s 截图 |
| **R11** | 焦点模型：主体代表 focus 任务（最后一条告警，否则第一个在工作）；点击次要 Agent 切换焦点 | 多任务切换 |
| **R12** | 展开时眨眼；`open` / `close` 各一声；音效为运行时合成，不携带音频文件 | 逐项触发核对 |

### 3. 与「外发与在场」的边界

R6 是「完全不打扰」的实现，R7 是「必须被打扰」的例外。
**二者按事件类型分级，不是全局开关**：运行状态可静默降级，告警独占且不设超时。
不存在「所有状态一律弹出」或「所有状态一律静默」这两种形态。

## 每轮执行流程

1. 记录现状与具体问题，建立能失败的复现信号。
2. 只修改能解释该问题的实现；设置优化保留原有字段和保存语义。
3. 使用模拟数据检查首屏、浅深色、展开细项、异步内容、中断和四个贴边方向。
4. 逐张查看截图，发现截断、冗余滚动、控件比例或对齐问题就修正并重测。
5. 构建并自动重启，核对原生界面的进入和返回。模拟浏览器检查不能替代原生结果。
6. 在独立 review 中记录发现、修正、命令结果、未完成门禁；发版执行现有 release 链路。

## 本轮关注点

Agent 用量返回先核对 native viewport 交接；设置以六项常用控制为首屏，其他内容折叠。保持 330px 宽度、固定返回栏和独立滚动正文。检查默认首屏是否需要滚动，而不是仅检查页面是否存在。

## 回归入口与验收记录

```sh
node scripts/test-island-return.mjs
node scripts/test-island-click.mjs
node scripts/test-island-motion.mjs
node scripts/test-functional-ui.mjs
cargo test --locked --manifest-path app/src-tauri/Cargo.toml
```

原生检查：展开 → 点击 Agent → 等待用量 → 返回；再进入设置，检查常用项、键盘展开更多设置和正文滚动。重复快速返回和报告加载时返回。四边和主题使用模拟数据检查，避免为测试改动用户偏好。自检发现必须写明“现象 → 修正 → 重测结果”；有未通过项时不能将整轮标记为验收完成。

2026-10-03 返回复查：原生几何记录曾出现 300×344 后再次变为 300×328；验收需要覆盖返回后采样更新，而不只检查导航结束时的尺寸。使用真实前端移除动作文字，确认高度变化进入表面过渡，正文和焦点不重播。macOS 包络主线程单次提交的依据为 [Apple NSWindow setFrame 文档](https://developer.apple.com/documentation/appkit/nswindow/setframe(_:display:animate:)) 与 Tao 的两个独立异步 setter 实现。

A1 viewport交接回归：故障注入360ms尺寸反馈复现原240ms等待到期后提前settled；另一夹具复现匹配一帧后回退却解除几何。成功条件收紧为目标viewport连续两帧匹配，超时走失败清理而非成功回调。两类复现及完全无反馈场景均纳入test-island-return；这是模拟控制器证据，不替代真实窗口逐帧验收。

# 07 · 综合方案：一款跨 Agent 的管理工具

> 本文是前面所有输入的收敛处。用户先后给了五类材料：
> ① 本项目的预期变化（侧边栏/极简首层/高级设置/低占用）② [CC Switch](https://github.com/farion1231/cc-switch)
> ③ [Magpie](https://usemagpie.ai/) ④ [OpenSquilla](https://github.com/TokenRhythm/opensquilla)
> ⑤ 陈大黄的 [Cloudflare 边缘架构推文](08-chendahuang-cloudflare-research.md)（实现思想的一种）。
> 本文回答一个问题：**这些合在一起，产品是什么。**

## 0. 先说定位（用户已明确）

> 「我们这个项目不做 Agent，而是做一个跨 Agent 的管理工具，并补充一些从开源项目中获取的经验。」

这句话是全部设计的前提。它直接否掉了三条诱人的路：

| 诱人的路 | 为什么不做 |
| :--- | :--- |
| 自己当 agent（OpenSquilla 的形态） | 我们是**管** agent 的，不是下场当 agent |
| 架 LLM 网关（Magpie 的形态） | 那会让本产品"转发 Agent 的全部流量"，性质从监控变成中转 |
| 用 ML 做模型路由（OpenSquilla 的路由器） | 为"切哪个模型"引入 LightGBM + 训练数据 + 特征工程，收益/复杂度比不成立 |

**所以三个开源项目都不是功能来源，是经验来源。** 这一点先说清，否则方案会写偏。

## 1. 产品定义

**AgentIsland 是一款跨 Agent 的本机管理工作台。** 它知道你机器上每个 AI 编码 agent
此刻在干什么、花了多少 token、用的哪个模型/账号，并能替你管这些配置与待办。

三个名词撑起它：

| 名词 | 含义 |
| :--- | :--- |
| **跨 Agent** | 同时管很多个 agent（Claude Code、Codex、Cursor、Cline、OpenCode…），不是某一家的配套 |
| **本机管理** | 读写本机配置、读本机会话日志、统计本机 token。**不碰网络、不转发流量、不持有密钥** |
| **工作台** | 侧边栏常驻，极简首层 + 高级设置详情，低资源占用 |

### 1.1 一句话

> 机器上所有 AI 编码 agent 的状态、花费、配置与待办，一个侧边栏看完、管完。

### 1.2 我们与相邻产品的边界

| 产品 | 它做 | 我们做 | 分界 |
| :--- | :--- | :--- | :--- |
| **CC Switch** | 切换 agent 的 API Provider 配置 | 也做，且保留注释缩进地原子写 | 重叠，但我们的切入点是"管全部 agent"而非"切 provider" |
| **Magpie** | 网关：拦请求、翻译协议、多账号调度 | **不做**。只做配置层，并在界面写明"不含跨厂商模型" | 我们不让流量过手 |
| **OpenSquilla** | 自己当 agent + harness-native 路由 | **不做**。只借它的诊断回放/权限降权/计價口径 | 我们不当执行者 |
| **系统活动监视器** | 看全部进程 | 只关心 agent 这类进程，且懂它们的会话语义 | 我们从进程往下钻一层 |

## 2. 四个能力面

### 2.1 看清（已有资产，本轮保住的）

五态状态机（`offline`/`idle`/`working`/`attention`/`completed`）、五种会话方言尾读、
CPU 差分、Token 净消耗统计、死锁三态、可观测性五类结论。

这是本产品的**地基**，也是与相邻产品最硬的差异——CC Switch 不知道 agent 此刻是否卡死，
我们知道。

### 2.2 管配置（来自 CC Switch， Phase 2）

保存/切换/还原 agent 的配置文件档位。**只做本机实扫到的 Claude Code 与 Codex 两家。**

能力边界必须对用户讲明：它切的是**同厂商多套 key/账号**，不能让 Claude Code 用上 Kimi。
原因见 [05-magpie-research.md](05-magpie-research.md)。

工程要求：原子写时**保留配置文件的注释、顺序与缩进**（学 Magpie 自述做到的一点）。

### 2.3 管待办（来自 ToDos，Phase 3）

本地清单：标题 + 完成态 + 创建时间。无分组无标签无日期。
落 `data_dir/agentisland/todos.json`，损坏降级为空清单而非崩溃。

### 2.4 管得安心（来自 OpenSquilla 的经验，待办项）

三条可落地，不阻塞当前 Phase：

1. **Guest 降权三原则**补进 `LocalEventServer`：认证失败与未认证同权；远端不进审批队列；
   边界在所有执行面一致。这是本项目**已知的安全短板**。
2. **脱敏清单补上下文敏感项**：现有规则不含客户名/项目名/channel 标识。
3. **诊断可回放**：把"刚才发生了什么"做成可导出、可安全分享的决策日志
   （含"证据被脱敏后结论退化但退化要说出来"）。

## 3. 界面：双形态 + 极简首层

### 3.1 两种形态并存（用户已确认）

| | 灵动岛（保留） | 侧边栏（新增，主形态） |
| :--- | :--- | :--- |
| 尺寸 | 372×520 | 窄高可拉伸 |
| 键盘 | 不接 | 接 |
| 模块 | 仅"看清" | 看清 + 管配置 + 管待办 + 高级设置 |
| 气质 | 不打断注意力的被动感知 | 键盘可达的信息密度 |

**为什么不二选一**：`AgentIsland` 这个名字的隐喻与 38 个版本的品牌资产都绑在灵动岛上，
删掉它名字一起失效；而侧边栏给的键盘可达与信息容量是灵动岛给不了的。两者不可互替。

`shell_mode` 默认 `island`，老用户首屏零感知。

### 3.2 侧边栏信息架构

```
┌──────────────┬─────────────────────────┐
│ ◆ AgentIsland│  [极简首层]              │
│              │                          │
│ ▸ 看清   3   │  当前活动 Agent 一览       │
│ ▸ 配置       │  + 一行摘要               │
│ ▸ 待办   5   │  + 「高级设置 ›」          │
│              │                          │
│ ⚙ 高级设置    │   ← 全部详情从此进        │
└──────────────┴─────────────────────────┘
```

首层**只放监控摘要**：Agent 不工作时连列表都收起，只留呼吸灯。
侧栏图标带计数：看清=活跃数、待办=未完成数、配置=当前档位名。

**朴素入口进丰富详情**——这是你要的"入口简单、内部信息丰富"。

## 4. 技术路线

Tauri v2 + Rust 核心（`app/` 已跑通）。Rust 核心 2670 行中约 2100 行（79%）与界面形态无关，
直接复用；只有 `main.rs` 窗口壳与 `placement.rs` 定位按 `shell_mode` 分派。

新增 `provider.rs`（~数百行）、`todos.rs`（~百行），前端新增 `sidebar.css` 与三个模块页。
`css/tokens.css`（三端同源设计令牌）零改动。

## 5. 成本与风险（诚实的部分）

### 5.1 这一版拿不到什么

| 拿不到 | 为什么 | 何时可能有 |
| :--- | :--- | :--- |
| 让 Claude Code 用 Kimi/DeepSeek | 需要网关做协议翻译，用户已确认第一版不做 | 独立立项 |
| 管 15 个 agent 的模型切换 | 本机只扫到 2 家有配置文件 | 用户装了就加 |
| 待办分组/标签/日期 | 轻量优先，最小集先行 | 有真实需求再扩 |
| 资源占用优化 | 用户口径：先做完再评估 | Phase 4 之后 |

### 5.2 最大的两个风险

1. **泻密**：管配置就要碰真实 API key。对策：密钥只走文件不进 DTO、不进日志，
   掩码层做成**结构断言**（有测试盯着，不靠"记得加"）。
2. **双形态让代码翻倍**：对策：`island` 分支零改动、共用组件抽到独立文件、两壳不共根容器、
   切换 10 次无窗口残留纳入验收。

## 7. 三个开源项目分别贡献了什么

| 项目 | 贡献 | 性质 |
| :--- | :--- | :--- |
| **CC Switch** | 一块功能：agent 配置的保存与切换 | 功能来源（唯一） |
| **Magpie** | ① 一条必须讲明的能力边界 ② 保留注释缩进的原子写 ③ 信息架构参考（菜单栏面板一格一 agent 一模型） | 功能边界 + 工程实践 |
| **OpenSquilla** | ① 诊断可回放且"退化要说出来" ② Guest 降权三原则 ③ 模式名只用一代 ④ 分享前脱敏清单 ⑤ "省一次按下游计价" | 经验（无功能） |
| **陈大黄（推文）** | 一条实现思想：**把偶发峰值交给有弹性的底座，自己的代码只写业务本身**；"不自己写守护进程/连接池"的等价纪律 | 思想（无功能，本产品不上云） |

**一句话总结：三个开源项目里，只有一个给了功能，另两个给了边界感和工程纪律。**

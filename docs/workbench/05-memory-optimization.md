# 后台内存优化：测量与实施方案

状态：方案阶段。用户要求先分析、识别模块、制定策略；本文件不表示性能改造已实施。

产品约束：常驻态是贴边小控件 + 托盘、Agent 监控、IM 远程通知、Token 计量。工作台可逐渐扩展为重型应用，但只能在用户主动打开时承担其资源成本。Tauri 不是必须保留的前提：优化无法达标时，可拆分进程并替换 UI 技术方案。不能通过暂停必要监控或丢弃计数实现低内存。

## 1. 实测基线与边界

2026-10-02，正式应用默认启动、未手动打开工作台，v0.0.287 主进程：

| 指标 | 单次实测 | 解释 |
| --- | ---: | --- |
| 主进程 RSS | 约 585 MiB | 驻留页，不能与所有子进程直接相加当独占内存 |
| 主进程 physical footprint | 521.8 MiB | vmmap 报告的物理占用；peak 570.0 MiB |
| Malloc Large (empty) | 驻留 250.3 MiB，交换 213.8 MiB | 有大量已经空闲的大块分配区域；不能把它们当仍存活的 Token 对象 |
| malloc zone bytes allocated | 15.9 MiB | zone 表的活跃分配，不代表进程所有框架/映射/图形内存 |

同一启动时间附近有三个 WebContent，RSS 约 32/61/57 MiB，GPU 约 39 MiB、Networking 约 4 MiB。它们由 launchd 托管，不能靠父 PID 精确归属；这是候选关联，不作为已确认独占进程合计。没有关闭其他应用验证归属。

同一未重启进程的后续样本出现 RSS 约 291 MiB、随后 footprint 395.4 MiB；采样期间有构建活动，不能据此认定优化收益或稳定下降。占用会波动，需要统一时点与系统负载。

工具：`ps -axo pid,ppid,rss,comm`、`vmmap -summary <应用PID>`。只输出指标；完整本机进程与映射摘要留在忽略目录。单次样本没有证明泄漏或长期稳定趋势。

## 2. 确认的非必要工作与待验证模块

- **隐藏窗口已创建**：tauri.conf.json 同时声明 island/sidebar/workbench。visible=false 仅隐藏，未延迟创建。启动只需要当前常驻形态；未打开工作台时不需要工作台 WebView。
- **关闭只是隐藏**：conceal_workbench_window 和 CloseRequested 保留工作台实例；没有空闲销毁策略。
- **隐藏页面继续更新**：workbench 的 engine://tick 回调始终保存快照并 renderWorkbenchMonitorOnly；后台侧边栏也订阅更新。engine_loop 向应用广播快照。
- **数据缓存缺少全局字节预算**：Token 明细是每文件 20,000 条、70 天窗口，状态表触及 8,000 个文件后删一批。单文件上限不是全局内存上限；峰值 collected/unique/fold 临时集合也需要量化。不能直接丢历史，ADR 0007 要求累计保和。
- **分配高水位待定位**：大块 empty malloc 是实测信号，但不能直接归因 WebView 或 Token。JSONL 按行读，不过完整 Value 仍会物化正文；DSH 投影使用 read_to_string。需追踪一次启动/扫描/分析请求分别引起的分配。
- **不值得优先做**：缩小图标、微调 CSS、替换几个字符串不会解释数百 MiB；也不应先换整套桌面框架或强制清空正确的累计数据。

## 3. 分阶段策略

| 阶段 | 具体动作 | 风险与验收 |
| --- | --- | --- |
| P0 基线与归因 | 记录启动 30s、5min、30min；首次打开、隐藏、再次打开；分主进程 footprint/候选 WebKit/CPU；给 Token 索引记录文件数、明细数、去重键数、容量与扫描峰值，不记录正文 | 没有归因前不承诺具体省多少；区分存活对象、allocator 保留页、压缩/交换 |
| P1 按需窗口 | 默认只创建当前 island 或 sidebar；工作台首次点击托盘/深链/快捷入口才创建；多次同时请求只创建一个 | 保留 macOS 材质、Dock 显隐、单实例；导航先入队，新窗口拿最新快照后首绘，不能等下一次 tick 才显示 |
| P2 隐藏页面暂停 | 隐藏后暂停 DOM 刷新、报表请求与页面定时任务；事件只保留一个最新快照，恢复时一次补齐；发动机监控和通知继续运行 | 分开 UI 渲染生命周期与监控生命周期，不因工作台隐藏漏掉等待确认/完成通知 |
| P3 工作台回收 | 明确关闭可销毁；普通隐藏保留短暂宽限期，候选 60–120s 后销毁；保存页面/窗口位置/滚动位置 | 先处理未保存表单和待办草稿；不能把密码、Webhook 或通知凭据序列化到文件；支持用户选择保持工作台常驻 |
| P4 主进程数据预算 | 先追踪大块分配来源；对读取器使用选择性反序列化/流式提取，避免物化正文；复用小缓冲，裁掉巨型缓冲容量；Token 索引采用全局字节预算、LRU、历史按模型/时间折入 | 超预算不得静默少算或跳过长行；冷扫描与增量计数必须一致，累计、24h、图表和通知阈值回归必须通过 |
| P5 后台调度 | 精简重复 clone/序列化；UI 只向可见窗口发布，隐藏窗口只留最新值；未打开分析页时不预构建明细图表；空闲扫描降低频率、文件戳变更触发更新 | 托盘/贴条状态仍及时；新鲜 Token 增长、阈值和远程通知不能被降频破坏 |

先做 P0+P1+P2；因为它们既可测又有明确闲置工作证据。P4 的分配追踪同步推进：主进程 522 MiB 说明单靠关掉一个 WebView 未必足够。是否实施 P3 的销毁时机，在验证草稿恢复后定案。

## 4. 目标与验收

候选预算：后台仅贴条+托盘时，已确认归属的整体 footprint 目标约 100 MiB，暂定 150 MiB 为进入架构替换评估的上界。Rust 服务目标 30–50 MiB，其余预算给常驻控件和平台运行时。不能把 UI 子进程排除后宣称达标；共享页用进程组工具复核，避免重复计数。这是待基线验证的工程目标，不是当前实现承诺。工作台冷打开目标 1s 内首绘，热恢复 300ms 内；需在真实机器记录 p95。

- 连续空闲 30min，内存不持续线性增长；打开/关闭工作台 20 次后回到可解释的稳定范围。
- 主进程、WebKit、GPU 分开报；以 footprint 为主要内存指标，RSS/压缩/交换辅助，避免重复相加共享页。
- 未打开工作台时窗口登记表不包含 workbench；需要时一份实例，所有导航入口正确。
- UI 不更新时 CPU 接近空闲；贴条、菜单、监控、Token 计数、阈值、IM 通知仍正常。
- 数值通过相同输入的冷/热扫描对照；全局预算不得使累计缩水。
- 应用重启、Dock 显隐、单实例、三形态 UI、凭据脱敏门禁全部通过后才发版。

最终生命周期决策应进入 CONTEXT / ADR；测量数据与本阶段计划仍放本文件，不把未实施方案写成 README 功能。

## 5. 无法达标时的架构路线

先测一个不创建工作台、不创建第二常驻窗口的版本，以及单独运行 Rust 监控核心的版本；用差值判断 UI 固定成本和监控分配成本。如果核心自身过高，先治理读取/缓存/allocator 高水位；替换 UI 不会自动修复核心分配。如果 UI 固定成本占主要预算，进入下一路线，不无限微调 CSS 或开关掩饰。

```text
轻量常驻服务（Rust）
  ├─ Agent 状态 / Token 账本与阈值 / IM 通知 / 钥匙串
  ├─ 托盘 + 一个轻量原生贴边控件
  └─ 用户主动打开 → 独立工作台进程
                       ├─ 工作区 / 报表 / 配置 / 后续重型功能
                       └─ 明确关闭 → 退出进程并归还工作台资源
```

- 工作台通过本机 IPC 获取小快照与按需明细；不复制完整会话库，不重跑第二套监控，不接管通知队列。凭据留在服务与钥匙串，不传递给前端持久化。
- 可先保留现有 Web 工作台代码作为独立 UI 进程；常驻贴边控件若 WKWebView 固定成本仍过高，改为原生平台控件。Rust 跨平台核心和共享协议保留，平台 UI 用适配层实现，不恢复归档 SwiftUI 端。
- 工作台崩溃、更新或退出不得中断通知和计量；服务与 UI 分别测量启动/稳定/销毁曲线。
- 全部替换是最后一个工程选项，不先假定新框架更省内存。候选方案须用真实贴边交互与相同监控输入做小原型，比较内存、空闲 CPU、冷启动、平台一致性和维护成本，再定案。
- 一轮有边界的窗口/后台优化若仍不能接近预算，立即评估进程拆分/原生常驻 UI；不以“现在用的是 Tauri”作为继续接受数百 MiB 的理由。

# 功能融合与双入口方案

2026-10-03。整体产品、现有功能、技术栈与体验方案见 [26 号](26-product-master-plan.md)。本文承接功能融合细节，是一份待实施的产品方案；下面的“目标”不代表功能已经可用。当前可用能力以 README 和实现为准。

## 1. 产品方向

AgentIsland 作为本机智能体工作台，统一状态、会话、任务、配置与窗口。灵动岛回答“现在发生了什么，我要处理什么”，工作台回答“如何组织、配置和复盘”。同一份数据模型支撑两个入口，不为每个外部工具再造一套导航。

**放进灵动岛的条件**：高频、即时、无需复杂表单，通常一次点击完成。默认只显示在线状态、明确的待确认/完成/异常原因和单行用量摘要；通过渐进展开承接少量快捷操作。

**放进工作台的条件**：需要比较、编辑、预览、权限、历史、批量操作或撤销。重模块进入页面后才加载。

## 1.1 功能融合的交付口径

用户明确：拆解上游产品的能力，转译成 AgentIsland 内建功能。连接上游应用、打开官网、读取外部服务状态只是可选互操作，不能计为功能融合完成。产品不要求安装 CC Switch、Magpie 或 Todos 才能使用相应内建能力。保留外部连接作为次级入口，停止以连接适配数量衡量主线进度。

| 借鉴来源 | 拆出的内建能力 | 工作台交付 | 灵动岛承接 | 验收依据 |
| --- | --- | --- | --- | --- |
| CC Switch | 接口/模型档位治理、作用范围、差异、备份回滚、MCP/Skills 管理 | 共用配置核心，逐工具核实文件与写入能力；支持预览、冲突拒绝和还原 | 经验证的快捷选择与生效提示 | 不启动 CC Switch，也能完成配置流程；只读清单不计为编辑能力 |
| Magpie | 工具与模型的紧凑选择、统一目录、配置快照 | 本地模型按接口与协议去重；直接选择档位并复用差异/备份流程 | 稳定后提供与当前工具相关的单项快捷动作 | 不启动 Magpie，也能选目标、预览和写入；不推断运行会话已切换 |
| Todos | 项目任务、运行/产出历史、人工关口 | 本地任务与来源绑定，方案/结果/问题独立呈现，版本与验收分开 | 明确待回答/确认/验收及来源入口 | 不连接 Todos，也能组织和处理本地任务；手工标记与来源批准区分 |
| New API | 模型/接口治理、协议能力、路由策略、额度与用量管理 | 先内建接口配置、协议约束和带来源的预算/用量；代理执行、渠道健康与故障转移单列后续设计和验收 | 已有预算异常与具体原因 | 不安装 New API，也能使用本地管理；只读状态不计为路由或网关交付 |

网关执行、渠道故障转移、限流和账单属于另一组业务能力，需明确请求授权、凭据、重复计费与常驻预算后按批次实现；不从一个“已连接”标签推导这些能力。功能融合不等于把所有上游模块照搬，采用本项目适用的能力，保留轻量目标。借鉴交互和能力不自动授权复用源代码；实际复用仍需许可证核对。

## 1.2 平台路线与交付顺序

用户已确定：**macOS → Windows → Linux → Web 与移动端**。三种桌面系统都要有同一套产品能力；按平台逐个完成和验收，不能将跨平台构建成功当作产品已经可用。Web 与移动端属于桌面端稳定后的阶段，两者之间及 Android / iOS 之间尚未确定先后。

| 阶段 | 目标 | 转入下一阶段的条件 |
| --- | --- | --- |
| macOS | 完成灵动岛与工作台、任务流程、配置连接和窗口布局，作为桌面体验基准 | 本方案桌面范围交付；跳转与动画稳定；输入不被采样覆盖；资源、权限、迁移、打包及发布验收通过 |
| Windows | 提供同一套桌面能力，适配窗口、托盘、会话入口、凭据与安装更新 | Windows 真机验证核心流程、权限拒绝、多屏、窗口布局撤销和版本升级；能力差异明确展示 |
| Linux | 提供同一套桌面能力，核实桌面环境与窗口管理器差异 | 明确支持的发行版和桌面环境，分别验证目标环境；窗口操控限制按实际能力显示 |
| Web 与 Android / iOS | 桌面端稳定后独立规划 | 重新确定场景、连接方式、权限、交互和验收，不将桌面页面直接缩小复用 |

共享的是任务/运行/产出、用量来源、配置元数据和状态口径；平台相关的进程探测、应用与会话导航、窗口布局、凭据引用、通知、安装更新由适配层承接。平台差异通过能力表返回界面，未验证能力不显示为可用。保留同一产品的信息架构与品质标准，系统材质、窗口行为和权限引导遵循各平台习惯。

移动 App 需要特殊定制，候选场景是查看进展、处理明确的人工关口和回到来源；触屏导航、推送与后台行为在移动阶段重新设计。Web 的远程数据来源、桌面桥接或服务端架构届时评估；浏览器不能直接获得桌面进程和窗口权限。当前不引入云端同步或远程执行作为桌面功能的前置依赖。

第 8 节 A–E 是 macOS 内部的功能实施顺序。Windows 在 macOS 范围完成后接续，Linux 再接续；当前阶段整理共享契约和平台边界，不并行开发后续平台 UI。

## 4. 功能落位

| 功能 | 灵动岛 | 工作台 | 优先级 |
| --- | --- | --- | --- |
| 工作 / 待确认 / 已完成 | 精简状态、具体动作、来源会话入口 | 会话列表、待处理队列、历史 | P0 |
| CPU / 内存 / 卡死提醒 | 原因和检查入口，不显示裸分数 | 趋势、依据、可观测性说明 | P0 |
| Token / 费用 | 单行 24h / 累计摘要 | 趋势、模型/工具拆分、导出 | 已有；继续收敛 |
| Todos 工作流 | 至多一条需处理任务、数量与具体动作；进入来源会话/任务 | 项目看板、运行记录、方案/结果及会话关联 | P1，先借鉴本地交互；服务接入另行验证 |
| 模型 / Provider | 可选快捷入口；只显示配置目标与生效提示 | 连接、工具适配、档位、差异与回滚 | P1 |
| 接口 / 协议 / 额度治理 | 简短预算异常与具体原因 | 内建接口和模型配置、协议能力、预算与来源对照；借鉴 New API | P1；请求执行另设验收 |
| 请求路由 / 渠道治理 | 经验证的异常摘要 | 内建策略、渠道健康与故障转移；按授权、计费和资源要求独立实施 | 后续能力；外部连接不抵扣交付 |
| MCP / Skills / 提示词 | 不放编辑器 | 内建管理、作用范围、差异、备份与按工具应用 | Codex MCP、用户 Skills 启停及本地提示词库、Codex/Claude Code 用户指令预览应用还原已接入；安装同步、其他配置适配与客户端加载待验收 |
| GUI 多窗口排列 | 配置好后可选一个“应用布局”快捷动作 | 窗口选择、屏幕与布局预览、应用、撤销、保存 | P1 |
| 工作空间 | 仅当前空间名称与快速进入 | 项目 + 任务 + 工具 + 配置 + 窗口布局的组合 | P3，等各模块稳定 |

默认灵动岛不增加整排功能按钮。快捷动作最多展示与当前状态直接相关的一项；其他操作进入工作台。

## 5. 工作台信息架构与操作

目标一级导航为：**概览、会话、任务、模型与连接、用量、窗口布局**；管理组为：**工具与扩展、通知、设置**。导出并入用量的页内动作。模块实际完成后才把入口加入界面，避免可点却不可用。

- 概览：运行摘要、需处理事项、实时监控、当前任务。具体配置进入独立页。
- 会话：按工具与项目筛选；“查看用量”和“打开会话”分开。无法定位的工具明确提示能力限制。
- 任务：看板按未开始、执行中、需处理、已结束分组，需处理进一步区分待回答、待确认方案和待验收结果。任务关联项目、工具和来源会话；简单待办保留，勾选不会替用户批准工具操作。
- 模型与连接：一个入口里以工具/连接/档位分层；当前配置与实际运行模型分开显示。写入前差异预览，写入后标明何时生效。
- 窗口布局：选择要排列的工具窗口 → 选择屏幕和模板 → 预览 → 应用 → 可撤销。不默认移动所有应用。

## 5.1 Todos 工作流的具体借鉴

[任务文档](https://todos.dev/zh/docs/todos)明确区分方案确认与改动审核；[方案与改动](https://todos.dev/zh/docs/plans-and-diffs)保存按次运行和文档版本；[收件箱](https://todos.dev/zh/docs/inbox)集中人工关口并处理过期提问。这三点优先转译为本地工作台能力。

| 需处理类型 | 灵动岛示例 | 点击目的地 | 工作台承接 |
| --- | --- | --- | --- |
| 待回答 | “Codex · 请选择实现方式” | 对应问题/来源会话 | 问题全文与可用选项 |
| 待确认方案 | “TraeWork · 待确认重构方案” | 对应方案/来源会话 | 方案、影响范围、修订版本 |
| 待验收结果 | “Codex · 待验收登录页” | 对应结果/来源会话 | 产出、diff、预览与验证依据 |
| 执行失败 | “工具名 · 构建失败” | 对应失败运行 | 失败原因、最后进度、手动重试 |

以上为目标交互示例，当前尚未取得 TraeWork 精确会话协议。动作类型由可信事件/任务上报提供；仅有通用 attention 时显示“待确认”并保留原文，不能推测它一定有方案。Agent 执行结束先记“结果就绪”；只有明确验收事件才进入“已验收”。进程退出和低 CPU 均不能推导任务已完成。

数据方案：简单待办维持 `kind=manual` 及原有完成语义；Agent 任务单独关联 `project_id`、`agent_id`、来源系统及稳定 `task_id`。每次执行保存 `run_id`，方案/结果引用自己的 `artifact_id` 与版本，`attention_kind` 表示人工行动类别。新模型扩展现有存储时迁移保留旧 ID、文字、完成状态，不能将普通清单全变成调度任务。

首版使用已有事件和用户关联建立本地记录；精确工具能力按适配表显示。先做任务看板、来源绑定、人工关口和只读历史，再考虑提案卡、定时任务与团队编排。调度执行属于后续显式能力，当前研究不安装或运行 Todos 执行机。

[官方 MCP 文档](https://todos.dev/zh/docs/mcp)允许只读授权，建议作为可选服务连接独立实现：凭据通过钥匙串/环境变量引用，按需查询；外部任务带来源标记，缓存超时和断线可见。打开来源与批准、取消、验收分开，不因读取权限而展示可用的写动作。

[定时文档](https://todos.dev/zh/docs/schedules)中的“到点取消遗留运行”不直接沿用。我们的初步方案是同一任务在运行时跳过新触发并记录原因；任何取消或重跑须遵循明确的任务策略。

**验收**：三类人工关口各有对应入口；旧问题过期后不能回答；重跑产生新运行并保留旧产出；缺少来源 ID 不误绑最新会话；执行结束不自动变成人工验收；简单待办迁移无损；后台采样不覆写输入。外部调度、远程机器、云端沙箱和团队记忆列为后续研究，避免首版常驻负担。

## 6. GUI 多窗口排列首版

先支持 macOS，再按平台实现原生适配。首版模板：左右并排、主窗 + 两个辅窗、均分网格。按显示器可用工作区计算，避开菜单栏和 Dock；每个窗口检查可移动、可缩放和最小尺寸。

macOS 调研入口：[Apple AXUIElement](https://developer.apple.com/documentation/applicationservices/axuielement)。后续实现前需要核实各工具窗口的可写属性和权限行为。技术选型为平台适配器，能力判断结果回传 UI；不能只凭应用进程存在就假设其窗口可调整。

只在用户配置布局时引导授予所需系统权限。权限不足、窗口已关闭、全屏、其他桌面、最小尺寸限制分别给出原因。应用前保存原始几何；部分失败时给出逐窗结果及撤销入口，不假报全部成功。撤销只针对本次仍存在的同一窗口。标题只在本机界面使用，不进入发布截图、遥测或日志。

## 7. 配置与网关接入边界

优先交付内建配置、模型、任务与用量能力，保持低开销监控。外部网关连接为可选互操作；已做的连接偏好与状态读取不是功能融合主线。代理执行不默认启用，不靠安装上游产品替代内建实现。

1. 每个工具只允许一个配置写入方。检测外部改动后重新读、展示差异，避免与其他工具互相覆盖。
2. 服务地址、模型和认证引用是连接配置；密钥只通过环境变量或钥匙串使用，导出不包含值，不读取各工具 OAuth 凭据来复用登录。
3. 可选外部服务 API 以实测版本和权限为准，先只读验证；这是互操作的实施顺序，不是内建治理的前置依赖。打开控制台与 API 可访问分别显示。
4. 本机会话用量和网关账单分别显示来源与口径；未核对关联不能相加，不能由当前配置反推历史请求的供应商。
5. 请求探测由用户手动执行，明确可能发出测试请求；超时、失败和缓存时间可见，隐藏页面暂停刷新。
6. 同一连接不串联多个协议翻译层。协议支持和工具实际使用能力分别验证。

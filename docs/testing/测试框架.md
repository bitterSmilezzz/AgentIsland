# AgentIsland 可持续扩充的测试框架

> 需求设计基线，2026-10-14，持续实施。runner、注册表、基础 profile、JSON/JUnit 报告与 macOS CI 配置已落地；其余分层与指标仍是验收目标，不能据本文宣称通过。当前命令见 [自动开发流水线](../ops/自动开发流水线.md)，实际运行与限制见 [统一交付记录](测试自动化交付.md)。服务商成本、系统权限和真实账号测试须单独授权。
> 范围：[需求](../spec/需求.md)、[功能对齐](../spec/功能对齐清单.md)、[逐项验收矩阵](../spec/需求测试矩阵.md)。目标是让漏测和不完整证据可检测，不承诺零缺陷。

## 1. 一个可扩充的证据图

每项需求稳定ID；测试登记父需求、场景/风险、实现/测试路径、正例/负例/故障、宿主OS/目标平台、工具与版本、前置资源/输入产物、超时/清理、是否费用/外部访问、所属门禁及证据状态。

链路：需求版本 → 设计/变更 → 测试清单 → 执行run → 构建SHA/工作树指纹 → 独立审查 → 同包验收 → 授权合并/发布。

新增需求必须在矩阵出现；新增测试必须登记；删除/放宽断言要附需求变更与独立审查。未知需求ID、重复test ID、未登记测试、丢变体、空扫描、遗漏必需层和过期证据都由元测试阻断。旧事故绑定永久回归，名称变化不丢关联。

## 2. 分层框架

| 层 | 范围 | 主要方法 | 环境 |
| --- | --- | --- | --- |
| L0 契约/清单 | schema、需求测试关系、版本、扫描、配置、迁移与发布清单 | schema校验、目录枚举、负例、清单自检 | 干净检出，无用户数据 |
| L1 纯逻辑 | 状态机、路由策略、预算/配额、时间窗口、权限、队列、版本 | 固定时钟/RNG、表驱动、属性测试、模型状态机 | 合成数据，确定性 |
| L2 格式/协议 | JSONL/SQLite/schema、4类LLM协议、MCP/runtime、SMS/邮件/push回执 | golden/差分、round-trip、分片/乱序/重复/畸形、限额/fuzz | 脱敏夹具、本地模拟服务 |
| L3 模块集成 | 引擎→任务→通知，路由→认证→上游→用量，执行→Git→版本 | 真临时文件/DB/socket、假客户端、故障注入 | 独立HOME、临时repo/钥匙串/端口 |
| L4 UI浏览器 | 三种桌面壳、完整任务/路由界面、手机适配、草稿/焦点/滚动 | Playwright真实DOM/键盘/鼠标、AX/截图与几何 | 锁包+浏览器版本、合成内容 |
| L5 正式包原生 | App身份、签名、启动/单实例/Dock/托盘、窗口、系统通知 | 新构建同哈希、原生输入/读回/视觉验收 | 隔离Mac VM，后续Windows实机/VM |
| L6 客户端/服务 | 支持的Agent实际版本、真实协议/账号、邮箱/SMS/手机送达 | 官方客户端受控端点优先；授权沙箱/设备实测 | 可选明确选择，额度/收件人白名单 |
| L7 长时/故障 | 资源、背压、队列、并发、睡眠断网、崩溃恢复、升级回滚 | soak、基准、混沌、重复创建释放、故障恢复 | 固定负载/预算、独立环境 |
| L8 自动开发/发布 | 收需求→授权→开发→测试→审查→合并→候选发布→复盘 | 假Agent确定性场景+少量受控真Agent；流水线负例 | 隔离worktree、假Git远端/沙箱部署 |

源码回归先于构建；新构建/签名先于随包CLI和原生门禁；最终审查与CI绑定同一个SHA。独立项可失败后继续汇总，依赖失败下游blocked，不去验证旧包。

## 3. 关键专项覆盖

### 监控准确性

建立每Agent×版本×OS的真值回放：静止/工作/新用户轮/工具续轮/多确认/完成/退出/PID复用/exec/数据库锁/日志重写/时钟回拨/睡眠恢复。测误报、漏报、状态滞后和重复通知，分工具报告，不用总平均掩盖低覆盖。采样CPU/文件写入只是弱证据。真实来源缺失时明确未验。

### 网关

4类协议共16个有向组合（12互转+4原生），按模型实际支持特性细分文本、tools、并行工具、reasoning、图片、usage、取消/错误/finish。校验ID、参数分片和工具结果不丢；不支持字段明确拒绝/降级。fallback在首字节前后分支分别验证，不重复工具副作用；请求级账目和每次上游尝试账目分别对账。

策略固定时钟、RNG、配额、reset与权重；嵌套组/重复候选/循环/深度/Strict/Pause/意图超时/长上下文升级全覆盖。账号、模型、内容拒绝分类不串，防止一个错误使所有账号休眠。未知额度不当零；更新策略不污染在途轮次。

### 通知与费用

统一事件ID+渠道幂等键；重复/乱序/重启/租约过期测试。受理、设备送达、用户已读独立；未知回执不能算成功。SMS超时可能“服务端已受理但客户端未收到ACK”，必须先查幂等结果而非盲重发收费；超过预算停止并走已授权备用渠道。常规CI零真实短信/邮件，真发送须测试号码/邮箱、发送额度、环境授权和清理。

本轮交付的**通知入站账本**（NOT-01 的入队幂等 / 重启恢复 / 批量并发）落在这一节：入站身份按
「agent + 规范事件类型 + 稳定 id」分域，未带 id 的接入按内容与到达秒兜底；未确认提醒的安全摘要
跨进程恢复、确认后不复活；突发有界并显式报告重复、冲突与淘汰。验收同时覆盖两层——
`rust.default` / `not01.*` 的定向与真实 HTTP 用例，以及 `not01.ledgerrestart` 的**三次独立进程**验收。

本轮另新增一个常驻进程内的合成诊断入口 `--notify-ledger-probe <临时目录> <1|2|3>`，只用于该跨进程
重启验收。它的边界是收敛的：只监听 `127.0.0.1:0` 临时端口、不读用户配置、不取令牌、不外发、不开 GUI、
不派发真实系统通知，目录必须是系统临时目录下**带所有权标记的空目录**；`scripts/test-notify-ledger-restart.py`
跑三次独立进程，并校验账本 0600 且**不含**私密正文与原始 client id。

同时修正 `scripts/restart-app.sh`：它原先用 `pkill -f`（SIGTERM）重启，**不经过 Tauri 退出链**，
而通知账本的写盘收尾钉在 `RunEvent::ExitRequested`/`Exit` 上——于是本仓库唯一规定的重启动作恰好
绕过了新加的收尾。现在先走 Apple Event 优雅退出（等最多 8 秒），未生效才用信号兜底并明说。

### 任务执行与安全

外部监控来源与自有执行产物分开；独立worktree，计划确认绑定版本，修改计划重新审；Done不自动代表merge，merge不自动代表deploy。并发抢任务、机器掉线、重复ACK、取消后迟到结果、重启pending、base分支移动、冲突修复后diff变化都必须重新核对，不能重复执行副作用。

权限按人/Agent/机器/项目/API key/操作/有效期判定；原工具安全设置保持，不能照抄Todos“无sandbox”作为默认。测试提示词注入、恶意MCP/技能内容、symlink/路径越界、跨团队/项目读取、凭据回显、授权撤销、远程控制重放，副作用前再次授权检查。

## 4. 自动开发闭环（参考 Magpie 自动维护）

1. **收集/澄清**：输入来源与报告人场景、重复需求关联、范围/预算/权限；无法决定的关键项暂停并提问。
2. **需求版本**：验收场景先登记；按风险选择必需测试层。需求变化使相关计划/审批失效。
3. **Red check**：缺陷修复先重现报告人的真实操作面；保存旧版本/回放失败证据。新增能力以合同/负例建起判别力，不为文案修改制造无意义测试。
4. **开发与Break check**：最小实现、接口/不变量、边界/失败/并发；门禁至少有能编译的破坏反例，破坏生产工作树禁止。
5. **独立审查**：作者和审查者分开，审查提交SHA/产物一致；修改后相关检查与审查失效，禁止借用旧绿灯。
6. **候选门禁**：必需测试全通过且CI终态完成；Not run/blocked明确记录，不能省略。预授权合并仅匹配已审SHA，发布绑定同一包、版本、签名与清理证据。
7. **失败暂停**：失败/权限不足/预算耗尽保留现场，通知所有者，不静默放宽测试或重复执行。flaky可单独调查，原失败保持。
8. **复盘**：每任务结束/事故/候选发布记录LESSON：规则、原因、commit/issue/test、Seen日期与Done right；跨三个不同日期重复教训建议转规范+回归，严重安全立即处理。夜间批处理的具体触发/幂等/权限须定义，不能只建空LESSONS文件。

用户参考自动维护机制不等于本轮授权真实自动发布。项目级预授权策略、需求确认与发布门按 [需求§5](../spec/需求.md#5-全自动开发采用的参考与权限边界)。

## 5. runner、profile与清单（设计）

现有 Python 3 编排沿用 Rust/Node/Python/Bash 测试，单份 JSON 清单、argv 数组执行、JSON/JUnit/Markdown 输出；Bash 只在声明宿主运行。fast/ci/browser/package/native/client/manual/automation/soak 为当前入口；下表包含后续分层目标，protocol/delivery/release 未逐一实现时必须明确未验。崩溃/重启恢复尚无实现，已从 profile 中移除而不是留一个指向 soak 的别名。

| profile | 范围 | 用途 |
| --- | --- | --- |
| fast | L0/L1/必要L2/前端逻辑 | 开发反馈、无付费外部请求 |
| ci | L0–L4及runner元测试 | 每PR；固定工具/浏览器，平台缺层显式blocked |
| package | 构建+随包CLI | 已过源码回归的候选 |
| native | L5，同包hash | Mac基准后接Windows |
| protocol / client / delivery | L6按显式清单 | 官方客户端、真服务和设备分开 |
| soak / recovery | L7 | 长时协议、预算、升级回滚（soak 已接线；崩溃/重启恢复无实现，profile 已移除） |
| automation | L8 | 全自动开发系统自身的安全与失败行为 |
| release | 所有适用必需层与授权检查 | 不自动支付/放宽门禁/修改用户环境 |

结果状态：passed/failed/blocked/not_selected/not_applicable。适用的必需检查blocked即总失败；不适用附能力契约，未实现不能写不适用。run ID、需求版本、HEAD/工作树指纹、工具版本、平台/宿主、构建hash、退出码、清理结果、审查SHA完整登记。外部响应/会话/凭据禁止原样入公开证据。

## 6. 扩展与充分性的门槛

- 新provider/runtime/通知渠道/平台必须提交能力schema、脱敏/golden样本、正负故障场景、登记和独立验收，不允许只有“接入成功”截图。
- 关键状态/权限/路由/账目使用分支/属性/变异测判别力；Rust覆盖率用正规工具试验后采集，JS同理。覆盖率按模块与风险报告，不能用“973条测试”或总百分比证明需求完整。
- 需求测试映射登记率目标100%；候选版本的适用必需检查执行率100%、严重阻断0。未覆盖/未验明确列出，不能用空清单满足。
- 资源/延迟/SMS费用/并发阈值必须有可测基线与限制；未定阈值时结论为“预算未判定”，不是PASS。
- 新模块先用模拟/故障实验，真服务只补合同无法证明的环节；真设备最终证明到达与原生交互，单元测试不能替代。
- 测试元测试覆盖：发现遗漏、重复ID、空范围、子进程非零、超时回收、错误前置、旧构建、伪成功回执、未执行、断言删除、并发日志污染、清理失败与中断。失败信号必须能传到自动开发/发布顶层。

## 7. 现有资产迁入与实施顺序

现有release引用45个不同test文件，磁盘47个，另有UI冒烟与原生probe；这些只是本轮静态盘点，不证明全新需求覆盖。先完整展开循环及壳变体，登记每个现有测试与对应需求；既有Ready/Accepted/关口、存储、通知、配置测试保留。

实施顺序：需求/对齐矩阵→现有资产登记/runner自测→Mac核心/协议模拟环境→UI/新包原生→网关与执行/通知分模块验收→端到端自动流水线→真实服务/长测/灾备→Windows→Android/iOS→Web→Linux。此处是建设顺序，不是声明全部已做。
